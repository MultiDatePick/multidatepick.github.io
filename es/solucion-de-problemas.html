Busca el mensaje que ves o elige una categoría y sigue la solución. Todas las imágenes son del componente real.

Categorías

Nada en esta página coincide. Prueba con menos palabras u otra categoría, o escribe a soporte con una captura de pantalla de lo que ves.

Configuración y ubicación

Avisos y advertencias que ve un administrador al colocar un calendario en una página o al crear su configuración.

No aparece el botón Guardar

Por qué: el componente no tiene un registro principal y no está configurado para mostrar todos los registros. Las páginas de aplicación y de inicio no tienen registro propio.

Solución

  1. Abre la configuración en el asistente de configuración y responde a ¿Los registros de quién? (lo habitual es Solo de quien lo ve), o define Vincular cada selección a este registro (App Builder: Static Parent Record Id) con el registro al que pertenecen las fechas.
  2. Comprueba que el objeto, el campo de fecha y el campo de relación están rellenos, o define Config Name (Nombre de configuración).

En un flujo, el botón Guardar aparece en cuanto Parent Record Id está enlazado. Sigue oculto cuando en el asistente ¿Quién las guarda? está en Mi flujo las guarda, o cuando Parent Record Id está en blanco: entonces el botón Siguiente del flujo lleva las fechas.

Aviso ámbar: «Componente incorrecto para esta configuración»

Por qué: Config Name apunta a una configuración guardada para otro componente.

Solución

  1. Haz que Config Name apunte a una configuración creada para este componente, o
  2. Cambia al componente para el que se creó la configuración, o
  3. Abre la configuración en el asistente de configuración y cambia su Tipo de componente.

Aviso ámbar: «Configuración no coincidente»

Por qué: el registro de la página, o el registro de Vincular cada selección a este registro, es de un objeto distinto del que busca el campo de relación de la configuración.

Solución

  1. Coloca el componente en una página de registro del objeto que indica el aviso, o
  2. Vincula cada selección a un registro de ese objeto, o
  3. Usa una configuración creada para el objeto de esta página.

Aviso rojo: «Este componente no pudo cargar sus datos»

Por qué: un nombre de campo u objeto de la configuración es incorrecto, o el usuario no puede usar MultiDatePick o leer el objeto y sus campos.

Solución

  1. Lee el recuadro gris: indica el campo, el objeto o la clase de Apex exactos. Si falta el acceso a MultiDatePick, el aviso dice qué conjunto de permisos asignar.
  2. Nombre incorrecto: copia el nombre de API exacto desde Configuración, Gestor de objetos.
  3. Sin acceso: asigna el conjunto de permisos MultiDatePick - User y el acceso a tus propios objetos. En un sitio público de Experience, asigna MultiDatePick - Guest al usuario invitado y dale acceso de lectura a tus propios objetos.

Resource Booking muestra «Configuración requerida»

Por qué: Resource Booking necesita un objeto de recurso, un objeto de reserva, un campo de fecha de la reserva y un campo de recurso de la reserva. El panel enumera los que faltan.

Solución

  1. Define Config Name con una configuración de Resource Booking del asistente de configuración, o
  2. Rellena cada propiedad que enumera el panel.

«No se encontró ninguna configuración llamada "Room_Bookings"»

Por qué: Config Name usa el nombre de API de la configuración, el de la lista Configuraciones existentes del asistente de configuración (por ejemplo Contact_Event), no su etiqueta. Un error de escritura, la etiqueta o una configuración guardada hace un momento que aún se está desplegando: todos acaban aquí.

Solución

  1. Abre el asistente de configuración, luego Configuraciones existentes, y copia el nombre de API de la configuración.
  2. Pégalo en Config Name en el componente y guarda la página.
  3. ¿Acabas de guardar la configuración? Salesforce la despliega en segundo plano, lo que tarda de 30 segundos a 2 minutos. Actualiza Configuraciones existentes hasta que aparezca y recarga la página.

Si el mensaje dice en cambio que el usuario no tiene acceso a MultiDatePick, consulta sin acceso a MultiDatePick.

«El registro de Static Parent Record Id (a015g00000XyZ12AAB) ya no existe»

Por qué: el calendario guarda cada selección en un único registro fijo, definido en Vincular cada selección a este registro (App Builder: Static Parent Record Id), y ese registro se eliminó. No se puede guardar nada hasta que apunte a un registro que exista.

Solución

  1. Abre la configuración en el asistente de configuración y elige otro registro en Vincular cada selección a este registro.
  2. En una página sin Config Name, pega el Id de un registro actual en Static Parent Record Id en App Builder.

Las fechas se guardan, pero no aparecen la próxima vez

Por qué: Mostrar fechas ya guardadas (App Builder: Load Existing Dates) está desactivado. Los registros se guardaron, pero el calendario se abre vacío cada vez.

Solución

  1. Activa Mostrar fechas ya guardadas.
  2. Recarga la página. Aparecen las fechas guardadas, con el color de su estado si hay un campo de estado definido.

«Este calendario no puede mostrar los registros existentes ni guardar otros nuevos: el campo "Visit Date" de Visit está cifrado con Shield Platform Encryption»

Por qué: Salesforce no puede buscar ni ordenar por un campo protegido con Shield Platform Encryption, y el calendario busca y ordena sus registros por sus campos de fecha, hora y nombre. Esos campos no deben estar cifrados. Los campos que el calendario solo muestra, como las notas de la tarjeta emergente, pueden seguir cifrados.

Solución

  1. Desactiva el cifrado del campo que indica el mensaje, en Configuración, Política de cifrado, o
  2. Abre la configuración en el asistente de configuración y elige en su lugar un campo de fecha u hora sin cifrar.

Un filtro «no coincide con un campo y un valor», o «No se pudieron cargar los recursos»

Por qué: un filtro nombra un campo que no está en el objeto, un campo por el que Salesforce no puede filtrar o un valor que no encaja con el campo. El calendario dice cuál, por ejemplo Filtro de registros: "Status__c=Confrimed" no coincide con un campo y un valor filtrables de Visit. o No se pudieron cargar los recursos: la condición "Active__c es yes" no corresponde a ese campo.

Solución

  1. Abre la configuración en el asistente de configuración.
  2. Vuelve a elegir el campo y el valor en las listas de Solo registros donde (los registros que se muestran) o Mostrar solo aquellos donde (las salas o personas que se ofrecen).
  3. ¿Lo escribes en App Builder? Usa el nombre de API del campo y un valor que encaje con su tipo: una casilla admite true o false, y una fecha, 2026-12-31.

«Rellenar automáticamente (Priority = High) usa Priorty__c, un campo que Visit no tiene»

Por qué: Rellenar automáticamente (App Builder: Default Field Values) rellena campos en cada registro nuevo, y uno de sus pares nombra un campo que el objeto no tiene. El asistente de configuración lo indica en Revisar, con el nombre del campo que no encontró. Un valor que el campo no admite, como un valor de lista de selección que no está en su lista, aparece en cambio cuando el calendario guarda: Valores de campo predeterminados: "Priority=Urgent" no coincide con un campo y un valor de Visit.

Solución

  1. Abre la configuración en el asistente de configuración y corrige el par en Rellenar automáticamente (Priority = High). Comprueba el nombre de API del campo en el Gestor de objetos.
  2. Escribe un valor que encaje con el campo: las casillas admiten true o false, las fechas yyyy-mm-dd o TODAY+7, y las listas de selección, uno de sus valores.
  3. Separa varios pares con punto y coma: Priority=High; Type=Call.

«Duration no es un campo numérico», o una reserva ocupa todo el día

Por qué: Campo con los minutos (App Builder: Duration Field) debe ser un campo numérico de la reserva, no una fórmula, un resumen acumulado, una divisa ni un porcentaje. Cuando está definido y Termina a las se deja en blanco, cada reserva termina a su hora de inicio más esos minutos, así que un registro sin minutos no tiene fin y ocupa todo el día.

Solución

  1. Elige un campo numérico que guarde la duración en minutos, o crea uno.
  2. Rellena una sola vez los minutos de los registros antiguos, por ejemplo con una actualización de datos o un flujo. A partir de ahí, cada guardado, movimiento y cambio de tamaño desde el calendario los escribe.

«Visit no tiene un tipo de registro activo Install, que este calendario asigna a los registros nuevos»

Por qué: Tipo de registro de las reservas nuevas nombra un tipo de registro que se desactivó o se renombró. Un mensaje relacionado, Confirmed no es un valor de Visit Status para los registros de tipo Repair, significa que el estado elegido no es uno de los valores que ofrece ese tipo de registro.

Solución

  1. Abre la configuración en el asistente de configuración y elige un tipo activo en Tipo de registro de las reservas nuevas, o elige El predeterminado de cada persona o Dejar que cada persona elija.
  2. Para un estado: añade el valor a los valores de lista de selección de ese tipo de registro en el Gestor de objetos, o elige otro estado.

Si el mensaje dice que la persona no puede crear registros de ese tipo, consulta tipo de registro no permitido.

«Solo los administradores ven esto, en el generador: este calendario cuenta la capacidad pero no tiene Config Name»

Por qué: sin una configuración guardada indicada en la página, el calendario solo puede contar las reservas que ve el usuario. Las que la colaboración le oculta quedan fuera, así que una hora completa puede parecer libre.

Solución

  1. Guarda la configuración en el asistente de configuración.
  2. Escribe su nombre en Config Name en el componente. Así los recuentos incluyen todas las reservas, solo como números.

Solo los administradores ven esta nota, en App Builder. Los usuarios, nunca.

No aparece el botón Añadir al calendario después de guardar

Por qué: Show Add to Calendar After Saving (Mostrar «Añadir al calendario» después de guardar) está desactivado. Viene desactivado por defecto.

Solución

  1. Actívalo en las propiedades del componente o en la configuración y guarda un registro. El botón aparece en una barra bajo el mensaje de confirmación.
  2. ¿Ves «Añadir a Google Calendar» en su lugar? El navegador bloqueó la creación del archivo, así que un único evento recibe un enlace de Google Calendar.

Reservas y disponibilidad

Por qué no se puede elegir o reservar un día, una hora, una sala o una persona.

Resource Booking muestra «No hay recursos disponibles»

Por qué: la lista de recursos llegó vacía. Suele deberse a un filtro que no coincide con nada, a un objeto de recurso incorrecto o a que aún no hay registros de recurso.

Solución

  1. Comprueba Mostrar solo aquellos donde (App Builder: Resource Filter Field y Resource Filter Value) con un registro real.
  2. Comprueba Lista de opciones y Campo con el nombre de cada uno (App Builder: Resource Object API Name y Resource Name Field).
  3. Crea al menos un registro de recurso.

Aviso ámbar: «La capacidad necesita ambos campos de hora»

Por qué: Cuántos a la vez (App Builder: Capacity Field) está definido, pero falta el campo de hora de inicio o de fin de la reserva, así que no se puede aplicar la capacidad.

Solución

  1. Define Empieza a las y Termina a las (App Builder: Booking Start Time Field y Booking End Time Field), o
  2. Vacía Cuántos a la vez.

No puedo elegir otra fecha

Por qué: el componente tiene un límite de fechas: Max Dates Allowed (Máximo de fechas permitidas).

Solución

  1. Deselecciona una fecha para elegir otra, o
  2. Sube el límite, o ponlo en 0 para quitarlo.

No puedo reservar otra hora

Por qué: se ha alcanzado un límite de reservas. Max Time Slots (Máx. franjas horarias) limita las franjas en total, Max Bookings per Day (Máx. reservas por día) limita las reservas distintas en un mismo día (las horas contiguas cuentan como una) y Limit per Person (Límite por persona) limita las reservas futuras de un cliente, contadas en el servidor.

Solución

  1. Sube el límite, o ponlo en 0 para quitarlo.
  2. El personal puede superar «Límite por persona» tras una confirmación. Los visitantes del sitio, no.

Algunos días u horas aparecen en gris

Por qué: una regla de reserva los cierra. Minimum Notice (Hours) (Antelación mínima en horas) cierra lo que empieza demasiado pronto, Book Up To (Days Ahead) (Reservar hasta: días de antelación) cierra los días que quedan fuera de la ventana móvil, y Earliest o Latest Selectable Date (Primera o última fecha seleccionable), las fechas bloqueadas y el horario comercial de cada recurso cierran el resto.

Solución

  1. Revisa esos ajustes en el componente o en su configuración. Con 0 se desactivan la antelación y la ventana.
  2. Haz clic en una franja horaria cerrada: un cierre explica por qué lo está.

La franja justo después de una reserva aparece ocupada

Por qué: Buffer Between Bookings (Minutes) (Margen entre reservas en minutos) deja tiempo libre después de cada reserva del mismo recurso, para limpieza o preparación.

Solución

  1. Reduce el margen, o ponlo en 0 para reservas consecutivas.
  2. Cuando una hora está ocupada se sigue aplicando: con Omitir franjas en conflicto, una franja que cae en el margen se omite y se notifica como cualquier otro conflicto.

Solo aparecen algunas horas de inicio

Por qué: Solo estas horas está definido, así que la cuadrícula ofrece solo las horas de inicio de la lista. En Resource Booking, Horas propias de cada recurso tiene prioridad cuando una sala o persona tiene su propia lista. El horario comercial, los cierres, la antelación mínima y los conflictos siguen cerrando una hora de la lista.

Solución

  1. Edita la lista, o elige Cada intervalo, en el componente o en su configuración.
  2. Revisa la lista propia del recurso en su campo Horas propias de cada recurso.

«Estas selecciones ya no están dentro del período de reserva»

Por qué: la página estuvo abierta tanto tiempo que el día o la hora elegidos entraron en el plazo de Minimum Notice. Al guardar se vuelve a comprobar la regla, para que una página antigua no pueda reservar demasiado tarde.

Solución

  1. Quita las fechas que indica el mensaje o elige una hora posterior.
  2. Vuelve a guardar.

«No se puede reservar: ya está completo o cerrado el: 3 dic» o «Ya está completo o cerrado, así que se omitirá al guardar»

Por qué: otra reserva ya ocupa esa hora, o un cierre la cubre. Cuando una hora está ocupada decide qué pasa: Bloquear rechaza toda la reserva, Omitir franjas en conflicto reserva los demás días e indica los que dejó fuera, y Permitir (reservar de todos modos) ofrece un botón Reservar de todos modos.

Solución

  1. Quita las fechas que indica el mensaje, o elige otra hora u otro recurso.
  2. Un administrador puede cambiar Cuando una hora está ocupada en las reglas de reserva de la configuración.

«Límite diario alcanzado (2 de 2)»

Por qué: Máximo de reservas al día (App Builder: Daily Limit Field) es un número en cada sala o persona, como los 2 trabajos al día de un técnico. Cuando un día llega a ese número de reservas, se cierra para ese recurso, y al guardar ahí aparece Se alcanzó el límite diario, así que no se guardó nada. Cada registro cuenta una vez, una reserva de varios días cuenta en cada día y los estados que liberan la hora nunca cuentan.

Solución

  1. Elige otro día u otro recurso.
  2. Sube el número en el registro del recurso, o déjalo en blanco para no tener límite.
  3. Con Cuando una hora está ocupada en Permitir (reservar de todos modos), una reserva puede superar el límite.

«Garden Room no acepta reservas, así que no se guardó nada»

Por qué: el valor de Cuántos a la vez o de Máximo de reservas al día del recurso es 0. Un 0 significa que no acepta ninguna reserva, con cualquier opción de Cuando una hora está ocupada. Los selectores, la cuadrícula de horas y la vista Semana lo muestran en gris.

Solución

  1. Elige otro recurso.
  2. Para abrirlo a reservas, pon en su registro un número de 1 o más, o déjalo en blanco para no tener límite.

«Estas fechas ya pasaron y no se pueden reservar» o «Estas horas ya pasaron»

Por qué: el calendario no reserva días ni horas que ya pasaron. Un día elegido ayer en una página que se quedó abierta toda la noche, o una hora de hoy que ya pasó, se rechaza al guardar.

Solución

  1. Quita las fechas u horas que indica el mensaje y elige otras posteriores.
  2. ¿Necesitas registrar días pasados, como partes de horas? Un administrador puede activar Permitir fechas pasadas en la configuración.

«Estas fechas están cerradas: 25 dic. Elija otra fecha u hora.»

Por qué: un cierre cubre ese día: un registro de la Lista de días cerrados del calendario, como un festivo o un permiso del personal. Un cierre que nombra una sala o una persona cierra solo ese recurso. Tanto el calendario como el guardado lo rechazan.

Solución

  1. Elige otra fecha u hora.
  2. Si el día debería estar abierto, edita o elimina el registro de cierre, o restringe Solo cierres donde en la configuración.

«Garden Room no se puede reservar en este calendario. Elija un recurso de la lista.»

Por qué: la sala o persona no está en la lista de este calendario, porque Mostrar solo aquellos donde la deja fuera. Suele pasar cuando un registro cambió después de abrir la página, por ejemplo una sala marcada como inactiva. El servidor lo rechaza al guardar, mover y reasignar.

Solución

  1. Recarga la página y elige un recurso de la lista.
  2. Si debería ofrecerse, actualiza el registro del recurso o cambia Mostrar solo aquellos donde en la configuración.

«Los recursos seleccionados no tienen ninguna hora de inicio en común»

Por qué: con Reservar varios a la vez, una misma hora tiene que servir para todas las salas o personas elegidas. Su horario comercial o sus horas de inicio propias no coinciden, así que ninguna hora les sirve a todas. Un mensaje más corto, Los recursos seleccionados no tienen horario comercial coincidente, significa lo mismo.

Solución

  1. Elige menos recursos, o recursos que trabajen en el mismo horario.
  2. Un administrador puede revisar el horario y las horas de inicio propias de cada recurso.

Dos personas reservaron la misma hora

Por qué: uno de dos ajustes lo permite. Cuando una hora está ocupada en Permitir (reservar de todos modos) deja que el personal reserve a propósito sobre una hora ocupada. O bien El filtro también decide qué está ocupado está activado con un filtro que usa ME, así que solo las reservas propias de cada persona ocupan una hora. El asistente avisa del segundo caso: «El filtro también decide qué está ocupado» está activado y «Solo registros donde» usa ME, así que solo las reservas propias de cada persona ocupan una hora: dos personas pueden reservar la misma hora.

Solución

  1. Pon Cuando una hora está ocupada en Bloquear o en Omitir franjas en conflicto.
  2. Desactiva El filtro también decide qué está ocupado, salvo que cada persona reserve de verdad solo su propio tiempo.

«Límite por persona está activado, pero no hay ningún Campo de cliente»

Por qué: Límite por persona cuenta las reservas de cada cliente mediante Para quién es (App Builder: Client Field). Si no hay ningún campo definido, o es uno en el que Salesforce no puede buscar, como un texto largo, la reserva no se puede contar y se rechaza el guardado. Los administradores ven Límite por persona no puede contar las reservas por Notes en App Builder.

Solución

  1. Abre la configuración en el asistente de configuración y elige un campo de texto, de correo electrónico o de búsqueda en Para quién es.
  2. O pon Límite por persona en 0 para desactivarlo.

«Salesforce no respondió, así que es posible que esta reserva ya esté guardada»

Por qué: la conexión se cortó o Salesforce tardó demasiado después de pulsar Reservar, así que el calendario no pudo saber si el guardado terminó. Se vuelve a cargar solo para que lo compruebes.

Solución

  1. Busca la reserva en el calendario recargado.
  2. Vuelve a reservar solo si no está.

Invitados del sitio público

Calendarios en un sitio público de Experience Cloud, donde los visitantes reservan sin iniciar sesión.

Los invitados ven un calendario vacío

Por qué: la regla de colaboración para invitados aún no está en vigor, o al perfil de invitado le falta un paso.

Solución

  1. Define el valor predeterminado externo de toda la organización del objeto como Privado y haz clic en Recalcular en Configuración, Configuración de colaboración.
  2. Asigna el conjunto de permisos MultiDatePick - Guest al usuario invitado y dale permiso de Leer en cada uno de tus objetos y campos.
  3. Activa el sitio. Publicarlo no basta.

La lista completa de seis pasos para invitados está en la Guía del usuario. Comprobar mi sitio, en el asistente de configuración, revisa cada paso por ti.

Comprobar mi sitio dice «Requiere corrección»

Por qué: Comprobar mi sitio, en los pasos Revisar y Listo del asistente de configuración para un calendario de sitio, prueba el sitio tal como lo encuentra un invitado. Cada línea que dice Requiere corrección es un paso que falta, e indica qué hacer.

Solución

  1. El sitio aún no está en línea: en Espacios de trabajo del sitio, ve a Administración, Configuración, haz clic en Activar y después publica.
  2. Conjunto de permisos MultiDatePick - Guest: abre el usuario invitado y añádelo en Asignaciones de conjuntos de permisos.
  3. Acceso a objetos o Acceso a campos: da al usuario invitado Leer en lo que muestra el calendario y Modificar en lo que guarda una reserva.
  4. Un invitado no puede ver ninguno de los recursos: añade una regla de colaboración de usuarios invitados en el objeto de recurso, en Configuración, Configuración de colaboración.

Solo un administrador con MultiDatePick - Setup puede ejecutar la comprobación.

«Esta organización aún no tiene ningún sitio de Experience Cloud»

Por qué: Comprobar mi sitio no encontró ningún sitio que comprobar, así que no hay ningún sitio que elegir. El mensaje completo es Esta organización aún no tiene ningún sitio de Experience Cloud. Active Experiencias digitales en Configuración y cree un sitio; después, compruébelo aquí. La configuración en sí está bien y se puede guardar.

Solución

  1. En Configuración, busca Experiencias digitales, abre Configuración y marca Activar Experiencias digitales. Salesforce no permite volver a desactivarlo.
  2. Crea el sitio en Experiencias digitales, Todos los sitios, Nuevo.
  3. Vuelve a abrir la configuración en el asistente de configuración y pulsa Comprobar mi sitio en Revisar.

«Este calendario no puede guardar aquí: no indica ninguna configuración guardada para este objeto»

Por qué: la reserva de un invitado del sitio o de un usuario del portal se comprueba en el servidor con una configuración guardada, para que nadie pueda saltarse la privacidad ni las reglas de reserva. El calendario de la página del sitio no tiene Config Name, aunque el objeto ya tiene una configuración guardada.

Solución

  1. Abre la página del sitio en Experience Builder.
  2. Define el Config Name del calendario con la configuración guardada para este sitio y publica.

«Este calendario no se puede usar aquí: su configuración guardada no está preparada para un sitio público»

Por qué: la página del sitio indica una configuración creada para el personal. Los invitados del sitio y los usuarios del portal solo pueden usar una configuración guardada para un sitio, así que la privacidad y las reglas de un calendario interno nunca llegan al público por error.

Solución

  1. Define el Config Name del calendario con una configuración guardada para el sitio, o
  2. Crea una: en el asistente de configuración, responde a ¿Dónde va a estar este calendario? con En un sitio público y guárdala con un nombre nuevo.

«Esta página vincula las reservas a un registro que los visitantes del sitio no pueden ver»

Por qué: cada reserva del sitio se vincula a un único registro, definido en Las reservas se vinculan a, y el usuario invitado no puede leerlo. Salesforce mantiene los registros privados para los invitados salvo que una regla de colaboración de usuarios invitados los comparta.

Solución

  1. En Configuración, Configuración de colaboración, añade en el objeto de ese registro una regla de colaboración de usuarios invitados que lo comparta con el usuario invitado del sitio, con acceso de Solo lectura.
  2. Vuelve a ejecutar Comprobar mi sitio: Registro al que se vinculan las reservas debería salir correcto.

«No se guardó en esta página pública»

Por qué: Salesforce permite a los invitados del sitio leer y crear registros, pero nunca cambiarlos ni eliminarlos. Los visitantes pueden ver y reservar. Los usuarios con sesión iniciada y con acceso pueden editar.

Solución

  1. No hay nada que corregir: es la regla de Salesforce para invitados. Para que las personas cambien sus propias reservas, dales un inicio de sesión (un sitio para miembros), o deja que el personal haga el cambio.

«Cada reserva de este calendario dura 60 minutos, así que esta hora no se puede reservar»

Por qué: para los invitados del sitio y los usuarios del portal, el servidor comprueba cada reserva con la configuración guardada: Duración de la reserva, Solo estas horas, los estados que se pueden elegir, la antelación, el período de reserva y los límites. La página estaba abierta mientras el administrador cambiaba uno de ellos, así que ofreció algo que la configuración ya no permite. Relacionados: Este calendario acepta reservas solo en las horas de inicio indicadas y El estado Requested no se puede elegir en este calendario.

Solución

  1. Recarga la página y vuelve a reservar.
  2. ¿Se sigue rechazando? El administrador del sitio puede revisar esas reglas en la configuración indicada en Config Name.

Los miembros del sitio no ven los registros que han creado

Por qué: la colaboración de Experience Cloud. Los usuarios del sitio solo ven los registros que la colaboración les concede.

Solución

  1. Añade una regla de colaboración (o un conjunto de colaboración para miembros) en el objeto donde se guardan las fechas, o
  2. Abre su valor predeterminado externo de toda la organización.

«El sitio no permite que otros sitios web lo muestren»

Por qué: pusiste el calendario en tu propio sitio web con el código de inserción, y el sitio de Salesforce se niega a mostrarse dentro de otro sitio web, que es su comportamiento predeterminado.

Solución

  1. En Experience Builder, abre Configuración y luego Seguridad y privacidad.
  2. Define Clickjack Protection Level en Allow framing of site pages on external domains.
  3. Añade tu sitio web en Trusted Domains for Inline Framing y publica.

Los invitados ven la lista de ubicaciones, pero no el mapa

Por qué: el mapa lo dibuja un servicio de Salesforce que el sitio bloquea hasta que es de confianza. El calendario no puede saber si un sitio lo bloquea, así que en un sitio se abre con la lista y ofrece el mapa.

Solución

  1. En Experience Builder, abre Configuración y luego Seguridad y privacidad.
  2. Añade maps.a.forceusercontent.com como sitio de confianza para marcos y publica.

Permisos y seguridad

El calendario funciona con los permisos de cada usuario. Empieza por el conjunto de permisos adecuado y después da acceso a tus propios objetos y campos.

Conjunto de permisosAsignar a
MultiDatePick - UserTodos los que usan los calendarios
MultiDatePick - SetupAdministradores que crean configuraciones. Incluye el asistente de configuración.
MultiDatePick - All AccessAdministradores que los crean y los usan
MultiDatePick - GuestEl usuario invitado de un sitio público de Experience Cloud

Los mensajes de error indican qué falla: el campo, el objeto o la regla de validación. Cuando un mensaje termina en Detalles:, ese texto es la descripción de la propia Salesforce. Envíalo a tu administrador, o a nosotros, y dirá exactamente dónde mirar.

«Necesita una licencia de MultiDatePick para usar este calendario»

Por qué: MultiDatePick se licencia por usuario, y a este usuario no se le ha asignado una licencia. El calendario se sustituye por este aviso y se rechazan los guardados. Los invitados del sitio nunca necesitan licencia.

Solución

  1. En Configuración, abre Paquetes instalados y después Gestionar licencias junto a MultiDatePick.
  2. Haz clic en Agregar usuarios y añade al usuario. Verá el calendario la próxima vez que cargue la página.

«Este usuario no tiene acceso a MultiDatePick, así que no se cargó la configuración»

Por qué: el usuario no tiene ningún conjunto de permisos de MultiDatePick, así que Salesforce no deja que el calendario ejecute sus clases para él. El aviso rojo lo indica, con las palabras de la propia Salesforce en el recuadro gris.

Solución

  1. Asigna MultiDatePick - User al usuario, o MultiDatePick - All Access a un administrador que también crea configuraciones.
  2. En un sitio público, asigna MultiDatePick - Guest al usuario invitado del sitio.

«You do not have access to the Apex class named 'MultiDatePickConfigDeployer'»

Por qué: son palabras de la propia Salesforce y significan que falta un conjunto de permisos: el usuario no tiene ningún conjunto de permisos de MultiDatePick, así que Salesforce no deja que el calendario ejecute sus clases. El nombre de la clase cambia según lo que estuviera haciendo el calendario. La línea suele aparecer en el recuadro gris bajo el aviso rojo, debajo de Este usuario no tiene acceso a MultiDatePick.

Solución

  1. Asigna MultiDatePick - User al usuario, o MultiDatePick - All Access a un administrador que también crea configuraciones.
  2. En un sitio público, asigna MultiDatePick - Guest al usuario invitado del sitio.
  3. Recarga la página.

El registro no se abre, o aparece «privilegios insuficientes»

Por qué: el usuario no puede leer el objeto principal, o la colaboración le oculta ese registro. En un flujo de pantalla, puede que el usuario no tenga permiso para ejecutar flujos.

Solución

  1. Asigna MultiDatePick - User.
  2. Da permiso de Leer en el objeto principal mediante un conjunto de permisos.
  3. Comprueba que la colaboración concede ese registro al usuario.
  4. En un flujo de pantalla, marca Usuario de flujo (Flow User) en el registro del usuario, o da el permiso de usuario Ejecutar flujos (Run Flows) en un conjunto de permisos.

«Sin acceso de lectura al campo X del objeto Y»

Por qué: el usuario no tiene seguridad a nivel de campo de lectura en un campo que muestra el calendario: un campo de estado, de tarjeta al pasar el cursor, de fecha o de hora.

Solución

  1. Concede Leer en el campo que indica el mensaje.
  2. Hazlo también para los administradores. Un campo personalizado nuevo queda oculto para todos, incluidos los administradores del sistema, hasta que un conjunto de permisos lo concede.

«Time group failed to save» (no se pudo guardar el grupo horario), «No se pudieron crear las reservas» o «No puede editar el campo» con el nombre de un campo

Por qué: el usuario puede leer los campos, pero no puede modificar uno que escribe el guardado. Suele ser un campo de estado, una segunda lista de selección o un campo de hora añadidos más tarde, o un campo que se rellena automáticamente en cada registro nuevo.

Solución

  1. Concede Modificar en todos los campos que escribe el calendario: fecha, hora de inicio y de fin, estado, segunda lista de selección, campo de nombre, la búsqueda al registro principal y cada campo de Rellenar automáticamente.
  2. Concede Crear en el objeto donde se guardan los registros.

«No tiene permiso para hacer esto» con «derechos de acceso insuficientes en el Id. de referencia cruzada»

Por qué: el nuevo registro apunta a un registro que el usuario no puede ver: el principal o el recurso.

Solución

  1. Da al menos Leer en los objetos principal y de recurso, y colaboración en esos registros.
  2. En un sitio público, haz que los invitados reserven sobre un objeto personalizado. Salesforce restringe el acceso de los invitados a Contactos y Cuentas.

«No tiene acceso a los cierres que usa este calendario»

Por qué: el usuario no puede leer el objeto que guarda los días cerrados, así que el calendario no puede saber qué días están cerrados. Su mensaje gemelo, No tiene acceso a los registros que muestra este calendario, significa lo mismo para las propias reservas.

Solución

  1. Da permiso de Leer en el objeto y en los campos que indica el mensaje, mediante un conjunto de permisos.
  2. Comprueba que la colaboración concede esos registros al usuario.

«No puede crear registros de Visit del tipo de registro Install»

Por qué: el calendario asigna a las reservas nuevas un tipo de registro que el perfil o los conjuntos de permisos de este usuario no incluyen.

Solución

  1. Añade el tipo de registro al perfil del usuario o a un conjunto de permisos.
  2. O pon Tipo de registro de las reservas nuevas en Dejar que cada persona elija, que solo muestra los tipos que cada persona puede crear.

«Salesforce no le permitió asignar este registro (Visit) a Alex Chen»

Por qué: la sala o persona de la reserva es un usuario de Salesforce, y Salesforce se negó a convertirlo en propietario. El mensaje termina con el motivo: no tienes acceso para asignarle registros, el usuario está inactivo o su tipo de usuario no puede ser propietario de este tipo de registro.

Solución

  1. Elige a otra persona.
  2. O pide a tu administrador de Salesforce acceso para asignar registros a ese usuario, o que active al usuario.

«No tiene permiso para guardar configuraciones de MultiDatePick»

Por qué: las configuraciones se guardan como metadatos de Salesforce, lo que requiere el permiso «Modificar metadatos mediante funciones de API de metadatos». El conjunto de permisos MultiDatePick - Setup lo concede.

Solución

  1. Asigna MultiDatePick - Setup, o MultiDatePick - All Access, al administrador que crea las configuraciones.

Flujos y acciones

El calendario en un flujo de pantalla (Screen Flow) y los botones que ejecutan un flujo.

Una pantalla de flujo ignora la configuración del asistente

Por qué: Config Name está vacío o mal escrito. Si está vacío, el componente usa sin avisar sus valores predeterminados. Si está mal escrito, muestra «No se encontró ninguna configuración llamada ...».

Solución

  1. Define Config Name con el nombre de la configuración exactamente como lo guardó el asistente de configuración.
  2. No toques las entradas de activar/desactivar. Todas las casillas salen de la configuración.

«Algunas fechas elegidas aún no están guardadas. Haga clic en Guardar o quítelas antes de continuar.»

Por qué: se pulsó el botón Siguiente de la pantalla mientras el calendario aún tenía selecciones sin guardar, que se perderían. Con horas, el mensaje dice Algunas horas elegidas aún no están reservadas.

Solución

  1. Haz clic primero en Guardar (o Reservar) y después en Siguiente.
  2. O quita las selecciones que no quieras y después haz clic en Siguiente.

«No puede ejecutar Send Reminder: necesita el permiso "Run Flows" o acceso a su flujo»

Por qué: el botón de acción del calendario ejecuta un flujo, y Salesforce solo deja iniciarlo a quien puede ejecutar ese flujo.

Solución

  1. Da al usuario el permiso Ejecutar flujos (Run Flows) en un conjunto de permisos, o
  2. Da a su perfil o conjunto de permisos acceso a ese flujo (Configuración, Flujos, el flujo, Modificar acceso).

«El flujo se detuvo con un error» o «Esta acción no está disponible aquí»

Por qué: el primero significa que el flujo de un botón de acción se ejecutó y falló. El segundo, que el botón ya no se ofrece para este registro: la acción se quitó de la configuración guardada o está definida para otros estados.

Solución

  1. Si es un error del flujo, un administrador abre el historial de ejecuciones o el registro de depuración del flujo para ver qué paso falló.
  2. Si la acción no está disponible, recarga la página y revisa los estados de la acción en las acciones de la configuración.

«Este flujo no tiene ninguna variable de entrada recordId ni recordIds»

Por qué: el asistente de configuración pasa el registro en el que se hizo clic al flujo de una acción en una variable llamada recordId (un registro) o recordIds (varios, desde el Modo edición). Sin ninguna de las dos, el flujo no sabrá qué registros usar.

Solución

  1. En Flow Builder, añade una variable de tipo Texto llamada recordId, o una colección de Texto llamada recordIds, disponible para entrada.
  2. Guarda y activa el flujo, y vuelve a elegirlo en el asistente.

Diagrama de Gantt

Tareas, vínculos entre ellas y progreso en la vista de Gantt.

No aparece la vista de Gantt en el selector

Por qué: la vista de Gantt, igual que la vista Mapa, hay que activarla expresamente. Si Available Views (Vistas disponibles) está en blanco, se ofrecen Calendario, Línea de tiempo, Semana, Ocupación y Agenda.

Solución

  1. En el asistente de configuración, marca Ofrecer la vista de Gantt en la pestaña Vistas, o añade gantt a Available Views (Vistas disponibles).
  2. Para que el calendario se abra en ella, pon View en gantt.

«Site survey no puede ir el 6 dic: este calendario no permite ese día. No se guardó nada.»

Por qué: el Gantt mantiene las mismas reglas de reserva que el calendario. Una tarea no puede moverse a un día u hora cerrados, a una persona que ya tiene otra tarea ese día ni a un recurso que no acepta reservas. El mensaje indica la regla cada vez.

Solución

  1. Arrastra la tarea a otro día, o asígnala a alguien libre.
  2. Si el día debería estar abierto, un administrador revisa los cierres y los días que se pueden elegir en la configuración.

«Install no puede esperar a Testing: se formaría un ciclo»

Por qué: Testing ya espera a Install, directamente o a través de otras tareas, así que vincularlas al revés haría que ninguna pudiera empezar. Una pregunta relacionada, ¿Reemplazar el vínculo?, aparece cuando las tareas se vinculan con un campo de la tarea: entonces cada tarea solo puede esperar a otra.

Solución

  1. Quita primero el vínculo que va en sentido contrario, o vincula otra tarea.
  2. Para que una tarea pueda esperar a varias, vincula las tareas con un objeto de vínculo aparte: asistente de configuración, Vista de Gantt, Vínculos entre tareas.

«El estado queda como estaba» o «Completado queda como estaba, no 100 %»

Por qué: Estado de una tarea terminada une Porcentaje completado y Estado: una tarea al 100 % recibe ese estado, y una tarea con ese estado pasa al 100 %. Cuando el usuario no puede editar uno de los dos campos, o el campo de estado no ofrece ese valor, solo se guarda el cambio que hizo, y este mensaje explica por qué.

Solución

  1. Da al usuario permiso de Modificar en el campo de porcentaje completado y en el campo de estado.
  2. Comprueba que el campo de estado ofrece el valor elegido para ese tipo de registro, elige otro en los ajustes de la vista de Gantt o déjalo en blanco para mantenerlos separados.

«No se guardó nada. Solo lectura para usted: Site survey»

Por qué: el usuario puede ver la tarea, pero no editarla, por la colaboración, la seguridad de campos o el propietario del registro. Su tarjeta dice Solo lectura para usted.

Solución

  1. Pide al propietario de la tarea, o a un administrador, que te dé acceso de edición mediante la colaboración.
  2. Comprueba que tu conjunto de permisos da Modificar en los campos de fecha de la tarea.

Importar configuración

Pegar una configuración de la Config Library o de otra org en la pestaña Importar / Exportar del asistente de configuración.

«Esto no es una configuración completa» o «Esto parece XML, no JSON»

Por qué: el texto pegado no es una configuración completa. Se cortó al copiarlo, es XML de metadatos de Salesforce o un flujo en lugar del JSON de la configuración, o contiene un archivo entero de configuraciones (más de 100 KB).

Solución

  1. Vuelve a copiar la configuración con el botón de copiar de la Config Library, o con Exportar configuración en la otra org.
  2. Pega el texto completo, desde la primera { hasta la última }.

¿Tienes el XML de un flujo? Despliégalo como flujo: Desplegar un flujo desde VS Code.

«Esta configuración no funciona sin Related_Object__c»

Por qué: a la configuración pegada le falta un ajuste que toda configuración necesita, como el objeto, el campo de fecha o el tipo de componente.

Solución

  1. Vuelve a copiar la configuración completa, o
  2. Exporta una configuración que funcione desde tu org para ver la forma que necesita y añade los ajustes que faltan.

Un ajuste «guardaría "Confirmed", que Visit Status no tiene, así que Salesforce rechazaría cada guardado»

Por qué: un ajuste de la configuración importada, como Rellenar automáticamente o Estados que se pueden elegir, usa un valor de estado que tu campo de estado no tiene. Si se guarda así, se rechazaría cada reserva. En el paso Asocie los valores de estado, un valor marcado con Su campo no tiene un valor así se omite hasta que elijas uno.

Solución

  1. Vuelve a Asocie los valores de estado.
  2. Elige cuál de tus valores significa lo mismo en cada caso y después haz clic en Aplicar & desplegar.

«Su flujo Send_Reminder no está en esta org»

Por qué: la configuración importada tiene un botón de acción que ejecuta un flujo que tu org no tiene.

Solución

  1. En el paso Acciones, elige uno de tus propios flujos para el botón, o elige Omitir esta acción.
  2. Puedes añadir la acción más tarde en las acciones de la configuración.
