2. Estructuras de registro: cuándo usar cada una

La estructura de registro define cómo una selección se convierte en registros. Depende de tres decisiones independientes, y todas las combinaciones funcionan.

Decisión 1
Hora

Date: solo fechas, sin horas.

Date Time / Booking: cada registro tiene hora de inicio y de fin.

Extra: activa Consolidate Time Span (Consolidar rango de tiempo) para tener un registro principal que cubre todo el rango horario, más un sub-bloque hijo por cada hueco dentro de él.

Decisión 2
Recurso

Ninguno: Date, Date Time o Booking sin recurso.

Un solo recurso: Booking con una lista desplegable de recursos.

Varios recursos: Booking con casillas, un registro por cada recurso marcado.

Decisión 3
Rango

Por clic: cada fecha seleccionada es un registro. Cinco clics, cinco registros.

Por rango: las fechas consecutivas se agrupan en un registro con inicio y fin. Define End Date Field API Name (Campo de fecha de fin).

El asistente de configuración distingue seis estructuras: un registro por fecha, uno por rango de fechas, uno por bloque de tiempo, principal más sub-bloques, un solo recurso y varios recursos.

Ejemplos prácticos: elige la estructura

Cada caso de abajo corresponde a una estructura. El asistente de configuración muestra las mismas seis como tarjetas.

Solicitud de vacaciones

¿Necesitas horas? No, solo fechas.

¿Necesitas un selector de recursos? No.

¿Deben unirse las fechas contiguas? Sí. Unas vacaciones de lunes a viernes deben ser UN solo registro.

→ Por rango: un registro que empieza el lunes y termina el viernes.

Reserva de sala de conferencias

¿Necesitas horas? Sí, cada reserva tiene inicio y fin.

¿Necesitas un selector de recursos? Sí, para elegir una sala.

¿Deben unirse las fechas contiguas? No, cada reserva es un registro.

→ Un solo recurso: un registro por fecha × bloque de tiempo, vinculado a la sala.

Formación en 3 salas

¿Necesitas horas? Sí, el mismo horario cada día.

¿Necesitas un selector de recursos? Sí, varias salas con casillas.

¿Deben unirse las fechas contiguas? Sí, dura de lunes a viernes.

→ Varios recursos, por rango: un registro por sala que cubre toda la semana.

Formación de jornada completa con pausa para comer

¿Necesitas horas? Sí, de 9:00 a 17:00 con un hueco para comer.

¿Necesitas un selector de recursos? No.

¿Hay que registrar el hueco? Sí, como registro hijo propio.

→ Principal más sub-bloques: un registro principal de 9:00 a 17:00 y un sub-bloque para la comida.

3. Recorrido por el asistente de configuración

El asistente de configuración guarda una configuración una sola vez. Escribe su nombre en Config Name (Nombre de configuración) en cualquier página o pantalla de flujo y esa ubicación la usará. Si cambias la configuración, todas las ubicaciones se actualizan.

  1. 1 Ubicación
  2. 2 Estructura
  3. 3 Inicio rápido
  4. 4 Revisar

Paso 1: Ubicación

Elige dónde va el calendario: una página de registro de cualquier objeto, estándar o personalizado, una página de aplicación o de inicio, un flujo de pantalla (Screen Flow) o un sitio público. Para una página de registro, busca su objeto; para las demás, el objeto en el que se guardan las selecciones. Después elige un tamaño, de Tiny a Full Width. Al lado hay dos pestañas más: Configuraciones existentes, para editar una configuración guardada, e Importar, para pegar una de la Config Library. ¿Prefieres ver todos los ajustes a la vez? Abrir todos los ajustes en una sola página.

Paso 2: Estructura

Seis tarjetas, cada una con un pequeño dibujo de lo que se elige y de lo que llega a Salesforce: un registro por día, por rango o por franja horaria, un registro con pausas, reservar una sala o persona, o varias a la vez. Rango, franja horaria y pausas pueden añadir una sala o persona. La estructura elige el componente por ti.

Paso 3: Inicio rápido

Elige el objeto en el que se guarda cada selección y el asistente rellena las opciones más probables: el vínculo con el registro de la página, la fecha, el título, el estado, la tarjeta emergente y, en las reservas, el nombre, la capacidad y el horario del recurso. Puedes cambiar lo que quieras. Las pestañas recorren el resto: Campos, Qué se reserva, Horas, Reglas, Días cerrados, Vistas, Tarjeta emergente, Estado y Otros ajustes. Todos los ajustes del calendario están en alguna de ellas; pulsa Ir a la revisión cuando termines.

Paso 4: Revisar

Todas las secciones en una lista, cada una con un enlace Cambiar, un nombre sugerido y una vista previa funcional. Haz clic en Guardar configuración: el asistente implementa la configuración en 30 a 60 segundos y luego te muestra el Config Name que debes pegar y el componente que debes arrastrar a la página. Al terminar puedes añadir una descripción opcional.

Configuraciones existentes e Importar

Las configuraciones guardadas aparecen en Configuraciones existentes: haz clic en una para editarla o exportarla. La pestaña Importar acepta el JSON de cualquier tarjeta de la Config Library o una exportación de otra organización.

En un flujo de pantalla, define Config Name y ya está. Todas las casillas salen de la configuración, así que nunca necesitas un $GlobalConstant. Enlaza el registro principal con Parent Record Id.

Los componentes se ejecutan con los permisos de cada usuario, así que los usuarios también necesitan acceso a tus objetos y campos:

  • Objetos: Leer y Crear en el objeto donde se guardan los registros, y Leer en cualquier objeto de recurso, cierre o hijo que lea el calendario.
  • Campos, lectura: todos los campos que muestra el calendario (fecha, estado, campos al pasar el cursor).
  • Campos, edición: todos los campos que escribe (fecha, horas, estado, segunda lista de selección, campo de nombre, la búsqueda al registro principal). Si el usuario no puede editar un campo, el guardado falla aunque la lectura funcione.
  • Registros referenciados: al menos Leer en el registro principal y en el recurso a los que apunta el nuevo registro.
Los administradores también necesitan acceso a los campos. Un campo personalizado recién creado es invisible para todos, incluidos los administradores del sistema, hasta que un conjunto de permisos lo concede. Si al guardar parece faltar un campo, revisa primero la seguridad a nivel de campo.

Cada mensaje de error y su causa están en Solución de problemas: errores de acceso. Los sitios para invitados necesitan algunos pasos más: consulta Páginas públicas para invitados.

5. Guardar con un clic o guardar desde el flujo

Hay dos formas de guardar. Elige la que mejor encaje con la ubicación.

Guardar con un clic

El componente escribe los registros por sí mismo. Rellena cuatro ajustes y aparece su propio botón Guardar. Un clic y se crean los registros hijos. Sin elementos de flujo ni código.

Dónde usarlo: páginas de registro, páginas de aplicación, páginas de inicio, sitios de Experience Cloud y pantallas de flujo con un registro principal.

Guardar desde el flujo

El componente entrega la selección a tu flujo. Usa la acción incluida Parse Date Entries from JSON y después tus propios elementos Bucle y Crear registros.

Dónde usarlo: pantallas de flujo en las que quieres control total: aprobaciones, registros condicionales, validaciones adicionales.

El asistente de configuración los rellena por ti. Cuando los cuatro tienen valor, aparece el botón Guardar.

Guardar solo añade

Guardar con un clic solo crea registros nuevos. Deseleccionar una fecha nunca borra un registro guardado, así que un clic equivocado no puede hacerte perder datos. Para cambiar o eliminar registros, usa el modo edición o la lista relacionada.

  • Cambiar la fecha, las horas, el recurso o el estado, y el registro se actualiza
  • Eliminar con confirmación en dos clics, para que nada se borre por accidente

El modo edición funciona en todas las vistas

Con Enable Edit Mode activado, el botón Editar aparece en todas las vistas. Haz clic en un registro de Línea de tiempo, Semana o Agenda para añadirlo al conjunto en edición, igual que una fecha en el calendario mensual. Un cambio de estado masivo desde la línea de tiempo funciona exactamente igual que desde el calendario.

Línea de tiempo: filas contraídas

Cuando un recurso tiene reservas solapadas, su fila se contrae en una sola franja con una etiqueta N a la vez. Un desplegable abre un carril por reserva. Las filas contraídas siguen admitiendo arrastrar, pasar el cursor y hacer clic.

Línea de tiempo: arrastra para reprogramar

Con Enable Edit Mode activado, las barras de la línea de tiempo se pueden arrastrar. Agarra el centro para mover una reserva a otros días, o un borde para cambiar su inicio o su fin. La barra muestra dónde quedará y se guarda al soltar. Con zoom de Día, los mismos gestos cambian las horas.

Programa personas, no solo salas

Resource Object API Name (Objeto de recurso) acepta cualquier objeto. Pon User y la línea de tiempo se convierte en un cuadrante de personal, Semana en una cuadrícula de turnos y Ocupación en un panel de capacidad del equipo.

  • User no tiene un campo de capacidad estándar. Añade uno personalizado (por ejemplo Daily Capacity) para ver la ocupación en porcentajes.
  • Asigna Business Hours Start Field (Campo de inicio del horario comercial) y Business Hours End Field (Campo de fin del horario comercial) a campos de User y la cuadrícula semanal seguirá el horario de cada persona.

La Config Library tiene dos ejemplos ya preparados: Planificación de la capacidad del equipo y Cuadrante de turnos del personal.

8. Reserva de recursos y capacidad (componente Booking)

Un solo recurso

Los usuarios eligen un recurso en una lista desplegable. La cuadrícula de horarios carga las reservas y la capacidad de ese recurso.

Varios recursos

Activa Allow Multiple Resources (Permitir varios recursos) y la lista desplegable se convierte en casillas. La cuadrícula muestra solo las franjas libres en todos los recursos marcados, y Guardar los reserva todos a la vez.

Capacidad

Permite que varias reservas compartan una franja, con indicadores 3/5 en vivo. Una franja completa deja de aceptar reservas.

AjusteFunciónNombre de API
Capacity FieldUn campo numérico en el recurso, por ejemplo Capacity = 5.capacityField
Show Availability CountMuestra los indicadores X/Y.showAvailabilityCount
Capacity AggregationCombined (predeterminado) suma reservas y capacidades de los recursos marcados: dos salas de 5 muestran 0/10. Distinct cuenta una sola vez un evento reservado en varios recursos y usa la mayor capacidad individual: una clase en 4 salas muestra 1/5, no 4/20.capacityAggregation
La capacidad necesita los dos campos de hora de la reserva. Sin Booking Start Time Field (Campo de hora de inicio) y Booking End Time Field (Campo de hora de fin) no hay franjas que contar, y el componente muestra un aviso ámbar en lugar del calendario.

Conflictos

Conflict Behavior (Comportamiento ante conflictos) decide qué pasa cuando una franja elegida ya está ocupada. Conflict Look-Ahead Days (Días de previsión de conflictos) define hasta cuándo se comprueba (por defecto, 360 días).

ValorQué ocurreIdeal para

10. Bloquear fechas, horas y recursos (cierres)

Cualquier calendario puede leer cierres de otro objeto y atenuar las fechas, franjas horarias o recursos que cubren, para que los usuarios solo reserven cuando estás abierto. Apunta unos pocos ajustes al objeto de cierres y el componente hace el resto. Los bloqueos de día completo funcionan en los tres componentes; los de hora y de recurso necesitan la cuadrícula de horarios de Date Time o Booking.

Bloquear u ocultar: ¿qué diferencia hay?

Suenan parecido, pero hacen lo contrario. Bloquear quita disponibilidad: la franja se ve, pero no se puede reservar. Ocultar saca registros de la vista, lo que libera sus franjas.

Un mismo estado puede hacer cualquiera de las dos cosas, según la función a la que lo conectes. Por ejemplo, una reserva Cancelled:
  • Ignored Statuses (Estados ignorados) = Cancelled → la reserva desaparece y su franja queda libre.
  • Blocked Dates Object = tu objeto de reservas, filtrado por Status = Cancelled → la reserva bloquea su fecha para que nadie vuelva a reservarla.
Oculta para liberar la franja. Bloquea para mantenerla cerrada.

Tres niveles de bloqueo

  1. Día completo: un cierre sin horas atenúa toda la fecha. En los tres componentes. Una fecha cerrada sigue cerrada aunque ya tenga reservas.
  2. Parte del día: un cierre con hora de inicio y de fin bloquea solo esas franjas. El resto del día sigue disponible. Las franjas bloqueadas se ven al seleccionar una fecha.
  3. Un recurso: un cierre que apunta a un recurso cierra solo ese recurso. En la vista de un solo recurso, la franja aparece tachada. En la vista combinada lleva una pequeña marca en la esquina y sigue disponible en los recursos abiertos.

¿Usas la cuadrícula de horarios? Lo que necesitas son bloqueos de parte del día. Los de día completo son para selectores solo de fecha.

Dos patrones para el objeto de cierres

  • El mismo objeto, marcado por estado: apunta Blocked Dates Object a tu objeto de reservas y filtra Status = Cancelled, de modo que las reservas canceladas hacen también de cierres. Es lo más sencillo, pero todos los calendarios de ese objeto los comparten. Consulta la configuración Reserva de citas con festivos en la Config Library.
  • Un objeto de cierres propio: un objeto Office Closure con una fecha, horas de inicio y fin opcionales, un campo Region y una búsqueda opcional a un recurso. Cada calendario filtra por su región, y un cierre puede apuntar a un solo recurso. Consulta la configuración Cierres de recursos por horas.

Para que cada persona bloquee su propio tiempo (por ejemplo, un responsable que bloquea una mañana), coloca en una página interna o un sitio un componente Date Time que guarde en el objeto de cierres.

Cómo se comportan las franjas bloqueadas

  • Aspecto: una franja totalmente cerrada aparece tachada y atenuada. Una franja cerrada solo para algunos de los recursos elegidos lleva una marca en la esquina.
  • Selección: una franja totalmente cerrada no se puede pulsar ni arrastrar.
  • Guardado: nada se guarda en un recurso, fecha y hora cerrados. Con varios recursos, solo se excluye el cerrado; los abiertos se reservan igual.

Una tabla de cierres, muchos calendarios

Añade al objeto de cierres un campo de etiqueta (Region, Location, Building) y pon el mismo campo en tus recursos. Así cada calendario usa Resource Filter Field / Value para mostrar sus recursos y Blocked Dates Filter Field / Value para leer sus cierres.

11. Páginas públicas para invitados (Experience Cloud)

Coloca un componente en un sitio de Experience Cloud y cualquiera podrá reservar sin iniciar sesión. Completa los cinco pasos antes de probar como invitado.

  1. Permisos de objeto. Da al usuario invitado del sitio permiso de Leer en cada objeto, y de Crear si los invitados envían datos. Salesforce nunca permite que los invitados editen ni eliminen registros, así que deja las páginas de edición, cancelación y eliminación para usuarios con sesión iniciada.
  2. Seguridad a nivel de campo en todos los campos que toca el componente, incluidos los de horario comercial del recurso y los de hora de los cierres. Un solo campo que falte detiene la consulta de recursos o de cierres.
  3. Una regla de colaboración para invitados (Leer) para que el invitado vea los registros. El valor predeterminado externo de toda la organización del objeto debe ser Privado para que la regla se aplique. Una regla implementada como metadatos necesita un clic en Recalcular en Configuración, Configuración de colaboración.
  4. El conjunto de permisos MultiDatePick - Guest en el usuario invitado del sitio. Incluye el acceso a las clases de Apex con las que el componente carga sus datos.
  5. Activa el sitio. Publicar y activar son pasos distintos.
¿Calendario vacío para los invitados? Si objetos, campos y acceso a clases parecen correctos, casi siempre es el recálculo de colaboración del paso 3. Los pasos 4 y 5 son los siguientes que más se olvidan.
  • Qué registro ven los invitados: una página pública usa Static Parent Record Id, así que todos los invitados reservan sobre el mismo registro principal (una oficina, una sede o un recurso). Para un registro por visitante, contrólalo desde un flujo con un parámetro de URL. Los calendarios realmente personales requieren usuarios con sesión iniciada.
  • Contactos y cuentas: Salesforce restringe mucho el acceso de los invitados a ellos. Haz que los invitados reserven sobre un objeto personalizado o usa un sitio autenticado.
  • Varios componentes en una página: no se sincronizan en vivo. Añade un aviso para actualizar entre ellos, de modo que un bloqueo hecho en uno se vea en el siguiente.

Los pasos de ubicación están en Páginas de aplicación, inicio y Experience. Un sitio completo de ejemplo está en Reservas en Experience Cloud.

12. Problemas habituales (preguntas frecuentes)

¿Ves un aviso, falta el botón Guardar o el calendario sale vacío? Solución de problemas muestra cada mensaje con una captura y la solución.

Mis colores de estado no se aplican
Revisa tres cosas. (a) ¿Es Status Field (Campo de estado) el nombre de API exacto de la lista de selección? Distingue mayúsculas y minúsculas. (b) ¿Usa Status Colors (Colores de estado de reserva) el formato Value:#hex, Value:#hex sin comillas? 'Confirmed':'#22C55E' lo rompe sin avisar. (c) ¿Tienen realmente los registros un valor en esa lista de selección?
Los registros se guardan con nombres inesperados
Revisa Record Name Field (Campo de nombre del registro): si el campo es corto, los nombres largos se cortan. Revisa Append Date to Record Name (Añadir fecha y hora al nombre): si está activado, la fecha y la hora seleccionadas se añaden a todos los nombres.
¿Cómo oculto los registros Cancelled de la cuadrícula de capacidad?
Define Ignored Statuses como Cancelled, o como una lista del tipo Cancelled,Rejected. Desaparecen del calendario y del recuento de capacidad.
¿Qué diferencia hay entre bloquear y ocultar?
Bloquear (cierres) mantiene visible una fecha, hora o recurso, pero sin poder reservarlo: festivos, mantenimiento, una sala cerrada. Ocultar quita registros, como los Cancelled, del calendario y de la capacidad, lo que libera la franja. Consulta Bloquear u ocultar.
No aparece el botón Editar
Activa Enable Edit Mode. Es el único requisito, en los tres componentes. El campo de estado es opcional: solo añade una lista desplegable de estados en el editor. Si el botón sigue sin aparecer, la página o la configuración tiene Enable Edit Mode desactivado.
Solo quiero algunos recursos (salas, no equipos)
Usa Resource Filter Field (Campo del filtro de recursos) y Resource Filter Value (Valor del filtro de recursos). Un valor: campo Active__c, valor true. Varios valores (O): North,South. Varios campos (Y): campo Type__c;Active__c, valor Conference Room;true.
Date Time sigue mostrando un único selector de hora compartido
El ajuste que buscas es Time Display Mode (Modo de visualización de hora): Grid o Dropdown. En modo Grid todas las fechas comparten la cuadrícula. Para una hora distinta en cada fecha, elige Dropdown y activa Allow Different Times Per Date (Permitir horas distintas).
¿Cómo paso de guardar desde el flujo a guardar con un clic?
Rellena Parent Record Id, Child Object API Name (Objeto relacionado), Date Field API Name (Campo de fecha) y Relationship Field API Name (Campo de relación). Quita la acción Parse Date Entries from JSON y el bucle que creaba los registros. Ahora los escribe el propio botón Guardar del componente.
Me sale un aviso de error sin detalles
Abre la consola de desarrollador del navegador y busca las líneas que empiezan por [MDP:ERROR]. El error completo siempre se registra ahí, aunque el aviso sea breve.
