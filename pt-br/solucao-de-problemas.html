Solução de problemas

Pesquise a mensagem que aparece na tela ou escolha uma categoria e siga a solução. Todas as imagens são do componente real.

Categorias

Nada nesta página corresponde. Tente menos palavras ou outra categoria, ou envie um e-mail ao suporte com uma captura de tela do que você vê.

Configuração e posicionamento

Avisos e alertas que o administrador vê ao colocar um calendário em uma página ou ao montar a configuração dele.

Não há botão Salvar

Por quê: o componente não tem um registro pai e não está configurado para mostrar todos os registros. Páginas de aplicativo e iniciais não têm registro próprio.

Solução

  1. Abra a configuração no Assistente de Configuração e responda Os registros de quem? (Só de quem está vendo é a resposta mais comum), ou defina Vincular cada seleção a este registro (App Builder: Static Parent Record Id) com o registro ao qual as datas pertencem.
  2. Verifique se o objeto, o campo de data e o campo de relacionamento estão preenchidos, ou defina Config Name.

Em um fluxo, o botão Salvar aparece assim que o Parent Record Id é vinculado. Ele fica oculto quando a resposta do assistente para Quem salva? é Meu fluxo salva, ou quando o Parent Record Id está em branco: nesse caso, o botão Avançar do fluxo leva as datas.

Aviso âmbar: "Componente incorreto para esta configuração"

Por quê: Config Name aponta para uma configuração salva para outro componente.

Solução

  1. Aponte Config Name para uma configuração feita para este componente, ou
  2. Troque pelo componente para o qual a configuração foi criada, ou
  3. Abra a configuração no Assistente de Configuração e mude o Tipo de Componente.

Aviso âmbar: "Incompatibilidade de configuração"

Por quê: o registro da página, ou o registro em Vincular cada seleção a este registro, é de um objeto diferente daquele para o qual aponta o campo de relacionamento da configuração.

Solução

  1. Coloque o componente em uma página de registro do objeto indicado no aviso, ou
  2. Vincule cada seleção a um registro desse objeto, ou
  3. Use uma configuração criada para o objeto desta página.

Aviso vermelho: "Este componente não conseguiu carregar seus dados"

Por quê: um nome de campo ou de objeto na configuração está errado, ou o usuário não pode usar o MultiDatePick ou ler o objeto e os campos dele.

Solução

  1. Leia a caixa cinza: ela indica exatamente o campo, o objeto ou a classe Apex. Quando falta acesso ao MultiDatePick, o aviso diz qual conjunto de permissões atribuir.
  2. Nome errado: copie o nome de API exato em Configuração, Gerenciador de objetos.
  3. Sem acesso: atribua o conjunto de permissões MultiDatePick - User e o acesso aos seus próprios objetos. Em um site público do Experience Cloud, atribua MultiDatePick - Guest ao usuário convidado e dê a ele acesso de leitura aos seus próprios objetos.

O Resource Booking mostra "Configuração Necessária"

Por quê: o Resource Booking precisa de um objeto de recurso, um objeto de reserva, um campo de data da reserva e um campo de recurso da reserva. O painel lista os que estão faltando.

Solução

  1. Defina Config Name com uma configuração de Resource Booking do Assistente de Configuração, ou
  2. Preencha cada propriedade que o painel lista.

"Nenhuma configuração chamada "Room_Bookings" foi encontrada"

Por quê: Config Name usa o nome de API da configuração, o que aparece na lista Configurações Existentes do Assistente de Configuração (por exemplo Contact_Event), não o rótulo. Um erro de digitação, o rótulo ou uma configuração salva há instantes que ainda está sendo implantada levam a esta mensagem.

Solução

  1. Abra o Assistente de Configuração, depois Configurações Existentes, e copie o nome de API da configuração.
  2. Cole-o em Config Name no componente e salve a página.
  3. Acabou de salvar a configuração? O Salesforce a implanta em segundo plano, o que leva de 30 segundos a 2 minutos. Atualize Configurações Existentes até ela aparecer e recarregue a página.

Se a mensagem disser que o usuário não tem acesso ao MultiDatePick, veja sem acesso ao MultiDatePick.

"O registro em Static Parent Record Id (a015g00000XyZ12AAB) não existe mais"

Por quê: o calendário salva cada seleção em um único registro fixo, definido em Vincular cada seleção a este registro (App Builder: Static Parent Record Id), e esse registro foi excluído. Nada pode ser salvo até que ele aponte para um registro que exista.

Solução

  1. Abra a configuração no Assistente de Configuração e escolha outro registro em Vincular cada seleção a este registro.
  2. Em uma página sem Config Name, cole o Id de um registro atual em Static Parent Record Id no App Builder.

As datas são salvas, mas não aparecem da próxima vez

Por quê: Mostrar datas já salvas (App Builder: Load Existing Dates) está desativado. Os registros foram salvos, mas o calendário abre vazio toda vez.

Solução

  1. Ative Mostrar datas já salvas.
  2. Recarregue a página. As datas salvas aparecem, coloridas por status se houver um campo de status definido.

"Este calendário não pode mostrar os registros existentes nem salvar novos: o campo "Visit Date" em Visit está criptografado com o Shield Platform Encryption"

Por quê: o Salesforce não consegue pesquisar nem ordenar por um campo protegido pelo Shield Platform Encryption, e o calendário encontra e ordena os registros pelos campos de data, hora e nome. Esses campos precisam ficar sem criptografia. Os campos que o calendário só exibe, como as notas do cartão ao passar o mouse, podem continuar criptografados.

Solução

  1. Desative a criptografia do campo indicado na mensagem, em Configuração, Política de criptografia, ou
  2. Abra a configuração no Assistente de Configuração e escolha um campo de data ou hora sem criptografia.

Um filtro "não corresponde a um campo e valor", ou "Não foi possível carregar os recursos"

Por quê: um filtro cita um campo que não existe no objeto, um campo pelo qual o Salesforce não consegue filtrar ou um valor que não combina com o campo. O calendário diz qual é, por exemplo Filtro de registros: "Status__c=Confrimed" não corresponde a um campo filtrável e valor em Visit. ou Não foi possível carregar os recursos: a condição "Active__c é yes" não combina com esse campo.

Solução

  1. Abra a configuração no Assistente de Configuração.
  2. Escolha de novo o campo e o valor nas listas de Só os registros em que (os registros exibidos) ou Mostrar só os itens em que (as salas ou pessoas oferecidas).
  3. Está digitando no App Builder? Use o nome de API do campo e um valor que combine com o tipo dele: uma caixa de seleção aceita true ou false, uma data aceita 2026-12-31.

"Valores de campo padrão: "Priority=Urgent" não corresponde a um campo e valor em Visit"

Por quê: Preencher automaticamente (App Builder: Default Field Values) define campos em cada novo registro, e um dos pares cita um campo que o objeto não tem, ou um valor que o campo não aceita, como um valor de lista de opções que não está na lista.

Solução

  1. Confira o nome de API do campo no Gerenciador de objetos.
  2. Escreva um valor que combine com o campo: caixas de seleção aceitam true ou false, datas aceitam yyyy-mm-dd ou TODAY+7, listas de opções aceitam um dos seus valores.
  3. Separe vários pares com ponto e vírgula: Priority=High; Type=Call.

"Duration não é um campo numérico", ou uma reserva ocupa o dia inteiro

Por quê: Campo com os minutos (App Builder: Duration Field) precisa ser um campo numérico na reserva, não uma fórmula, um resumo de totalização, uma moeda ou uma porcentagem. Quando ele está definido e Termina às fica em branco, cada reserva termina no horário de início mais esses minutos, então um registro sem os minutos não tem fim e ocupa o dia inteiro.

Solução

  1. Escolha um campo numérico que guarde a duração em minutos, ou crie um.
  2. Preencha os minutos nos registros antigos uma vez, por exemplo com uma atualização de dados ou um fluxo. A partir daí, cada gravação, movimentação e redimensionamento feito no calendário os preenche.

"Visit não tem um tipo de registro ativo Install, que este calendário atribui aos novos registros"

Por quê: Tipo de registro das novas reservas cita um tipo de registro que foi desativado ou renomeado. Uma mensagem parecida, Confirmed não é um valor de Visit Status para registros do tipo Repair, significa que o status escolhido não está entre os valores que esse tipo de registro oferece.

Solução

  1. Abra a configuração no Assistente de Configuração e escolha um tipo ativo em Tipo de registro das novas reservas, ou escolha O padrão de cada pessoa ou Deixar as pessoas escolherem.
  2. Para um status: adicione o valor aos valores da lista de opções desse tipo de registro no Gerenciador de objetos, ou escolha outro status.

Se a mensagem disser que a pessoa não pode criar registros desse tipo, veja tipo de registro não permitido.

"Só os administradores veem isto, no construtor: este calendário conta a capacidade mas não tem Config Name"

Por quê: sem uma configuração salva indicada na página, o calendário só consegue contar as reservas que o usuário vê. As reservas que o compartilhamento esconde dele ficam de fora, então um horário lotado pode parecer livre.

Solução

  1. Salve a configuração no Assistente de Configuração.
  2. Digite o nome dela em Config Name no componente. A contagem passa a incluir todas as reservas, só como números.

Só os administradores veem este aviso, no App Builder. Os usuários nunca o veem.

Sem botão Adicionar ao calendário depois de salvar

Por quê: Show Add to Calendar After Saving (Mostrar "Adicionar ao calendário" após Salvar) está desativado. Ele vem desativado por padrão.

Solução

  1. Ative nas propriedades do componente ou na configuração e salve um registro. O botão aparece em uma barra abaixo da notificação.
  2. Aparece "Adicionar ao Google Agenda" no lugar? O navegador bloqueou a criação do arquivo, então um evento único recebe um link do Google Agenda.

Reservas e disponibilidade

Por que um dia, um horário, uma sala ou uma pessoa não pode ser escolhido ou reservado.

O Resource Booking mostra "Nenhum recurso disponível"

Por quê: a lista de recursos voltou vazia. Normalmente é um filtro que não encontra nada, um objeto de recurso errado ou a falta de registros de recurso.

Solução

  1. Confira Mostrar só os itens em que (App Builder: Resource Filter Field e Value) com um registro real.
  2. Confira Lista de escolhas e Campo com o nome de cada um (App Builder: Resource Object API Name e Resource Name Field).
  3. Crie pelo menos um registro de recurso.

Aviso âmbar: "A capacidade precisa dos dois campos de hora"

Por quê: Quantos ao mesmo tempo (App Builder: Capacity Field) está definido, mas o campo de hora inicial ou final da reserva está vazio, então a capacidade não pode ser aplicada.

Solução

  1. Defina tanto Começa às quanto Termina às (App Builder: Booking Start Time Field e Booking End Time Field), ou
  2. Limpe Quantos ao mesmo tempo.

Não consigo escolher outra data

Por quê: o componente tem um limite de datas: Max Dates Allowed (Máximo de Datas Permitidas).

Solução

  1. Desmarque uma data para escolher outra, ou
  2. Aumente o limite, ou defina 0 para não ter limite.

Não consigo reservar outro horário

Por quê: um limite de reservas foi atingido. Max Time Slots (Máx. de horários) limita o total de horários, Max Bookings per Day (Máx. de reservas por dia) limita as reservas separadas em um mesmo dia (horários vizinhos contam como uma) e Limit per Person (Limite por pessoa) limita as reservas futuras de um cliente, contadas no servidor.

Solução

  1. Aumente o limite, ou defina 0 para não ter limite.
  2. A equipe pode passar de “Limite por pessoa” depois de uma confirmação. Os visitantes do site, não.

Alguns dias ou horários aparecem em cinza

Por quê: uma regra de reserva os fecha. Minimum Notice (Hours) (Antecedência Mínima) fecha tudo o que começa cedo demais, Book Up To (Days Ahead) (Reservar com até) fecha os dias além da janela móvel, e Earliest ou Latest Selectable Date, as datas bloqueadas e o horário comercial de cada recurso fecham o resto.

Solução

  1. Confira essas definições no componente ou na configuração. O valor 0 desativa a antecedência e a janela.
  2. Clique em um horário fechado: um aviso explica por que ele está fechado.

O horário logo depois de uma reserva aparece como ocupado

Por quê: Buffer Between Bookings (Minutes) (Intervalo entre Reservas) mantém um tempo livre depois de cada reserva no mesmo recurso, para limpeza ou preparação.

Solução

  1. Diminua o intervalo, ou defina 0 para reservas seguidas.
  2. Quando o horário está ocupado continua valendo: com Ignorar horários em conflito, um horário que esbarra no intervalo é pulado e informado como qualquer outro conflito.

Só aparecem alguns horários de início

Por quê: Somente estes horários está definido, então a grade oferece só os horários de início da lista. No Resource Booking, Horários próprios de cada recurso passa a valer quando uma sala ou pessoa tem a própria lista. O horário comercial, os fechamentos, a antecedência e os conflitos continuam fechando um horário da lista.

Solução

  1. Edite a lista, ou escolha Cada intervalo, no componente ou na configuração.
  2. Confira a lista própria do recurso no campo Horários próprios de cada recurso dele.

"Estas seleções não estão mais dentro do período de reserva"

Por quê: a página ficou aberta tempo suficiente para o dia ou horário escolhido cair dentro do período de Minimum Notice. Ao salvar, a regra é verificada de novo, para que uma página desatualizada não reserve em cima da hora.

Solução

  1. Remova as datas indicadas na mensagem, ou escolha um horário mais tarde.
  2. Salve de novo.

"Não é possível reservar. Já está lotado ou fechado em: 3 de dez." ou "Já está lotado ou fechado, então será ignorado ao salvar"

Por quê: outra reserva já ocupa esse horário, ou um fechamento o cobre. Quando o horário está ocupado decide o que acontece: Bloquear recusa o clique inteiro, Ignorar horários em conflito reserva os outros dias e cita os que deixou de fora, e Permitir (reservar mesmo assim) oferece um botão Reservar mesmo assim.

Solução

  1. Remova as datas indicadas na mensagem, ou escolha outro horário ou recurso.
  2. O administrador pode mudar Quando o horário está ocupado nas regras de reserva da configuração.

"Limite diário atingido (2 de 2)"

Por quê: Máximo de reservas por dia (App Builder: Daily Limit Field) é um número em cada sala ou pessoa, como os 2 serviços por dia de um técnico. Quando um dia chega a esse número de reservas, ele fecha para aquele recurso, e uma gravação nele mostra Limite diário atingido, então nada foi salvo. Cada registro conta uma vez, uma reserva de vários dias conta em cada dia, e os status que liberam o horário nunca contam.

Solução

  1. Escolha outro dia ou outro recurso.
  2. Aumente o número no registro do recurso, ou deixe em branco para não ter limite.
  3. Com Quando o horário está ocupado definido como Permitir (reservar mesmo assim), uma reserva pode passar do limite.

"Garden Room não aceita reservas, então nada foi salvo"

Por quê: o Quantos ao mesmo tempo ou o Máximo de reservas por dia do recurso é 0. O valor 0 significa que ele não aceita nenhuma reserva, em qualquer opção de Quando o horário está ocupado. Os seletores, a grade de horários e a Semana o mostram em cinza.

Solução

  1. Escolha outro recurso.
  2. Para liberá-lo para reservas, defina o número no registro dele como 1 ou mais, ou deixe em branco para não ter limite.

"Estas datas já passaram e não podem ser reservadas" ou "Estes horários já passaram"

Por quê: o calendário não reserva dias ou horários que já terminaram. Um dia escolhido ontem em uma página que ficou aberta durante a noite, ou um horário mais cedo hoje, é recusado ao salvar.

Solução

  1. Remova as datas ou horários indicados na mensagem e escolha outros mais tarde.
  2. Precisa registrar dias passados, como em uma folha de horas? O administrador pode ativar Permitir Datas Passadas na configuração.

"Estas datas estão fechadas: 25 de dez. Escolha outra data ou horário."

Por quê: um fechamento cobre o dia: um registro na Lista de dias fechados do calendário, como um feriado ou uma folga da equipe. Um fechamento que cita uma sala ou pessoa fecha só aquele recurso. O calendário e a gravação recusam o dia.

Solução

  1. Escolha outra data ou horário.
  2. Se o dia deveria estar aberto, edite ou exclua o registro de fechamento, ou restrinja Só os fechamentos em que na configuração.

"Garden Room não pode ser reservado neste calendário. Escolha um recurso da lista."

Por quê: a sala ou pessoa não está na lista deste calendário, porque Mostrar só os itens em que a deixa de fora. Isso costuma acontecer quando um registro mudou depois que a página abriu, por exemplo uma sala marcada como inativa. O servidor recusa ao salvar, mover e reatribuir.

Solução

  1. Recarregue a página e escolha um recurso da lista.
  2. Se ele deveria ser oferecido, atualize o registro do recurso, ou mude Mostrar só os itens em que na configuração.

"Os recursos selecionados não têm nenhum horário de início em comum"

Por quê: com Reservar vários de uma vez, um mesmo horário precisa servir para todas as salas ou pessoas escolhidas. O horário comercial ou os horários de início próprios delas não se sobrepõem, então nenhum horário serve para todas. Uma mensagem mais curta, Os recursos selecionados não têm horário comercial em comum, significa o mesmo.

Solução

  1. Escolha menos recursos, ou recursos que trabalhem no mesmo horário.
  2. O administrador pode conferir o horário de funcionamento e os horários de início próprios de cada recurso.

Duas pessoas reservaram o mesmo horário

Por quê: uma de duas configurações permite isso. Quando o horário está ocupado definido como Permitir (reservar mesmo assim) deixa a equipe reservar de propósito um horário já ocupado. Ou O filtro também decide o que está ocupado está ativado com um filtro que usa ME, então só as reservas de cada pessoa ocupam um horário. O assistente avisa sobre o segundo caso: "O filtro também decide o que está ocupado" está ativado e Só os registros em que usa ME, então só as reservas de cada pessoa ocupam um horário: duas pessoas podem reservar o mesmo horário.

Solução

  1. Defina Quando o horário está ocupado como Bloquear ou Ignorar horários em conflito.
  2. Desative O filtro também decide o que está ocupado, a menos que cada pessoa realmente reserve só o próprio horário.

"Limite por pessoa está ativado, mas nenhum Campo do cliente foi definido"

Por quê: Limite por pessoa conta as reservas de cada cliente pelo campo Para quem é (App Builder: Client Field). Sem campo definido, ou com um campo que o Salesforce não consegue pesquisar, como um texto longo, a reserva não pode ser contada, então a gravação é recusada. No App Builder, os administradores veem Limite por pessoa não pode contar as reservas por Notes.

Solução

  1. Abra a configuração no Assistente de Configuração e escolha um campo de texto, e-mail ou pesquisa em Para quem é.
  2. Ou defina Limite por pessoa como 0 para desativá-lo.

"O Salesforce não respondeu, então esta reserva pode já estar salva"

Por quê: a conexão caiu ou o Salesforce demorou depois do clique em Reservar, então o calendário não conseguiu saber se a gravação terminou. Ele se recarrega para você conferir.

Solução

  1. Procure a reserva no calendário recarregado.
  2. Reserve de novo só se ela não estiver lá.

Convidados do site público

Calendários em um site público do Experience Cloud, onde os visitantes reservam sem fazer login.

Os convidados veem um calendário vazio

Por quê: a regra de compartilhamento para convidados ainda não está valendo, ou falta uma etapa no perfil de convidado.

Solução

  1. Defina o padrão externo para toda a organização do objeto como Privado e clique em Recalcular em Configuração, Configurações de compartilhamento.
  2. Atribua o conjunto de permissões MultiDatePick - Guest ao usuário convidado e dê a ele leitura em cada um dos seus próprios objetos e campos.
  3. Ative o site. Só publicar não basta.

O checklist completo de cinco passos para convidados está no Guia do usuário. Verificar meu site, no Assistente de Configuração, testa cada passo para você.

Verificar meu site mostra "Requer correção"

Por quê: Verificar meu site, nas etapas Revisar e Concluído do Assistente de Configuração para um calendário de site, testa o site do jeito que um convidado o encontra. Cada linha com Requer correção é um passo que falta, e ela diz o que fazer.

Solução

  1. O site ainda não está no ar: nos Espaços de trabalho do site, vá para Administração, Configurações, clique em Ativar e depois publique.
  2. Conjunto de permissões MultiDatePick - Guest: abra o usuário convidado e adicione o conjunto em Atribuições de conjunto de permissões.
  3. Acesso a objetos ou Acesso a campos: dê ao usuário convidado leitura no que o calendário mostra e edição no que uma reserva salva.
  4. Um convidado não pode ver nenhum dos recursos: adicione uma regra de compartilhamento de usuário convidado no objeto de recurso, em Configuração, Configurações de compartilhamento.

Só um administrador com MultiDatePick - Setup pode executar a verificação.

"Este calendário não pode salvar aqui: ele não indica nenhuma configuração salva para este objeto"

Por quê: a reserva de um convidado do site ou de um usuário do portal é verificada no servidor com base em uma configuração salva, para que as regras de privacidade e de reserva não possam ser contornadas. O calendário na página do site não tem Config Name, mas o objeto já tem uma configuração salva.

Solução

  1. Abra a página do site no Experience Builder.
  2. Defina o Config Name do calendário com a configuração salva para este site e publique.

"Este calendário não pode ser usado aqui: a configuração salva dele não foi feita para um site público"

Por quê: a página do site indica uma configuração feita para a equipe interna. Convidados do site e usuários do portal só podem usar uma configuração salva para um site, para que a privacidade e as regras de um calendário interno nunca cheguem ao público por engano.

Solução

  1. Defina o Config Name do calendário com uma configuração salva para o site, ou
  2. Crie uma: no Assistente de Configuração, responda Onde você vai colocar este componente? com Site do Experience Cloud e salve com um novo nome.

"Esta página liga as reservas a um registro que os visitantes do site não podem ver"

Por quê: cada reserva feita no site fica ligada a um único registro, definido em As reservas ficam ligadas a, e o usuário convidado não consegue lê-lo. O Salesforce mantém os registros privados para convidados, a menos que uma regra de compartilhamento de usuário convidado os compartilhe.

Solução

  1. Em Configuração, Configurações de compartilhamento, adicione no objeto desse registro uma regra de compartilhamento de usuário convidado que o compartilhe com o usuário convidado do site, como Somente leitura.
  2. Execute Verificar meu site de novo: Registro ao qual as reservas ficam ligadas deve passar.

"Não salvo nesta página pública"

Por quê: o Salesforce permite que convidados do site leiam e criem registros, mas nunca que os alterem ou excluam. Os visitantes podem ver e reservar. Usuários conectados com acesso podem editar.

Solução

  1. Não há nada para corrigir: é a regra de convidados do Salesforce. Para que as pessoas alterem as próprias reservas, dê a elas um login (um site para membros), ou deixe a equipe fazer a alteração.

"Cada reserva deste calendário dura 60 minutos, então este horário não pode ser reservado"

Por quê: para convidados do site e usuários do portal, o servidor verifica cada reserva com base na configuração salva: duração da reserva, Somente estes horários, os status que as pessoas podem escolher, a antecedência, o período de reserva e os limites. A página estava aberta enquanto o administrador mudava uma dessas regras, então ofereceu algo que a configuração não permite mais. Relacionadas: Este calendário aceita reservas apenas nos horários de início listados e O status Requested não pode ser escolhido neste calendário.

Solução

  1. Recarregue a página e reserve de novo.
  2. Continua recusando? O administrador do site pode conferir essas regras na configuração indicada em Config Name.

Membros do site não veem os registros que criaram

Por quê: compartilhamento do Experience Cloud. Usuários do site só veem os registros que o compartilhamento libera para eles.

Solução

  1. Adicione uma regra de compartilhamento (ou um conjunto de compartilhamento para membros) no objeto onde as datas são salvas, ou
  2. Abra o padrão externo para toda a organização desse objeto.

"O site não permite que outros websites o mostrem"

Por quê: você colocou o calendário no seu próprio site com o código de incorporação, e o site do Salesforce se recusa a aparecer dentro de outro site, que é o comportamento padrão.

Solução

  1. No Experience Builder, abra Configurações e depois Segurança e privacidade.
  2. Defina Clickjack Protection Level como Allow framing of site pages on external domains.
  3. Adicione o seu site em Trusted Domains for Inline Framing e publique.

Os convidados veem a lista de locais, mas não o mapa

Por quê: o mapa é desenhado por um serviço do Salesforce que o site bloqueia até ser marcado como confiável. O calendário não consegue saber quando um site o bloqueia; por isso, em um site, ele abre na lista e oferece o mapa.

Solução

  1. No Experience Builder, abra Configurações e depois Segurança e privacidade.
  2. Adicione maps.a.forceusercontent.com como site confiável para frames e publique.

Permissões e segurança

O calendário roda com as permissões de cada usuário. Comece pelo conjunto de permissões certo e depois dê acesso aos seus próprios objetos e campos.

Conjunto de permissõesAtribuir a
MultiDatePick - UserTodos que usam os calendários
MultiDatePick - SetupAdministradores que criam configurações. Inclui o Assistente de Configuração.
MultiDatePick - All AccessAdministradores que criam e usam calendários
MultiDatePick - GuestO usuário convidado de um site público do Experience Cloud

As mensagens de erro dizem o que está errado: o campo, o objeto ou a regra de validação. Quando uma mensagem termina em Detalhes:, aquele texto é a descrição do próprio Salesforce. Envie para o seu administrador, ou para nós, e ele mostra exatamente onde procurar.

"Você precisa de uma licença do MultiDatePick para usar este calendário"

Por quê: o MultiDatePick é licenciado por usuário, e este usuário não recebeu uma licença. O calendário é substituído por este aviso, e as gravações são recusadas. Convidados do site nunca precisam de licença.

Solução

  1. Em Configuração, abra Pacotes instalados e depois Gerenciar licenças ao lado do MultiDatePick.
  2. Clique em Adicionar usuários e adicione o usuário. Ele verá o calendário no próximo carregamento da página.

"Este usuário não tem acesso ao MultiDatePick, por isso a configuração não foi carregada"

Por quê: o usuário não tem nenhum conjunto de permissões do MultiDatePick, então o Salesforce não deixa o calendário executar as classes dele para esse usuário. O aviso vermelho mostra isso, com as palavras do próprio Salesforce na caixa cinza.

Solução

  1. Atribua MultiDatePick - User ao usuário, ou MultiDatePick - All Access a um administrador que também cria configurações.
  2. Em um site público, atribua MultiDatePick - Guest ao usuário convidado do site.

O registro não abre, ou aparece "privilégios insuficientes"

Por quê: o usuário não tem acesso de leitura ao objeto pai, ou o compartilhamento esconde esse registro dele. Em um fluxo de tela, o usuário pode não ter permissão para executar fluxos.

Solução

  1. Atribua MultiDatePick - User.
  2. Dê permissão de leitura no objeto pai em um conjunto de permissões.
  3. Verifique se o compartilhamento libera esse registro para o usuário.
  4. Em um fluxo de tela, marque Usuário de fluxo (Flow User) no registro do usuário, ou dê a permissão de usuário Executar fluxos (Run Flows) em um conjunto de permissões.

"Sem acesso de leitura ao campo X no objeto Y"

Por quê: o usuário não tem leitura na segurança em nível de campo de um campo que o calendário exibe: um campo de status, de passar o mouse, de data ou de hora.

Solução

  1. Conceda leitura no campo indicado na mensagem.
  2. Faça isso também para os administradores. Um campo personalizado novo fica oculto para todos, inclusive Administradores do sistema, até que um conjunto de permissões o libere.

"Faixas de horário não salvas", "Falha ao criar as reservas" ou "Você não pode editar o campo" citando um campo

Por quê: o usuário consegue ler os campos, mas não pode editar um que a gravação preenche. Muitas vezes é um campo de status, de segunda lista de opções ou de hora adicionado depois, ou um campo preenchido automaticamente em cada novo registro.

Solução

  1. Conceda edição em todos os campos que o calendário grava: data, hora inicial e final, status, segunda lista de opções, campo de nome, o campo lookup do pai e cada campo de Preencher automaticamente.
  2. Conceda criação no objeto onde os registros são salvos.

"Você não tem permissão para fazer isso" com "direitos de acesso insuficientes na ID de referência cruzada" (insufficient access rights on cross-reference id)

Por quê: o novo registro aponta para um registro que o usuário não consegue ver: o pai ou o recurso.

Solução

  1. Dê pelo menos leitura nos objetos pai e de recurso, e compartilhamento nesses registros.
  2. Em um site público, faça as reservas de convidados em um objeto personalizado. O Salesforce restringe o acesso de convidados a Contatos e Contas.

"Você não tem acesso aos fechamentos usados por este calendário"

Por quê: o usuário não consegue ler o objeto que guarda os dias fechados, então o calendário não sabe quais dias estão fechados. A mensagem gêmea, Você não tem acesso aos registros exibidos neste calendário, significa o mesmo para as próprias reservas.

Solução

  1. Dê leitura no objeto e nos campos indicados na mensagem, em um conjunto de permissões.
  2. Verifique se o compartilhamento libera esses registros para o usuário.

"Você não pode criar registros de Visit do tipo de registro Install"

Por quê: o calendário atribui às novas reservas um tipo de registro que o perfil ou os conjuntos de permissões do usuário não incluem.

Solução

  1. Adicione o tipo de registro ao perfil do usuário ou a um conjunto de permissões.
  2. Ou defina Tipo de registro das novas reservas como Deixar as pessoas escolherem, que lista só os tipos que cada pessoa pode criar.

"O Salesforce não permitiu atribuir este registro (Visit) a Alex Chen"

Por quê: a sala ou pessoa da reserva é um usuário do Salesforce, e o Salesforce se recusou a torná-lo proprietário. A mensagem termina com o motivo: você não tem acesso para atribuir registros a essa pessoa, o usuário está inativo ou esse tipo de usuário não pode ser proprietário deste tipo de registro.

Solução

  1. Escolha outra pessoa.
  2. Ou peça ao seu administrador do Salesforce acesso para atribuir registros a esse usuário, ou que ative o usuário.

"Você não tem permissão para salvar configurações do MultiDatePick"

Por quê: as configurações são salvas como metadados do Salesforce, o que exige a permissão Modify Metadata Through Metadata API Functions. O conjunto de permissões MultiDatePick - Setup concede essa permissão.

Solução

  1. Atribua MultiDatePick - Setup, ou MultiDatePick - All Access, ao administrador que cria as configurações.

Fluxos e ações

O calendário em um fluxo de tela (Screen Flow) e os botões que executam um fluxo.

Uma tela de fluxo ignora as definições do assistente

Por quê: Config Name está vazio ou com erro de digitação. Vazio, o componente simplesmente usa os valores padrão. Com erro de digitação, ele mostra "Nenhuma configuração chamada ... foi encontrada".

Solução

  1. Defina Config Name com o nome da configuração exatamente como o Assistente de Configuração o salvou.
  2. Não mexa nas entradas de ativar/desativar. Todas as caixas de seleção vêm da configuração.

"Algumas datas escolhidas ainda não foram salvas. Clique em Salvar ou remova-as antes de continuar."

Por quê: o botão Avançar da tela foi clicado enquanto o calendário ainda tinha seleções que nunca foram salvas, e elas se perderiam. Com horários, a mensagem diz Alguns horários escolhidos ainda não foram reservados.

Solução

  1. Clique em Salvar (ou Reservar) primeiro e depois em Avançar.
  2. Ou remova as seleções que você não quer e clique em Avançar.

"Você não pode executar Send Reminder: é preciso ter a permissão "Run Flows" ou acesso ao fluxo dela"

Por quê: o botão de ação do calendário executa um fluxo, e o Salesforce só deixa iniciá-lo quem tem permissão para executar esse fluxo.

Solução

  1. Dê ao usuário a permissão Executar fluxos (Run Flows) em um conjunto de permissões, ou
  2. Dê ao perfil ou conjunto de permissões dele acesso a esse fluxo (Configuração, Fluxos, o fluxo, Editar acesso).

"O fluxo parou com um erro" ou "Esta ação não está disponível aqui"

Por quê: a primeira significa que o fluxo por trás de um botão de ação foi executado e falhou. A segunda significa que o botão não é mais oferecido para este registro: a ação foi removida da configuração salva, ou está definida para outros status.

Solução

  1. Para um erro de fluxo, o administrador abre o histórico de execução ou o log de depuração do fluxo para ver qual etapa falhou.
  2. Para uma ação indisponível, recarregue a página e confira os status da ação nas ações da configuração.

"Este fluxo não tem a variável de entrada recordId nem recordIds"

Por quê: o Assistente de Configuração passa o registro clicado para o fluxo de uma ação em uma variável chamada recordId (um registro) ou recordIds (vários, no modo de edição). Sem uma delas, o fluxo não sabe quais registros usar.

Solução

  1. No Flow Builder, adicione uma variável de texto chamada recordId, ou uma coleção de texto chamada recordIds, disponível para entrada.
  2. Salve e ative o fluxo e escolha-o de novo no assistente.

Gráfico de Gantt

Tarefas, vínculos entre elas e progresso na visualização de Gantt.

A visualização de Gantt não aparece no seletor

Por quê: a visualização de Gantt é opcional, como a visualização Mapa. Com Available Views em branco, o seletor oferece Calendário, Linha do tempo, Semana, Ocupação e Agenda.

Solução

  1. No Assistente de Configuração, marque Oferecer a visualização de Gantt na guia Visualizações, ou adicione gantt a Available Views.
  2. Para abrir direto nela, defina View como gantt.

"Site survey não pode ficar em 6 de dez.: este calendário não permite esse dia. Nada foi salvo."

Por quê: o Gantt segue as mesmas regras de reserva do calendário. Uma tarefa não pode ir para um dia ou horário fechado, para uma pessoa que já está em outra tarefa naquele dia ou para um recurso que não aceita reservas. A mensagem sempre cita a regra.

Solução

  1. Arraste a tarefa para outro dia, ou passe-a para alguém livre.
  2. Se o dia deveria estar aberto, o administrador confere os fechamentos e os dias que as pessoas podem escolher na configuração.

"Install não pode aguardar Testing: isso criaria um ciclo"

Por quê: Testing já aguarda Install, diretamente ou por meio de outras tarefas, então vinculá-las no sentido contrário faria com que nenhuma pudesse começar. Uma pergunta relacionada, Substituir o vínculo?, aparece quando as tarefas são vinculadas por um campo na tarefa: nesse caso, cada tarefa só pode aguardar uma outra.

Solução

  1. Remova primeiro o vínculo no sentido contrário, ou vincule outra tarefa.
  2. Para que uma tarefa possa aguardar várias, vincule as tarefas com um objeto de vínculo separado: Assistente de Configuração, Visualização de Gantt, Vínculos entre tarefas.

"O status fica como estava" ou "Concluído fica como estava, não 100%"

Por quê: Status de uma tarefa concluída liga Percentual concluído e Status: uma tarefa definida como 100% recebe esse status, e uma tarefa que recebe esse status vai para 100%. Quando o usuário não pode editar um dos dois campos, ou o campo de status não oferece o valor, só a alteração que ele fez é salva, e esta mensagem explica o motivo.

Solução

  1. Dê ao usuário edição no campo de Percentual concluído e no campo de status.
  2. Verifique se o campo de status oferece o valor escolhido para esse tipo de registro, ou escolha outro nas configurações da visualização de Gantt, ou deixe em branco para manter os dois separados.

"Nada foi salvo. Somente leitura para você: Site survey"

Por quê: o usuário consegue ver a tarefa, mas não editá-la, por causa do compartilhamento, da segurança de campo ou do proprietário do registro. O cartão dela diz Somente leitura para você.

Solução

  1. Peça ao proprietário da tarefa, ou a um administrador, acesso de edição pelo compartilhamento.
  2. Confira a edição nos campos de data da tarefa no seu conjunto de permissões.

Importar configuração

Colar uma configuração da Config Library ou de outra organização na guia Importar / Exportar do Assistente de Configuração.

"Isto não é uma configuração completa" ou "Isto parece XML, não JSON"

Por quê: o texto colado não é uma configuração inteira. Ele foi cortado na cópia, é XML de metadados do Salesforce ou um fluxo em vez do JSON da configuração, ou contém um arquivo inteiro de configurações (acima de 100 KB).

Solução

  1. Copie a configuração de novo com o botão de copiar da Config Library, ou com Exportar Configuração na outra organização.
  2. Cole o texto inteiro, da primeira { até a última }.

Tem o XML de um fluxo? Implante-o como fluxo: Implantar um fluxo pelo VS Code.

"Esta configuração não funciona sem Related_Object__c"

Por quê: a configuração colada deixa de fora uma definição que toda configuração precisa ter, como o objeto, o campo de data ou o tipo de componente.

Solução

  1. Copie a configuração de novo, inteira, ou
  2. Exporte uma configuração que funcione na sua organização para ver o formato necessário e adicione as definições que faltam.

Uma definição "salvaria "Confirmed", que Visit Status não tem, então o Salesforce recusaria todo salvamento"

Por quê: uma definição da configuração importada, como Preencher automaticamente ou Status que as pessoas podem escolher, usa um valor de status que o seu campo de status não tem. Salva assim, todas as reservas seriam recusadas. Na etapa Associe os valores de status, um valor marcado com Seu campo não tem um valor assim fica de fora até você escolher um.

Solução

  1. Volte para Associe os valores de status.
  2. Para cada um, escolha qual dos seus valores significa o mesmo e clique em Aplicar & Implantar.

"O fluxo Send_Reminder não está nesta organização"

Por quê: a configuração importada tem um botão de ação que executa um fluxo que a sua organização não tem.

Solução

  1. Na etapa Ações, escolha um dos seus próprios fluxos para o botão, ou escolha Ignorar esta ação.
  2. Você pode adicionar a ação depois, nas ações da configuração.
