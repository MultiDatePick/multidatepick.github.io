Implantar um fluxo pelo VS Code

Você copiou um fluxo inicial do artigo sobre loops em fluxos. Veja como levar esse fluxo para a sua organização Salesforce com o VS Code e o Salesforce CLI. Este é o caminho do desenvolvedor. Se preferir não mexer em um editor de código, siga o Guia de fluxo de tela: coloque o componente em uma tela e defina o Config Name.

O que isto faz: o XML copiado é um fluxo de tela (Screen Flow) pronto que incorpora o componente MultiDatePick, já ligado a um conjunto sensato de objetos e campos. Você o implanta uma vez e depois renomeia alguns nomes de API para os da sua organização. Na primeira vez leva uns 15 minutos; depois, alguns minutos.

1. O que você precisa

Três ferramentas gratuitas. Instale uma vez e você estará pronto para todas as implantações futuras:

  • Visual Studio Code: o editor de código.
  • Salesforce Extension Pack: adiciona os comandos SFDX ao VS Code. Instale pelo painel Extensions (pesquise "Salesforce Extension Pack").
  • Salesforce CLI (sf): a ferramenta de linha de comando pela qual a implantação é feita. Confirme que está instalada executando sf version no terminal do VS Code.

2. Configuração única

Pule esta seção se você já trabalha em um projeto SFDX conectado à sua organização.

A Autorize sua organização

Conecte o VS Code à sua organização Salesforce. Abra a Command Palette (Ctrl/Cmd + Shift + P) e execute SFDX: Authorize an Org, ou execute isto no terminal:

sf org login web --alias myorg

Um navegador se abre; faça login e aprove. Use primeiro um sandbox ou uma organização Developer, não a produção.

B Abra ou crie um projeto

Se você tem um projeto SFDX, abra a pasta dele no VS Code (File → Open Folder). Se não, crie um:

sf project generate --name multidatepick-flows
cd multidatepick-flows

Depois abra essa pasta no VS Code. Você deve ver uma estrutura force-app/main/default/ no painel Explorer.

3. Importe o XML copiado

1 Crie o arquivo do fluxo

No Explorer, expanda force-app/main/default/ e abra (ou crie) a pasta flows. Adicione um novo arquivo com o nome do seu fluxo, terminando em .flow-meta.xml, por exemplo On_Call_Rotation.flow-meta.xml. O nome vira o nome de API do fluxo, então use apenas letras, números e sublinhados.

Ou crie direto no terminal integrado do VS Code:

# Windows (PowerShell)
New-Item force-app/main/default/flows/On_Call_Rotation.flow-meta.xml -ItemType File -Force
# macOS / Linux
mkdir -p force-app/main/default/flows && touch force-app/main/default/flows/On_Call_Rotation.flow-meta.xml

2 Cole e salve

Cole o XML do fluxo inicial que você copiou do artigo sobre loops em fluxos no novo arquivo e salve (Ctrl/Cmd + S).

3 Implante na sua organização

Clique com o botão direito no arquivo no Explorer e escolha SFDX: Deploy Source to Org, ou execute isto no terminal:

sf project deploy start --source-dir force-app/main/default/flows/On_Call_Rotation.flow-meta.xml

Acompanhe o painel Output até aparecer Deploy Succeeded. Se ele relatar um erro de campo ou objeto, é esperado. A próxima etapa resolve isso.

4. Conclua no Flow Builder

4 Troque pelos nomes do seu objeto e dos seus campos

Na sua organização, vá até Configuração → Fluxos e abra o fluxo que você acabou de implantar. Procure os elementos e notas marcados com >>> UPDATE. Eles apontam para os nomes de API de objeto e campo que o exemplo presumiu. Altere cada um para o seu objeto, campo de data e campo lookup. Depois clique em Salvar e Ativar.

Agora coloque o fluxo em uma página ou em um botão, ou execute-o diretamente, e os usuários já podem selecionar datas.

Resumo dos comandos: 
sf org login web --alias myorg                 # authorize once
sf project generate --name multidatepick-flows  # only if you need a new project
sf project deploy start --source-dir force-app/main/default/flows/YOUR_FLOW.flow-meta.xml
Travou no CLI? O guia de configuração do CLI do Salesforce explica a instalação e o login em detalhes.
