1Instale o MultiDatePick pelo AppExchange

Um único pacote gerenciado: os três componentes, o Assistente de Configuração e as ações de fluxo.

InstalarNo anúncio do AppExchange (no lançamento), clique em Obter agora. Instale só para administradores, para todos os usuários ou para perfis específicos.
ConferirEm Configuração, Pacotes instalados aparece o MultiDatePick. No Lightning App Builder ou no Flow Builder, pesquise MultiDatePick para ver Dates, Dates & Times e Resource Booking.
AprenderO pacote traz tours guiados: Intro to MultiDatePick pergunta o que você quer fazer e depois inicia o tour Escolher, Reservar ou Planejar. Inicie-os pelo Assistente de Configuração.
IdiomasSe a sua organização usa o Workbench de tradução (Translation Workbench), o idioma de cada usuário precisa estar ativo em Configuração, Workbench de tradução, Configurações de idioma de tradução para que os valores de lista de opções traduzidos do MultiDatePick, como os valores de status, apareçam. Os rótulos dos campos e os textos do próprio calendário são traduzidos de qualquer forma.

2Atribua os conjuntos de permissões do MultiDatePick

A instalação não dá acesso a ninguém. Atribua um destes em Configuração, Conjuntos de permissões.

Conjunto de permissõesPara quem
MultiDatePick - SetupOs um ou dois administradores que criam configurações. Inclui o Assistente de Configuração.
MultiDatePick - UserTodos que usam os calendários. Sem o assistente.
MultiDatePick - All AccessAdministradores que criam e usam.
MultiDatePick - GuestO usuário convidado de um site público do Experience Cloud.

Seus objetos são à parte. Os usuários também precisam de acesso de leitura e criação aos objetos e campos que a configuração usa. Se faltar algo, o calendário informa exatamente qual campo ou objeto.

4Adicione um calendário a uma página de registro do Salesforce

No Lightning App Builder, arraste o componente MultiDatePick para a página, digite o Config Name e salve. A demo de importação acima termina exatamente nisso.

PáginaO que você define
Página de registroConfig Name. O registro da página é o pai automaticamente.
Páginas de aplicativo e iniciaisConfig Name. Static Parent Record Id só quando a resposta do assistente é De um registro específico.

Página nova? Ative-a. Depois de Salvar, clique em Ativar quando o Lightning App Builder pedir e atribua a página como padrão da organização ou a um aplicativo e um perfil. Enquanto uma página nova não for ativada, ninguém a vê.

Load Existing Dates (Pré-Carregar Datas Existentes) mostra as datas já salvas. Salvar só adiciona registros; nunca exclui os existentes.

Páginas de aplicativo e iniciais: os registros de quem?

Essas páginas não têm um registro próprio. O assistente pergunta de quem são os registros a mostrar; Só de quem está vendo é o padrão e não precisa de mais nada. Escolha De um registro específico para salvar sempre no mesmo registro fixo (Static Parent Record Id).

Passo a passo completo e casos de uso: páginas de aplicativo, iniciais e do Experience Cloud.

5Adicione o MultiDatePick a um fluxo de tela

Vincule o Parent Record Id e cada componente salva os próprios registros, sem precisar de loop. No Flow Builder, abra uma tela, pesquise MultiDatePick, arraste o componente, defina o Config Name e vincule o Parent Record Id ao registro para o qual o fluxo é executado, como {!recordId}.

As caixas de seleção vêm da configuração. Com o Config Name definido, você nunca mexe numa caixa de seleção no Flow Builder. As exclusivas do fluxo (Required, Show Inline) ficam desligadas, a menos que você as ative.

Quem pode executá-lo. Toda pessoa que executa o fluxo precisa da caixa Usuário de fluxo (Flow User) marcada no registro de usuário, ou da permissão de usuário Executar fluxos (Run Flows) em um conjunto de permissões. Sem isso, o Salesforce mostra “Privilégios insuficientes” no lugar do fluxo.

O que o fluxo recebe de volta

ComponenteUse
Resource BookingSalva os próprios registros. Leia bookingSuccessCount e bookingConflictDates.
DatesselectedDates, ou selectedDateRangesJson para intervalos.
Dates & TimesselectedDatesWithTimesJson.

Quer controle total? No Assistente de Configuração, responda Quem salva? com Meu fluxo salva (ou deixe o Parent Record Id em branco) no Dates ou no Dates & Times, e a seleção vai para o fluxo. Adicione a ação Parse Date Entries from JSON, percorra a saída dela com um loop e crie um registro por entrada. Tudo com cliques. Todos os detalhes estão no Guia de fluxo de tela.

Dúvidas de configuração

Respostas curtas para o que os administradores perguntam primeiro.

Preciso de Apex ou de um desenvolvedor para configurar o MultiDatePick?

Não. Você instala o pacote, cria uma configuração no Assistente de Configuração escolhendo objetos e campos em listas e coloca o componente numa página ou numa tela de fluxo. Sem necessidade de Apex.

Qual conjunto de permissões do MultiDatePick devo atribuir?

MultiDatePick - Setup para os administradores que criam configurações, MultiDatePick - User para todos que só usam os calendários, MultiDatePick - All Access para administradores que fazem as duas coisas e MultiDatePick - Guest para o usuário convidado de um site público do Experience Cloud. Os usuários também precisam de acesso aos seus próprios objetos e campos.

Por que não aparece o botão Salvar no calendário da minha página de aplicativo ou página inicial?

Páginas de aplicativo e iniciais não têm um registro próprio. No Assistente de Configuração, responda “Os registros de quem?” (“Só de quem está vendo”, “De todos” ou “Só os que correspondem” não precisam de pai; “De um registro específico” precisa do Static Parent Record Id) e salve a configuração de novo.

Preciso marcar cada caixa de seleção no Flow Builder?

Não. Defina o Config Name com a configuração que você salvou no Assistente de Configuração e todas as caixas de seleção vêm dela. Só se você deixar o Config Name de lado e definir as propriedades à mão é que precisa marcar as caixas.

Dá para levar uma configuração do MultiDatePick para outra organização Salesforce?

Sim. Exporte-a na aba Configurações Existentes e cole o JSON na aba Importar / Exportar da outra organização. A importação permite associar nomes de objetos ou campos que sejam diferentes.

Quais objetos do Salesforce preciso para o MultiDatePick?

Reservar precisa de um objeto de reserva com uma data e uma pesquisa para um objeto de recurso com um nome. Escolher precisa de um objeto filho com uma data e uma pesquisa para o registro ao qual pertence. Planejar precisa de um objeto com uma data de início; uma pesquisa para um projeto agrupa as tarefas. Use seus próprios objetos ou os objetos prontos MDP Schedule e MDP Resource que vêm com o MultiDatePick.
