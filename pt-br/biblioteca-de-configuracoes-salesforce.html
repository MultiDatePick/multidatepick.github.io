Como funciona a importação de uma configuração

Estas configurações de exemplo foram montadas sobre os objetos de demonstração que vêm com o MultiDatePick (Schedule__c, Event__c, Resource__c). Sua organização quase sempre vai usar objetos e nomes de campo próprios. Isso é esperado e tem suporte.

  1. Copiar para o Assistente de Configuração em qualquer cartão abaixo.
  2. Cole na aba Importar do Assistente de Configuração (Iniciador de aplicativos, Assistente de Configuração do MultiDatePick, Importar).
  3. Mapeie os campos: se algum objeto ou campo citado no JSON não existir na sua organização, o assistente mostra um painel de mapeamento inteligente de campos com cada referência ausente e uma lista dos objetos e campos correspondentes da sua organização. Escolha o substituto de cada um e clique em Aplicar & Implantar.
  4. Use o Config Name: coloque o componente numa página Lightning, num site do Experience Cloud ou numa tela de fluxo e digite o Config Name.

Sem código, sem editar XML. O assistente reescreve a configuração com as suas escolhas antes de implantar os metadados, então a configuração importada chega pronta para ir para uma página de registro na sua organização. Se tudo já bater (por exemplo, ao clonar entre sandboxes), a etapa de mapeamento é pulada automaticamente.

Nenhuma configuração daqui serve? Crie uma no assistente.

Cada objeto e campo é uma lista de opções filtrada pela sua organização, então uma configuração funcionando leva poucos minutos e nenhum nome de API.

Quer usar num fluxo de tela (Screen Flow)? Use a mesma configuração.

Arraste o componente para uma tela de fluxo e digite o Config Name. Para um fluxo que salva um registro por data ou por turno, veja o artigo sobre loops em fluxos.

Uma configuração, cinco formas de ver

Toda configuração abaixo define uma View (Exibição) padrão e uma lista de Available Views (Visualizações Disponíveis). Os dados, os campos e o comportamento ao salvar continuam idênticos: só muda o layout. Os usuários alternam pelos botões acima do calendário, e você decide quais eles recebem.

calendar

Grade do mês

O padrão. Um mês por vez, cores de status por dia, clique ou arraste para escolher datas. Ideal quando a pergunta é "o que acontece no dia 14?".

timeline

Recursos na vertical, datas na horizontal

Duas semanas por padrão, para que cada reserva tenha espaço para o nome. Reservas de vários dias aparecem como uma única barra. Recursos muito ocupados se recolhem numa só linha, que você pode expandir.

week

Dia por hora

Sete dias na horizontal, seu horário comercial na vertical. Arraste na horizontal, na vertical ou nos dois sentidos para selecionar um bloco de tempo em vários dias de uma vez.

utilization

Mapa de calor de capacidade

Porcentagem da capacidade usada por recurso por dia, em cores do verde ao vermelho. Precisa de um Campo de Capacidade para mostrar porcentagens em vez de contagens simples.

Somente leitura
agenda

Lista cronológica

Os próximos 60 dias numa lista simples e fácil de percorrer, com horários e status. Boa para uma passagem de turno, um resumo diário ou uma tela de celular.

Somente leitura
Antes de escolher o padrão. Ocupação e Agenda são somente leitura, então não servem como padrão para uma configuração cujo objetivo é reservar: coloque-as em Available Views e use como padrão uma visualização que grava. E a visualização padrão sempre aparece no seletor, esteja ou não na lista, então Available Views só precisa das extras.

Painel de Recursos (Somente Leitura)

Uma tela na parede ou um resumo para a diretoria. Toda visualização oferecida é somente leitura ou feita primeiro para leitura, o modo de edição está desligado para ninguém reservar por engano, e datas passadas são permitidas para o painel olhar tanto para trás quanto para frente.

Agendamento com Consultores

A pessoa é o recurso. Cada consultor, representante, assessor ou gerente de contas vira uma linha reservável, então a reunião com o cliente é agendada com um usuário real do Salesforce, não com uma sala. Abre na Semana porque um atendimento de 30 minutos é uma questão de horário; a Linha do tempo responde quem tem espaço nesta semana, e a Agenda é a leitura cronológica para a reunião rápida da manhã.

User como recurso: Resource Object API Name é User, filtrado por uma caixa de seleção personalizada Is_Advisor__c, para que o seletor traga só os consultores, e não todos os usuários ativos da organização. Business Hours Start Field e Business Hours End Field no User dão a cada pessoa o próprio expediente, então a grade semanal mostra as horas em que ela realmente trabalha. Conflict Behavior é block, porque uma pessoa nunca pode ter dois compromissos ao mesmo tempo.
Configurações principais
  • Resource Object API Name (Objeto de Recurso) User resourceObjectApiName
  • Resource Filter Field (optional) (Campo de Filtro de Recurso) Is_Advisor__c resourceFilterField
  • Booking Resource Field (Campo de Recurso da Reserva) bookingResourceField
  • Second Picklist Field (Segundo campo de lista de opções) Meeting_Type__c secondStatusField
  • Conflict Behavior (Comportamento de Conflito) block conflictBehavior
  • Blocked Dates Object (Objeto Fonte de Datas Bloqueadas) blockedDatesSourceObject
  • Hover Popover Fields (Campos ao Passar o Mouse) hoverFields

Casos de uso de sub-blocos

Com Consolidate Time Span ativado, as lacunas entre os horários selecionados são detectadas automaticamente e salvas como registros separados num objeto filho. Os usuários também podem marcar horários como sub-blocos manualmente.

  • Escala de turnos com intervalos: o funcionário seleciona das 8h às 17h; a lacuna do almoço, das 12h às 13h, cria automaticamente um registro num objeto Break__c
  • Roteiros de viagem: o usuário bloqueia janelas de viagem; as conexões entre voos viram registros de Travel_Leg__c
  • Cronogramas de treinamento: o instrutor seleciona os blocos de aula; os períodos livres entre as sessões são salvos como registros de Available_Slot__c
  • Expedientes com compromissos: o gestor define o horário de trabalho; as lacunas para reuniões ou atendimentos são salvas automaticamente num objeto Appointment__c
Importante: todas as configurações desta biblioteca usam nomes de objetos e campos de exemplo. Antes de importar, troque os valores em laranja pelos nomes de API do seu objeto de registro e dos seus campos. Se você usa sub-blocos, troque os valores em roxo pelo seu objeto filho e pelos campos dele. Se você usa datas bloqueadas, troque também os valores em vermelho. Todo o resto funciona como está.
