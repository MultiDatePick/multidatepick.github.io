Salesforce 版 MultiDatePick のはじめに

インストールし、セットアップウィザードで設定を作成して、Lightning ページか画面フロー (Screen Flow) にカレンダーを配置します。

  1. 1インストールAppExchange から
  2. 2権限セット作る人と使う人
  3. 3セットアップウィザードまたは設定をインポート
  4. 4Lightning ページレコード、アプリケーション、ホーム、サイト
  5. 5画面フローConfig Name を設定

どの MultiDatePick コンポーネントを使えばよいですか?

要件に合う最もシンプルなものから始めましょう。3 つとも 1 つのパッケージに含まれ、すべての機能を使えます。

Date

日付だけ。範囲、繰り返しパターン、状況の色分け。

Date コンポーネントのガイド →

Date Time

日付と時刻。タイムグリッドと競合チェックが加わります。

Date Time コンポーネントのガイド →

Booking

会議室、設備、人を、空き状況と定員付きで。

Booking コンポーネントのガイド →
必要なことDateDate TimeBooking
複数の日付、範囲、繰り返しパターン✓✓✓
状況の色分け、ホバー表示、編集モード✓✓✓
時間枠グリッドと競合の検出-✓✓

1AppExchange から MultiDatePick をインストールする

1 つの管理パッケージに、3 つのコンポーネント、セットアップウィザード、フローアクションが含まれています。

インストールAppExchange のリスト (公開時) で Get It Now をクリックします。管理者のみ、全ユーザー、または特定のプロファイルを対象にインストールします。
確認[設定] の [インストール済みパッケージ] に MultiDatePick が表示されます。Lightning App Builder または Flow Builder で MultiDatePick を検索すると、Dates、Dates & Times、Resource Booking が表示されます。
使い方を学ぶパッケージにはガイド付きのフローが含まれています: Intro to MultiDatePick と、Dates、Date Time、Booking それぞれの Deep Dive フローです。セットアップウィザードから起動できます。

2MultiDatePick の権限セットを割り当てる

インストールしただけでは、誰にもアクセス権は付与されません。[設定] の [権限セット] で、次のいずれかを割り当ててください。

権限セット割り当てる相手
MultiDatePick - Setup設定を作成する 1〜2 名の管理者。セットアップウィザードを含みます。
MultiDatePick - Userカレンダーを使うすべてのユーザー。ウィザードは含みません。
MultiDatePick - All Access設定の作成と利用の両方を行う管理者。

自社のオブジェクトの権限は別です。ユーザーには、設定で使うオブジェクトと項目への参照・作成のアクセス権も必要です。足りないものがあれば、カレンダーが該当する項目やオブジェクトを具体的に表示します。

アプリケーションランチャーから MultiDatePick セットアップウィザードを開きます。オブジェクトと項目はすべてドロップダウンで選べ、操作に合わせてライブプレビューが更新されます。

手順に沿って案内してほしいデータに関する 3 つの質問に答えると、ウィザードがコンポーネントを選び、残りを自動入力します。初めての方におすすめです。
すべてのプロパティを設定すべてのプロパティを表示し、何も事前設定しません。上級者や既存の設定の編集におすすめです。

保存した設定は再利用できます。ページやフローに必要なのは設定名だけです。[既存の設定] タブで設定を [複製] してバリエーションを作ったり、別の組織用に JSON として [エクスポート] したりできます。

4Salesforce のレコードページにカレンダーを追加する

Lightning App Builder で MultiDatePick コンポーネントをページにドラッグし、Config Name を入力して保存します。上のインポートのデモも、まさにこの操作で終わります。

ページ設定するもの
レコードページConfig Name。ページのレコードが自動的に親になります。
アプリケーション・ホーム・Experience ページConfig Name に加えて、日付を紐付けるレコードを Static Parent Record Id に指定します。

Load Existing Dates をオンにすると、保存済みの日付が表示されます。保存はレコードを追加するだけで、既存のレコードを削除することはありません。

アプリケーション・ホーム・Experience ページ: Static Parent Record Id を設定

これらのページには自身のレコードがないため、どのレコードに保存するかをコンポーネントに指定します。

詳しい手順と活用例: アプリケーション・ホーム・Experience ページ。

5画面フローに MultiDatePick を追加する

Flow Builder で画面を開き、MultiDatePick を検索してコンポーネントをドラッグし、Config Name を設定します。

チェックボックスは設定から読み込まれます。Config Name を設定すれば、Flow Builder でチェックボックスに触れる必要はありません。フロー専用のもの (Required、Show Inline、Output Date Ranges as JSON) は、自分でオンにしない限りオフのままです。

フローが受け取るもの

コンポーネント使う出力
Bookingレコードは自分で保存します。bookingSuccessCount と bookingConflictDates を参照します。
DateselectedDates。範囲の場合は selectedDateRangesJson。
Date TimeselectedDatesWithTimesJson。

JSON からレコードを作成するには、Parse Date Entries from JSON アクションを追加し、その出力をループして、エントリごとに 1 件ずつレコードを作成します。すべてクリック操作だけです。詳細はすべて画面フローガイドにあります。

新しく設定したときに最もよく起きる 4 つのケースです。それぞれの解決方法はトラブルシューティングのページに詳しく載っています。

症状解決策
保存ボタンがないStatic Parent Record Id を設定します。詳細
フローがウィザードの設定を無視するConfig Name をウィザードで保存したとおりに正確に入力します。詳細
Booking に「設定が必要です」と表示されるConfig Name に Booking の設定を指定します。詳細
「データを読み込めませんでした」という赤いバナーグレーのボックスを読んでください。原因となる項目やアクセス権が表示されています。詳細

設定に関するよくある質問

管理者が最初に抱く疑問に簡潔にお答えします。

MultiDatePick の設定に Apex や開発者は必要ですか?

いいえ。パッケージをインストールし、ドロップダウンからオブジェクトと項目を選んでセットアップウィザードで設定を作成し、コンポーネントをページやフロー画面に配置するだけです。Apex は不要です。

どの MultiDatePick 権限セットを割り当てればよいですか?

設定を作成する管理者には MultiDatePick - Setup、カレンダーを使うだけのユーザーには MultiDatePick - User、両方を行う管理者には MultiDatePick - All Access を割り当てます。ユーザーには、自社のオブジェクトと項目へのアクセス権も必要です。

アプリケーションページやホームページのカレンダーに保存ボタンが表示されないのはなぜですか?

アプリケーションページ、ホームページ、Experience ページには、そのページ自体のレコードがありません。Static Parent Record Id に日付を紐付けるレコードを設定すると、保存ボタンが表示されます。

Flow Builder ですべてのチェックボックスを設定する必要がありますか?

いいえ。Config Name にセットアップウィザードで保存した設定を指定すれば、チェックボックスの設定はすべて設定から読み込まれます。Config Name を使わずにプロパティを手動で設定する場合だけ、チェックボックスを自分で設定します。

MultiDatePick の設定を別の Salesforce 組織に移せますか?

はい。[既存の設定] タブからエクスポートし、移行先の組織の [インポート] タブに JSON を貼り付けます。オブジェクト名や項目名が異なる場合も、スマートな項目マッピングで対応付けられます。
