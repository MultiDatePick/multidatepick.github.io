1. 3 つのコンポーネント: 使い分け

MultiDatePick には、共通の基盤の上に作られた 3 つの Lightning Web コンポーネントが含まれています。データに合うものを選んでください。

複数の日付をまとめて選択。出欠確認、出席、休暇、利用停止日、祝日カレンダーに最適です。

2. レコード形式: 使い分け

レコード形式とは、選択内容をどのようにレコードにするかです。3 つの独立した選択で決まり、どの組み合わせでも動作します。

選択 1
時刻

Date: 日付のみ、時刻なし。

Date Time / Booking: 各レコードに開始時刻と終了時刻があります。

追加オプション: Consolidate Time Span（時間範囲を統合） をオンにすると、時間範囲全体で 1 件の親レコードを作り、その中の空き時間ごとにサブブロックの子レコードを作ります。

選択 2
リソース

なし: リソースなしの Date、Date Time、または Booking。

単一リソース: リソースのドロップダウン付きの Booking。

複数リソース: チェックボックス付きの Booking。チェックしたリソースごとに 1 件のレコード。

選択 3
範囲

クリックごと: 選択した日付ごとに 1 件のレコード。5 回クリックすれば 5 件のレコード。

範囲ごと: 連続した日付を、開始日と終了日を持つ 1 件のレコードにまとめます。End Date Field API Name を設定してください。

セットアップウィザードでは 6 つの形式に名前があります: 日付ごとに 1 レコード、日付範囲ごとに 1 レコード、時間帯ごとに 1 レコード、親 + サブブロック、単一リソース、複数リソース。

具体例: 構成を選ぶ

以下の各シナリオは、いずれか 1 つの構成に当てはまります。セットアップウィザードにも同じ 6 つがカードで表示されます。

休暇申請

時刻は必要ですか? いいえ、日付だけです。

リソースの選択は必要ですか? いいえ。

連続した日付はまとめますか? はい。月曜から金曜の休暇は 1 件のレコードにすべきです。

→ 範囲ごと: 開始が月曜、終了が金曜の 1 件のレコード。

会議室の予約

時刻は必要ですか? はい、各予約に開始時刻と終了時刻があります。

リソースの選択は必要ですか? はい、会議室を 1 つ選びます。

連続した日付はまとめますか? いいえ、予約ごとに 1 件のレコードです。

→ 単一リソース: 日付 × 時間帯ごとに 1 件のレコードを会議室に紐付けて作成。

3 つの会議室での研修

時刻は必要ですか? はい、毎日同じ開始時刻と終了時刻です。

リソースの選択は必要ですか? はい、チェックボックスで複数の会議室を選びます。

連続した日付はまとめますか? はい、月曜から金曜まで続きます。

→ 複数リソース、範囲ごと: 会議室ごとに 1 週間全体をカバーする 1 件のレコード。

時刻は必要ですか? はい、午前 9 時から午後 5 時、昼休憩あり。

リソースの選択は必要ですか? いいえ。

空き時間も記録しますか? はい、独自の子レコードとして記録します。

→ 親 + サブブロック: 午前 9 時から午後 5 時の親レコード 1 件と、昼休憩のサブブロック 1 件。

3. セットアップウィザードの手順

セットアップウィザードで設定を一度保存します。任意のページやフロー画面で、その名前を Config Name（設定名） に入力すれば、その配置で設定が使われます。設定を変更すると、すべての配置に反映されます。

  1. 1 配置場所
  2. 2 構成
  3. 3 クイックスタート
  4. 4 確認

ステップ 1: 配置場所

カレンダーを置く場所を選びます: 標準・カスタムを問わず任意のオブジェクトのレコードページ、アプリページまたはホームページ、画面フロー、公開サイト。レコードページならそのオブジェクトを、それ以外なら選択内容の保存先オブジェクトを検索します。次に、最小から全幅までサイズを選びます。隣には 2 つのタブがあります。保存済みの設定を編集する既存の設定と、Config Library の設定を貼り付けるインポートです。すべての設定を一度に見たい場合は、すべての設定を1ページで開くを使います。

ステップ 2: 構成

6 枚のカードに、選ぶものと Salesforce に保存されるものが小さな図で示されています。1 日に 1 レコード、範囲ごとに 1 レコード、時間ブロックごとに 1 レコード、休憩を含む 1 レコード、部屋や人を 1 つ予約、複数をまとめて予約の 6 つです。範囲、時間ブロック、休憩付きの構成には部屋や人を追加できます。構成を選ぶとコンポーネントが自動で決まります。

ステップ 3: クイックスタート

各選択の保存先オブジェクトを選ぶと、ウィザードが可能性の高い選択肢を入力します: ページのレコードへのリンク、日付、タイトル、ステータス、ホバーカード、予約の場合はリソースの名前・定員・営業時間。どれも変更できます。残りはタブで順に設定します: 項目、予約対象、時間、ルール、休業日、ビュー、ホバーカード、ステータス、その他の設定。カレンダーのすべての設定はいずれかのタブにあります。終わったら確認へスキップをクリックします。

ステップ 4: 確認

すべてのセクションが 1 つのリストに並び、それぞれに変更リンク、提案された名前、動作するプレビューが付きます。設定を保存をクリックすると、ウィザードが 30〜60 秒で設定をデプロイし、貼り付ける Config Name とページにドラッグするコンポーネントを表示します。完了後に説明を追加することもできます (任意)。

既存の設定とインポート

保存した設定は 既存の設定 に一覧表示されます。クリックすると編集やエクスポートができます。インポート タブでは、Config Library の任意のカードの JSON や、別の組織からのエクスポートを取り込めます。

画面フロー (Screen Flow) では、Config Name を設定するだけで完了です。チェックボックスはすべて設定から読み込まれるため、$GlobalConstant は不要です。親レコードは Parent Record Id にバインドします。

4. 権限セットとアクセス権

パッケージには 4 つの権限セットが含まれています。[設定] の [権限セット] で割り当ててください。

権限セット対象者セットアップウィザードカレンダーの利用
MultiDatePick - Setup設定を作成する管理者✓ はいいいえ
MultiDatePick - Userカレンダーを使うすべてのユーザーいいえ✓ はい
MultiDatePick - All Access設定を作成し、利用もする管理者✓ はい✓ はい
MultiDatePick - Guest公開 Experience Cloud サイトのゲストユーザーいいえ✓ 表示と予約

コンポーネントは各ユーザー自身の権限で動作するため、ユーザーには自社のオブジェクトと項目へのアクセス権も必要です:

  • オブジェクト: レコードの保存先オブジェクトの参照と作成、およびカレンダーが読み取るリソース、休業、子オブジェクトの参照。
  • 項目 (参照): カレンダーが表示するすべての項目 (日付、状況、ホバー項目)。
  • 項目 (編集): カレンダーが書き込むすべての項目 (日付、時刻、状況、2 つ目の選択リスト、名前項目、親への参照)。ユーザーが編集できない項目があると、参照はできても保存に失敗します。
  • 参照先のレコード: 新しいレコードが指す親とリソースへの、少なくとも参照権限。
管理者にも項目へのアクセス権が必要です。 新しく作成したカスタム項目は、権限セットで付与するまで、システム管理者を含む全員から見えません。保存時に項目が見つからないようなら、まず項目レベルセキュリティを確認してください。

各エラーメッセージとその原因は トラブルシューティング: アクセスエラー にあります。ゲストサイトにはいくつか追加の手順が必要です: 公開ゲストページ を参照してください。

5. クリックで保存とフローによる保存

保存方法は 2 つあります。配置に合うほうを選んでください。

クリックで保存 (Click to Save)

コンポーネント自身がレコードを書き込みます。4 つの設定を入力すると、専用の 保存 ボタンが表示されます。クリックすると子レコードが作成されます。フロー要素もコードも不要です。

使う場所: レコードページ、アプリケーションページ、ホームページ、Experience サイト、親レコードのあるフロー画面。

フローによる保存 (Flow-Managed Save)

コンポーネントは選択内容をフローに渡します。付属の Parse Date Entries from JSON アクションを使い、続けて独自のループ要素とレコード作成要素を配置します。

使う場所: 承認、条件付きのレコード作成、追加の入力チェックなど、すべてを制御したいフロー画面。

クリックで保存: 4 つの設定

セットアップウィザードがこれらを入力します。4 つすべてに値が入ると、保存ボタンが表示されます。

設定内容API 参照名
子オブジェクトの API 参照名（Child Object API Name）レコードの保存先オブジェクトrelatedObjectApiName
日付項目の API 参照名（Date Field API Name）そのオブジェクトの日付項目dateFieldApiName
関連項目の API 参照名（Relationship Field API Name）親レコードへの参照項目relationshipFieldApiName

フロー画面のボタンは 2 つ。 クリックで保存をオンにすると、コンポーネントの 保存 がレコードを書き込み、フローの 次へ は先に進むだけです。ユーザーは先に保存をクリックし、それから次へをクリックします。

ページがどの親レコードを使うか、またフローで親レコードを選ぶべき場合については アプリケーション・ホーム・Experience ページ で解説しています。

フローによる保存: 出力

4 つの設定を空欄のままにします。保存ボタンは非表示になり、選択内容は次のフロー出力から渡されます:

出力内容コンポーネント

JSON を Parse Date Entries from JSON に渡します。ループで処理できるリストが返され、各項目には開始日、終了日、開始時刻、終了時刻、リソース ID が含まれます。詳しい手順: フローのレシピ。

保存は追加のみ

クリックで保存は新しいレコードを作成するだけです。日付の選択を解除しても保存済みのレコードは削除されないため、クリックを間違えてもデータは失われません。レコードを変更・削除するには、編集モード または関連リストを使います。

6. 状況の色と編集モード

状況の色とフィルター

オブジェクトの任意の選択リストでレコードを色分けし、一部の値を非表示にし、エンドユーザーが選べる値を制限できます。

設定機能API 参照名
状況項目（Status Field）色分けに使う選択リスト。例: Confirmed / Tentative / Cancelled。statusField
状況の色（Status Colors）値ごとの色。例: Confirmed:#22C55E, Tentative:#fbbf24。空欄にすると自動の配色になります。statusColors
状況の色表示（Status Color Display）色を表示する場所: カレンダー、グリッド、または両方。空欄にすると、色のないすっきりした顧客向けページになります。statusColorDisplay

選択可能な状況（Selectable Statuses）エンドユーザーが選べる値を制限します。例えば顧客は Requested のみ、スタッフにはすべての値を表示できます。selectableStatuses
1 つのオブジェクトに 2 つのページ。 顧客向けページは色なし、選べる状況は Requested のみ、No-Show と Cancelled は非表示にできます。同じレコードを使うバックオフィス向けページでは色を表示し、すべての状況を選べるようにします。

編集モード

Enable Edit Mode（編集モードを有効化） をオンにすると、編集 ボタンが表示されます。編集モードでは、ユーザーは次の操作ができます:

  • 既存のレコードを、日付と状況付きのカードで確認する
  • 日付をクリックして、そのレコードを編集対象に加える
  • 日付、時刻、リソース、状況を変更すると、レコードが更新される
  • 2 回クリックの確認で削除するため、誤って消えることはない

7. 表示: 1 つのコンポーネントで 5 つのレイアウト

どのコンポーネントも 5 つのレイアウトを表示できます。同じ項目の対応付けで同じレコードを読み取り、同じ競合ルール、ブロック日付、営業時間に従い、同じ方法で保存します。表示を切り替えて変わるのはレコードの見え方だけで、意味は変わりません。

8. リソース予約と定員 (Booking コンポーネント)

単一リソース

複数リソース

Allow Multiple Resources（複数リソースを許可） をオンにすると、ドロップダウンがチェックボックスに変わります。グリッドにはチェックしたすべてのリソースで空いている時間枠だけが表示され、保存するとまとめて予約されます。

定員

複数の予約で 1 つの時間枠を共有でき、3/5 のバッジがリアルタイムで表示されます。満員の時間枠は予約を受け付けません。

10. 日付・時刻・リソースのブロック (休業日)

どのカレンダーも別のオブジェクトから休業日を読み取り、対象の日付、時間枠、リソースをグレー表示にできます。これにより、ユーザーは営業中の時間だけを予約できます。いくつかの設定を休業オブジェクトに向けるだけで、あとはコンポーネントが処理します。終日のブロックは 3 つのコンポーネントすべてで使えます。時刻とリソースのブロックには、Date Time または Booking のタイムグリッドが必要です。

ブロックと非表示の違いは?

似ているようで、働きは正反対です。ブロックは空きをなくします: 時間枠は表示されますが予約できません。非表示はレコードを表示から外すため、その時間枠が空きます。

ブロックの 3 つのレベル

  1. 終日: 時刻のない休業日は、その日付全体をグレー表示にします。3 つのコンポーネントすべてで使えます。予約がすでにある日付でも、休業日は休業日のままです。
  2. 1 日の一部: 開始時刻と終了時刻のある休業日は、その時間枠だけをブロックします。残りの時間は予約できます。ブロックされた時間枠は、日付を選択すると表示されます。
  3. 1 つのリソース: リソースを指す休業日は、そのリソースだけを休業にします。単一リソースの表示では時間枠に取り消し線が付きます。合計の表示では隅に小さな印が付き、空いているリソースでは引き続き予約できます。

タイムグリッドを使うなら、1 日の一部のブロックが適しています。終日のブロックは日付のみの選択に向いています。

休業オブジェクトの 2 つのパターン

  • 同じオブジェクトを状況で区別: Blocked Dates Object を予約オブジェクトに向け、Status = Cancelled で絞り込むと、キャンセルされた予約が休業日を兼ねます。最も簡単ですが、そのオブジェクトを使うすべてのカレンダーで共有されます。Config Library の 祝日を考慮したアポイント予約 設定を参照してください。
  • 専用の休業オブジェクト: 日付、任意の開始・終了時刻、Region 項目、任意のリソース参照を持つ Office Closure オブジェクト。各カレンダーは自分の地域で絞り込み、休業日を 1 つのリソースに限定することもできます。時間単位のリソース休業 設定を参照してください。

利用者が自分の時間をブロックできるようにするには (担当者が午前中をブロックするなど)、休業オブジェクトに保存する Date Time コンポーネントを社内ページやサイトに配置します。

ブロックされた時間枠の動作

  • 見た目: 完全に休業の時間枠は取り消し線付きでグレー表示されます。選択したリソースの一部だけが休業の時間枠には、隅に印が付きます。
  • 選択: 完全に休業の時間枠は、クリックもドラッグもできません。
  • 保存: 休業中のリソース、日付、時刻には何も保存されません。複数リソースの場合は休業中のリソースだけが除外され、空いているリソースは予約されます。

1 つの休業日テーブルで多くのカレンダーに対応

休業オブジェクトにタグ項目 (Region、Location、Building) を持たせ、同じ項目をリソースにも追加します。各カレンダーは Resource Filter Field / Value で自分のリソースを表示し、Blocked Dates Filter Field / Value で自分の休業日を読み取ります。

11. 公開ゲストページ (Experience Cloud)

コンポーネントを Experience Cloud サイトに配置すると、誰でもログインせずに予約できます。ゲストとしてテストする前に、5 つの手順をすべて済ませてください。

  1. オブジェクト権限。 サイトのゲストユーザーに各オブジェクトの参照権限を付与し、ゲストが送信する場合は作成権限も付与します。Salesforce ではゲストはレコードの編集や削除ができないため、編集、キャンセル、削除のページはログインユーザー向けにしてください。
  2. コンポーネントが扱うすべての項目の項目レベルセキュリティ。リソースの営業時間項目や休業日の時刻項目も含みます。1 つでも欠けると、リソースや休業日のクエリが止まります。
  3. ゲストがレコードを参照できるようにするゲストユーザー共有ルール (参照)。ルールを適用するには、オブジェクトの外部組織の共有設定が 非公開 である必要があります。メタデータとしてデプロイしたルールは、[設定] の [共有設定] で 再計算 を 1 回クリックする必要があります。
  4. サイトのゲストユーザーに MultiDatePick - Guest 権限セット。コンポーネントがデータを読み込むための Apex クラスへのアクセス権が含まれています。
  5. サイトを有効化します。 公開と有効化は別の手順です。
ゲストにはカレンダーが空に見える? オブジェクト、項目、クラスへのアクセス権がすべて正しく見えるなら、原因はほぼ必ず手順 3 の共有の再計算です。次に見落とされやすいのは手順 4 と 5 です。
  • ゲストに表示されるレコード: 公開ページは Static Parent Record Id を使うため、すべてのゲストが同じ親レコード (1 つのオフィス、拠点、リソース) に対して予約します。訪問者ごとのレコードにするには、URL パラメーター付きのフローで制御します。ユーザーごとのカレンダーには、ログインユーザーが必要です。
  • 取引先責任者と取引先: Salesforce はこれらへのゲストアクセスを厳しく制限しています。ゲストの予約にはカスタムオブジェクトを使うか、認証済みサイトを使ってください。
  • 1 ページに複数のコンポーネント: リアルタイムでは同期しません。一方で行ったブロックがもう一方に反映されるよう、間に更新を促す表示を入れてください。

配置の手順は アプリケーション・ホーム・Experience ページ にあります。サイト全体の作成例は Experience Cloud での予約 を参照してください。

12. よくある注意点 (FAQ)

バナーが表示される、保存ボタンがない、カレンダーが空、といった場合は、トラブルシューティング で各メッセージをスクリーンショットと対処法付きで確認できます。

状況の色が反映されない
3 点を確認してください。(a) Status Field（状況項目） は選択リストの API 名と完全に一致していますか? 大文字と小文字は区別されます。(b) Status Colors は引用符なしの Value:#hex, Value:#hex 形式ですか? 'Confirmed':'#22C55E' と書くと、エラーなしで機能しなくなります。(c) レコードのその選択リストに実際に値が入っていますか?
レコードが予期しない名前で保存される
Record Name Field（レコード名項目） を確認してください: 項目の文字数が少ないと、長い名前は切り捨てられます。Append Date to Record Name も確認してください: オンにすると、選択した日付と時刻がすべての名前に追加されます。
Cancelled のレコードを定員グリッドから非表示にするには?
Ignored Statuses を Cancelled、または Cancelled,Rejected のようなリストに設定します。カレンダーと定員の集計から外れます。
ブロックと非表示の違いは?
ブロック (休業日) は、日付、時刻、リソースを表示したまま予約できなくします: 祝日、メンテナンス、閉鎖中の会議室など。非表示は、Cancelled などのレコードをカレンダーと定員から外し、時間枠を空けます。ブロックと非表示の違い を参照してください。
編集ボタンが表示されない
Enable Edit Mode をオンにしてください。3 つのコンポーネントとも、必要なのはそれだけです。Status Field は任意で、エディターに状況のドロップダウンが追加されるだけです。それでもボタンが表示されない場合は、ページまたは設定で Enable Edit Mode がオフになっています。
一部のリソースだけを表示したい (設備ではなく会議室だけ)
Resource Filter Field と Resource Filter Value（リソースフィルター値） を使います。値が 1 つの場合: 項目 Active__c、値 true。複数の値 (OR): North,South。複数の項目 (AND): 項目 Type__c;Active__c、値 Conference Room;true。
Date Time で共通の時刻選択が 1 つしか表示されない
使う設定は Time Display Mode（時刻表示モード） です: Grid または Dropdown。Grid モードでは、すべての日付が 1 つのグリッドを共有します。日付ごとに別の時刻にするには、Dropdown を選び、Allow Different Times Per Date をオンにします。
フローによる保存からクリックで保存に切り替えるには?
Parent Record Id、Child Object API Name、Date Field API Name、Relationship Field API Name を入力します。Parse Date Entries from JSON アクションと、レコードを作成していたループを削除します。これでコンポーネント自身の保存ボタンがレコードを書き込みます。
詳細のないエラーメッセージが表示される
ブラウザーの開発者コンソールを開き、[MDP:ERROR] で始まる行を探してください。メッセージが短くても、完全なエラーは常にそこに記録されています。

13. フローのレシピ

ここにあるものはすべて Flow Builder で作成します。Apex は不要です。

選択した日付をループ処理する

  1. Date Time コンポーネントを配置した画面を追加します。クリックで保存の設定は空欄のままにします。
  2. 画面の後に Parse Date Entries from JSON アクションを追加し、Dates With Times JSON (Output) を渡します。
  3. アクションが返すリストをループ処理します。各項目には開始日、終了日、開始時刻、終了時刻があります。
  4. ループ内で値をレコード変数に割り当て、コレクションに追加します。レコードはループの後で一度に作成します。

最初と最後の日付を親レコードに集計する

親レコードに子の最も早い日付と最も遅い日付を表示したい場合は、データに合うノーコードの方法を選びます。

現在の構成方法
主従関係親に積み上げ集計項目を 2 つ追加します: 日付項目の MIN と日付項目の MAX。これで完了です。
参照関係子オブジェクトにレコードトリガーフロー (保存後) を作成します。同じ親を持つ子オブジェクトのレコードを日付の昇順で取得し、最初のレコードだけを使います。降順でも同じことを行います。2 つの日付で親の開始日と終了日を更新します。

その他のフローのパターン: 画面フローガイド。

  • Booking: オブジェクトの対応付け
