設定と配置

カレンダーをページに配置するときや設定を作成するときに、管理者に表示されるバナーと警告です。

保存ボタンが表示されない

原因: 親レコードがなく、すべてのレコードを表示する設定にもなっていません。アプリケーションページとホームページには、そのページ自体のレコードがありません。

解決策

  1. セットアップウィザードで設定を開いて 誰のレコードですか? に答える (通常は 閲覧者のみ) か、すべての選択をこのレコードに関連付け (App Builder: Static Parent Record Id) に日付を紐付けるレコードを設定します。
  2. オブジェクト、日付項目、リレーション項目が入力されているか確認するか、Config Name（設定名） を設定します。

フローでは、Parent Record Id が関連付けられていれば保存ボタンが表示されます。ウィザードの 誰が保存しますか? が フローが保存 の場合や、Parent Record Id が空欄の場合は非表示のままで、フローの [次へ] ボタンが日付を引き渡します。

黄色のバナー: 「この設定には適切でないコンポーネントです」

原因: Config Name が、別のコンポーネント用に保存された設定を指しています。

解決策

  1. Config Name を、このコンポーネント用に作成した設定に変更する、または
  2. その設定に合ったコンポーネントに入れ替える、または
  3. セットアップウィザードで設定を開き、コンポーネント種別を変更します。

黄色のバナー: 「設定が一致しません」

原因: ページのレコード、または すべての選択をこのレコードに関連付け のレコードが、設定のリレーション項目の参照先オブジェクトと異なります。

解決策

  1. バナーに表示されたオブジェクトのレコードページにコンポーネントを配置する、または
  2. そのオブジェクトのレコードにすべての選択を関連付ける、または
  3. このページのオブジェクト用に作成した設定を使います。

赤いバナー: 「このコンポーネントはデータを読み込めませんでした」

原因: 設定の項目名またはオブジェクト名が間違っているか、ユーザーが MultiDatePick を実行できないか、オブジェクトやその項目を参照できません。

解決策

  1. 灰色のボックスを確認します。該当する項目、オブジェクト、または Apex クラスが正確に表示されています。MultiDatePick へのアクセス権がない場合は、割り当てる権限セットがバナーに表示されます。
  2. 名前の誤り: [設定] の [オブジェクトマネージャー] から正確な API 参照名をコピーします。
  3. アクセス権がない: 権限セット MultiDatePick - User を割り当て、自社のオブジェクトへのアクセス権も付与します。公開 Experience サイトでは、ゲストユーザーに MultiDatePick - Guest を割り当て、自社のオブジェクトへの参照権限を付与します。

Resource Booking に「設定が必要です」と表示される

原因: Resource Booking には、リソースオブジェクト、予約オブジェクト、予約日項目、予約リソース項目が必要です。不足しているものがパネルに一覧表示されます。

解決策

  1. Config Name にセットアップウィザードで作成した Resource Booking 用の設定を指定する、または
  2. パネルに表示されたプロパティをすべて入力します。

「"Room_Bookings" という名前の設定が見つかりません」

原因: Config Name には、表示ラベルではなく、セットアップウィザードの [既存の設定] 一覧にある設定の API 名 (例: Contact_Event) を入力します。入力ミス、表示ラベルの入力、保存した直後でまだデプロイ中の設定は、どれもこのメッセージになります。

解決策

  1. セットアップウィザードを開き、[既存の設定] で設定の API 名をコピーします。
  2. コンポーネントの Config Name に貼り付け、ページを保存します。
  3. 設定を保存した直後ですか? Salesforce はバックグラウンドでデプロイするため、30 秒から 2 分かかります。[既存の設定] に表示されるまで更新してから、ページを再読み込みしてください。

メッセージに、ユーザーに MultiDatePick へのアクセス権がないと表示される場合は、MultiDatePick へのアクセス権がないを参照してください。

「Static Parent Record Id のレコード（a015g00000XyZ12AAB）は存在しないため、保存できません」

原因: カレンダーはすべての選択を、すべての選択をこのレコードに関連付け (App Builder: Static Parent Record Id) で指定した 1 つの固定レコードに保存しますが、そのレコードが削除されています。存在するレコードを指定するまで、何も保存できません。

解決策

  1. セットアップウィザードで設定を開き、すべての選択をこのレコードに関連付け で別のレコードを選びます。
  2. Config Name のないページでは、App Builder の Static Parent Record Id に、現在あるレコードの Id を貼り付けます。

日付は保存されるのに、次に開くと表示されない

原因: 保存済みの日付を表示 (App Builder: Load Existing Dates) がオフになっています。レコードは保存されていますが、カレンダーは毎回空の状態で開きます。

解決策

  1. 保存済みの日付を表示 をオンにします。
  2. ページを再読み込みします。保存済みの日付が表示され、状況項目が設定されていれば状況の色で表示されます。

「このカレンダーでは、既存のレコードを表示することも新しいレコードを保存することもできません。Visit の項目『Visit Date』が Shield Platform Encryption で暗号化されています」

原因: Salesforce は、Shield Platform Encryption で保護された項目で検索も並べ替えもできません。カレンダーはレコードを日付、時刻、名前の項目で検索して並べ替えるため、これらの項目は暗号化しないでください。ホバーカードのメモなど、表示するだけの項目は暗号化したままで構いません。

解決策

  1. [設定] の [暗号化ポリシー] で、メッセージに表示された項目の暗号化を解除する、または
  2. セットアップウィザードで設定を開き、代わりに暗号化されていない日付または時刻の項目を選びます。

フィルターが「項目と値に一致しません」、または「リソースを読み込めませんでした」

原因: フィルターに、オブジェクトにない項目、Salesforce で絞り込めない項目、または項目に合わない値が指定されています。カレンダーはどれが原因かを表示します。例: レコードフィルター: 「Status__c=Confrimed」は Visit の絞り込み可能な項目と値に一致しません。 または リソースを読み込めませんでした。条件「Active__c が yes」はその項目に合いません。

解決策

  1. セットアップウィザードで設定を開きます。
  2. 次の条件のレコードのみ (表示するレコード) または 次の条件のものだけ表示 (提示する会議室や担当者) の一覧から、項目と値を選び直します。
  3. App Builder で入力する場合は、項目の API 参照名と、項目のデータ型に合った値を使います。チェックボックスは true または false、日付は 2026-12-31 です。

「既定の項目値: 『Priority=Urgent』は Visit の項目と値に一致しません」

原因: 自動で入力 (App Builder: Default Field Values) は新しいレコードごとに項目を設定します。その組み合わせの 1 つに、オブジェクトにない項目か、項目に入らない値 (選択リストにない値など) が指定されています。

解決策

  1. [オブジェクトマネージャー] で項目の API 参照名を確認します。
  2. 項目に合った値を書きます。チェックボックスは true または false、日付は yyyy-mm-dd または TODAY+7、選択リストはその値のいずれかです。
  3. 複数の組み合わせはセミコロンで区切ります: Priority=High; Type=Call

「Duration は数値項目ではありません」、または予約が 1 日全体を占める

原因: 分数を保存する項目 (App Builder: Duration Field) は、予約オブジェクトの数値項目である必要があります。数式、積み上げ集計、通貨、パーセントは使えません。この項目を設定して 終了 を空欄にすると、各予約は開始時刻にその分数を足した時刻に終わります。そのため、分数が空のレコードには終了がなく、1 日全体を占めます。

解決策

  1. 長さを分単位で保持する数値項目を選ぶか、新しく作成します。
  2. 既存のレコードの分数を、データ更新やフローなどで一度だけ入力します。それ以降は、カレンダーでの保存、移動、サイズ変更のたびに自動で書き込まれます。

「Visit には有効なレコードタイプ『Install』がありません。このカレンダーは新しいレコードにこのタイプを設定します」

原因: 新しい予約のレコードタイプ に、無効化または名前が変更されたレコードタイプが指定されています。関連するメッセージ Confirmed は、レコードタイプ「Repair」の Visit Status では使用できません は、選んだステータスがそのレコードタイプで使える値ではないという意味です。

解決策

  1. セットアップウィザードで設定を開き、新しい予約のレコードタイプ で有効なタイプを選ぶか、各ユーザーのデフォルト または ユーザーが選択 を選びます。
  2. ステータスの場合: [オブジェクトマネージャー] でそのレコードタイプの選択リスト値に値を追加するか、別のステータスを選びます。

メッセージに、そのタイプのレコードを作成できないと表示される場合は、許可されていないレコードタイプを参照してください。

「これはビルダーで管理者にだけ表示されます。このカレンダーは定員を数えますが Config Name がありません」

原因: ページに保存済みの設定名が指定されていないと、カレンダーは閲覧者が参照できる予約しか数えられません。共有によって見えない予約が数に入らないため、満員の時間が空いているように見えることがあります。

解決策

  1. セットアップウィザードで設定を保存します。
  2. コンポーネントの Config Name にその名前を入力します。これで、すべての予約が数に含まれます (件数のみで、内容は表示されません)。

この注意は App Builder で管理者にだけ表示されます。ユーザーには表示されません。

保存後に「カレンダーに追加」ボタンが表示されない

原因: Show Add to Calendar After Saving（保存後に「カレンダーに追加」を表示） がオフになっています。初期設定ではオフです。

解決策

  1. コンポーネントのプロパティまたは設定でオンにしてから、レコードを保存します。トーストの下のバーにボタンが表示されます。
  2. 代わりに「Google カレンダーに追加」が表示される場合は、ブラウザーがファイルの作成をブロックしています。そのため、予定が 1 件のときは Google カレンダーへのリンクが表示されます。

予約と空き状況

日、時間、会議室、担当者を選べない、または予約できない理由。

Resource Booking に「利用可能なリソースがありません」と表示される

原因: リソースの一覧が空で返されました。多くの場合、どのレコードにも一致しないフィルター、誤ったリソースオブジェクト、またはリソースレコードがまだないことが原因です。

解決策

  1. 次の条件のものだけ表示 (App Builder: Resource Filter Field and Value) を実際のレコードと照らし合わせて確認します。
  2. 選択対象のリスト と 各対象の名前の項目 (App Builder: Resource Object API Name and Resource Name Field) を確認します。
  3. リソースレコードを 1 件以上作成します。

黄色のバナー: 「定員には開始時刻と終了時刻の両方が必要です」

原因: 同時に予約できる数 (App Builder: Capacity Field) は設定されていますが、予約の開始時刻または終了時刻の項目が空のため、定員を適用できません。

解決策

  1. 開始 と 終了 (App Builder: Booking Start Time Field and Booking End Time Field) の両方を設定する、または
  2. 同時に予約できる数 を空にします。

これ以上日付を選べない

原因: コンポーネントに日付数の上限 (Max Dates Allowed) があります。

解決策

  1. 日付の選択を 1 つ解除してから別の日付を選ぶ、または
  2. 上限を引き上げるか、0 に設定して上限をなくします。

これ以上予約できない

原因: 予約の上限に達しています。Max Time Slots は時間枠の合計数を、Max Bookings per Day は 1 日あたりの個別の予約数 (隣り合う時間は 1 件と数えます) を、Limit per Person は 1 人の顧客の今後の予約数をサーバー側で数えて制限します。

解決策

  1. 上限を引き上げるか、0 に設定して上限をなくします。
  2. スタッフは確認のうえで「1 人あたりの上限」を超えて予約できます。サイトの訪問者はできません。

一部の日や時間がグレー表示になっている

原因: 予約ルールによって受付が閉じられています。Minimum Notice (Hours) は開始が近すぎる枠を、Book Up To (Days Ahead) は予約可能期間より先の日を閉じます。それ以外は、Earliest / Latest Selectable Date、ブロック日付、各リソースの営業時間によるものです。

解決策

  1. コンポーネントまたは設定でこれらを確認します。0 にすると事前通知と予約可能期間の制限がなくなります。
  2. 閉じている時間枠をクリックすると、閉じている理由が表示されます。

予約の直後の時間枠が予約済みと表示される

原因: Buffer Between Bookings (Minutes) により、同じリソースの予約のあとに、片付けや準備のための時間が確保されています。

解決策

  1. バッファーを短くするか、0 にして予約を連続で入れられるようにします。
  2. 時間が埋まっているとき の設定は引き続き有効です。競合する時間枠をスキップ の場合、バッファーにかかる枠はスキップされ、ほかの競合と同じように報告されます。

一部の開始時刻しか表示されない

原因: これらの時刻のみ が設定されているため、グリッドにはリストにある開始時刻だけが表示されます。Resource Booking では、会議室や担当者が独自のリストを持っていれば 各リソース独自の時刻 が優先されます。リストにある時刻でも、営業時間、休業日、事前通知、ほかの予約との重複にあたる場合は選べません。

解決策

  1. コンポーネントまたはその設定で、リストを編集するか すべての間隔 を選びます。
  2. リソースの「各リソース独自の時刻」項目にある独自のリストを確認します。

「次の選択は予約可能期間外になりました」

原因: ページを開いたままにしている間に、選択した日や時刻が Minimum Notice の期間内に入りました。保存時にルールを再チェックするため、古いページから直前の予約が入ることはありません。

解決策

  1. メッセージに表示された日付を外すか、もっと遅い時刻を選びます。
  2. もう一度保存します。

「予約できません。次の日付は満席または休業です：12月3日」または「すでに満席または休業のため、保存時にスキップされます」

原因: その時間がすでにほかの予約で埋まっているか、休業日にあたります。どうなるかは 時間が埋まっているとき で決まります。ブロック は操作全体を拒否し、競合する時間枠をスキップ はほかの日を予約して除外した日を表示し、許可（強制予約） は「このまま予約」ボタンを表示します。

解決策

  1. メッセージに表示された日付を外すか、別の時間またはリソースを選びます。
  2. 管理者は、設定の予約ルールで 時間が埋まっているとき を変更できます。

「1 日の上限に達しました（2/2）」

原因: 1 日の最大予約数 (App Builder: Daily Limit Field) は、技術者の 1 日 2 件の作業のように、会議室や担当者ごとに設定する数値です。1 日の予約がその数に達すると、そのリソースのその日は受付が終わり、保存すると 1 日の上限に達したため、何も保存しませんでした と表示されます。各レコードは 1 件として数え、複数日にわたる予約は日ごとに数えます。時間を空けるステータスは数えません。

解決策

  1. 別の日か別のリソースを選びます。
  2. リソースのレコードで数値を上げるか、空欄にして上限をなくします。
  3. 時間が埋まっているとき を 許可（強制予約） にすると、上限を超えて予約できます。

「Garden Room は予約を受け付けていないため、何も保存しませんでした」

原因: リソースの 同時に予約できる数 または 1 日の最大予約数 が 0 です。0 は、時間が埋まっているときの設定にかかわらず、予約をまったく受け付けないという意味です。リソースの選択欄、時間グリッド、週ビューではグレー表示になります。

解決策

  1. 別のリソースを選びます。
  2. 予約を受け付けるには、そのレコードの数値を 1 以上にするか、空欄にして上限をなくします。

「過去の日付は予約できません」または「次の時刻はすでに過ぎているため予約できません」

原因: カレンダーは、すでに過ぎた日や時間を予約しません。ページを開いたまま夜を越し、前日に選んだ日や、今日のすでに過ぎた時間は、保存時に拒否されます。

解決策

  1. メッセージに表示された日付や時刻を外し、それより後の日時を選びます。
  2. タイムシートなど、過去の日を記録する必要がありますか? 管理者が設定で 過去の日付を許可 をオンにできます。

「受付終了のため予約できない日付です: 12月25日。別の日付または時間を選んでください。」

原因: その日は休業日にあたります。祝日やスタッフの休暇など、カレンダーの 休業日のリスト にあるレコードです。会議室や担当者を指定した休業日は、そのリソースだけを閉じます。カレンダーでも保存時でも拒否されます。

解決策

  1. 別の日付または時間を選びます。
  2. その日を受け付けるべき場合は、休業日のレコードを編集または削除するか、設定の 次の条件の休業のみ で対象を絞ります。

「Garden Room はこのカレンダーでは予約できません。リストからリソースを選んでください。」

原因: その会議室や担当者は 次の条件のものだけ表示 の条件から外れるため、このカレンダーのリストにありません。ページを開いた後にレコードが変更された場合 (会議室が無効にされたなど) によく起こります。保存、移動、再割り当てのときにサーバーが拒否します。

解決策

  1. ページを再読み込みし、リストからリソースを選びます。
  2. そのリソースを提示すべき場合は、リソースのレコードを更新するか、設定の 次の条件のものだけ表示 を変更します。

「選択したリソースに共通の開始時刻がないため、すべてに予約できる時刻はありません」

原因: 複数を同時に予約 では、選んだすべての会議室や担当者に合う時間が必要です。営業時間や独自の開始時刻が重ならないため、すべてに合う時間がありません。短いメッセージ 選択したリソースには重複する営業時間がありません も同じ意味です。

解決策

  1. 選ぶリソースを減らすか、同じ時間帯に稼働するリソースを選びます。
  2. 管理者は、各リソースの営業時間と独自の開始時刻を確認できます。

2 人が同じ時間を予約できてしまった

原因: 次の 2 つの設定のどちらかが原因です。時間が埋まっているとき を 許可（強制予約） にすると、スタッフは意図的に埋まっている時間に予約できます。または、フィルターで予約済みの判定も行う がオンで、フィルターに ME が使われているため、各ユーザー自身の予約だけが時間を予約済みにしています。後者はウィザードが警告します: 「フィルターで予約済みの判定も行う」がオンで、「次の条件のレコードのみ」に ME が使われています。各ユーザー自身の予約だけが時間を予約済みにするため、2 人が同じ時間を予約できます。

解決策

  1. 時間が埋まっているとき を ブロック または 競合する時間枠をスキップ にします。
  2. 各ユーザーが本当に自分の時間だけを予約する場合を除き、フィルターで予約済みの判定も行う をオフにします。

「『1 人あたりの上限』がオンですが、『顧客項目』が設定されていません」

原因: 1 人あたりの上限 は、予約の対象者 (App Builder: Client Field) を使って顧客ごとの予約を数えます。項目が設定されていない場合や、ロングテキストなど Salesforce が検索できない項目の場合は予約を数えられないため、保存が拒否されます。管理者には App Builder で 「1 人あたりの上限」で Notes ごとに予約を数えられません と表示されます。

解決策

  1. セットアップウィザードで設定を開き、予約の対象者 でテキスト、メール、または参照項目を選びます。
  2. または、「1 人あたりの上限」を 0 にしてオフにします。

「Salesforce から応答がなかったため、この予約はすでに保存されている可能性があります」

原因: 予約ボタンを押した後に接続が切れたか Salesforce の応答が遅れたため、カレンダーは保存が完了したかを判断できませんでした。確認できるよう、カレンダーは自動で再読み込みされます。

解決策

  1. 再読み込みしたカレンダーで予約を探します。
  2. 見つからない場合にだけ、もう一度予約します。

公開サイトのゲスト

訪問者がサインインせずに予約する、公開 Experience Cloud サイトのカレンダー。

ゲストに空のカレンダーが表示される

原因: ゲスト用の共有ルールがまだ有効になっていないか、ゲストプロファイルの手順が抜けています。

解決策

  1. オブジェクトのデフォルトの外部アクセス権を [非公開] に設定し、[設定] の [共有設定] で [再計算] をクリックします。
  2. ゲストユーザーに権限セット MultiDatePick - Guest を割り当て、自社の各オブジェクトと項目の参照権限を付与します。
  3. サイトを有効化します。公開するだけでは不十分です。

ゲスト向けの 5 ステップのチェックリストはユーザーガイドに掲載しています。セットアップウィザードの サイトをチェック で、各ステップを自動でテストできます。

「サイトをチェック」で「要修正」と表示される

原因: サイトをチェック は、サイト用カレンダーのセットアップウィザードの「確認」と「完了」のステップにあり、ゲストが利用するのと同じ方法でサイトをテストします。「要修正」と表示された行はそれぞれ抜けている手順で、何をすべきかが表示されます。

解決策

  1. サイトはまだ公開されていません: サイトのワークスペースで [管理]、[設定] の順に開き、「有効化」をクリックしてから公開します。
  2. 権限セット MultiDatePick - Guest: ゲストユーザーを開き、[権限セットの割り当て] で追加します。
  3. オブジェクトアクセス または 項目アクセス: カレンダーが表示するものへの参照権限と、予約が保存するものへの編集権限をゲストユーザーに付与します。
  4. ゲストはリソースをどれも参照できません: [設定] の [共有設定] で、リソースオブジェクトにゲストユーザー共有ルールを追加します。

チェックを実行できるのは、MultiDatePick - Setup を持つ管理者だけです。

「このカレンダーはここでは保存できません。このオブジェクトの保存済みの設定が指定されていません」

原因: サイトのゲストやポータルユーザーの予約は、プライバシーや予約ルールを回避できないよう、サーバー上で保存済みの設定と照合されます。サイトページのカレンダーに Config Name がない一方で、オブジェクトにはすでに保存済みの設定があります。

解決策

  1. Experience Builder でサイトページを開きます。
  2. カレンダーの Config Name に、このサイト用に保存した設定を指定してから公開します。

「このカレンダーはここでは使用できません。保存済みの設定が公開サイト用ではありません」

原因: サイトページに、スタッフ用に作成した設定が指定されています。サイトのゲストとポータルユーザーはサイト用に保存した設定しか使えないため、スタッフ用カレンダーのプライバシーやルールが誤って一般公開されることはありません。

解決策

  1. カレンダーの Config Name をサイト用に保存した設定にする、または
  2. 新しく作成します。セットアップウィザードで このコンポーネントをどこに配置しますか? に Experience サイト と答え、新しい名前で保存します。

「このページは、サイトの訪問者が参照できないレコードに予約を関連付けているため、まだ予約を受け付けられません」

原因: サイトからの予約はすべて 予約の関連付け先 で指定した 1 つのレコードに関連付けられますが、ゲストユーザーはそのレコードを参照できません。Salesforce では、ゲストユーザー共有ルールで共有しない限り、レコードはゲストに公開されません。

解決策

  1. [設定] の [共有設定] で、そのレコードのオブジェクトにゲストユーザー共有ルールを追加し、サイトのゲストユーザーと共有します (参照のみ)。
  2. もう一度 サイトをチェック を実行します。予約の関連付け先レコード が合格になるはずです。

「この公開ページでは保存されません」

原因: Salesforce では、サイトのゲストはレコードの参照と作成はできますが、変更や削除はできません。訪問者は表示と予約ができ、アクセス権のあるサインイン済みユーザーは編集できます。

解決策

  1. 修正は不要です。これは Salesforce のゲストに関するルールです。自分の予約を変更できるようにするには、サインイン (メンバーサイト) を用意するか、スタッフが変更してください。

「このカレンダーの予約は 1 件 60 分です。この時間は予約できません」

原因: サイトのゲストとポータルユーザーの予約は、サーバーがすべて保存済みの設定と照合します。対象は予約の長さ、これらの時刻のみ、選べる状況、事前通知、予約可能期間、各上限です。ページを開いている間に管理者がそのいずれかを変更したため、設定で許可されなくなったものが表示されていました。関連するメッセージ: このカレンダーは指定された開始時刻にのみ予約を受け付けます、このカレンダーではステータス Requested を選択できません。

解決策

  1. ページを再読み込みして、もう一度予約します。
  2. それでも拒否される場合は、サイトの管理者が Config Name に指定された設定でこれらのルールを確認できます。

サイトメンバーが自分で作成したレコードを参照できない

原因: Experience Cloud の共有設定です。サイトユーザーには、共有によってアクセス権が与えられたレコードしか表示されません。

解決策

  1. 日付の保存先オブジェクトに共有ルール (メンバーの場合は共有セット) を追加する、または
  2. そのオブジェクトのデフォルトの外部アクセス権を広げます。

「サイトは、ほかのウェブサイトでの表示を許可していません」

原因: 埋め込みコードで自社のウェブサイトにカレンダーを配置しましたが、Salesforce サイトは既定で、ほかのウェブサイト内での表示を拒否します。

解決策

  1. Experience Builder で [設定]、[セキュリティとプライバシー] の順に開きます。
  2. 「クリックジャック保護レベル」を Allow framing of site pages on external domains に設定します。
  3. 「Trusted Domains for Inline Framing」に自社のウェブサイトを追加してから公開します。

ゲストに場所のリストは表示されるが、地図が表示されない

原因: 地図は Salesforce のサービスで描画されますが、サイトはそのサービスを信頼済みにするまでブロックします。サイトが地図をブロックしているかどうかはカレンダーから判別できないため、サイトではリストを先に表示し、地図も選べるようにしています。

解決策

  1. Experience Builder で [設定]、[セキュリティとプライバシー] の順に開きます。
  2. maps.a.forceusercontent.com をフレームの信頼済みサイトとして追加してから公開します。

権限とセキュリティ

カレンダーは各ユーザー自身の権限で動作します。まず適切な権限セットを割り当て、そのうえで自社のオブジェクトと項目へのアクセス権を付与します。

権限セット割り当て先
MultiDatePick - Userカレンダーを使うすべてのユーザー
MultiDatePick - Setup設定を作成する管理者。セットアップウィザードも含みます。
MultiDatePick - All Access設定を作成し、利用もする管理者
MultiDatePick - Guest公開 Experience Cloud サイトのゲストユーザー

エラーメッセージには、何が問題なのか (項目、オブジェクト、入力規則) が表示されます。メッセージの最後に 詳細: がある場合、その部分は Salesforce 自身による説明です。管理者または当社に送っていただければ、どこを確認すべきかが正確にわかります。

「このカレンダーを使用するには MultiDatePick ライセンスが必要です」

原因: MultiDatePick はユーザー単位のライセンスで、このユーザーにはまだ割り当てられていません。カレンダーの代わりにこのお知らせが表示され、保存も拒否されます。サイトのゲストにライセンスは不要です。

解決策

  1. [設定] で [インストール済みパッケージ] を開き、MultiDatePick の横にある [ライセンスの管理] をクリックします。
  2. [ユーザーを追加] をクリックしてユーザーを追加します。次にページを読み込んだときからカレンダーが表示されます。

「このユーザーには MultiDatePick へのアクセス権がないため、設定は読み込まれませんでした」

原因: ユーザーに MultiDatePick の権限セットがないため、Salesforce はそのユーザーに対してカレンダーのクラスの実行を許可しません。赤いバナーにこのメッセージが表示され、灰色のボックスに Salesforce 自身の説明が表示されます。

解決策

  1. ユーザーに MultiDatePick - User を割り当てます。設定も作成する管理者には MultiDatePick - All Access を割り当てます。
  2. 公開サイトでは、サイトのゲストユーザーに MultiDatePick - Guest を割り当てます。

レコードが開かない、または「権限が不十分です」と表示される

原因: ユーザーが親オブジェクトを参照できないか、共有設定によってそのレコードが見えなくなっています。画面フローの場合は、ユーザーにフローの実行が許可されていない可能性があります。

解決策

  1. MultiDatePick - User を割り当てます。
  2. 権限セットで親オブジェクトの参照権限を付与します。
  3. 共有によってユーザーがそのレコードにアクセスできるか確認します。
  4. 画面フローの場合は、ユーザーレコードの フローユーザー (Flow User) をオンにするか、権限セットで フローを実行 (Run Flows) ユーザー権限を付与します。

「オブジェクト『Y』の項目『X』への読み取りアクセス権がありません」

原因: カレンダーが表示する項目 (状況、ホバー、日付、時刻の項目) に対して、ユーザーに項目レベルセキュリティの参照権限がありません。

解決策

  1. メッセージに表示された項目の参照権限を付与します。
  2. 管理者にも付与してください。新しいカスタム項目は、権限セットで付与されるまで、システム管理者を含むすべてのユーザーに非表示です。

「Time group failed to save」(時間グループを保存できませんでした)、「予約の作成に失敗しました」、または項目名とともに「項目を編集する権限がありません」と表示される

原因: ユーザーは項目を参照できますが、保存時に書き込む項目のいずれかを編集できません。あとから追加した状況、2 つ目の選択リスト、時刻の項目や、新しいレコードごとに自動で入力される項目でよく起こります。

解決策

  1. カレンダーが書き込むすべての項目に編集権限を付与します。日付、開始時刻と終了時刻、状況、2 つ目の選択リスト、名前項目、親への参照項目、自動で入力 の各項目です。
  2. レコードの保存先オブジェクトに作成権限を付与します。

「この操作を行う権限がありません」と「insufficient access rights on cross-reference id」が表示される

原因: 新しいレコードが、ユーザーが参照できないレコード (親またはリソース) を指しています。

解決策

  1. 親オブジェクトとリソースオブジェクトに少なくとも参照権限を付与し、それらのレコードへの共有を設定します。
  2. 公開サイトでは、ゲストの予約はカスタムオブジェクトに保存してください。Salesforce はゲストによる取引先責任者と取引先へのアクセスを制限しています。

「このカレンダーが使う休業日へのアクセス権がありません」

原因: ユーザーが休業日を保存しているオブジェクトを参照できないため、カレンダーはどの日が休業日か判断できません。よく似たメッセージ このカレンダーに表示されるレコードへのアクセス権がありません は、予約そのものについて同じことを意味します。

解決策

  1. 権限セットで、メッセージが示すオブジェクトと項目に参照権限を付与します。
  2. 共有によってユーザーがそれらのレコードにアクセスできるか確認します。

「レコードタイプ『Install』の Visit レコードを作成する権限がありません」

原因: カレンダーが新しい予約に設定するレコードタイプが、このユーザーのプロファイルや権限セットに含まれていません。

解決策

  1. ユーザーのプロファイルまたは権限セットにレコードタイプを追加します。
  2. または、新しい予約のレコードタイプ を ユーザーが選択 にします。各ユーザーが作成できるタイプだけが一覧に表示されます。

「Salesforce により、この Visit を Alex Chen に割り当てることは許可されませんでした」

原因: 予約の会議室や担当者が Salesforce ユーザーで、Salesforce がそのユーザーを所有者にすることを拒否しました。メッセージの最後に理由が表示されます。そのユーザーにレコードを割り当てるアクセス権がない、ユーザーが無効になっている、またはその種類のユーザーがこの種類のレコードの所有者になれない、のいずれかです。

解決策

  1. 別のユーザーを選択します。
  2. または、そのユーザーにレコードを割り当てるアクセス権か、ユーザーの有効化を Salesforce 管理者に依頼します。

「MultiDatePick の設定を保存する権限がありません」

原因: 設定は Salesforce のメタデータとして保存されるため、「Modify Metadata Through Metadata API Functions」権限が必要です。この権限は MultiDatePick - Setup 権限セットで付与されます。

解決策

  1. 設定を作成する管理者に MultiDatePick - Setup または MultiDatePick - All Access を割り当てます。

フローとアクション

画面フロー (Screen Flow) 上のカレンダーと、フローを実行するボタン。

フロー画面でウィザードの設定が反映されない

原因: Config Name が空か、つづりが間違っています。空の場合、コンポーネントは何も言わずに既定の設定で動作します。つづりが間違っている場合は 「"..." という名前の設定が見つかりません」 と表示されます。

解決策

  1. Config Name に、セットアップウィザードで保存したとおりの設定名を正確に入力します。
  2. オン/オフの入力はそのままにします。チェックボックスはすべて設定から読み込まれます。

「選んだ日付の一部がまだ保存されていません。続行する前に保存をクリックするか、選択を解除してください。」

原因: 保存していない選択がカレンダーに残ったまま画面の [次へ] ボタンが押されたため、選択が失われるところでした。時間の場合は 選んだ時間の一部はまだ予約されていません と表示されます。

解決策

  1. 先に保存 (または予約) をクリックしてから、[次へ] をクリックします。
  2. または、不要な選択を解除してから [次へ] をクリックします。

「Send Reminder を実行できません: 『Run Flows』権限、またはそのフローへのアクセス権が必要です」

原因: カレンダーのアクションボタンはフローを実行します。Salesforce では、そのフローを実行できるユーザーしか開始できません。

解決策

  1. 権限セットでユーザーに フローを実行 (Run Flows) 権限を付与する、または
  2. ユーザーのプロファイルまたは権限セットに、そのフローへのアクセス権を付与します ([設定]、[フロー]、対象のフロー、[アクセス権を編集])。

「フローがエラーで停止しました」または「このアクションはここでは使用できません」

原因: 前者は、アクションボタンの背後にあるフローが実行され、失敗したという意味です。後者は、このレコードではそのボタンがもう提示されないという意味です。保存済みの設定からアクションが削除されたか、ほかのステータス用に設定されています。

解決策

  1. フローのエラーの場合は、管理者がフローの実行履歴またはデバッグログを開き、どのステップで失敗したかを確認します。
  2. アクションが使用できない場合は、ページを再読み込みしてから、設定のアクションでそのアクションのステータスを確認します。

「このフローには入力変数 recordId も recordIds もないため、どのレコードを使うか判断できません」

原因: セットアップウィザードは、クリックされたレコードをアクションのフローに recordId (1 件) または recordIds (編集モードからの複数件) という名前の変数で渡します。どちらもないと、フローはどのレコードを使うか判断できません。

解決策

  1. Flow Builder で、recordId という名前のテキスト変数、または recordIds という名前のテキストのコレクション変数を追加し、「入力で使用可能」にします。
  2. フローを保存して有効化し、ウィザードでもう一度選びます。

ガントチャート

ガントビューのタスク、タスク間のリンク、進捗。

切り替えにガントビューが表示されない

原因: ガントビューは、地図ビューと同じく自分でオンにする表示です。Available Views（利用可能な表示）が空欄の場合は、カレンダー、タイムライン、週、稼働率、予定一覧だけが表示されます。

解決策

  1. セットアップウィザードの「ビュー」タブでガントビューを表示するをオンにするか、Available Views に gantt を追加します。
  2. 最初からガントビューで開くには、View を gantt に設定します。

「Site survey を 12月6日 に置けません。このカレンダーではその日を使えません。何も保存されていません。」

原因: ガントチャートにはカレンダーと同じ予約ルールが適用されます。タスクは、休業の日や時間、その日すでに別のタスクを担当している人、予約を受け付けないリソースには移動できません。メッセージにはその都度、該当するルールが表示されます。

解決策

  1. タスクを別の日にドラッグするか、空いている人に割り当てます。
  2. その日を使えるようにすべき場合は、管理者が設定の休業日と選択できる日を確認します。

「Install は Testing を待てません。循環してしまいます」

原因: Testing は、直接またはほかのタスクを通じて、すでに Install を待っています。逆向きにリンクすると、どちらも開始できなくなります。関連する確認 リンクを置き換えますか? は、タスクの項目でタスクをリンクしている場合に表示されます。この場合、各タスクが待てるのはほかの 1 つのタスクだけです。

解決策

  1. 先に逆向きのリンクを削除するか、別のタスクをリンクします。
  2. 1 つのタスクが複数のタスクを待てるようにするには、別のリンクオブジェクトでタスクをリンクします: セットアップウィザード、ガントビュー、タスク間のリンク。

「状況はそのままです」または「完了は 100% にならず、そのままです」

原因: 完了したタスクの状況 は、完了率と状況を連動させます。100% にしたタスクにはその状況が設定され、その状況にしたタスクは 100% になります。閲覧者が 2 つの項目のどちらかを編集できない場合や、状況項目にその値がない場合は、変更した内容だけが保存され、このメッセージで理由が表示されます。

解決策

  1. ユーザーに、完了率の項目と状況項目の両方の編集権限を付与します。
  2. 状況項目に、そのレコードタイプで選んだ値があるか確認するか、ガントビューの設定で別の値を選ぶか、空欄にして連動させないようにします。

「保存されませんでした。Site survey は閲覧のみのため変更できません。」

原因: 閲覧者はタスクを参照できますが、共有、項目レベルセキュリティ、またはレコードの所有者の関係で編集できません。カードには あなたは閲覧のみ と表示されます。

解決策

  1. タスクの所有者または管理者に、共有で編集アクセス権を付与するよう依頼します。
  2. 権限セットで、タスクの日付項目に編集権限があるか確認します。

設定のインポート

Config Library や別の組織からコピーした設定を、セットアップウィザードの [インポート / エクスポート] タブに貼り付けるとき。

「完全な設定ではありません」または「これは XML のように見え、JSON ではありません」

原因: 貼り付けたテキストが 1 つの完全な設定ではありません。コピー中に途切れた、設定の JSON ではなく Salesforce メタデータ XML やフローである、または設定のファイル全体 (100 KB 超) である、のいずれかです。

解決策

  1. Config Library のコピーボタン、または別の組織の「設定をエクスポート」で、もう一度設定をコピーします。
  2. 最初の { から最後の } まで、テキスト全体を貼り付けます。

フローの XML の場合は、フローとしてデプロイします: VS Code からフローをデプロイする。

「この設定は Related_Object__c がないと動作しません」

原因: 貼り付けた設定に、オブジェクト、日付項目、コンポーネント種別など、すべての設定に必要な項目が欠けています。

解決策

  1. 設定全体をもう一度コピーする、または
  2. 自分の組織で動作している設定をエクスポートして必要な形式を確認し、不足している設定を追加します。

設定が「Visit Status にない値『Confirmed』を保存するため、Salesforce はすべての保存を拒否します」と表示される

原因: インポートした設定の 自動で入力 や 選べる状況 などの設定が、自社のステータス項目にないステータス値を使っています。そのまま保存すると、すべての予約が拒否されます。ステータス値を対応付ける ステップでは、この値に相当する値がないため除外されます と表示された値は、値を選ぶまで除外されます。

解決策

  1. ステータス値を対応付ける に戻ります。
  2. それぞれの値について、自社の値のうち同じ意味のものを選び、[適用してデプロイ] をクリックします。

「フロー Send_Reminder はこの組織にありません」

原因: インポートした設定に、自社の組織にないフローを実行するアクションボタンがあります。

解決策

  1. アクション ステップで、ボタン用に自社のフローを選ぶか、このアクションをスキップ を選びます。
  2. アクションは、あとで設定のアクションで追加できます。

まだ解決しない場合は

表示されている画面のスクリーンショットをお送りください。解決までサポートします。
