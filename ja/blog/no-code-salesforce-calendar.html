ノーコードの Salesforce カレンダー: 45 の作業を 1 行のコードも書かずに

FullCalendar をカスタマイズできるのは、開発者がいる場合です。MultiDatePick なら、カレンダーを必要とする管理者自身がカスタマイズできます。日常的なカレンダーの 45 の作業を並べて比較したので、どちらが優れているかひと目でわかります。

公開日 2026 年 11 月 3 日 · MultiDatePick

「最もカスタマイズできるカレンダー LWC は?」「Salesforce のカレンダーはコードなしでカスタマイズできる?」「FullCalendar に代わるノーコードの選択肢は?」といった検索は、どれも同じことを尋ねています。答えを分けるのは、「誰が」カスタマイズするのかという一点です。

FullCalendar は JavaScript ライブラリです。すべてのオプションがコードの中にあるため、Salesforce では開発者が Lightning Web コンポーネント、レコードを読み込んで保存する Apex、テスト、デプロイを用意し、変更のたびにそれを繰り返します。MultiDatePick は完成済みの Salesforce カレンダーです。すべてのオプションは、管理者がセットアップウィザードか Lightning App Builder で選ぶ設定で、標準オブジェクトにもカスタムオブジェクトにも使えます。Apex も JavaScript もデプロイも不要です。

結論: ノーコードの Salesforce カレンダーなら MultiDatePick を選んでください。カレンダーのページへの配置から、ダブルブッキングの防止、9 言語での表示まで、以下の 45 の作業はすべて MultiDatePick では設定、FullCalendar ではコードです。

誰がカスタマイズするのか?

「カスタマイズできる」には 2 種類あります。ライブラリは、それを使ってコードを書く人がカスタマイズするものです。何でも実現できますが、何をするにも開発プロジェクトになります。設定型のコンポーネントは、それを使う人がカスタマイズするものです。選択肢はすべて構築、テスト、セキュリティ対策が済んでいて、必要なものを選ぶだけです。

Salesforce では、この違いがカレンダーの担い手を決めます。FullCalendar なら、開発者、コードカバー率 75% の Apex テスト、そして変更のたびのデプロイが必要です。MultiDatePick なら、会議室や担当者、日程を業務でどう予約しているかを知っている管理者が担い、変更は保存した時点で反映されます。

ノーコードのカスタマイズはどこで行うのか

45 の作業はどれも、管理者が次のいずれかの場所で選ぶ設定です。

セットアップウィザード

ページとレコードについて質問し、該当しそうな項目を自動入力して、保存前に実際のカレンダーを表示する Lightning タブです。

Lightning App Builder

すべての設定はコンポーネントのプロパティでもあるので、ほかのページに影響を与えずに 1 つのページだけを調整できます。

Config Library

会議室から休暇まで、インポートして調整するだけの既製のセットアップが 47 種類。

エクスポートとインポート

設定は JSON なので、Sandbox や別の組織に移せます。足りない項目は自動で対応付けられます。

Flow Builder

カレンダーをフロー画面に置き、選んだ日付を次のステップで使えます。

Experience Builder

同じカレンダーを公開サイトに置き、ゲストにも同じルールを適用できます。

よくある質問

Salesforce 向けのノーコードのカレンダー LWC はありますか?

はい。MultiDatePick は、クリック操作だけで設定できる Lightning Web コンポーネントのカレンダーです。セットアップウィザードか Lightning App Builder で、標準オブジェクトにもカスタムオブジェクトにも設定できます。レコードの読み込みと保存はコンポーネント自身が行うので、Apex や JavaScript を書く必要はありません。

FullCalendar は MultiDatePick よりカスタマイズ性が高いのですか?

それは開発者にとっての話です。FullCalendar はライブラリなので、誰かがコードを書いて保守すれば何でも実現できます。管理者にとっては MultiDatePick のほうがカスタマイズしやすいカレンダーです。予約ルールから 9 言語対応まで、よくある 45 の作業がどれも 1 つの設定で済みます。

Salesforce 管理者は開発者なしで MultiDatePick を設定できますか?

はい。セットアップウィザードがページとレコードについて質問し、該当しそうな項目を自動で入力して、実際のカレンダーをライブプレビューで表示します。あとはコンポーネントをページにドラッグし、Config Name を入力するだけです。

カレンダーからレコードを保存するのに Apex は必要ですか?

MultiDatePick なら不要です。保存時に、日付ごと、期間ごと、時間ブロックごと、またはリソースごとに 1 件のレコードを作成するか、日付を画面フローに渡します。保存はすべて表示中のユーザーとして実行され、共有設定と項目レベルセキュリティが適用されます。

あとからデプロイなしでカレンダーを変更できますか?

はい。セットアップウィザードで設定を開き、オプションを変更して保存するだけで、カレンダーは次回の読み込み時に変更を反映します。設定はカスタムメタデータなので、必要なら変更セットや Salesforce CLI で移行することもできます。

ノーコードのカレンダーは画面フローや Experience Cloud サイトでも使えますか?

はい。同じコンポーネントをフロー画面に置けば、選んだ日付が Flow 変数になります。公開 Experience Cloud サイトに置けば、ゲストも同じルールで予約できます。
