1Install MultiDatePick from AppExchange

One managed package: the three components, the Setup Wizard and the Flow actions.

InstallOn the AppExchange listing (at launch), click Get It Now. Install for admins only, all users, or specific profiles.
Check itSetup, Installed Packages lists MultiDatePick. In Lightning App Builder or Flow Builder, search MultiDatePick to see Dates, Dates & Times and Resource Booking.
Learn itThe package ships guided flows: Intro to MultiDatePick, plus a Deep Dive flow each for Dates, Date Time and Booking. Start them from the Setup Wizard.

2Assign the MultiDatePick permission sets

Installing grants no one access. Assign one of these in Setup, Permission Sets.

Permission setGive it to
MultiDatePick - SetupThe one or two admins who build configs. Includes the Setup Wizard.
MultiDatePick - UserEveryone who uses the calendars. No wizard.
MultiDatePick - All AccessAdmins who build and use them.

Your objects are separate. Users also need read and create access to the objects and fields your config uses. If something is missing, the calendar names the exact field or object.

Open MultiDatePick Setup Wizard from the App Launcher. Four steps; it fills in the fields it can work out, and the live preview shows the calendar before you save.

4Add a calendar to a Salesforce record page

In Lightning App Builder, drag the MultiDatePick component onto the page, type your Config Name, and save. The import demo above ends on exactly this.

PageWhat you set
Record pageConfig Name. The page record is the parent automatically.
App, Home and Experience pagesConfig Name plus Static Parent Record Id: the record the dates belong to.

Load Existing Dates shows dates already saved. Saving only adds records; it never deletes existing ones.

App, Home and Experience pages: set Static Parent Record Id

These pages have no record of their own, so tell the component which record to save against.

5Add MultiDatePick to a Screen Flow

In Flow Builder, open a Screen, search MultiDatePick, drag the component on, and set Config Name.

Checkboxes come from the config. With Config Name set, you never touch a checkbox in Flow Builder. The flow-only ones (Required, Show Inline, Output Date Ranges as JSON) stay off unless you turn them on.

What the flow gets back

ComponentUse
BookingSaves its own records. Read bookingSuccessCount and bookingConflictDates.
DateselectedDates, or selectedDateRangesJson for ranges.
Date TimeselectedDatesWithTimesJson.

To create records from JSON, add the Parse Date Entries from JSON action, loop its output, and create one record per entry. All clicks. Every detail is on the Flow Cheat Sheet.

Setup questions

Short answers to what admins ask first.

Do I need Apex or a developer to set up MultiDatePick?

No. You install the package, build a config in the Setup Wizard by picking objects and fields from dropdowns, and drop the component on a page or a Flow screen. No Apex required.

Which MultiDatePick permission set should I assign?

MultiDatePick - Setup for the admins who build configs, MultiDatePick - User for everyone who only uses the calendars, and MultiDatePick - All Access for admins who do both. Users also need access to your own objects and fields.

Why is there no Save button on my App Page or Home Page calendar?

App, Home and Experience pages have no record of their own. Set Static Parent Record Id to the record the dates belong to and the Save button appears.

Do I have to set every checkbox in Flow Builder?

No. Set Config Name to the config you saved in the Setup Wizard and every checkbox setting comes from the config. Only if you skip Config Name and set properties by hand do you set the checkboxes yourself.

Can I move a MultiDatePick config to another Salesforce org?

Yes. Export it from the Existing Configurations tab, then paste the JSON into the Import tab in the other org. Smart Field Mapping lets you match any object or field names that differ.
