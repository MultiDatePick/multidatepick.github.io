1Install MultiDatePick from AppExchange

One managed package: the three components, the Setup Wizard and the Flow actions.

InstallMultiDatePick is not on the AppExchange yet: get notified at launch, and try every feature on the live demo today, no login. Once it is listed, click Get It Now and install for admins only, all users, or specific profiles.
Check itSetup, Installed Packages lists MultiDatePick. In Lightning App Builder or Flow Builder, search MultiDatePick to see Dates, Dates & Times and Resource Booking.
Learn itThe package ships guided tours: Intro to MultiDatePick asks what you want to do, then starts the Book, Pick or Plan tour. Start them from the Setup Wizard. In Professional Edition the tours don't run, and Salesforce allows five Screen Flows per org there in all: the four tours count toward them, so one is left for a flow of your own.
LanguagesIf your org uses the Translation Workbench, each user's language must be active in Setup, Translation Workbench, Translation Language Settings for MultiDatePick's translated picklist values, such as the status values, to show. Field labels and the calendar's own text are translated either way.

2Assign the MultiDatePick permission sets

Installing grants no one access. Assign one of these in Setup, Permission Sets.

Permission setGive it to
MultiDatePick - SetupThe one or two admins who build configs. Includes the Setup Wizard.
MultiDatePick - UserEveryone who uses the calendars. No wizard.
MultiDatePick - All AccessAdmins who build and use them.
MultiDatePick - GuestThe guest user of a public Experience Cloud site.

Your objects are separate. Users also need read and create access to the objects and fields your config uses. If something is missing, the calendar names the exact field or object.

4Add a calendar to a Salesforce record page

In Lightning App Builder, drag the MultiDatePick component onto the page, type your Config Name, and save. The import demo above ends on exactly this.

PageWhat you set
Record pageConfig Name. The page record is the parent automatically.
App and Home pagesConfig Name. Static Parent Record Id only when the wizard's answer is One record's.

On the page or behind a button. Show Inline (Always Visible) is ticked when you drag a calendar onto a page, so the calendar sits on the page. Untick it to show a button that opens the calendar in a pop-up instead.

New page? Activate it. After Save, click Activate when Lightning App Builder asks, and assign the page as the org default or to an app and profile. Until a new page is activated, no one sees it.

Load Existing Dates shows dates already saved. Saving only adds records; it never deletes existing ones.

App and Home pages: whose records?

These pages have no record of their own. The wizard asks whose records to show; Just the person looking is the default and needs nothing else. Pick One record's to save against one fixed record, and paste its Id under Link every pick to this record.

Full walkthrough and use cases: App, Home and Experience pages.

5Add MultiDatePick to a Screen Flow

Bind Parent Record Id and every component saves its own records, no Loop needed. In Flow Builder, open a Screen, search MultiDatePick, drag the component on, set Config Name, and bind Parent Record Id to the record the flow runs for, such as {!recordId}.

Checkboxes come from the config. With Config Name set, you never touch a checkbox in Flow Builder. The flow-only ones (Required, Show Inline) stay off unless you turn them on.

Who can run it. Everyone who runs the flow needs the Flow User checkbox on their user record, or the Run Flows user permission in a permission set. Without it, Salesforce shows “Insufficient Privileges” instead of the flow.

What the flow gets back

Want full control? In the Setup Wizard, answer Who saves them? with My flow saves them (or leave Parent Record Id blank) on Dates or Dates & Times, and the picks go to the flow. Add the Parse Date Entries from JSON action, loop its output, and create one record per entry. All clicks. Every detail is on the Flow Cheat Sheet.

Set a date on the page’s own record

MultiDatePick saves picks as records of their own. To write one picked date into a Date field on the record itself, such as a Follow-up Date on an Account, use a small Screen Flow.

  1. In Flow Builder, make a Screen Flow with a Text variable named recordId, available for input.
  2. Add a Screen with Dates. Set Max Dates Allowed to 1 and leave Parent Record Id blank, so the pick goes to the flow instead of being saved.
  3. Add a Loop over the component’s Selected Dates (Output) (it holds the one date), and inside it an Update Records element: the record whose Id is {!recordId}, your Date field set to a formula DATEVALUE({!Loop_Item}), with your loop’s own name in place of Loop_Item.
  4. Save, activate, and add the flow to the record page with the Flow component (pass the record Id into recordId), or as a quick action.

Setup questions

Short answers to what admins ask first.

Do I need Apex or a developer to set up MultiDatePick?

No. You install the package, build a config in the Setup Wizard by picking objects and fields from dropdowns, and drop the component on a page or a Flow screen. No Apex required.

Which MultiDatePick permission set should I assign?

MultiDatePick - Setup for the admins who build configs, MultiDatePick - User for everyone who only uses the calendars, MultiDatePick - All Access for admins who do both, and MultiDatePick - Guest for the guest user of a public Experience Cloud site. Users also need access to your own objects and fields.

Why is there no Save button on my App Page or Home Page calendar?

App and Home pages have no record of their own. In the Setup Wizard, answer Whose records? (Just the person looking, Everyone's or Only ones that match need no parent; One record's asks for that record's Id under Link every pick to this record) and save the config again.

Do I have to set every checkbox in Flow Builder?

No. Set Config Name to the config you saved in the Setup Wizard and every checkbox setting comes from the config. Only if you skip Config Name and set properties by hand do you set the checkboxes yourself.

Can I move a MultiDatePick config to another Salesforce org?

Yes. Export it from the Existing Configurations tab, then paste the JSON into the Import / Export tab in the other org. The import lets you match any object or field names that differ.

What Salesforce objects do I need for MultiDatePick?

Book needs a booking object with a Date and a lookup to a resource object with a Name. Pick needs one child object with a Date and a lookup to the record it belongs to. Plan needs one object with a start date; a project lookup groups the tasks. Use your own objects, or the ready-made MDP Schedule and MDP Resource that come with MultiDatePick.
