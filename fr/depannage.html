Configuration et placement

Bannières et avertissements qu'un administrateur voit en plaçant un calendrier sur une page ou en créant sa configuration.

Il n'y a pas de bouton Enregistrer

Pourquoi : le composant n'a pas d'enregistrement parent et n'est pas réglé pour afficher tous les enregistrements. Les pages d'application et d'accueil n'ont pas d'enregistrement propre.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration et répondez à Les enregistrements de qui ? (Seulement la personne qui consulte est la réponse habituelle), ou renseignez Lier chaque choix à cet enregistrement (App Builder : Static Parent Record Id) avec l'enregistrement auquel appartiennent les dates.
  2. Vérifiez que l'objet, le champ date et le champ de relation sont renseignés, ou renseignez Config Name.

Dans un flux, le bouton Enregistrer s'affiche dès que Parent Record Id est lié. Il reste masqué quand la réponse à Qui les enregistre ? dans l'assistant est Mon flux les enregistre, ou quand Parent Record Id est vide : c'est alors le bouton Suivant du flux qui transmet les dates.

Bannière orange : « Composant incorrect pour cette configuration »

Pourquoi : Config Name désigne une configuration enregistrée pour un autre composant.

Solution

  1. Faites pointer Config Name vers une configuration créée pour ce composant, ou
  2. Remplacez-le par le composant pour lequel la configuration a été créée, ou
  3. Ouvrez la configuration dans l'assistant de configuration et changez son Type de composant.

Bannière orange : « Incohérence de configuration »

Pourquoi : l'enregistrement de la page, ou celui de Lier chaque choix à cet enregistrement, appartient à un autre objet que celui visé par le champ de relation de la configuration.

Solution

  1. Placez le composant sur une page d'enregistrement de l'objet indiqué par la bannière, ou
  2. Liez chaque choix à un enregistrement de cet objet, ou
  3. Utilisez une configuration créée pour l'objet de cette page.

Bannière rouge : « Ce composant n'a pas pu charger ses données »

Pourquoi : un nom de champ ou d'objet est erroné dans la configuration, ou l'utilisateur ne peut pas exécuter MultiDatePick ou lire l'objet et ses champs.

Solution

  1. Lisez l'encadré gris : il indique exactement le champ, l'objet ou la classe Apex. Si l'accès à MultiDatePick manque, la bannière indique l'ensemble d'autorisations à attribuer.
  2. Nom erroné : copiez le nom d'API exact depuis Configuration, Gestionnaire d'objets.
  3. Pas d'accès : attribuez l'ensemble d'autorisations MultiDatePick - User ainsi que l'accès à vos propres objets. Sur un site Experience public, attribuez MultiDatePick - Guest à l'utilisateur invité et donnez-lui l'accès en lecture à vos propres objets.

Resource Booking affiche « Configuration requise »

Pourquoi : Resource Booking a besoin d'un objet ressource, d'un objet de réservation, d'un champ date de réservation et d'un champ ressource de réservation. Le panneau liste ceux qui manquent.

Solution

  1. Renseignez Config Name avec une configuration Resource Booking de l'assistant de configuration, ou
  2. Renseignez chaque propriété listée par le panneau.

« Aucune configuration nommée “Room_Bookings” n’a été trouvée »

Pourquoi : Config Name attend le nom d'API de la configuration, celui de la liste Configurations existantes de l'assistant de configuration (par exemple Contact_Event), pas son libellé. Une faute de frappe, le libellé, ou une configuration enregistrée il y a un instant et encore en cours de déploiement mènent tous ici.

Solution

  1. Ouvrez l'assistant de configuration, puis Configurations existantes, et copiez le nom d'API de la configuration.
  2. Collez-le dans Config Name sur le composant et enregistrez la page.
  3. Vous venez d'enregistrer la configuration ? Salesforce la déploie en arrière-plan, ce qui prend de 30 secondes à 2 minutes. Actualisez Configurations existantes jusqu'à ce qu'elle apparaisse, puis rechargez la page.

Si le message indique plutôt que l'utilisateur n'a pas accès à MultiDatePick, consultez pas d'accès à MultiDatePick.

« L’enregistrement de Static Parent Record Id (a015g00000XyZ12AAB) n’existe plus »

Pourquoi : le calendrier enregistre chaque choix sur un seul enregistrement fixe, défini dans Lier chaque choix à cet enregistrement (App Builder : Static Parent Record Id), et cet enregistrement a été supprimé. Rien ne peut être enregistré tant qu'il ne pointe pas vers un enregistrement existant.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration et choisissez un autre enregistrement sous Lier chaque choix à cet enregistrement.
  2. Sur une page sans Config Name, collez l'Id d'un enregistrement existant dans Static Parent Record Id, dans App Builder.

Les dates s'enregistrent, mais n'apparaissent pas la fois suivante

Pourquoi : Afficher les dates déjà enregistrées (App Builder : Load Existing Dates) est désactivé. Les enregistrements sont bien créés, mais le calendrier s'ouvre vide à chaque fois.

Solution

  1. Activez Afficher les dates déjà enregistrées.
  2. Rechargez la page. Les dates enregistrées apparaissent, colorées par statut si un champ de statut est défini.

« Ce calendrier ne peut ni afficher les enregistrements existants ni en enregistrer de nouveaux : le champ “Visit Date” de Visit est chiffré avec Shield Platform Encryption »

Pourquoi : Salesforce ne peut ni rechercher ni trier selon un champ protégé par Shield Platform Encryption, or le calendrier trouve et ordonne ses enregistrements par leurs champs de date, d'heure et de nom. Ces champs doivent rester non chiffrés. Les champs que le calendrier se contente d'afficher, comme les notes de la carte au survol, peuvent rester chiffrés.

Solution

  1. Désactivez le chiffrement du champ indiqué par le message, dans Configuration, Politique de chiffrement, ou
  2. Ouvrez la configuration dans l'assistant de configuration et choisissez plutôt un champ de date ou d'heure non chiffré.

Un filtre « ne correspond à aucun champ filtrable ni valeur », ou « Impossible de charger les ressources »

Pourquoi : un filtre nomme un champ absent de l'objet, un champ que Salesforce ne peut pas filtrer, ou une valeur qui ne convient pas au champ. Le calendrier indique lequel, par exemple Filtre d'enregistrements : « Status__c=Confrimed » ne correspond à aucun champ filtrable ni valeur sur Visit. ou Impossible de charger les ressources : la condition « Active__c est yes » ne correspond pas à ce champ.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration.
  2. Choisissez à nouveau le champ et la valeur dans les listes sous Uniquement les enregistrements où (les enregistrements affichés) ou N'afficher que ceux où (les salles ou personnes proposées).
  3. Vous le saisissez dans App Builder ? Utilisez le nom d'API du champ et une valeur adaptée à son type : une case à cocher prend true ou false, une date 2026-12-31.

« Remplir automatiquement (Priority = High) utilise Priorty__c, un champ que Visit n’a pas »

Pourquoi : Remplir automatiquement (App Builder: Default Field Values) renseigne des champs sur chaque nouvel enregistrement, et l'une de ses paires nomme un champ que l'objet n'a pas. L'assistant de configuration le signale à l'étape Vérifier, en nommant le champ introuvable. Une valeur que le champ ne peut pas contenir, comme une valeur de liste de sélection absente de sa liste, apparaît plutôt à l'enregistrement dans le calendrier : Valeurs de champ par défaut : « Priority=Urgent » ne correspond à aucun champ ni valeur sur Visit.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration et corrigez la paire sous Remplir automatiquement (Priority = High). Vérifiez le nom d'API du champ dans le Gestionnaire d'objets.
  2. Écrivez une valeur adaptée au champ : les cases à cocher prennent true ou false, les dates yyyy-mm-dd ou TODAY+7, les listes de sélection l'une de leurs valeurs.
  3. Séparez plusieurs paires par des points-virgules : Priority=High; Type=Call.

« Duration n’est pas un champ numérique », ou une réservation occupe toute sa journée

Pourquoi : Champ des minutes (App Builder : Duration Field) doit désigner un champ numérique de la réservation, pas une formule, un cumul, une devise ou un pourcentage. Quand il est défini et que Se termine à reste vide, chaque réservation se termine à son début plus ces minutes : un enregistrement sans minutes n'a donc pas de fin et occupe toute sa journée.

Solution

  1. Choisissez un champ numérique qui contient la durée en minutes, ou créez-en un.
  2. Renseignez une fois les minutes des anciens enregistrements, par exemple avec une mise à jour de données ou un flux. Ensuite, chaque enregistrement, déplacement et redimensionnement depuis le calendrier les écrit.

« Visit n'a pas de type d'enregistrement actif Install, que ce calendrier donne aux nouveaux enregistrements »

Pourquoi : Type d'enregistrement des nouvelles réservations nomme un type d'enregistrement désactivé ou renommé. Un message voisin, Confirmed n'est pas une valeur de Visit Status pour les enregistrements de type Repair, signifie que le statut choisi ne fait pas partie des valeurs proposées par ce type d'enregistrement.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration et choisissez un type actif sous Type d'enregistrement des nouvelles réservations, ou choisissez Celui par défaut de chaque personne ou Laisser chacun choisir.
  2. Pour un statut : ajoutez la valeur aux valeurs de liste de sélection de ce type d'enregistrement dans le Gestionnaire d'objets, ou choisissez un autre statut.

Si le message indique que la personne ne peut pas créer d'enregistrements de ce type, consultez type d'enregistrement non autorisé.

« Seuls les administrateurs voient ceci, dans le générateur : ce calendrier compte la capacité mais n'a pas de Config Name »

Pourquoi : sans configuration enregistrée nommée sur la page, le calendrier ne peut compter que les réservations que l'utilisateur voit. Celles que le partage lui masque sont omises, et un horaire complet peut sembler libre.

Solution

  1. Enregistrez la configuration dans l'assistant de configuration.
  2. Saisissez son nom dans Config Name sur le composant. Les comptes incluent alors toutes les réservations, sous forme de nombres uniquement.

Seuls les administrateurs voient cette note, dans App Builder. Les utilisateurs, jamais.

Pas de bouton Ajouter au calendrier après l'enregistrement

Pourquoi : Show Add to Calendar After Saving (Afficher « Ajouter au calendrier » après l’enregistrement) est désactivé. C'est le réglage par défaut.

Solution

  1. Activez-le dans les propriétés du composant ou dans la configuration, puis enregistrez un enregistrement. Le bouton apparaît dans une barre sous la notification.
  2. Vous voyez « Ajouter à Google Agenda » à la place ? Le navigateur a bloqué la création d'un fichier : un événement unique reçoit alors un lien Google Agenda.

Réservations et disponibilités

Pourquoi un jour, une heure, une salle ou une personne ne peut pas être choisi ou réservé.

Resource Booking affiche « Aucune ressource disponible »

Pourquoi : la liste des ressources est revenue vide. En général un filtre qui ne correspond à rien, un mauvais objet ressource, ou aucun enregistrement de ressource pour l'instant.

Solution

  1. Vérifiez N'afficher que ceux où (App Builder : Resource Filter Field and Value) sur un enregistrement réel.
  2. Vérifiez Liste des choix proposés et Champ du nom de chacun (App Builder : Resource Object API Name et Resource Name Field).
  3. Créez au moins un enregistrement de ressource.

Bannière orange : « La capacité requiert les deux champs d'heure »

Pourquoi : Combien à la fois (App Builder : Capacity Field) est renseigné, mais un champ d'heure de début ou de fin de réservation est vide : la capacité ne peut donc pas être appliquée.

Solution

  1. Renseignez Commence à et Se termine à (App Builder : Booking Start Time Field et Booking End Time Field), ou
  2. Videz Combien à la fois.

Je ne peux pas choisir une autre date

Pourquoi : le composant a une limite de dates : Max Dates Allowed (Nombre max. de dates autorisées).

Solution

  1. Désélectionnez une date pour en choisir une autre, ou
  2. Augmentez la limite, ou mettez-la à 0 pour ne plus en avoir.

Je ne peux pas réserver un autre horaire

Pourquoi : une limite de réservation est atteinte. Max Time Slots plafonne le nombre total de créneaux, Max Bookings per Day plafonne les réservations distinctes sur une journée (des horaires qui se suivent comptent pour une seule), et Limit per Person plafonne les réservations à venir d'un client, comptées sur le serveur.

Solution

  1. Augmentez la limite, ou mettez-la à 0 pour ne plus en avoir.
  2. Le personnel peut dépasser « Limite par personne » après confirmation. Les visiteurs du site, non.

Certains jours ou horaires sont grisés

Pourquoi : une règle de réservation les ferme. Minimum Notice (Hours) (Préavis minimum (heures)) ferme tout ce qui commence trop tôt, Book Up To (Days Ahead) (Réservable jusqu’à (jours à l’avance)) ferme les jours au-delà de la fenêtre glissante, et les dates sélectionnables au plus tôt ou au plus tard, les dates bloquées et les heures ouvrables de chaque ressource ferment le reste.

Solution

  1. Vérifiez ces paramètres sur le composant ou sa configuration. La valeur 0 désactive le préavis et la fenêtre.
  2. Cliquez sur un créneau fermé : un message indique pourquoi il est fermé.

Le créneau juste après une réservation apparaît comme pris

Pourquoi : Buffer Between Bookings (Minutes) (Battement entre les réservations (minutes)) garde un temps libre après chaque réservation sur la même ressource, pour le nettoyage ou la remise en état.

Solution

  1. Réduisez le temps de battement, ou mettez-le à 0 pour des réservations enchaînées.
  2. Quand un horaire est pris s'applique toujours : avec Ignorer les créneaux en conflit, un créneau qui tombe dans le battement est ignoré et signalé comme n'importe quel autre conflit.

Seules certaines heures de début s'affichent

Pourquoi : Uniquement ces heures est renseigné : la grille ne propose que les heures de début de la liste. Sur Resource Booking, Heures propres à chaque ressource prend le relais quand une salle ou une personne a sa propre liste. Les heures d'ouverture, les fermetures, le préavis et les conflits peuvent toujours fermer une heure de la liste.

Solution

  1. Modifiez la liste, ou choisissez Chaque intervalle, sur le composant ou dans sa configuration.
  2. Vérifiez la liste propre à la ressource dans son champ Heures propres à chaque ressource.

« Ces sélections ne sont plus dans la période de réservation »

Pourquoi : la page est restée ouverte assez longtemps pour que le jour ou l'heure choisis tombent dans le délai de préavis minimum. L'enregistrement revérifie la règle pour qu'une page restée ouverte ne puisse pas réserver trop tard.

Solution

  1. Retirez les dates indiquées par le message, ou choisissez une heure plus tardive.
  2. Enregistrez à nouveau.

« Réservation impossible. Déjà complet ou fermé le : 3 déc. » ou « Déjà complet ou fermé, donc ignoré lors de l'enregistrement »

Pourquoi : une autre réservation occupe déjà cet horaire, ou une fermeture le couvre. Quand un horaire est pris décide de la suite : Bloquer refuse toute la demande, Ignorer les créneaux en conflit réserve les autres jours et nomme ceux laissés de côté, et Autoriser (réserver quand même) propose un bouton Réserver quand même.

Solution

  1. Retirez les dates indiquées par le message, ou choisissez un autre horaire ou une autre ressource.
  2. Un administrateur peut modifier Quand un horaire est pris dans les règles de réservation de la configuration.

« Limite quotidienne atteinte (2 sur 2) »

Pourquoi : Réservations max. par jour (App Builder : Daily Limit Field) est un nombre porté par chaque salle ou personne, comme les 2 interventions par jour d'un technicien. Dès qu'une journée compte autant de réservations, elle se ferme pour cette ressource, et un enregistrement ce jour-là affiche Limite quotidienne atteinte, donc rien n’a été enregistré. Chaque enregistrement compte une fois, une réservation sur plusieurs jours compte chaque jour, et les statuts qui libèrent l'horaire ne comptent jamais.

Solution

  1. Choisissez un autre jour ou une autre ressource.
  2. Augmentez le nombre sur l'enregistrement de la ressource, ou laissez-le vide pour ne fixer aucune limite.
  3. Avec Quand un horaire est pris réglé sur Autoriser (réserver quand même), une réservation peut dépasser la limite.

« Garden Room n'accepte aucune réservation, donc rien n'a été enregistré »

Pourquoi : Combien à la fois ou Réservations max. par jour vaut 0 pour cette ressource. Un 0 signifie qu'elle n'accepte aucune réservation, quel que soit le réglage de Quand un horaire est pris. Les sélecteurs, la grille horaire et la vue Semaine la grisent.

Solution

  1. Choisissez une autre ressource.
  2. Pour l'ouvrir aux réservations, réglez le nombre sur son enregistrement à 1 ou plus, ou laissez-le vide pour ne fixer aucune limite.

« Ces dates sont passées et ne peuvent pas être réservées » ou « Ces heures sont passées »

Pourquoi : le calendrier ne réserve pas les jours ou les heures déjà écoulés. Un jour choisi hier sur une page restée ouverte toute la nuit, ou une heure plus tôt dans la journée, est refusé à l'enregistrement.

Solution

  1. Retirez les dates ou heures indiquées par le message et choisissez-en de plus tardives.
  2. Besoin de saisir des jours passés, pour des feuilles de temps par exemple ? Un administrateur peut activer Autoriser les dates passées dans la configuration.

« Ces dates sont fermées : 25 déc. Choisissez une autre date ou une autre heure. »

Pourquoi : une fermeture couvre ce jour : un enregistrement de la Liste des jours fermés du calendrier, comme un jour férié ou un congé du personnel. Une fermeture qui nomme une salle ou une personne ne ferme que cette ressource. Le calendrier et l'enregistrement la refusent tous deux.

Solution

  1. Choisissez une autre date ou une autre heure.
  2. Si le jour doit être ouvert, modifiez ou supprimez l'enregistrement de fermeture, ou restreignez Uniquement les fermetures où dans la configuration.

« Garden Room ne peut pas être réservé dans ce calendrier. Choisissez une ressource dans la liste. »

Pourquoi : la salle ou la personne n'est pas dans la liste de ce calendrier, car N'afficher que ceux où l'exclut. Cela arrive souvent quand un enregistrement a changé après l'ouverture de la page, par exemple une salle passée à inactive. Le serveur la refuse à l'enregistrement, au déplacement et à la réaffectation.

Solution

  1. Rechargez la page et choisissez une ressource dans la liste.
  2. Si elle doit être proposée, mettez à jour l'enregistrement de la ressource, ou modifiez N'afficher que ceux où dans la configuration.

« Les ressources sélectionnées n'ont aucune heure de début en commun »

Pourquoi : avec Réserver plusieurs à la fois, un même horaire doit convenir à chaque salle ou personne choisie. Leurs heures d'ouverture ou leurs propres heures de début ne se chevauchent pas, donc aucun horaire ne convient à toutes. Un message plus court, Les ressources sélectionnées n'ont pas d'heures ouvrables qui se chevauchent, signifie la même chose.

Solution

  1. Choisissez moins de ressources, ou des ressources qui ont les mêmes horaires.
  2. Un administrateur peut vérifier les heures d'ouverture et les heures de début propres à chaque ressource.

Deux personnes ont réservé le même horaire

Pourquoi : l'un de deux réglages le permet. Quand un horaire est pris réglé sur Autoriser (réserver quand même) laisse le personnel réserver volontairement un horaire déjà pris. Ou Le filtre décide aussi de ce qui est occupé est activé avec un filtre qui utilise ME : seules les réservations de chaque personne occupent alors un horaire. L'assistant avertit dans le second cas : « Le filtre décide aussi de ce qui est occupé » est activé et « Uniquement les enregistrements où » utilise ME : seules les réservations de chaque personne occupent un horaire, et deux personnes peuvent réserver le même horaire.

Solution

  1. Réglez Quand un horaire est pris sur Bloquer ou Ignorer les créneaux en conflit.
  2. Désactivez Le filtre décide aussi de ce qui est occupé, sauf si chacun ne réserve vraiment que son propre temps.

« Limite par personne est activée, mais aucun Champ client n'est défini »

Pourquoi : Limite par personne compte les réservations de chaque client via Pour qui (App Builder : Client Field). Sans champ défini, ou avec un champ dans lequel Salesforce ne peut pas rechercher, comme un texte long, une réservation ne peut pas être comptée, et l'enregistrement est refusé. Les administrateurs voient Limite par personne ne peut pas compter les réservations par Notes dans App Builder.

Solution

  1. Ouvrez la configuration dans l'assistant de configuration et choisissez un champ texte, e-mail ou de référence sous Pour qui.
  2. Ou réglez Limite par personne sur 0 pour la désactiver.

« Salesforce n'a pas répondu : cette réservation est peut-être déjà enregistrée »

Pourquoi : la connexion a été coupée ou Salesforce a été lent après l'appui sur Réserver, et le calendrier n'a pas pu savoir si l'enregistrement avait abouti. Il se recharge de lui-même pour que vous puissiez vérifier.

Solution

  1. Cherchez la réservation dans le calendrier rechargé.
  2. Ne réservez à nouveau que si elle n'y est pas.

Invités du site public

Calendriers sur un site Experience Cloud public, où les visiteurs réservent sans se connecter.

Les invités voient un calendrier vide

Pourquoi : la règle de partage invité n'est pas encore appliquée, ou une étape manque dans le profil invité.

Solution

  1. Réglez l'accès externe par défaut de l'objet sur Privé, puis cliquez sur Recalculer dans Configuration, Paramètres de partage.
  2. Attribuez l'ensemble d'autorisations MultiDatePick - Guest à l'utilisateur invité et donnez-lui la Lecture sur chacun de vos propres objets et champs.
  3. Activez le site. Le publier ne suffit pas.

La liste de contrôle invité complète en six étapes se trouve dans le Guide de l'utilisateur. Vérifier mon site dans l'assistant de configuration teste chaque étape pour vous.

Vérifier mon site affiche « À corriger »

Pourquoi : Vérifier mon site, aux étapes Vérifier et Terminé de l'assistant de configuration pour un calendrier de site, teste le site tel qu'un invité le découvre. Chaque ligne marquée À corriger correspond à une étape manquante et indique quoi faire.

Solution

  1. Le site n’est pas encore en ligne : dans les Espaces de travail du site, allez dans Administration, Paramètres, cliquez sur Activer, puis publiez.
  2. Ensemble d’autorisations MultiDatePick - Guest : ouvrez l'utilisateur invité et ajoutez-le sous Attributions d'ensembles d'autorisations.
  3. Accès aux objets ou Accès aux champs : donnez à l'utilisateur invité la Lecture sur ce que le calendrier affiche et la Modification sur ce qu'une réservation enregistre.
  4. Un invité ne voit aucune des ressources : ajoutez une règle de partage d’utilisateur invité sur l'objet ressource dans Configuration, Paramètres de partage.

Seul un administrateur disposant de MultiDatePick - Setup peut lancer la vérification.

« Cette organisation n’a pas encore de site Experience Cloud »

Pourquoi : Vérifier mon site n'a trouvé aucun site à vérifier, il n'y a donc aucun site à choisir. Le message complet est Cette organisation n’a pas encore de site Experience Cloud. Activez Expériences numériques dans Configuration et créez un site, puis vérifiez-le ici. La configuration elle-même est correcte et peut être enregistrée.

Solution

  1. Dans Configuration, recherchez Expériences numériques, ouvrez Paramètres et cochez Activer les Expériences numériques. Salesforce ne permet pas de le désactiver ensuite.
  2. Créez le site dans Expériences numériques, Tous les sites, Nouveau.
  3. Rouvrez la configuration dans l'assistant de configuration et cliquez sur Vérifier mon site à l'étape Vérifier.

« Ce calendrier ne peut pas enregistrer ici : il n'indique aucune configuration enregistrée pour cet objet »

Pourquoi : la réservation d'un invité du site ou d'un utilisateur du portail est vérifiée sur le serveur par rapport à une configuration enregistrée, pour que la confidentialité et les règles de réservation ne puissent pas être contournées. Le calendrier de la page du site n'a pas de Config Name, alors que l'objet a déjà une configuration enregistrée.

Solution

  1. Ouvrez la page du site dans Experience Builder.
  2. Réglez le Config Name du calendrier sur la configuration enregistrée pour ce site, puis publiez.

« Ce calendrier ne peut pas être utilisé ici : sa configuration enregistrée n'est pas prévue pour un site public »

Pourquoi : la page du site nomme une configuration créée pour le personnel. Les invités du site et les utilisateurs du portail ne peuvent utiliser qu'une configuration enregistrée pour un site, afin que la confidentialité et les règles d'un calendrier interne n'arrivent jamais au public par erreur.

Solution

  1. Réglez le Config Name du calendrier sur une configuration enregistrée pour le site, ou
  2. créez-en une : dans l'assistant de configuration, répondez à Où ce calendrier sera-t-il affiché ? par Sur un site public et enregistrez-la sous un nouveau nom.

« Cette page lie les réservations à un enregistrement que les visiteurs du site ne peuvent pas voir »

Pourquoi : chaque réservation du site est liée à un même enregistrement, défini dans Les réservations sont liées à, et l'utilisateur invité ne peut pas le lire. Salesforce garde les enregistrements privés pour les invités, sauf si une règle de partage d’utilisateur invité les partage.

Solution

  1. Dans Configuration, Paramètres de partage, ajoutez sur l'objet de cet enregistrement une règle de partage d’utilisateur invité qui le partage avec l'utilisateur invité du site, en Lecture seule.
  2. Relancez Vérifier mon site : Enregistrement auquel les réservations sont liées doit passer.

« Non enregistré sur cette page publique »

Pourquoi : Salesforce permet aux invités d'un site de lire et de créer des enregistrements, mais jamais de les modifier ni de les supprimer. Les visiteurs peuvent consulter et réserver. Les utilisateurs connectés qui ont l'accès peuvent modifier.

Solution

  1. Rien à corriger : c'est la règle de Salesforce pour les invités. Pour que les gens modifient leurs propres réservations, donnez-leur un compte de connexion (un site pour membres), ou laissez le personnel faire la modification.

« Chaque réservation de ce calendrier dure 60 minutes, donc ce créneau ne peut pas être réservé »

Pourquoi : pour les invités du site et les utilisateurs du portail, le serveur vérifie chaque réservation par rapport à la configuration enregistrée : Durée de réservation, Uniquement ces heures, les statuts proposés au choix, le préavis, la période de réservation et les limites. La page était ouverte pendant que l'administrateur modifiait l'un d'eux, et elle a proposé quelque chose que la configuration n'autorise plus. Messages voisins : Ce calendrier n'accepte les réservations qu'aux heures de début indiquées et Le statut Requested ne peut pas être choisi dans ce calendrier.

Solution

  1. Rechargez la page et réservez à nouveau.
  2. Toujours refusé ? L'administrateur du site peut vérifier ces règles dans la configuration indiquée dans Config Name.

Les membres du site ne voient pas les enregistrements qu'ils ont créés

Pourquoi : le partage Experience Cloud. Les utilisateurs du site ne voient que les enregistrements auxquels le partage leur donne accès.

Solution

  1. Ajoutez une règle de partage (ou un ensemble de partage pour les membres) sur l'objet où les dates sont enregistrées, ou
  2. Ouvrez son accès externe par défaut à l'échelle de l'organisation.

« Le site n’autorise pas d’autres sites web à l’afficher »

Pourquoi : vous avez placé le calendrier sur votre propre site web avec le code d'intégration, et le site Salesforce refuse d'être affiché dans un autre site web, ce qui est son comportement par défaut.

Solution

  1. Dans Experience Builder, ouvrez Paramètres, puis Sécurité et confidentialité.
  2. Réglez Clickjack Protection Level sur Allow framing of site pages on external domains.
  3. Ajoutez votre site web sous Trusted Domains for Inline Framing, puis publiez.

Les invités voient la liste des lieux, mais pas la carte

Pourquoi : la carte est dessinée par un service Salesforce que le site bloque tant qu'il n'est pas approuvé. Le calendrier ne peut pas savoir si un site la bloque : sur un site, il s'ouvre donc sur la liste et propose la carte.

Solution

  1. Dans Experience Builder, ouvrez Paramètres, puis Sécurité et confidentialité.
  2. Ajoutez maps.a.forceusercontent.com comme site de confiance pour les cadres, puis publiez.

Autorisations et sécurité

Le calendrier s'exécute avec les autorisations propres à chaque utilisateur. Commencez par le bon ensemble d'autorisations, puis donnez l'accès à vos propres objets et champs.

Ensemble d'autorisationsÀ attribuer à
MultiDatePick - UserTous ceux qui utilisent les calendriers
MultiDatePick - SetupLes administrateurs qui créent les configurations. Inclut l'assistant de configuration.
MultiDatePick - All AccessLes administrateurs qui les créent et les utilisent
MultiDatePick - GuestL'utilisateur invité d'un site Experience Cloud public

Les messages d'erreur nomment ce qui ne va pas : le champ, l'objet ou la règle de validation. Quand un message se termine par Détails :, ce texte est la description fournie par Salesforce lui-même. Transmettez-le à votre administrateur, ou à nous : il indique exactement où chercher.

« Vous avez besoin d’une licence MultiDatePick pour utiliser ce calendrier »

Pourquoi : MultiDatePick est licencié par utilisateur, et aucune licence n'a été attribuée à cet utilisateur. Le calendrier est remplacé par ce message, et les enregistrements sont refusés. Les invités d'un site n'ont jamais besoin de licence.

Solution

  1. Dans Configuration, ouvrez Packages installés, puis Gérer les licences à côté de MultiDatePick.
  2. Cliquez sur Ajouter des utilisateurs et ajoutez l'utilisateur. Il voit le calendrier au prochain chargement de la page.

« Cet utilisateur n'a pas accès à MultiDatePick, la configuration n'a donc pas été chargée »

Pourquoi : l'utilisateur n'a aucun ensemble d'autorisations MultiDatePick, donc Salesforce ne laisse pas le calendrier exécuter ses classes pour lui. La bannière rouge l'indique, avec le texte de Salesforce lui-même dans l'encadré gris.

Solution

  1. Attribuez MultiDatePick - User à l'utilisateur, ou MultiDatePick - All Access à un administrateur qui crée aussi des configurations.
  2. Sur un site public, attribuez MultiDatePick - Guest à l'utilisateur invité du site.

« You do not have access to the Apex class named 'MultiDatePickConfigDeployer' »

Pourquoi : ce sont les propres mots de Salesforce, et ils signalent un ensemble d'autorisations manquant : l'utilisateur n'a aucun ensemble d'autorisations MultiDatePick, donc Salesforce ne laisse pas le calendrier exécuter ses classes. Le nom de la classe varie selon ce que faisait le calendrier. La ligne se trouve généralement dans l'encadré gris sous la bannière rouge, sous Cet utilisateur n'a pas accès à MultiDatePick.

Solution

  1. Attribuez MultiDatePick - User à l'utilisateur, ou MultiDatePick - All Access à un administrateur qui crée aussi des configurations.
  2. Sur un site public, attribuez MultiDatePick - Guest à l'utilisateur invité du site.
  3. Rechargez la page.

L'enregistrement ne s'ouvre pas, ou « privilèges insuffisants »

Pourquoi : l'utilisateur ne peut pas lire l'objet parent, ou le partage lui masque cet enregistrement. Sur un flux d'écran, l'utilisateur n'a peut-être pas le droit d'exécuter des flux.

Solution

  1. Attribuez MultiDatePick - User.
  2. Donnez la Lecture sur l'objet parent dans un ensemble d'autorisations.
  3. Vérifiez que le partage donne à l'utilisateur l'accès à cet enregistrement.
  4. Sur un flux d'écran, cochez Utilisateur de flux (Flow User) sur la fiche utilisateur, ou donnez l'autorisation utilisateur Exécuter des flux (Run Flows) dans un ensemble d'autorisations.

« Pas d'accès en lecture au champ X sur l'objet Y »

Pourquoi : l'utilisateur n'a pas la Lecture en sécurité au niveau du champ sur un champ affiché par le calendrier : un champ de statut, de survol, de date ou d'heure.

Solution

  1. Accordez la Lecture sur le champ indiqué dans le message.
  2. Faites-le aussi pour les administrateurs. Un nouveau champ personnalisé est masqué pour tout le monde, Administrateurs système compris, tant qu'un ensemble d'autorisations ne l'accorde pas.

« Time group failed to save » (plage horaire non enregistrée), « Échec de la création des réservations » ou « Vous ne pouvez pas modifier le champ » suivi d'un nom de champ

Pourquoi : l'utilisateur peut lire les champs, mais ne peut pas modifier l'un de ceux qu'écrit l'enregistrement. Souvent un champ de statut, de seconde liste de sélection ou d'heure ajouté après coup, ou un champ rempli automatiquement sur chaque nouvel enregistrement.

Solution

  1. Accordez la Modification sur chaque champ écrit par le calendrier : date, heure de début et de fin, statut, seconde liste de sélection, champ de nom, référence vers le parent et chaque champ de Remplir automatiquement.
  2. Accordez la Création sur l'objet dans lequel les enregistrements sont créés.

« Vous n’avez pas l’autorisation de faire cela » avec « insufficient access rights on cross-reference id »

Pourquoi : le nouvel enregistrement pointe vers un enregistrement que l'utilisateur ne peut pas voir : le parent ou la ressource.

Solution

  1. Donnez au minimum la Lecture sur les objets parent et ressource, et le partage sur ces enregistrements.
  2. Sur un site public, faites réserver les invités sur un objet personnalisé. Salesforce restreint l'accès des invités aux contacts et aux comptes.

« Vous n'avez pas accès aux fermetures utilisées par ce calendrier »

Pourquoi : l'utilisateur ne peut pas lire l'objet qui contient les jours fermés, donc le calendrier ne peut pas savoir quels jours sont fermés. Son jumeau, Vous n'avez pas accès aux enregistrements affichés par ce calendrier, signifie la même chose pour les réservations elles-mêmes.

Solution

  1. Donnez la Lecture sur l'objet et les champs indiqués par le message, dans un ensemble d'autorisations.
  2. Vérifiez que le partage donne à l'utilisateur l'accès à ces enregistrements.

« Vous ne pouvez pas créer d'enregistrements Visit du type d'enregistrement Install »

Pourquoi : le calendrier donne aux nouvelles réservations un type d'enregistrement que le profil ou les ensembles d'autorisations de cet utilisateur n'incluent pas.

Solution

  1. Ajoutez le type d'enregistrement au profil de l'utilisateur ou à un ensemble d'autorisations.
  2. Ou réglez Type d'enregistrement des nouvelles réservations sur Laisser chacun choisir, qui ne liste que les types que chaque personne peut créer.

« Salesforce ne vous a pas permis d'affecter cet enregistrement (Visit) à Alex Chen »

Pourquoi : la salle ou la personne de la réservation est un utilisateur Salesforce, et Salesforce a refusé d'en faire le propriétaire. Le message se termine par la raison : vous n'avez pas l'accès nécessaire pour lui affecter des enregistrements, l'utilisateur est inactif, ou son type d'utilisateur ne peut pas être propriétaire de ce type d'enregistrement.

Solution

  1. Choisissez une autre personne.
  2. Ou demandez à votre administrateur Salesforce l'accès nécessaire pour affecter des enregistrements à cet utilisateur, ou d'activer l'utilisateur.

« Vous n’êtes pas autorisé à enregistrer des configurations MultiDatePick »

Pourquoi : les configurations sont enregistrées sous forme de métadonnées Salesforce, ce qui nécessite l'autorisation Modify Metadata Through Metadata API Functions. L'ensemble d'autorisations MultiDatePick - Setup l'accorde.

Solution

  1. Attribuez MultiDatePick - Setup, ou MultiDatePick - All Access, à l'administrateur qui crée les configurations.

Flux et actions

Le calendrier dans un flux d'écran (Screen Flow), et les boutons qui lancent un flux.

Un écran de flux ignore les paramètres de mon assistant

Pourquoi : Config Name est vide ou mal orthographié. Vide, le composant utilise discrètement ses valeurs par défaut. Mal orthographié, il affiche « Aucune configuration nommée ... n’a été trouvée ».

Solution

  1. Renseignez Config Name avec le nom de la configuration exactement tel que l'assistant de configuration l'a enregistré.
  2. Ne touchez pas aux entrées activé/désactivé. Chaque case à cocher vient de la configuration.

« Certaines dates choisies ne sont pas encore enregistrées. Cliquez sur Enregistrer ou retirez-les avant de continuer. »

Pourquoi : le bouton Suivant de l'écran a été pressé alors que le calendrier contenait encore des choix jamais enregistrés, qui seraient perdus. Avec des heures, le message indique Certains créneaux choisis ne sont pas encore réservés.

Solution

  1. Cliquez d'abord sur Enregistrer (ou Réserver), puis sur Suivant.
  2. Ou retirez les choix dont vous ne voulez pas, puis cliquez sur Suivant.

« Vous ne pouvez pas lancer Send Reminder : il faut l’autorisation “Run Flows” ou un accès à son flux »

Pourquoi : le bouton d'action du calendrier lance un flux, et Salesforce ne laisse le lancer qu'aux personnes autorisées à exécuter ce flux.

Solution

  1. Donnez à l'utilisateur l'autorisation Exécuter des flux (Run Flows) dans un ensemble d'autorisations, ou
  2. Donnez à son profil ou à son ensemble d'autorisations l'accès à ce flux (Configuration, Flux, le flux, Modifier l'accès).

« Le flux s’est arrêté sur une erreur » ou « Cette action n’est pas disponible ici »

Pourquoi : le premier signifie que le flux derrière un bouton d'action s'est exécuté et a échoué. Le second, que le bouton n'est plus proposé pour cet enregistrement : l'action a été retirée de la configuration enregistrée, ou elle est prévue pour d'autres statuts.

Solution

  1. Pour une erreur de flux, un administrateur ouvre l'historique d'exécution ou le journal de débogage du flux pour voir quelle étape a échoué.
  2. Pour une action non disponible, rechargez la page, puis vérifiez les statuts de l'action dans les actions de la configuration.

« Ce flux n’a pas de variable d’entrée recordId ni recordIds »

Pourquoi : l'assistant de configuration transmet l'enregistrement cliqué au flux d'une action dans une variable nommée recordId (un enregistrement) ou recordIds (plusieurs, depuis le Mode édition). Sans l'une d'elles, le flux ne sait pas quels enregistrements utiliser.

Solution

  1. Dans Flow Builder, ajoutez une variable Texte nommée recordId, ou une collection Texte nommée recordIds, disponible en entrée.
  2. Enregistrez et activez le flux, puis choisissez-le à nouveau dans l'assistant.

Diagramme de Gantt

Les tâches, leurs liens et leur avancement dans la vue Gantt.

La vue Gantt n'apparaît pas dans le sélecteur

Pourquoi : la vue Gantt s'active à la demande, comme la vue Carte. Available Views (Vues disponibles) laissé vide propose Calendrier, Chronologie, Semaine, Occupation et Agenda.

Solution

  1. Dans l'assistant de configuration, cochez Proposer la vue Gantt dans l'onglet Vues, ou ajoutez gantt à Available Views (Vues disponibles).
  2. Pour qu'elle s'ouvre par défaut, réglez View (Vue) sur gantt.

« Site survey ne peut pas aller le 6 déc. : ce calendrier n'autorise pas ce jour. Rien n'a été enregistré. »

Pourquoi : le Gantt applique les mêmes règles de réservation que le calendrier. Une tâche ne peut pas aller sur un jour ou un horaire fermé, sur une personne déjà prise par une autre tâche ce jour-là, ni sur une ressource qui n'accepte aucune réservation. Le message nomme la règle à chaque fois.

Solution

  1. Faites glisser la tâche sur un autre jour, ou confiez-la à quelqu'un de disponible.
  2. Si le jour doit être ouvert, un administrateur vérifie les fermetures et les jours sélectionnables dans la configuration.

« Install ne peut pas attendre Testing : cela créerait une boucle »

Pourquoi : Testing attend déjà Install, directement ou via d'autres tâches : les lier dans l'autre sens signifierait qu'aucune des deux ne pourrait commencer. Une question voisine, Remplacer le lien ?, apparaît quand les tâches sont liées par un champ de la tâche : chaque tâche ne peut alors attendre qu'une seule autre.

Solution

  1. Supprimez d'abord le lien dans l'autre sens, ou liez une autre tâche.
  2. Pour qu'une tâche puisse en attendre plusieurs, reliez les tâches par un objet de lien distinct : assistant de configuration, Vue Gantt, Liens entre les tâches.

« Le statut reste inchangé » ou « Terminé reste inchangé, pas 100 % »

Pourquoi : Statut d'une tâche terminée lie Pourcentage terminé et le statut : une tâche mise à 100 % reçoit ce statut, et une tâche qui reçoit ce statut passe à 100 %. Quand l'utilisateur ne peut pas modifier l'un des deux champs, ou que le champ de statut ne propose pas la valeur, seule la modification qu'il a faite est enregistrée, et ce message explique pourquoi.

Solution

  1. Donnez à l'utilisateur la Modification sur le champ Pourcentage terminé et sur le champ de statut.
  2. Vérifiez que le champ de statut propose la valeur choisie pour ce type d'enregistrement, ou choisissez-en une autre dans les paramètres de la vue Gantt, ou laissez-le vide pour garder les deux indépendants.

« Rien n'a été enregistré. Lecture seule pour vous : Site survey »

Pourquoi : l'utilisateur voit la tâche mais ne peut pas la modifier, à cause du partage, de la sécurité des champs ou du propriétaire de l'enregistrement. Sa carte indique Lecture seule pour vous.

Solution

  1. Demandez au propriétaire de la tâche, ou à un administrateur, de vous donner l'accès en modification via le partage.
  2. Vérifiez la Modification sur les champs de date de la tâche dans votre ensemble d'autorisations.

Import de configuration

Coller une configuration de la Config Library ou d'une autre organisation dans l'onglet Importer / Exporter de l'assistant de configuration.

« Ce n'est pas une configuration complète » ou « Cela ressemble à du XML, et non à du JSON »

Pourquoi : le texte collé n'est pas une configuration entière. Il a été coupé pendant la copie, c'est du XML de métadonnées Salesforce ou un flux au lieu du JSON de la configuration, ou il contient tout un fichier de configurations (plus de 100 Ko).

Solution

  1. Copiez à nouveau la configuration avec le bouton de copie de la Config Library, ou avec Exporter la configuration dans l'autre organisation.
  2. Collez tout le texte, du premier { au dernier }.

Vous avez du XML de flux ? Déployez-le plutôt comme un flux : Déployer un flux depuis VS Code.

« Cette configuration ne peut pas fonctionner sans Related_Object__c »

Pourquoi : la configuration collée omet un paramètre dont toute configuration a besoin, comme l'objet, le champ date ou le type de composant.

Solution

  1. Copiez à nouveau la configuration en entier, ou
  2. Exportez une configuration qui fonctionne depuis votre organisation pour voir la forme attendue, et ajoutez les paramètres manquants.

Un paramètre « enregistrerait “Confirmed”, que Visit Status n’a pas : Salesforce refuserait chaque enregistrement »

Pourquoi : un paramètre de la configuration importée, comme Remplir automatiquement ou Statuts proposés au choix, utilise une valeur de statut que votre champ de statut ne contient pas. En l'état, chaque réservation serait refusée. À l'étape Associez les valeurs de statut, une valeur marquée Votre champ n’a pas de valeur équivalente est ignorée tant que vous n'en choisissez pas une.

Solution

  1. Revenez à Associez les valeurs de statut.
  2. Pour chacune, choisissez celle de vos valeurs qui a le même sens, puis cliquez sur Appliquer et déployer.

« Son flux Send_Reminder n’existe pas dans cette organisation »

Pourquoi : la configuration importée a un bouton d'action qui lance un flux absent de votre organisation.

Solution

  1. À l'étape Actions, choisissez l'un de vos propres flux pour le bouton, ou choisissez Ignorer cette action.
  2. Vous pourrez ajouter l'action plus tard dans les actions de la configuration.
