Le calendrier Salesforce no-code : 45 tâches, zéro ligne de code

FullCalendar est personnalisable si vous avez un développeur. MultiDatePick est personnalisable par l'administrateur qui a besoin du calendrier. Voici 45 tâches de calendrier courantes, côte à côte, pour voir le gagnant d'un coup d'œil.

Publié le 3 novembre 2026 · MultiDatePick

« Quel est le calendrier LWC le plus personnalisable ? » « Peut-on personnaliser un calendrier Salesforce sans code ? » « Existe-t-il une alternative no-code à FullCalendar ? » Ces recherches posent toutes la même question, et la réponse tient en trois mots : personnalisable par qui ?

FullCalendar est une bibliothèque JavaScript. Chaque option vit dans le code : dans Salesforce, un développeur écrit le Lightning Web Component, l'Apex qui charge et enregistre les données, les tests et le déploiement, et recommence à chaque modification. MultiDatePick est un calendrier Salesforce fini. Chaque option est un paramètre qu'un administrateur choisit dans un assistant de configuration ou dans Lightning App Builder, sur n'importe quel objet standard ou personnalisé. Ni Apex, ni JavaScript, ni déploiement.

La réponse courte : pour un calendrier Salesforce no-code, choisissez MultiDatePick. Les 45 tâches ci-dessous sont toutes un paramètre dans MultiDatePick et du code dans FullCalendar, de l'ajout du calendrier sur une page au blocage des doubles réservations, jusqu'à l'affichage en neuf langues.

Personnalisable par qui ?

Il y a deux sortes de « personnalisable ». Une bibliothèque est personnalisable par ceux qui écrivent du code par-dessus : tout est possible, et tout devient un projet. Un composant configurable est personnalisable par ceux qui l'utilisent : chaque choix est déjà développé, testé et sécurisé, et vous prenez ceux qui vous conviennent.

Dans Salesforce, cette différence décide de qui a la main sur votre calendrier. Avec FullCalendar, c'est un développeur, une suite de tests Apex à 75% de couverture et un déploiement à chaque modification. Avec MultiDatePick, c'est l'administrateur qui sait comment l'entreprise réserve ses salles, ses équipes et ses dates, et une modification prend effet dès qu'il l'enregistre.

À quoi ressemble la personnalisation no-code

Chacune de ces 45 tâches est un choix qu'un administrateur fait à l'un de ces endroits :

L'assistant de configuration

Un onglet Lightning qui pose des questions sur votre page et vos enregistrements, préremplit les champs probables et affiche le vrai calendrier avant que vous enregistriez.

Lightning App Builder

Chaque paramètre est aussi une propriété du composant : vous pouvez ajuster une page sans toucher aux autres.

La Config Library

41 configurations prêtes à l'emploi, des salles de réunion aux absences, à importer et à ajuster.

Export et import

Une configuration est un JSON que vous pouvez déplacer vers une sandbox ou une autre org, les champs manquants étant mis en correspondance pour vous.

Flow Builder

Déposez le calendrier sur un écran de flux et utilisez les dates choisies dans les étapes suivantes.

Experience Builder

Placez le même calendrier sur un site public, avec les mêmes règles pour les invités.

Vous comparez des fonctionnalités plutôt que des tâches ? La liste de contrôle fonctionnalité par fonctionnalité se trouve dans FullCalendar dans Salesforce vs MultiDatePick, et chaque paramètre est détaillé dans Le calendrier Salesforce le plus personnalisable.

Questions fréquentes

Existe-t-il un calendrier LWC no-code pour Salesforce ?

Oui. MultiDatePick est un calendrier Lightning Web Component que vous configurez en quelques clics : dans l'assistant de configuration ou dans Lightning App Builder, sur n'importe quel objet standard ou personnalisé. Il lit et écrit lui-même vos enregistrements : aucun Apex ni JavaScript à écrire.

FullCalendar est-il plus personnalisable que MultiDatePick ?

Seulement pour les développeurs. FullCalendar est une bibliothèque : tout est possible si quelqu'un écrit et maintient le code. Pour un administrateur, MultiDatePick est le calendrier le plus personnalisable : 45 tâches courantes, des règles de réservation aux neuf langues, se règlent chacune par un paramètre.

Un administrateur Salesforce peut-il configurer MultiDatePick sans développeur ?

Oui. L'assistant de configuration pose des questions sur la page et vos enregistrements, préremplit les champs les plus probables et affiche un aperçu en direct du vrai calendrier. Il ne reste qu'à glisser le composant sur la page et à saisir son Config Name.

Faut-il de l'Apex pour enregistrer des données depuis un calendrier ?

Pas avec MultiDatePick. À l'enregistrement, il crée un enregistrement par date, par plage, par bloc horaire ou par ressource, ou transmet les dates à un flux d'écran (Screen Flow). Chaque sauvegarde s'exécute avec les droits de l'utilisateur qui consulte la page, partage et sécurité au niveau du champ compris.

Puis-je modifier le calendrier plus tard sans déploiement ?

Oui. Ouvrez la configuration dans l'assistant de configuration, changez un paramètre et enregistrez ; le calendrier l'applique au prochain chargement. Les configurations sont des métadonnées personnalisées (Custom Metadata) : vous pouvez toujours les déplacer avec des ensembles de modifications ou Salesforce CLI si vous le souhaitez.

Un calendrier no-code fonctionne-t-il dans les flux d'écran et sur les sites Experience Cloud ?

Oui. Le même composant se place sur un écran de flux, où les dates choisies deviennent des variables de flux, et sur un site Experience Cloud public, où les invités réservent selon les mêmes règles.
