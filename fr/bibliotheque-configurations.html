Comment fonctionne l'import d'une configuration

Ces exemples de configuration reposent sur les objets de démonstration fournis avec MultiDatePick (Schedule__c, Event__c, Resource__c). Votre org utilisera presque toujours ses propres objets et noms de champs. C'est prévu, et pris en charge.

  1. Copier pour l'assistant sur n'importe quelle carte ci-dessous.
  2. Collez-la dans l'onglet Importer de l'assistant de configuration (Lanceur d'application, MultiDatePick Setup Wizard, Importer).
  3. Faites correspondre les champs : si des objets ou des champs cités dans le JSON n'existent pas dans votre org, l'assistant affiche un panneau de mappage intelligent des champs qui liste chaque référence manquante, avec une liste déroulante des objets et champs correspondants de votre org. Choisissez le remplacement de chacun et cliquez sur Appliquer & déployer.
  4. Utilisez son Config Name : placez le composant sur une page Lightning, un site Experience ou un écran de flux, et saisissez le Config Name.

Pas de code, pas de XML à modifier. L'assistant réécrit la configuration avec vos choix avant le déploiement des métadonnées : la configuration importée arrive prête à être déposée sur une page d'enregistrement de votre org. Si tout correspond déjà (par exemple quand vous clonez d'une sandbox à l'autre), l'étape de mappage est sautée automatiquement.

Aucune configuration ne vous convient ? Créez-en une dans l'assistant.

Chaque objet et chaque champ se choisit dans une liste déroulante filtrée sur votre org : une configuration opérationnelle prend quelques minutes, sans aucun nom d'API.

Vous la voulez dans un flux d'écran (Screen Flow) ? Utilisez la même configuration.

Faites glisser le composant sur un écran de flux et saisissez le Config Name. Pour un flux qui enregistre un enregistrement par date ou par poste, consultez l'article sur les boucles de flux.

Une configuration, cinq façons de la voir

Chaque configuration ci-dessous définit une View par défaut et une liste Available Views (Vues disponibles). Les données, les champs et le comportement d'enregistrement restent identiques : seule la présentation change. Les utilisateurs basculent avec les pastilles au-dessus du calendrier, et c'est vous qui décidez lesquelles ils obtiennent.

calendar

Grille mensuelle

La vue par défaut. Un mois à la fois, des couleurs de statut par jour, un clic ou un glisser pour choisir des dates. Idéale quand la question est « que se passe-t-il le 14 ? ».

timeline

Les ressources en lignes, les dates en colonnes

Deux semaines par défaut, pour que chaque réservation ait la place d'afficher son nom. Les réservations sur plusieurs jours forment une seule barre. Les ressources chargées se replient sur une seule ligne que l'on peut déplier.

week

Jour par heure

Sept jours en colonnes, vos heures ouvrables en lignes. Faites glisser horizontalement, verticalement ou les deux pour sélectionner un bloc horaire sur plusieurs jours d'un coup.

utilization

Heatmap de capacité

Le pourcentage de capacité utilisé par ressource et par jour, du vert au rouge. Il faut un Capacity Field (Champ Capacité) pour afficher des pourcentages plutôt que des nombres bruts.

Lecture seule
agenda

Liste chronologique

Les 60 prochains jours en une liste simple et facile à parcourir, avec heures et statuts. Idéale pour une passation, un point quotidien ou un écran mobile.

Lecture seule
Avant de choisir la vue par défaut. Occupation et Agenda sont en lecture seule : ce sont de mauvais choix par défaut pour une configuration dont tout le rôle est de réserver. Mettez-les dans Available Views et ouvrez plutôt sur une vue modifiable. La vue par défaut est d'ailleurs toujours proposée dans le sélecteur, que vous la listiez ou non : Available Views n'a donc besoin que des vues supplémentaires.

Cas d'usage des sous-blocs

Quand Consolidate Time Span est activé, les écarts entre les créneaux choisis sont détectés automatiquement et enregistrés comme enregistrements distincts sur un objet enfant. Les utilisateurs peuvent aussi marquer manuellement des créneaux comme sous-blocs.

  • Planning de postes avec pauses : l'employé sélectionne de 08:00 à 17:00 ; la pause déjeuner de 12:00 à 13:00 crée automatiquement un enregistrement sur un objet Break__c
  • Itinéraires de voyage : l'utilisateur bloque des plages de déplacement ; les escales entre les vols deviennent des enregistrements Travel_Leg__c
  • Plannings de formation : le formateur sélectionne ses blocs d'enseignement ; les périodes libres entre les sessions sont enregistrées comme Available_Slot__c
  • Plannings de travail avec rendez-vous : le manager définit les heures de travail ; les écarts pour réunions ou rendez-vous s'enregistrent automatiquement sur un objet Appointment__c

Si vous utilisez des sous-blocs, remplacez les valeurs en violet par votre objet enfant et ses champs. Si vous utilisez des dates bloquées, remplacez aussi les valeurs en rouge.
