Einrichtung und Platzierung

Banner und Warnungen, die ein Admin sieht, während er einen Kalender auf einer Seite platziert oder seine Konfiguration erstellt.

Es gibt keine Schaltfläche Speichern

Warum: Die Komponente hat keinen übergeordneten Datensatz und ist nicht so eingestellt, dass sie alle Datensätze zeigt. App- und Startseiten haben keinen eigenen Datensatz.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten und beantworten Sie Wessen Datensätze? (meist Nur die betrachtende Person), oder setzen Sie Jede Auswahl mit diesem Datensatz verknüpfen (App Builder: Static Parent Record Id) auf den Datensatz, zu dem die Termine gehören.
  2. Prüfen Sie, ob Objekt, Datumsfeld und Beziehungsfeld ausgefüllt sind, oder setzen Sie Config Name.

Im Flow erscheint Speichern, sobald Parent Record Id gebunden ist. Ausgeblendet bleibt die Schaltfläche, wenn im Assistenten bei Wer speichert sie? die Antwort Mein Flow speichert sie gewählt ist oder Parent Record Id leer ist: Dann übergibt die Schaltfläche Weiter des Flows die Termine.

Gelbes Banner: „Falsche Komponente für diese Konfiguration“

Warum: Config Name verweist auf eine Konfiguration, die für eine andere Komponente gespeichert wurde.

Lösung

  1. Richten Sie Config Name auf eine Konfiguration für diese Komponente aus, oder
  2. setzen Sie die Komponente ein, für die die Konfiguration gebaut wurde, oder
  3. öffnen Sie die Konfiguration im Einrichtungsassistenten und ändern Sie den Komponententyp.

Gelbes Banner: „Konfigurationskonflikt“

Warum: Der Datensatz der Seite oder der Datensatz in Jede Auswahl mit diesem Datensatz verknüpfen gehört zu einem anderen Objekt als dem, auf das das Beziehungsfeld der Konfiguration verweist.

Lösung

  1. Platzieren Sie die Komponente auf einer Datensatzseite des Objekts, das im Banner steht, oder
  2. Verknüpfen Sie jede Auswahl mit einem Datensatz dieses Objekts, oder
  3. verwenden Sie eine Konfiguration, die für das Objekt dieser Seite gebaut ist.

Rotes Banner: „Diese Komponente konnte ihre Daten nicht laden“

Warum: Ein Feld- oder Objektname in der Einrichtung ist falsch, oder der Benutzer darf MultiDatePick nicht ausführen oder das Objekt und seine Felder nicht lesen.

Lösung

  1. Lesen Sie den grauen Kasten: Er nennt das genaue Feld, Objekt oder die Apex-Klasse. Fehlt der Zugriff auf MultiDatePick, sagt das Banner, welcher Berechtigungssatz zuzuweisen ist.
  2. Falscher Name: Kopieren Sie den exakten API-Namen aus Setup, Objekt-Manager.
  3. Kein Zugriff: Weisen Sie den Berechtigungssatz MultiDatePick - User zu und geben Sie Zugriff auf Ihre eigenen Objekte. Auf einer öffentlichen Experience Cloud-Site weisen Sie dem Gastbenutzer MultiDatePick - Guest zu und geben ihm Lesezugriff auf Ihre eigenen Objekte.

Resource Booking meldet „Konfiguration erforderlich“

Warum: Resource Booking braucht ein Ressourcenobjekt, ein Buchungsobjekt, ein Buchungsdatumsfeld und ein Buchungsressourcen-Feld. Der Bereich listet auf, was fehlt.

Lösung

  1. Setzen Sie Config Name auf eine Resource Booking-Konfiguration aus dem Einrichtungsassistenten, oder
  2. füllen Sie jede Eigenschaft aus, die der Bereich auflistet.

„Keine Konfiguration namens "Room_Bookings" gefunden“

Warum: Config Name erwartet den API-Namen der Konfiguration aus der Liste Vorhandene Konfigurationen im Einrichtungsassistenten (zum Beispiel Contact_Event), nicht ihre Bezeichnung. Ein Tippfehler, die Bezeichnung oder eine gerade gespeicherte Konfiguration, die noch bereitgestellt wird, führen alle zu dieser Meldung.

Lösung

  1. Öffnen Sie den Einrichtungsassistenten, dann Vorhandene Konfigurationen, und kopieren Sie den API-Namen der Konfiguration.
  2. Fügen Sie ihn in Config Name an der Komponente ein und speichern Sie die Seite.
  3. Konfiguration gerade gespeichert? Salesforce stellt sie im Hintergrund bereit, was 30 Sekunden bis 2 Minuten dauert. Aktualisieren Sie Vorhandene Konfigurationen, bis sie erscheint, und laden Sie dann die Seite neu.

Sagt die Meldung stattdessen, dass der Benutzer keinen Zugriff auf MultiDatePick hat, lesen Sie Kein Zugriff auf MultiDatePick.

„Der Datensatz in Static Parent Record Id (a015g00000XyZ12AAB) existiert nicht mehr“

Warum: Der Kalender speichert jede Auswahl an einem festen Datensatz, festgelegt in Jede Auswahl mit diesem Datensatz verknüpfen (App Builder: Static Parent Record Id), und dieser Datensatz wurde gelöscht. Gespeichert werden kann erst wieder, wenn dort ein vorhandener Datensatz steht.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten und wählen Sie unter Jede Auswahl mit diesem Datensatz verknüpfen einen anderen Datensatz.
  2. Auf einer Seite ohne Config Name fügen Sie im App Builder die ID eines vorhandenen Datensatzes in Static Parent Record Id ein.

Termine werden gespeichert, beim nächsten Mal aber nicht angezeigt

Warum: Bereits gespeicherte Daten anzeigen (App Builder: Load Existing Dates) ist aus. Die Datensätze sind gespeichert, aber der Kalender öffnet sich jedes Mal leer.

Lösung

  1. Schalten Sie Bereits gespeicherte Daten anzeigen ein.
  2. Laden Sie die Seite neu. Gespeicherte Termine erscheinen, nach Status eingefärbt, wenn ein Statusfeld gesetzt ist.

„Dieser Kalender kann vorhandene Datensätze weder anzeigen noch neue speichern: Das Feld "Visit Date" auf Visit ist mit Shield Platform Encryption verschlüsselt“

Warum: Salesforce kann nicht nach einem Feld suchen oder sortieren, das Shield Platform Encryption schützt, und der Kalender findet und sortiert seine Datensätze über ihre Datums-, Uhrzeit- und Namensfelder. Diese Felder dürfen nicht verschlüsselt sein. Felder, die der Kalender nur anzeigt, etwa Notizen auf der Hover-Karte, können verschlüsselt bleiben.

Lösung

  1. Heben Sie die Verschlüsselung für das Feld, das die Meldung nennt, unter Setup, Verschlüsselungsrichtlinie auf, oder
  2. öffnen Sie die Konfiguration im Einrichtungsassistenten und wählen Sie stattdessen ein unverschlüsseltes Datums- oder Uhrzeitfeld.

Ein Filter „passt zu keinem filterbaren Feld und Wert“ oder „Ressourcen konnten nicht geladen werden“

Warum: Ein Filter nennt ein Feld, das es am Objekt nicht gibt, ein Feld, nach dem Salesforce nicht filtern kann, oder einen Wert, der nicht zum Feld passt. Der Kalender sagt, was davon zutrifft, zum Beispiel Datensatzfilter: "Status__c=Confrimed" passt zu keinem filterbaren Feld und Wert auf Visit. oder Ressourcen konnten nicht geladen werden: Die Bedingung „Active__c ist yes“ passt nicht zu diesem Feld.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten.
  2. Wählen Sie Feld und Wert erneut aus den Listen unter Nur Datensätze mit (die angezeigten Datensätze) oder Nur anzeigen, wenn (die angebotenen Räume oder Personen).
  3. Tragen Sie es im App Builder ein? Verwenden Sie den API-Namen des Felds und einen Wert, der zu seinem Typ passt: Ein Kontrollkästchen nimmt true oder false, ein Datum 2026-12-31.

„Automatisch ausfüllen (Priority = High) verwendet Priorty__c, ein Feld, das Visit nicht hat“

Warum: Automatisch ausfüllen (App Builder: Default Field Values) setzt Felder bei jedem neuen Datensatz, und eines seiner Paare nennt ein Feld, das es am Objekt nicht gibt. Der Einrichtungsassistent meldet das im Schritt Prüfen und nennt das Feld, das er nicht gefunden hat. Einen Wert, den das Feld nicht aufnehmen kann, etwa einen Auswahllistenwert, der nicht in seiner Liste steht, meldet stattdessen der Kalender beim Speichern: Standardfeldwerte: "Priority=Urgent" passt zu keinem Feld und Wert auf Visit.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten und korrigieren Sie das Paar unter Automatisch ausfüllen (Priority = High). Prüfen Sie den API-Namen des Felds im Objekt-Manager.
  2. Schreiben Sie einen Wert, der zum Feld passt: Kontrollkästchen nehmen true oder false, Datumsfelder yyyy-mm-dd oder TODAY+7, Auswahllisten einen ihrer Werte.
  3. Trennen Sie mehrere Paare mit Semikolons: Priority=High; Type=Call.

„Duration ist kein Zahlenfeld“, oder eine Buchung belegt den ganzen Tag

Warum: Feld für die Minuten (App Builder: Duration Field) muss ein Zahlenfeld an der Buchung sein, kein Formel-, Rollup-Auswertungs-, Währungs- oder Prozentfeld. Ist es gesetzt und Endet um leer, endet jede Buchung zu ihrem Beginn plus diesen Minuten. Ein Datensatz ohne Minuten hat daher kein Ende und belegt den ganzen Tag.

Lösung

  1. Wählen Sie ein Zahlenfeld, das die Länge in Minuten enthält, oder legen Sie eines an.
  2. Tragen Sie die Minuten an älteren Datensätzen einmal nach, zum Beispiel mit einer Datenaktualisierung oder einem Flow. Ab dann schreibt jedes Speichern, Verschieben und Ändern der Dauer im Kalender sie selbst.

„Visit hat keinen aktiven Datensatztyp Install, den dieser Kalender neuen Datensätzen gibt“

Warum: Datensatztyp neuer Buchungen nennt einen Datensatztyp, der deaktiviert oder umbenannt wurde. Eine verwandte Meldung, Confirmed ist kein zulässiger Wert für Visit Status bei Datensätzen vom Typ Repair, bedeutet, dass der gewählte Status keiner der Werte ist, die dieser Datensatztyp anbietet.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten und wählen Sie unter Datensatztyp neuer Buchungen einen aktiven Typ, oder wählen Sie Standard der jeweiligen Person oder Personen wählen lassen.
  2. Bei einem Status: Fügen Sie den Wert im Objekt-Manager zu den Auswahllistenwerten dieses Datensatztyps hinzu, oder wählen Sie einen anderen Status.

Sagt die Meldung, dass die Person keine Datensätze dieses Typs erstellen darf, lesen Sie Datensatztyp nicht erlaubt.

„Nur Administratoren sehen dies, im Builder: Dieser Kalender zählt die Kapazität, hat aber keinen "Config Name"“

Warum: Ohne eine gespeicherte Konfiguration, die auf der Seite genannt ist, kann der Kalender nur die Buchungen zählen, die der Betrachter sehen kann. Buchungen, die Freigaben vor ihm verbergen, fehlen, und eine volle Zeit kann frei aussehen.

Lösung

  1. Speichern Sie die Konfiguration im Einrichtungsassistenten.
  2. Tragen Sie ihren Namen in Config Name an der Komponente ein. Die Zählung umfasst dann jede Buchung, nur als Zahlen.

Nur Admins sehen diesen Hinweis, im App Builder. Benutzer sehen ihn nie.

Nach dem Speichern keine Schaltfläche Zum Kalender hinzufügen

Warum: Show Add to Calendar After Saving („Zum Kalender hinzufügen“ nach dem Speichern anzeigen) ist aus. Standardmäßig ist es ausgeschaltet.

Lösung

  1. Schalten Sie es in den Eigenschaften der Komponente oder in der Konfiguration ein und speichern Sie dann einen Datensatz. Die Schaltfläche erscheint in einer Leiste unter der Toast-Meldung.
  2. Sie sehen stattdessen „Zu Google Kalender hinzufügen“? Der Browser hat das Erstellen einer Datei blockiert, daher bekommt ein einzelner Termin einen Google Kalender-Link.

Buchung und Verfügbarkeit

Warum sich ein Tag, eine Uhrzeit, ein Raum oder eine Person nicht wählen oder buchen lässt.

Resource Booking meldet „Keine Ressourcen verfügbar“

Warum: Die Ressourcenliste kam leer zurück. Meist passt ein Filter auf nichts, das Ressourcenobjekt ist falsch, oder es gibt noch keine Ressourcendatensätze.

Lösung

  1. Prüfen Sie Nur anzeigen, wenn (App Builder: Resource Filter Field und Value) an einem echten Datensatz.
  2. Prüfen Sie Liste, aus der gewählt wird und Feld mit dem Namen (App Builder: Resource Object API Name und Resource Name Field).
  3. Legen Sie mindestens einen Ressourcendatensatz an.

Gelbes Banner: „Kapazität benötigt beide Zeitfelder“

Warum: Wie viele gleichzeitig (App Builder: Capacity Field) ist gesetzt, aber ein Feld für Start- oder Endzeit der Buchung ist leer. Die Kapazität ließe sich so nicht durchsetzen.

Lösung

  1. Setzen Sie sowohl Beginnt um als auch Endet um (App Builder: Booking Start Time Field und Booking End Time Field), oder
  2. leeren Sie Wie viele gleichzeitig.

Ich kann keinen weiteren Termin wählen

Warum: Die Komponente hat ein Terminlimit: Max Dates Allowed (Maximal zulässige Daten).

Lösung

  1. Heben Sie die Auswahl eines Termins auf, um einen anderen zu wählen, oder
  2. erhöhen Sie das Limit, oder setzen Sie es auf 0 für kein Limit.

Ich kann keine weitere Zeit buchen

Warum: Ein Buchungslimit ist erreicht. Max Time Slots begrenzt die Zeitfenster insgesamt, Max Bookings per Day die einzelnen Buchungen an einem Tag (direkt aufeinanderfolgende Zeiten zählen als eine), und Limit per Person die anstehenden Buchungen eines Kunden, gezählt auf dem Server.

Lösung

  1. erhöhen Sie das Limit, oder setzen Sie es auf 0 für kein Limit.
  2. Mitarbeitende können „Limit pro Person“ nach einer Bestätigung überschreiten. Website-Besucher nicht.

Einige Tage oder Uhrzeiten sind ausgegraut

Warum: Eine Buchungsregel sperrt sie. Minimum Notice (Hours) / Mindestvorlauf (Stunden) sperrt alles, was zu bald beginnt, Book Up To (Days Ahead) / Buchbar bis (Tage im Voraus) sperrt Tage jenseits des rollierenden Zeitraums, und frühestes oder spätestes wählbares Datum, gesperrte Tage und die Geschäftszeiten jeder Ressource sperren den Rest.

Lösung

  1. Prüfen Sie diese Einstellungen an der Komponente oder ihrer Konfiguration. Mit 0 sind Vorlauf und Zeitraum ausgeschaltet.
  2. Klicken Sie auf ein gesperrtes Zeitfenster: Ein Hinweis sagt, warum es geschlossen ist.

Das Zeitfenster direkt nach einer Buchung erscheint als belegt

Warum: Buffer Between Bookings (Minutes) / Puffer zwischen Buchungen (Minuten) hält nach jeder Buchung auf derselben Ressource Zeit frei, zum Aufräumen oder Umrüsten.

Lösung

  1. Verringern Sie den Puffer, oder setzen Sie ihn auf 0 für Buchungen direkt hintereinander.
  2. Wenn eine Zeit belegt ist gilt weiterhin: Mit Kollidierende Zeitfenster überspringen wird ein Puffertreffer übersprungen und wie jede andere Überschneidung gemeldet.

Nur einige Startzeiten erscheinen

Warum: Nur diese Zeiten ist gesetzt, daher bietet das Raster nur die aufgeführten Startzeiten an. Bei Resource Booking übernimmt Eigene Zeiten jeder Ressource, wenn ein Raum oder eine Person eine eigene Liste hat. Geschäftszeiten, Schließungen, Mindestvorlauf und Konflikte sperren eine aufgeführte Zeit trotzdem.

Lösung

  1. Bearbeiten Sie die Liste, oder wählen Sie Jedes Intervall, an der Komponente oder in ihrer Konfiguration.
  2. Prüfen Sie die eigene Liste der Ressource in ihrem Feld Eigene Zeiten jeder Ressource.

„Diese Auswahl liegt nicht mehr im Buchungszeitraum“

Warum: Die Seite war so lange offen, dass der gewählte Tag oder die Uhrzeit inzwischen in den Mindestvorlauf fällt. Beim Speichern wird die Regel erneut geprüft, damit eine veraltete Seite nicht zu kurzfristig bucht.

Lösung

  1. Entfernen Sie die Termine, die die Meldung nennt, oder wählen Sie eine spätere Uhrzeit.
  2. Speichern Sie erneut.

„Buchung nicht möglich. Bereits ausgebucht oder geschlossen am: 3. Dez.“ oder „Bereits ausgebucht oder geschlossen, daher beim Speichern übersprungen“

Warum: Eine andere Buchung belegt diese Zeit bereits, oder eine Schließung deckt sie ab. Wenn eine Zeit belegt ist entscheidet, was passiert: Blockieren lehnt den ganzen Klick ab, Kollidierende Zeitfenster überspringen bucht die anderen Tage und nennt die ausgelassenen, und Zulassen (trotzdem buchen) bietet die Schaltfläche Trotzdem buchen an.

Lösung

  1. Entfernen Sie die Termine, die die Meldung nennt, oder wählen Sie eine andere Zeit oder Ressource.
  2. Ein Admin kann Wenn eine Zeit belegt ist in den Buchungsregeln der Konfiguration ändern.

„Tageslimit erreicht (2 von 2)“

Warum: Höchstens Buchungen pro Tag (App Builder: Daily Limit Field) ist eine Zahl an jedem Raum oder jeder Person, etwa 2 Einsätze pro Tag für einen Techniker. Hat ein Tag so viele Buchungen, ist er für diese Ressource geschlossen, und ein Speichern dort meldet Tageslimit erreicht, daher wurde nichts gespeichert. Jeder Datensatz zählt einmal, eine Buchung über mehrere Tage zählt an jedem Tag, und Status, die die Zeit freigeben, zählen nie.

Lösung

  1. Wählen Sie einen anderen Tag oder eine andere Ressource.
  2. Erhöhen Sie die Zahl am Ressourcendatensatz, oder lassen Sie sie leer für kein Limit.
  3. Ist Wenn eine Zeit belegt ist auf Zulassen (trotzdem buchen) gesetzt, kann eine Buchung das Limit überschreiten.

„Garden Room nimmt keine Buchungen an, daher wurde nichts gespeichert“

Warum: Wie viele gleichzeitig oder Höchstens Buchungen pro Tag steht bei der Ressource auf 0. Eine 0 heißt, dass sie überhaupt keine Buchungen annimmt, bei jeder Einstellung von Wenn eine Zeit belegt ist. Die Auswahlfelder, das Zeitraster und die Ansicht Woche grauen sie aus.

Lösung

  1. Wählen Sie eine andere Ressource.
  2. Um sie für Buchungen zu öffnen, setzen Sie die Zahl an ihrem Datensatz auf 1 oder mehr, oder lassen Sie sie leer für kein Limit.

„Diese Daten liegen in der Vergangenheit und können nicht gebucht werden“ oder „Diese Uhrzeiten sind bereits vorbei“

Warum: Der Kalender bucht keine Tage oder Uhrzeiten, die schon vorbei sind. Ein Tag, der gestern auf einer über Nacht offenen Seite gewählt wurde, oder eine Uhrzeit früher am heutigen Tag wird beim Speichern abgelehnt.

Lösung

  1. Entfernen Sie die Termine oder Uhrzeiten, die die Meldung nennt, und wählen Sie spätere.
  2. Müssen Sie vergangene Tage erfassen, etwa für Stundenzettel? Ein Admin kann Vergangene Daten zulassen in der Konfiguration einschalten.

„Diese Daten sind geschlossen: 25. Dez. Wählen Sie ein anderes Datum oder eine andere Uhrzeit.“

Warum: Eine Schließung deckt den Tag ab: ein Datensatz in der Liste geschlossener Tage des Kalenders, etwa ein Feiertag oder Mitarbeiterurlaub. Eine Schließung, die einen Raum oder eine Person nennt, schließt nur diese Ressource. Kalender und Speichern lehnen den Tag beide ab.

Lösung

  1. Wählen Sie ein anderes Datum oder eine andere Uhrzeit.
  2. Soll der Tag offen sein, bearbeiten oder löschen Sie den Schließungsdatensatz, oder grenzen Sie Nur Schließungen mit in der Konfiguration ein.

„Garden Room kann in diesem Kalender nicht gebucht werden. Wählen Sie eine Ressource aus der Liste.“

Warum: Der Raum oder die Person steht nicht in der Liste dieses Kalenders, weil Nur anzeigen, wenn sie ausschließt. Das passiert oft, wenn sich ein Datensatz nach dem Öffnen der Seite geändert hat, zum Beispiel ein Raum, der auf inaktiv gesetzt wurde. Der Server lehnt sie beim Speichern, Verschieben und Neuzuweisen ab.

Lösung

  1. Laden Sie die Seite neu und wählen Sie eine Ressource aus der Liste.
  2. Soll sie angeboten werden, aktualisieren Sie den Ressourcendatensatz, oder ändern Sie Nur anzeigen, wenn in der Konfiguration.

„Die ausgewählten Ressourcen haben keine gemeinsame Startzeit“

Warum: Mit Mehrere auf einmal buchen muss eine Zeit für jeden gewählten Raum und jede gewählte Person passen. Ihre Geschäftszeiten oder eigenen Startzeiten überschneiden sich nicht, daher passt keine Zeit für alle. Eine kürzere Meldung, Die ausgewählten Ressourcen haben keine überlappenden Geschäftszeiten, bedeutet dasselbe.

Lösung

  1. Wählen Sie weniger Ressourcen oder solche mit denselben Arbeitszeiten.
  2. Ein Admin kann die Öffnungszeiten und eigenen Startzeiten jeder Ressource prüfen.

Zwei Personen haben dieselbe Zeit gebucht

Warum: Eine von zwei Einstellungen lässt es zu. Wenn eine Zeit belegt ist auf Zulassen (trotzdem buchen) erlaubt Mitarbeitenden, absichtlich über eine belegte Zeit zu buchen. Oder Filter bestimmt auch, was belegt ist ist eingeschaltet, mit einem Filter, der ME verwendet, sodass nur die eigenen Buchungen jeder Person eine Zeit belegen. Vor dem zweiten Fall warnt der Assistent: „Filter bestimmt auch, was belegt ist“ ist eingeschaltet und „Nur Datensätze mit“ verwendet ME. Deshalb belegen nur die eigenen Buchungen jeder Person eine Zeit: Zwei Personen können dieselbe Zeit buchen.

Lösung

  1. Setzen Sie Wenn eine Zeit belegt ist auf Blockieren oder Kollidierende Zeitfenster überspringen.
  2. Schalten Sie Filter bestimmt auch, was belegt ist aus, außer jede Person bucht wirklich nur ihre eigene Zeit.

„Limit pro Person ist aktiviert, aber es ist kein Kundenfeld festgelegt“

Warum: Limit pro Person zählt die Buchungen jedes Kunden über Für wen (App Builder: Client Field). Ist kein Feld gesetzt oder eines, das Salesforce nicht durchsuchen kann, etwa langer Text, lässt sich eine Buchung nicht zählen, und das Speichern wird abgelehnt. Admins sehen im App Builder Limit pro Person kann Buchungen nicht nach Notes zählen.

Lösung

  1. Öffnen Sie die Konfiguration im Einrichtungsassistenten und wählen Sie unter Für wen ein Text-, E-Mail- oder Nachschlagefeld.
  2. Oder setzen Sie Limit pro Person auf 0, um es auszuschalten.

„Salesforce hat nicht geantwortet, daher ist diese Buchung möglicherweise bereits gespeichert“

Warum: Nach dem Klick auf Buchen brach die Verbindung ab oder Salesforce war langsam, daher konnte der Kalender nicht erkennen, ob das Speichern abgeschlossen wurde. Er lädt sich selbst neu, damit Sie es sehen.

Lösung

  1. Suchen Sie die Buchung im neu geladenen Kalender.
  2. Buchen Sie nur dann erneut, wenn sie nicht da ist.

Gäste öffentlicher Sites

Kalender auf einer öffentlichen Experience Cloud-Site, auf der Besucher ohne Anmeldung buchen.

Gäste sehen einen leeren Kalender

Warum: Die Freigaberegel für Gäste greift noch nicht, oder im Gastprofil fehlt ein Schritt.

Lösung

  1. Setzen Sie die externe organisationsweite Standardeinstellung des Objekts auf Privat und klicken Sie dann in Setup, Freigabeeinstellungen auf Neu berechnen.
  2. Weisen Sie dem Gastbenutzer den Berechtigungssatz MultiDatePick - Guest zu und geben Sie ihm Lesen auf jedes Ihrer eigenen Objekte und Felder.
  3. Veröffentlichen Sie die Site nach jeder Änderung. Eine inaktive Site zeigt Gästen nichts.

Die vollständige Gast-Checkliste mit sechs Schritten steht unter App-, Start- & Experience-Seiten. Meine Site prüfen im Einrichtungsassistenten testet jeden Schritt für Sie.

„Meine Site prüfen“ meldet „Korrektur nötig“

Warum: Meine Site prüfen testet in den Schritten Prüfen und Fertig des Einrichtungsassistenten für einen Site-Kalender die Site so, wie ein Gast sie erlebt. Jede Zeile mit Korrektur nötig ist ein fehlender Schritt und nennt, was zu tun ist.

Lösung

  1. Die Site ist noch nicht live: Gehen Sie in den Arbeitsbereichen der Site zu Verwaltung, Einstellungen, klicken Sie auf Aktivieren und veröffentlichen Sie dann.
  2. Berechtigungssatz MultiDatePick - Guest: Öffnen Sie den Gastbenutzer und fügen Sie ihn unter Berechtigungssatzzuweisungen hinzu.
  3. Objektzugriff oder Feldzugriff: Geben Sie dem Gastbenutzer Lesen auf das, was der Kalender anzeigt, und Bearbeiten auf das, was eine Buchung speichert.
  4. Ein Gast sieht keine der Ressourcen: Fügen Sie unter Setup, Freigabeeinstellungen eine Freigaberegel für Gastbenutzer auf dem Ressourcenobjekt hinzu.

Nur ein Admin mit MultiDatePick - Setup kann die Prüfung ausführen.

„Diese Org hat noch keine Experience Cloud-Site“

Warum: Meine Site prüfen hat keine Site zum Prüfen gefunden, daher gibt es keine Site zur Auswahl. Die vollständige Meldung lautet Diese Org hat noch keine Experience Cloud-Site. Aktivieren Sie „Digitale Erlebnisse“ im Setup und erstellen Sie eine Site, dann prüfen Sie sie hier. Die Konfiguration selbst ist in Ordnung und lässt sich speichern.

Lösung

  1. Suchen Sie im Setup nach Digitale Erlebnisse, öffnen Sie Einstellungen und aktivieren Sie Digitale Erlebnisse aktivieren. Salesforce kann das nicht wieder ausschalten.
  2. Erstellen Sie die Site unter Digitale Erlebnisse, Alle Sites, Neu.
  3. Öffnen Sie die Konfiguration erneut im Einrichtungsassistenten und klicken Sie im Schritt Prüfen auf Meine Site prüfen.

„Dieser Kalender kann hier nicht speichern: Er nennt keine gespeicherte Konfiguration für dieses Objekt“

Warum: Die Buchung eines Site-Gasts oder Portalbenutzers wird auf dem Server gegen eine gespeicherte Konfiguration geprüft, damit sich Datenschutz- und Buchungsregeln nicht umgehen lassen. Der Kalender auf der Site-Seite hat keinen Config Name, während für das Objekt bereits eine gespeicherte Konfiguration existiert.

Lösung

  1. Öffnen Sie die Site-Seite im Experience Builder.
  2. Setzen Sie Config Name des Kalenders auf die Konfiguration, die für diese Site gespeichert ist, und veröffentlichen Sie dann.

„Dieser Kalender kann hier nicht verwendet werden: Seine gespeicherte Konfiguration ist nicht für eine öffentliche Website eingerichtet“

Warum: Die Site-Seite nennt eine Konfiguration, die für Mitarbeitende gebaut ist. Site-Gäste und Portalbenutzer dürfen nur eine Konfiguration nutzen, die für eine Site gespeichert ist, damit Datenschutz und Regeln eines Mitarbeiterkalenders nie versehentlich die Öffentlichkeit erreichen.

Lösung

  1. Setzen Sie Config Name des Kalenders auf eine für die Site gespeicherte Konfiguration, oder
  2. legen Sie eine an: Beantworten Sie im Einrichtungsassistenten Wo soll dieser Kalender angezeigt werden? mit Auf einer öffentlichen Website und speichern Sie sie unter einem neuen Namen.

„Diese Seite verknüpft Buchungen mit einem Datensatz, den Besucher der Site nicht sehen dürfen“

Warum: Jede Buchung von der Site wird mit einem Datensatz verknüpft, festgelegt in Buchungen gehören zu, und der Gastbenutzer darf ihn nicht lesen. Salesforce hält Datensätze vor Gästen privat, solange keine Freigaberegel für Gastbenutzer sie freigibt.

Lösung

  1. Fügen Sie unter Setup, Freigabeeinstellungen auf dem Objekt dieses Datensatzes eine Freigaberegel für Gastbenutzer hinzu, die ihn für den Gastbenutzer der Site freigibt, Schreibgeschützt.
  2. Führen Sie Meine Site prüfen erneut aus: Datensatz, zu dem Buchungen gehören sollte jetzt bestehen.

„Auf dieser öffentlichen Seite nicht gespeichert“

Warum: Salesforce erlaubt Site-Gästen, Datensätze zu lesen und zu erstellen, aber nie, sie zu ändern oder zu löschen. Besucher können ansehen und buchen. Angemeldete Benutzer mit Zugriff können bearbeiten.

Lösung

  1. Nichts zu beheben: Das ist die Gastregel von Salesforce. Damit Personen ihre eigenen Buchungen ändern können, geben Sie ihnen eine Anmeldung (eine Mitglieder-Site), oder lassen Sie Mitarbeitende die Änderung vornehmen.

„Jede Buchung in diesem Kalender dauert 60 Minuten, daher kann diese Zeit nicht gebucht werden“

Warum: Bei Site-Gästen und Portalbenutzern prüft der Server jede Buchung gegen die gespeicherte Konfiguration: Buchungsdauer, Nur diese Zeiten, die wählbaren Status, Vorlauf, Buchungszeitraum und Limits. Die Seite war offen, während der Admin eine dieser Einstellungen geändert hat, daher bot sie etwas an, das die Konfiguration nicht mehr erlaubt. Verwandt: Dieser Kalender nimmt Buchungen nur zu den aufgeführten Startzeiten an und Der Status Requested kann in diesem Kalender nicht gewählt werden.

Lösung

  1. Laden Sie die Seite neu und buchen Sie erneut.
  2. Weiterhin abgelehnt? Der Admin der Site kann diese Regeln in der Konfiguration prüfen, die in Config Name steht.

Site-Mitglieder sehen ihre eigenen Datensätze nicht

Warum: Freigaben in Experience Cloud. Site-Benutzer sehen nur Datensätze, die ihnen per Freigabe zugänglich sind.

Lösung

  1. Legen Sie auf dem Objekt, in dem die Termine gespeichert werden, eine Freigaberegel an (oder einen Freigabesatz für Mitglieder), oder
  2. öffnen Sie seine externe organisationsweite Standardeinstellung.

„Die Site lässt sich nicht von anderen Websites anzeigen“

Warum: Sie haben den Kalender mit dem Einbettungscode auf Ihrer eigenen Website eingebunden, und die Salesforce-Site lässt sich standardmäßig nicht in einer anderen Website anzeigen.

Lösung

  1. Öffnen Sie im Experience Builder die Einstellungen, dann Sicherheit und Datenschutz.
  2. Setzen Sie Clickjack Protection Level auf Allow framing of site pages on external domains.
  3. Fügen Sie Ihre Website unter Trusted Domains for Inline Framing hinzu und veröffentlichen Sie dann.

Gäste sehen die Liste der Standorte, aber keine Karte

Warum: Die Karte stammt von einem Salesforce-Dienst, den die Site blockiert, bis er als vertrauenswürdig eingetragen ist. Der Kalender kann nicht erkennen, ob eine Site ihn blockiert, daher öffnet er auf einer Site mit der Liste und bietet die Karte an.

Lösung

  1. Öffnen Sie im Experience Builder die Einstellungen, dann Sicherheit und Datenschutz.
  2. Fügen Sie maps.a.forceusercontent.com als vertrauenswürdige Site für Frames hinzu und veröffentlichen Sie dann.

Berechtigungen und Sicherheit

Der Kalender läuft mit den Berechtigungen des jeweiligen Benutzers. Beginnen Sie mit dem passenden Berechtigungssatz und geben Sie dann Zugriff auf Ihre eigenen Objekte und Felder.

BerechtigungssatzZuweisen an
MultiDatePick - UserAlle, die die Kalender nutzen
MultiDatePick - SetupAdmins, die Konfigurationen erstellen. Enthält den Einrichtungsassistenten.
MultiDatePick - All AccessAdmins, die sie erstellen und nutzen
MultiDatePick - GuestDen Gastbenutzer einer öffentlichen Experience Cloud-Site

Fehlermeldungen nennen, was falsch ist: das Feld, das Objekt oder die Validierungsregel. Endet eine Meldung mit Details:, ist der Text die Beschreibung von Salesforce selbst. Schicken Sie ihn an Ihren Admin oder an uns, dann ist klar, wo genau zu suchen ist.

„Sie benötigen eine MultiDatePick-Lizenz, um diesen Kalender zu verwenden“

Warum: MultiDatePick wird pro Benutzer lizenziert, und diesem Benutzer ist keine Lizenz zugewiesen. Der Kalender wird durch diesen Hinweis ersetzt, und Speichern wird abgelehnt. Site-Gäste brauchen nie eine Lizenz.

Lösung

  1. Öffnen Sie im Setup Installierte Pakete und dann Lizenzen verwalten neben MultiDatePick.
  2. Klicken Sie auf Benutzer hinzufügen und fügen Sie den Benutzer hinzu. Beim nächsten Laden der Seite sieht er den Kalender.

„Dieser Benutzer hat keinen Zugriff auf MultiDatePick, daher wurde die Konfiguration nicht geladen“

Warum: Der Benutzer hat keinen MultiDatePick-Berechtigungssatz, daher lässt Salesforce den Kalender seine Klassen für ihn nicht ausführen. Das rote Banner zeigt es, mit dem Originaltext von Salesforce im grauen Kasten.

Lösung

  1. Weisen Sie dem Benutzer MultiDatePick - User zu, oder MultiDatePick - All Access einem Admin, der auch Konfigurationen erstellt.
  2. Auf einer öffentlichen Site weisen Sie dem Gastbenutzer der Site MultiDatePick - Guest zu.

„You do not have access to the Apex class named 'MultiDatePickConfigDeployer'“

Warum: Das ist der Originaltext von Salesforce, und er bedeutet einen fehlenden Berechtigungssatz: Der Benutzer hat keinen MultiDatePick-Berechtigungssatz, daher lässt Salesforce den Kalender seine Klassen nicht ausführen. Der Klassenname hängt davon ab, was der Kalender gerade tat. Die Zeile steht meist im grauen Kasten unter dem roten Banner, unterhalb von Dieser Benutzer hat keinen Zugriff auf MultiDatePick.

Lösung

  1. Weisen Sie dem Benutzer MultiDatePick - User zu, oder MultiDatePick - All Access einem Admin, der auch Konfigurationen erstellt.
  2. Auf einer öffentlichen Site weisen Sie dem Gastbenutzer der Site MultiDatePick - Guest zu.
  3. Laden Sie die Seite neu.

Der Datensatz öffnet sich nicht, oder „Unzureichende Berechtigungen“

Warum: Der Benutzer darf das übergeordnete Objekt nicht lesen, oder Freigaben verbergen diesen Datensatz vor ihm. Bei einem Bildschirm-Flow darf der Benutzer womöglich keine Flows ausführen.

Lösung

  1. Weisen Sie MultiDatePick - User zu.
  2. Geben Sie in einem Berechtigungssatz Lesen auf das übergeordnete Objekt.
  3. Prüfen Sie, ob der Benutzer diesen Datensatz per Freigabe sehen darf.
  4. Bei einem Bildschirm-Flow aktivieren Sie Flow-Benutzer (Flow User) im Benutzerdatensatz oder geben die Benutzerberechtigung Flows ausführen (Run Flows) in einem Berechtigungssatz.

„Kein Lesezugriff auf das Feld X am Objekt Y“

Warum: Der Benutzer hat keine Lese-Berechtigung (Sicherheit auf Feldebene) für ein Feld, das der Kalender anzeigt: ein Status-, Hover-, Datums- oder Zeitfeld.

Lösung

  1. Gewähren Sie Lesen auf das Feld, das in der Meldung steht.
  2. Auch für Admins. Ein neues benutzerdefiniertes Feld ist für alle verborgen, Systemadministratoren eingeschlossen, bis ein Berechtigungssatz es freigibt.

„Time group failed to save“, „Buchungen konnten nicht erstellt werden“ oder „Sie können das Feld … nicht bearbeiten“ mit einem Feldnamen

Warum: Der Benutzer darf die Felder lesen, aber eines, das beim Speichern geschrieben wird, nicht bearbeiten. Oft ein Status-, eine zweite Auswahlliste oder ein Zeitfeld, das später hinzukam, oder ein Feld, das an jedem neuen Datensatz automatisch ausgefüllt wird.

Lösung

  1. Gewähren Sie Bearbeiten auf jedes Feld, das der Kalender schreibt: Datum, Start- und Endzeit, Status, zweite Auswahlliste, Namensfeld, das Lookup auf den übergeordneten Datensatz und jedes Feld in Automatisch ausfüllen.
  2. Gewähren Sie Erstellen auf das Objekt, in dem die Datensätze gespeichert werden.

„Sie haben keine Berechtigung dafür“ mit „insufficient access rights on cross-reference id“

Warum: Der neue Datensatz verweist auf einen Datensatz, den der Benutzer nicht sehen darf: den übergeordneten Datensatz oder die Ressource.

Lösung

  1. Geben Sie mindestens Lesen auf das übergeordnete Objekt und das Ressourcenobjekt sowie Freigaben für diese Datensätze.
  2. Lassen Sie Gäste auf einer öffentlichen Site über ein benutzerdefiniertes Objekt buchen. Salesforce schränkt den Gastzugriff auf Kontakte und Accounts ein.

„Sie haben keinen Zugriff auf die Schließungen, die dieser Kalender verwendet“

Warum: Der Benutzer darf das Objekt mit den geschlossenen Tagen nicht lesen, daher kann der Kalender nicht erkennen, welche Tage geschlossen sind. Die Schwestermeldung Sie haben keinen Zugriff auf die Datensätze, die dieser Kalender anzeigt bedeutet dasselbe für die Buchungen selbst.

Lösung

  1. Geben Sie in einem Berechtigungssatz Lesen auf das Objekt und die Felder, auf die die Meldung verweist.
  2. Prüfen Sie, ob Freigaben dem Benutzer diese Datensätze zugänglich machen.

„Sie können keine Visit-Datensätze vom Datensatztyp Install erstellen“

Warum: Der Kalender gibt neuen Buchungen einen Datensatztyp, den das Profil oder die Berechtigungssätze dieses Benutzers nicht enthalten.

Lösung

  1. Fügen Sie den Datensatztyp dem Profil des Benutzers oder einem Berechtigungssatz hinzu.
  2. Oder setzen Sie Datensatztyp neuer Buchungen auf Personen wählen lassen. Dann stehen nur die Typen zur Wahl, die die jeweilige Person erstellen darf.

„Salesforce hat nicht erlaubt, diesen Datensatz (Visit) Alex Chen zuzuweisen“

Warum: Der Raum oder die Person der Buchung ist ein Salesforce-Benutzer, und Salesforce hat abgelehnt, ihn zum Inhaber zu machen. Die Meldung endet mit dem Grund: Sie haben keinen Zugriff, um ihm Datensätze zuzuweisen, der Benutzer ist inaktiv, oder sein Benutzertyp kann diese Art von Datensatz nicht besitzen.

Lösung

  1. Wählen Sie eine andere Person.
  2. Oder bitten Sie Ihren Salesforce-Administrator um Zugriff, um diesem Benutzer Datensätze zuzuweisen, oder darum, den Benutzer zu aktivieren.

„Sie haben keine Berechtigung, MultiDatePick-Konfigurationen zu speichern“

Warum: Konfigurationen werden als Salesforce-Metadaten gespeichert, was die Berechtigung „Modify Metadata Through Metadata API Functions“ erfordert. Der Berechtigungssatz MultiDatePick - Setup gewährt sie.

Lösung

  1. Weisen Sie dem Admin, der Konfigurationen erstellt, MultiDatePick - Setup oder MultiDatePick - All Access zu.

Flows und Aktionen

Der Kalender in einem Bildschirm-Flow (Screen Flow) und Schaltflächen, die einen Flow starten.

Ein Flow-Bildschirm ignoriert meine Einstellungen aus dem Assistenten

Warum: Config Name ist leer oder falsch geschrieben. Ist es leer, nutzt die Komponente stillschweigend ihre Standardwerte. Ist es falsch geschrieben, meldet sie „Keine Konfiguration namens … gefunden“.

Lösung

  1. Setzen Sie Config Name exakt auf den Namen, unter dem der Einrichtungsassistent die Konfiguration gespeichert hat.
  2. Lassen Sie die Ein/Aus-Eingaben unberührt. Jedes Kontrollkästchen kommt aus der Konfiguration.

„Einige gewählte Daten sind noch nicht gespeichert. Klicken Sie auf Speichern oder entfernen Sie sie, bevor Sie fortfahren.“

Warum: Die Schaltfläche Weiter des Bildschirms wurde gedrückt, während der Kalender noch Auswahlen enthielt, die nie gespeichert wurden und sonst verloren gingen. Bei Zeiten lautet die Meldung Einige gewählte Zeiten sind noch nicht gebucht.

Lösung

  1. Klicken Sie zuerst auf Speichern (oder Buchen), dann auf Weiter.
  2. Oder entfernen Sie die nicht gewünschten Auswahlen, dann Weiter.

„Send Reminder kann nicht ausgeführt werden: Dafür brauchen Sie die Berechtigung "Run Flows" oder Zugriff auf den Flow“

Warum: Die Aktionsschaltfläche des Kalenders startet einen Flow, und Salesforce lässt ihn nur von Personen starten, die diesen Flow ausführen dürfen.

Lösung

  1. Geben Sie dem Benutzer in einem Berechtigungssatz die Berechtigung Flows ausführen (Run Flows), oder
  2. geben Sie seinem Profil oder Berechtigungssatz Zugriff auf diesen Flow (Setup, Flows, der Flow, Zugriff bearbeiten).

„Der Flow wurde mit einem Fehler beendet“ oder „Diese Aktion ist hier nicht verfügbar“

Warum: Die erste Meldung heißt, dass der Flow hinter einer Aktionsschaltfläche lief und fehlschlug. Die zweite heißt, dass die Schaltfläche für diesen Datensatz nicht mehr angeboten wird: Die Aktion wurde aus der gespeicherten Konfiguration entfernt, oder sie gilt für andere Status.

Lösung

  1. Bei einem Flow-Fehler öffnet ein Admin den Ausführungsverlauf oder das Debug-Protokoll des Flows, um zu sehen, welcher Schritt fehlschlug.
  2. Bei einer nicht verfügbaren Aktion laden Sie die Seite neu und prüfen dann die Status der Aktion in den Aktionen der Konfiguration.

„Dieser Flow hat keine Eingabevariable recordId oder recordIds“

Warum: Der Einrichtungsassistent übergibt den angeklickten Datensatz an den Flow einer Aktion in einer Variable namens recordId (ein Datensatz) oder recordIds (mehrere, aus dem Bearbeitungsmodus). Ohne eine davon weiß der Flow nicht, welche Datensätze er verwenden soll.

Lösung

  1. Fügen Sie im Flow Builder eine Textvariable namens recordId oder eine Textsammlung namens recordIds hinzu, die für die Eingabe verfügbar ist.
  2. Speichern und aktivieren Sie den Flow und wählen Sie ihn dann im Assistenten erneut aus.

Gantt-Diagramm

Aufgaben, ihre Verknüpfungen und der Fortschritt in der Gantt-Ansicht.

Die Gantt-Ansicht fehlt in der Ansichtsauswahl

Warum: Die Gantt-Ansicht muss eigens eingeschaltet werden, wie die Kartenansicht. Ist Available Views (Verfügbare Ansichten) leer, werden Calendar, Timeline, Week, Utilization und Agenda angeboten.

Lösung

  1. Aktivieren Sie im Einrichtungsassistenten auf der Registerkarte Ansichten Gantt-Ansicht anbieten, oder ergänzen Sie gantt in Available Views (Verfügbare Ansichten).
  2. Damit der Kalender mit ihr öffnet, setzen Sie View (Ansicht) auf gantt.

„Site survey kann nicht auf den 6. Dez. gelegt werden: Dieser Kalender lässt diesen Tag nicht zu. Es wurde nichts gespeichert.“

Warum: Das Gantt-Diagramm folgt denselben Buchungsregeln wie der Kalender. Eine Aufgabe lässt sich nicht auf einen geschlossenen Tag oder eine geschlossene Zeit verschieben, nicht zu einer Person, die an dem Tag schon an einer anderen Aufgabe arbeitet, und nicht zu einer Ressource, die keine Buchungen annimmt. Die Meldung nennt jedes Mal die Regel.

Lösung

  1. Ziehen Sie die Aufgabe auf einen anderen Tag, oder geben Sie sie jemandem, der frei ist.
  2. Soll der Tag offen sein, prüft ein Admin die Schließungen und die wählbaren Tage in der Konfiguration.

„Install kann nicht auf Testing warten, das ergäbe eine Schleife“

Warum: Testing wartet bereits auf Install, direkt oder über andere Aufgaben, und eine Verknüpfung in die andere Richtung hieße, dass keine von beiden beginnen könnte. Eine verwandte Frage, Verknüpfung ersetzen?, erscheint, wenn Aufgaben über ein Feld an der Aufgabe verknüpft sind: Dann kann jede Aufgabe nur auf eine andere warten.

Lösung

  1. Entfernen Sie zuerst die Verknüpfung in die andere Richtung, oder verknüpfen Sie eine andere Aufgabe.
  2. Damit eine Aufgabe auf mehrere warten kann, verknüpfen Sie Aufgaben über ein eigenes Verknüpfungsobjekt: Einrichtungsassistent, Gantt-Ansicht, Verknüpfungen zwischen Aufgaben.

„Der Status bleibt unverändert“ oder „Erledigt bleibt unverändert, nicht 100 %“

Warum: Status für eine erledigte Aufgabe verbindet Prozent erledigt und Status: Eine Aufgabe auf 100 % bekommt diesen Status, und eine Aufgabe mit diesem Status wird auf 100 % gesetzt. Kann der Betrachter eines der beiden Felder nicht bearbeiten oder bietet das Statusfeld den Wert nicht an, wird nur seine eigene Änderung gespeichert, und diese Meldung sagt, warum.

Lösung

  1. Geben Sie dem Benutzer Bearbeiten auf das Feld Prozent erledigt und auf das Statusfeld.
  2. Prüfen Sie, ob das Statusfeld den gewählten Wert für diesen Datensatztyp anbietet, oder wählen Sie in den Einstellungen der Gantt-Ansicht einen anderen, oder lassen Sie die Einstellung leer, um beide getrennt zu halten.

„Nichts gespeichert. Für Sie schreibgeschützt: Site survey“

Warum: Der Betrachter sieht die Aufgabe, darf sie aber nicht bearbeiten, wegen Freigaben, Feldsicherheit oder des Datensatzinhabers. Ihre Karte zeigt Für Sie schreibgeschützt.

Lösung

  1. Bitten Sie den Inhaber der Aufgabe oder einen Admin, Ihnen über Freigaben Bearbeitungszugriff zu geben.
  2. Prüfen Sie in Ihrem Berechtigungssatz Bearbeiten auf den Datumsfeldern der Aufgabe.

Konfigurationsimport

Eine Konfiguration aus der Config Library oder einer anderen Org in die Registerkarte Importieren / Exportieren des Einrichtungsassistenten einfügen.

„Das ist keine vollständige Konfiguration“ oder „Dies sieht aus wie XML, nicht wie JSON“

Warum: Der eingefügte Text ist keine vollständige Konfiguration. Er wurde beim Kopieren abgeschnitten, es ist Salesforce-Metadaten-XML oder ein Flow statt des JSON der Konfiguration, oder er enthält eine ganze Datei mit Konfigurationen (über 100 KB).

Lösung

  1. Kopieren Sie die Konfiguration erneut mit der Kopierschaltfläche der Config Library oder mit Konfiguration exportieren in der anderen Org.
  2. Fügen Sie den ganzen Text ein, von der ersten { bis zur letzten }.

Sie haben Flow-XML? Stellen Sie es stattdessen als Flow bereit: Einen Flow aus VS Code bereitstellen.

„Diese Konfiguration funktioniert nicht ohne Related_Object__c“

Warum: In der eingefügten Konfiguration fehlt eine Einstellung, die jede Konfiguration braucht, etwa das Objekt, das Datumsfeld oder der Komponententyp.

Lösung

  1. Kopieren Sie die Konfiguration erneut vollständig, oder
  2. exportieren Sie eine funktionierende Konfiguration aus Ihrer Org, um die nötige Form zu sehen, und ergänzen Sie die fehlenden Einstellungen.

Eine Einstellung „würde "Confirmed" speichern, das es in Visit Status nicht gibt, daher würde Salesforce jedes Speichern ablehnen“

Warum: Eine Einstellung in der importierten Konfiguration, etwa Automatisch ausfüllen oder Wählbare Status, verwendet einen Statuswert, den Ihr Statusfeld nicht enthält. So gespeichert, würde jede Buchung abgelehnt. Im Schritt Statuswerte zuordnen entfällt ein Wert mit dem Hinweis Ihr Feld hat keinen solchen Wert, bis Sie einen wählen.

Lösung

  1. Gehen Sie zurück zu Statuswerte zuordnen.
  2. Wählen Sie für jeden Wert, welcher Ihrer Werte dasselbe bedeutet, und klicken Sie dann auf Anwenden & bereitstellen.

„Der Flow Send_Reminder ist in dieser Org nicht vorhanden“

Warum: Die importierte Konfiguration hat eine Aktionsschaltfläche, die einen Flow startet, den Ihre Org nicht hat.

Lösung

  1. Wählen Sie im Schritt Aktionen einen Ihrer eigenen Flows für die Schaltfläche, oder wählen Sie Diese Aktion weglassen.
  2. Sie können die Aktion später in den Aktionen der Konfiguration hinzufügen.
