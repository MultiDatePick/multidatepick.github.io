So funktioniert der Import einer Konfiguration

Diese Beispielkonfigurationen sind auf die mitgelieferten Demo-Objekte von MultiDatePick (Schedule__c, Event__c, Resource__c) ausgelegt. Ihre Org verwendet fast immer eigene Objekte und Feldnamen. Das ist so vorgesehen und wird unterstützt.

  1. Für den Einrichtungsassistenten kopieren auf einer der Karten unten.
  2. Einfügen auf der Registerkarte Importieren des Einrichtungsassistenten (App Launcher, MultiDatePick Setup Wizard, Importieren).
  3. Felder zuordnen: Gibt es Objekte oder Felder aus dem JSON in Ihrer Org nicht, zeigt der Assistent einen Bereich Smart Field Mapping, der jeden fehlenden Verweis mit einem Dropdown passender Objekte bzw. Felder Ihrer Org auflistet. Wählen Sie jeweils den Ersatz und klicken Sie auf Anwenden & bereitstellen.
  4. Config Name verwenden: Platzieren Sie die Komponente auf einer Lightning-Seite, einer Experience Cloud-Site oder einem Flow-Bildschirm und geben Sie den Config Name ein.

Kein Code, kein XML-Bearbeiten. Der Assistent schreibt die Konfiguration vor der Metadaten-Bereitstellung mit Ihrer Auswahl um, sodass die importierte Konfiguration einsatzbereit für eine Datensatzseite in Ihrer Org ankommt. Passt schon alles (etwa beim Klonen zwischen Sandboxes), wird der Zuordnungsschritt automatisch übersprungen.

Keine passende Konfiguration dabei? Erstellen Sie eine im Assistenten.

Jedes Objekt und jedes Feld ist ein Dropdown, gefiltert auf Ihre Org, eine funktionierende Konfiguration dauert also ein paar Minuten und braucht keinen einzigen API-Namen.

Lieber in einem Bildschirm-Flow (Screen Flow)? Mit derselben Konfiguration.

Ziehen Sie die Komponente auf einen Flow-Bildschirm und geben Sie den Config Name ein. Für einen Flow, der einen Datensatz pro Termin oder Schicht speichert, siehe den Beitrag zu Flow-Schleifen.

Eine Konfiguration, fünf Ansichten

Jede Konfiguration unten legt eine Standard-Ansicht und eine Liste Available Views (Verfügbare Ansichten) fest. Daten, Felder und Speicherverhalten bleiben identisch: Nur das Layout ändert sich. Benutzer wechseln über die Schaltflächen über dem Kalender, und Sie entscheiden, welche sie bekommen.

calendar

Monatsraster

Der Standard. Ein Monat auf einmal, Statusfarben pro Tag, Termine per Klick oder Ziehen wählen. Am besten, wenn die Frage lautet: „Was ist am 14. los?“

timeline

Ressourcen untereinander, Tage nebeneinander

Standardmäßig zwei Wochen, damit jede Buchung Platz für ihren Namen hat. Mehrtägige Buchungen erscheinen als ein Balken. Ausgelastete Ressourcen klappen zu einer einzelnen Zeile zusammen, die Sie aufklappen können.

week

Tag nach Stunden

Sieben Tage nebeneinander, Ihre Geschäftszeiten untereinander. Ziehen Sie waagrecht, senkrecht oder beides, um einen Zeitblock über mehrere Tage auf einmal zu wählen.

utilization

Kapazitäts-Heatmap

Anteil der genutzten Kapazität pro Ressource und Tag, eingefärbt von Grün bis Rot. Braucht ein Capacity Field (Kapazitätsfeld), um Prozentwerte statt reiner Anzahlen zu zeigen.

agenda

Chronologische Liste

Die nächsten 60 Tage als flache, gut überblickbare Liste mit Uhrzeiten und Status. Gut für eine Übergabe, ein tägliches Briefing oder einen mobilen Bildschirm.

Beratertermine buchen

Die Person ist die Ressource. Jeder Berater, Vertriebsmitarbeiter, Consultant oder Account Manager wird zu einer buchbaren Zeile, sodass ein Kundentermin auf einen echten Salesforce-Benutzer statt auf einen Raum gebucht wird. Startet in der Woche, weil ein 30-Minuten-Termin eine Frage der Uhrzeit ist; die Zeitachse zeigt, wer diese Woche noch Luft hat, und die Agenda ist die chronologische Übersicht fürs Morgen-Meeting.

User als Ressource: Ressourcenobjekt ist User, gefiltert über ein benutzerdefiniertes Kontrollkästchen Is_Advisor__c, damit die Auswahl Berater enthält und nicht jeden aktiven Benutzer der Org. Geschäftszeiten-Startfeld und Geschäftszeiten-Endfeld am User geben jeder Person ihren eigenen Arbeitstag, sodass das Wochenraster die Stunden zeigt, die sie tatsächlich arbeitet. Konfliktverhalten ist block, denn eine Person darf nie doppelt gebucht sein.
Wichtige Einstellungen
  • Ressourcenobjekt User resourceObjectApiName
  • Ressourcenfilterfeld (optional) Is_Advisor__c resourceFilterField
  • Booking Resource Field (Buchungsressourcen-Feld) bookingResourceField
  • Zweites Auswahllistenfeld Meeting_Type__c secondStatusField
  • Conflict Behavior (Konfliktverhalten) block conflictBehavior
  • Objekt für gesperrte Daten blockedDatesSourceObject
  • Hover-Felder hoverFields

Anwendungsfälle für Unterblöcke

Ist Zeitspanne konsolidieren aktiviert, werden Lücken zwischen gewählten Zeitfenstern automatisch erkannt und als eigene Datensätze auf einem untergeordneten Objekt gespeichert. Benutzer können Zeitfenster auch manuell als Unterblock markieren.

  • Schichtplanung mit Pausen: Ein Mitarbeiter wählt 8 bis 17 Uhr; die Mittagslücke von 12 bis 13 Uhr legt automatisch einen Datensatz in einem Objekt Break__c an
  • Reisepläne: Der Benutzer blockt Reisezeiten; Umstiegszeiten zwischen Flügen werden zu Datensätzen in Travel_Leg__c
  • Schulungspläne: Die Lehrkraft wählt Unterrichtsblöcke; Freistunden zwischen den Sitzungen werden als Datensätze in Available_Slot__c gespeichert
  • Arbeitspläne mit Terminen: Die Führungskraft legt Arbeitszeiten fest; Lücken für Besprechungen oder Termine werden automatisch in einem Objekt Appointment__c gespeichert
Wichtig: Jede Konfiguration in dieser Library verwendet Beispielnamen für Objekte und Felder. Ersetzen Sie vor dem Import die orangefarbenen Werte durch die Objekt- und Feld-API-Namen Ihres Datensatzobjekts. Wenn Sie Unterblöcke nutzen, ersetzen Sie die violetten Werte durch Ihr untergeordnetes Objekt und dessen Felder. Wenn Sie gesperrte Termine nutzen, ersetzen Sie auch die roten Werte. Alles andere funktioniert unverändert.
