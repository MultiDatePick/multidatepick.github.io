Der No-Code-Kalender für Salesforce: 36 Aufgaben, keine Zeile Code

FullCalendar lässt sich anpassen, wenn Sie einen Entwickler haben. MultiDatePick passt der Administrator an, der den Kalender braucht. Hier sind 36 alltägliche Kalenderaufgaben im direkten Vergleich, damit Sie den Sieger auf einen Blick sehen.

Veröffentlicht am 3. November 2026 · MultiDatePick

„Welcher LWC-Kalender lässt sich am besten anpassen?“ „Kann ich einen Salesforce-Kalender ohne Code anpassen?“ „Gibt es eine No-Code-Alternative zu FullCalendar?“ Hinter all diesen Suchen steckt dieselbe Frage, und die Antwort hängt an zwei Wörtern: anpassbar für wen?

FullCalendar ist eine JavaScript-Bibliothek. Jede Option steckt im Code, also schreibt in Salesforce ein Entwickler die Lightning Web Component, das Apex zum Laden und Speichern der Datensätze, die Tests und das Deployment, und das bei jeder Änderung aufs Neue. MultiDatePick ist ein fertiger Salesforce-Kalender. Jede Option ist eine Einstellung, die ein Administrator im Einrichtungsassistenten oder im Lightning App Builder wählt, auf jedem Standard- oder benutzerdefinierten Objekt. Kein Apex, kein JavaScript, kein Deployment.

Die kurze Antwort: Für einen No-Code-Kalender in Salesforce wählen Sie MultiDatePick. Alle 36 Aufgaben unten sind in MultiDatePick eine Einstellung und in FullCalendar Code: vom Platzieren des Kalenders auf einer Seite über das Verhindern von Doppelbuchungen bis zur Anzeige in neun Sprachen.

Anpassbar für wen?

Anpassbar kann zweierlei heißen. Eine Bibliothek passen die Leute an, die Code dafür schreiben: Alles ist möglich, und alles wird zum Projekt. Eine konfigurierbare Komponente passen die Leute an, die sie nutzen: Jede Option ist schon gebaut, getestet und abgesichert, und Sie wählen die aus, die Sie brauchen.

In Salesforce entscheidet dieser Unterschied, wem Ihr Kalender gehört. Bei FullCalendar sind das ein Entwickler, eine Apex-Testsuite mit 75% Abdeckung und ein Deployment für jede Änderung. Bei MultiDatePick ist es der Administrator, der weiß, wie das Unternehmen seine Räume, Mitarbeiter und Termine bucht, und eine Änderung gilt, sobald er sie speichert.

36 Kalenderaufgaben im direkten Vergleich

Jede Zeile ist eine Aufgabe, die auf dem Tisch eines Administrators landet. Die grüne Zelle gewinnt: per Einstellung erledigt, ohne Code. „Code“ heißt: Ein Entwickler schreibt es in der Lightning Web Component und im Apex für FullCalendar.

So sieht No-Code-Anpassung aus

Jede dieser 36 Aufgaben ist eine Entscheidung, die ein Administrator an einer dieser Stellen trifft:

Der Einrichtungsassistent

Eine Lightning-Registerkarte, die nach Ihrer Seite und Ihren Datensätzen fragt, die naheliegenden Felder vorausfüllt und den echten Kalender zeigt, bevor Sie speichern.

Lightning App Builder

Jede Einstellung ist auch eine Eigenschaft der Komponente, sodass Sie eine Seite anpassen können, ohne die anderen anzufassen.

Die Config Library

41 fertige Konfigurationen, von Besprechungsräumen bis zu Abwesenheiten, zum Importieren und Anpassen.

Export und Import

Eine Konfiguration ist JSON, das Sie in eine Sandbox oder eine andere Org mitnehmen; fehlende Felder werden für Sie zugeordnet.

Flow Builder

Den Kalender auf einen Flow-Bildschirm ziehen und die gewählten Termine in den nächsten Schritten nutzen.

Experience Builder

Denselben Kalender auf eine öffentliche Website stellen, mit denselben Regeln für Gäste.

Häufige Fragen

Gibt es einen No-Code-Kalender als LWC für Salesforce?

Ja. MultiDatePick ist ein Kalender als Lightning Web Component, den Sie per Klick einrichten: im Einrichtungsassistenten oder im Lightning App Builder, auf jedem Standard- oder benutzerdefinierten Objekt. Er lädt und speichert Ihre Datensätze selbst, Sie schreiben also weder Apex noch JavaScript.

Lässt sich FullCalendar besser anpassen als MultiDatePick?

Nur für Entwickler. FullCalendar ist eine Bibliothek: Alles ist möglich, wenn jemand den Code schreibt und pflegt. Für Administratoren ist MultiDatePick der besser anpassbare Kalender: 36 gängige Aufgaben, von Buchungsregeln bis zu neun Sprachen, sind jeweils eine Einstellung.

Kann ein Salesforce-Administrator MultiDatePick ohne Entwickler einrichten?

Ja. Der Einrichtungsassistent fragt nach der Seite und Ihren Datensätzen, füllt die naheliegenden Felder vor und zeigt eine Live-Vorschau des echten Kalenders. Danach ziehen Sie die Komponente auf die Seite und tragen ihren Config Name ein.

Brauche ich Apex, um Datensätze aus einem Kalender zu speichern?

Mit MultiDatePick nicht. Beim Speichern schreibt MultiDatePick einen Datensatz pro Tag, pro Zeitraum, pro Zeitblock oder pro Ressource, oder gibt die Termine an einen Bildschirm-Flow (Screen Flow) weiter. Jedes Speichern läuft als der Benutzer, der die Seite ansieht, mit Freigaben und Sicherheit auf Feldebene.

Kann ich den Kalender später ohne Deployment ändern?

Ja. Öffnen Sie die Konfiguration im Einrichtungsassistenten, ändern Sie eine Einstellung und speichern Sie; der Kalender übernimmt sie beim nächsten Laden. Konfigurationen sind Benutzerdefinierte Metadaten (Custom Metadata), Sie können sie also weiterhin mit Änderungssets oder der Salesforce CLI verschieben, wenn Sie möchten.

Funktioniert ein No-Code-Kalender in Bildschirm-Flows und auf Experience Cloud-Sites?

Ja. Dieselbe Komponente kommt auf einen Flow-Bildschirm, wo die gewählten Termine zu Flow-Variablen werden, und auf eine öffentliche Experience Cloud-Site, wo Gäste nach denselben Regeln buchen.
