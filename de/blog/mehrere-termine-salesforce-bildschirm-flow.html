So wählen Benutzer mehrere Termine in einem Salesforce-Bildschirm-Flow (Screen Flow)

Flow bietet ein Datumsfeld pro Bildschirmelement. Wer neun Tage wählen muss, hat ein Problem. Hier sind die Möglichkeiten und was jede kostet.

Veröffentlicht am 1. Mai 2026 · Aktualisiert am 21. Oktober 2026 · MultiDatePick

Früher oder später stößt jeder Admin darauf. Ein Urlaubsantrag, ein Verfügbarkeitsformular, eine Schulungsanmeldung: Der Benutzer muss mehrere Tage auswählen, die nicht unbedingt aufeinanderfolgen, und die Standard-Datumskomponente von Flow erfasst genau einen.

Die Notlösungen, und warum sie wehtun

AnsatzSo läuft esDer Preis
Mehrere Datumsfelder auf einem BildschirmDatum 1, Datum 2, Datum 3, Datum 4...Feste Obergrenze, unschön und meist leer
Eine Schleife, die einzeln nachfragt"Weiteres Datum hinzufügen?" und zurück zum BildschirmAb etwa drei Tagen eine Qual
Ein FreitextfeldDer Benutzer tippt die Tage als Text einNicht auswertbar, nicht berichtsfähig, fehleranfällig
Nur Start- und EnddatumAls einen durchgehenden Zeitraum behandelnFalsch, sobald die Tage nicht zusammenhängen
Eine Mehrfachauswahlliste mit DatumswertenDatumswerte vorab erzeugenVeraltet schnell, braucht ständige Pflege
Eine Kalenderkomponente für mehrere TermineJeden benötigten Tag auf einem Bildschirm anklickenLiefert eine Sammlung, bereit für die Schleife

Die Notlösung mit Start und Ende ist die häufigste und die am unauffälligsten falsche. Aus "Ich brauche den 3., 4., 11. und 18. frei" wird der 3. bis 18., also sechzehn Tage unterstellte Abwesenheit. Die Daten sehen sauber aus und sind schlicht falsch.

Die echte Lösung: eine Bildschirmkomponente, die eine Sammlung zurückgibt

Was Flow eigentlich braucht, ist eine Bildschirmkomponente, in der der Benutzer so viele Tage anklicken kann, wie er will, und die eine Sammlung zurückgibt. Sobald es die gibt, ist der Rest des Flows Routine: Sammlung per Schleife durchlaufen, pro Tag einen Datensatz anlegen, fertig.

MultiDatePick liefert je nach dem, was Sie erfassen, mehrere Ausgaben:

AusgabeInhaltAPI-Name
Selected DatesEine Textsammlung mit ISO-Datumsangaben, bereit für die SchleifeselectedDates
Date Ranges JSONZusammengefasste Zeiträume, wenn aufeinanderfolgende Tage zu einem Datensatz werden sollenselectedDateRangesJson
Dates With Times JSONStart- und Endzeiten pro TagselectedDatesWithTimesJson
Successful Bookings Count, Conflict DatesWas gespeichert wurde und was kollidiert istbookingSuccessCount

Aus JSON wieder Datensätze machen

Zwei dieser Ausgaben sind JSON, weil Flow keinen eigenen Typ für "eine Liste von Objekten mit jeweils mehreren Feldern" hat. Text in einer Formel zu parsen ist keine Option. Das Paket bringt eine Flow-Aktion mit, Parse Date Entries from JSON, die das JSON entgegennimmt und eine richtige Sammlung mit From Date, To Date, Start Time und End Time zurückgibt. Diese Sammlung durchlaufen Sie per Schleife wie jede andere.

Ein Stolperstein, der regelmäßig eine Stunde kostet

Config Name setzen, nicht die Kontrollkästchen. Die Komponente hat eine lange Liste von Ein/Aus-Eigenschaften, und im Flow Builder ist ein leer gelassenes Kontrollkästchen leer statt false. All das können Sie überspringen: Bauen Sie den Kalender im Einrichtungsassistenten und tragen Sie dann den Namen dieser Konfiguration in die Eigenschaft Config Name ein. Jede Ein/Aus-Einstellung kommt dann aus der Konfiguration, und die wenigen reinen Flow-Einstellungen (Required, Show Inline, Output Date Ranges as JSON) bleiben aus, bis Sie sie einschalten. Nur wenn Sie auf Config Name verzichten und alles von Hand setzen, brauchen Sie $GlobalConstant.True oder $GlobalConstant.False bei den Kontrollkästchen, auf die es Ihnen ankommt.

Soll die Komponente die Datensätze selbst speichern? Übergeben Sie die Id des übergeordneten Datensatzes an Parent Record Id, dann legt sie pro Tag einen untergeordneten Datensatz an. Lassen Sie das Feld leer, um die Ausgabe per Schleife zu durchlaufen und die Datensätze auf Ihre eigene Weise anzulegen.

Die Datensatzform festlegen, bevor Sie bauen

Dieselben neun gewählten Tage können neun Datensätze werden, vier Datensätze, wenn aufeinanderfolgende Tage zu Zeiträumen zusammengefasst werden, oder ein übergeordneter Datensatz mit Unterblöcken. Jede Variante ist für einen anderen Bericht die richtige. Entscheiden Sie das, bevor Sie den Flow bauen, denn eine spätere Änderung bedeutet Datenmigration zusätzlich zur Überarbeitung des Flows.
