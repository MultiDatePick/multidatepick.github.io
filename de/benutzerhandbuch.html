2. Datensatzformen: wann welche passt

Eine Datensatzform legt fest, wie aus einer Auswahl Datensätze werden. Sie ergibt sich aus drei unabhängigen Entscheidungen, und jede Kombination funktioniert.

Entscheidung 1
Uhrzeit

Date: nur Termine, keine Uhrzeiten.

Date Time / Booking: jeder Datensatz hat eine Start- und Endzeit.

Zusatz: Aktivieren Sie Consolidate Time Span (Zeitspanne konsolidieren) für einen übergeordneten Datensatz über den ganzen Zeitraum plus einen Unterblock-Datensatz für jede Lücke darin.

Entscheidung 2
Ressource

Keine: Date, Date Time oder Booking ohne Ressource.

Eine Ressource: Booking mit einem Ressourcen-Dropdown.

Mehrere Ressourcen: Booking mit Kontrollkästchen, ein Datensatz pro angekreuzter Ressource.

Entscheidung 3
Zeitraum

Pro Klick: jedes ausgewählte Datum ist ein eigener Datensatz. Fünf Klicks, fünf Datensätze.

Pro Zeitraum: aufeinanderfolgende Tage werden zu einem Datensatz mit Start und Ende. Setzen Sie End Date Field API Name (Enddatumsfeld).

Der Einrichtungsassistent nennt sechs Formen: ein Datensatz pro Datum, einer pro Zeitraum, einer pro Zeitblock, übergeordneter Datensatz plus Unterblöcke, eine Ressource und mehrere Ressourcen.

Beispiele: die 3 Fragen beantworten

Beantworten Sie pro Szenario drei Fragen, und Sie landen bei einer Form. Der Einrichtungsassistent stellt dieselben drei.

Urlaubsantrag

Brauchen Sie Uhrzeiten? Nein, nur Tage.

Brauchen Sie eine Ressourcenauswahl? Nein.

Sollen aufeinanderfolgende Tage zusammengefasst werden? Ja. Urlaub von Mo bis Fr soll EIN Datensatz sein.

→ Pro Zeitraum: ein Datensatz, Beginn Mo, Ende Fr.

Besprechungsraum reservieren

Brauchen Sie Uhrzeiten? Ja, jede Buchung hat Beginn und Ende.

Brauchen Sie eine Ressourcenauswahl? Ja, einen Raum auswählen.

Sollen aufeinanderfolgende Tage zusammengefasst werden? Nein, jede Buchung ist ein eigener Datensatz.

→ Eine Ressource: ein Datensatz pro Datum × Zeitblock, mit dem Raum verknüpft.

Schulung in 3 Räumen

Brauchen Sie Uhrzeiten? Ja, jeden Tag derselbe Beginn und dasselbe Ende.

Brauchen Sie eine Ressourcenauswahl? Ja, mehrere Räume per Kontrollkästchen.

Sollen aufeinanderfolgende Tage zusammengefasst werden? Ja, sie läuft von Mo bis Fr.

→ Mehrere Ressourcen, pro Zeitraum: ein Datensatz pro Raum für die ganze Woche.

Ganztägige Schulung mit Mittagspause

Brauchen Sie Uhrzeiten? Ja, 9 bis 17 Uhr mit einer Mittagslücke.

Brauchen Sie eine Ressourcenauswahl? Nein.

Soll die Lücke erfasst werden? Ja, als eigener untergeordneter Datensatz.

→ Übergeordneter Datensatz plus Unterblöcke: ein übergeordneter Datensatz von 9 bis 17 Uhr, ein Unterblock für die Mittagspause.

3. Der Einrichtungsassistent Schritt für Schritt

Der Einrichtungsassistent speichert eine Konfiguration einmal. Geben Sie ihren Namen in Config Name auf einer beliebigen Seite oder in einem Flow-Bildschirm ein, und dieser Einsatzort verwendet sie. Ändern Sie die Konfiguration, und jeder Einsatzort folgt.

  1. 1 Name & Typ
  2. 2 Objekt & Felder
  3. 3 Zeitfelder
  4. 4 Status & Anzeige
  5. 5 Überprüfen & Speichern

Einstieg wählen

Die Registerkarte Neu erstellen bietet zwei Wege. Schritt für Schritt führen stellt drei Fragen und wählt Komponente und Form. Alle Eigenschaften konfigurieren öffnet jede Einstellung. Daneben gibt es zwei weitere Registerkarten: Vorhandene Konfigurationen, um eine gespeicherte Konfiguration zu bearbeiten, und Importieren, um eine aus der Config Library einzufügen.

Schritt 1: Name & Typ

Wählen Sie die Komponente (Date, Date Time oder Booking) und benennen Sie die Konfiguration. Diesen Namen geben Sie später in Config Name ein. In diesem Schritt legen Sie auch die Ansichten fest: die Standardansicht, welche Ansichten der Umschalter anbietet, und die Optionen für Zeitachse und Agenda.

Schritt 2: Objekt & Felder

Der wichtigste Schritt. Wählen Sie das Objekt mit den Datensätzen, sein Datumsfeld und das Beziehungsfeld zum übergeordneten Datensatz. Optionale Felder ergänzen Zeiträume, Ressourcen, Kapazität, Unterblöcke und gesperrte Termine. Booking-Konfigurationen legen hier auch Ressourcenobjekt, Kapazitätsfeld und Geschäftszeiten fest.

Schritt 3: Zeitfelder

Nur Date Time und Booking. Ordnen Sie das Start- und Endzeitfeld zu und legen Sie dann das Zeitintervall fest (jedes Intervall funktioniert; üblich sind 15, 30 oder 60 Minuten), die früheste und späteste Uhrzeit, den Anzeigemodus und was bei einem Konflikt passiert.

Schritt 4: Status & Anzeige

Statusfeld und -farben, auszublendende Status, Status, die Benutzer wählen dürfen, Hover-Felder, Bearbeitungsmodus, Datensatzbenennung, Schaltflächenbeschriftungen, Kalendergröße und Limits wie Max Dates Allowed (Maximale Auswahlen).

Schritt 5: Überprüfen & Speichern

Prüfen Sie die Zusammenfassung, testen Sie die Live-Vorschau und klicken Sie dann auf Konfiguration speichern. Der Assistent stellt die Konfiguration in 30 bis 60 Sekunden für Sie bereit. Danach können Sie optional eine Beschreibung hinzufügen.

Vorhandene Konfigurationen und Importieren

Gespeicherte Konfigurationen stehen unter Vorhandene Konfigurationen: Klicken Sie auf eine, um sie zu bearbeiten oder zu exportieren. Die Registerkarte Importieren nimmt das JSON jeder Karte der Config Library an oder einen Export aus einer anderen Org.

In einem Bildschirm-Flow (Screen Flow) setzen Sie Config Name und hören dort auf. Jedes Kontrollkästchen kommt aus der Konfiguration, Sie brauchen also nie eine $GlobalConstant. Binden Sie den übergeordneten Datensatz an Parent Record Id.

4. Berechtigungssätze & Zugriff

Das Paket liefert vier Berechtigungssätze. Weisen Sie sie im Setup unter Berechtigungssätze zu.

BerechtigungssatzWer ihn bekommtEinrichtungsassistentKalender nutzen
MultiDatePick - SetupDie Admins, die Konfigurationen erstellen✓ JaNein
MultiDatePick - UserAlle, die die Kalender nutzenNein✓ Ja
MultiDatePick - All AccessAdmins, die sie erstellen und nutzen✓ Ja✓ Ja
MultiDatePick - GuestDer Gastbenutzer einer öffentlichen Experience Cloud-SiteNein✓ Ansehen und buchen

Die Komponenten laufen mit den Berechtigungen des jeweiligen Benutzers, Benutzer brauchen also auch Zugriff auf Ihre Objekte und Felder:

  • Objekte: Lesen und Erstellen für das Objekt, in dem die Datensätze gespeichert werden, plus Lesen für jedes Ressourcen-, Schließtags- oder untergeordnete Objekt, das der Kalender liest.
  • Felder, lesen: jedes Feld, das der Kalender anzeigt (Datum, Status, Hover-Felder).
  • Felder, bearbeiten: jedes Feld, das er schreibt (Datum, Uhrzeiten, Status, zweite Auswahlliste, Namensfeld, das Lookup-Feld zum übergeordneten Datensatz). Ein Feld, das der Benutzer nicht bearbeiten darf, lässt das Speichern scheitern, auch wenn das Lesen funktioniert.
  • Referenzierte Datensätze: mindestens Lesen für den übergeordneten Datensatz und die Ressource, auf die der neue Datensatz verweist.
Auch Admins brauchen Feldzugriff. Ein brandneues benutzerdefiniertes Feld ist für alle unsichtbar, auch für Systemadministratoren, bis ein Berechtigungssatz es freigibt. Scheint ein Feld beim Speichern zu fehlen, prüfen Sie zuerst die Sicherheit auf Feldebene.

Jede Fehlermeldung und ihre Ursache finden Sie unter Fehlerbehebung: Zugriffsfehler. Gast-Sites brauchen ein paar zusätzliche Schritte: siehe Öffentliche Gastseiten.

5. Speichern per Klick vs. Speichern im Flow

Es gibt zwei Arten zu speichern. Wählen Sie die, die zum Einsatzort passt.

Speichern per Klick

Die Komponente schreibt die Datensätze selbst. Füllen Sie vier Einstellungen aus, und ihre eigene Schaltfläche Speichern erscheint. Ein Klick darauf erstellt die untergeordneten Datensätze. Keine Flow-Elemente, kein Code.

Einsatz auf: Datensatzseiten, App-Seiten, Startseiten, Experience Cloud-Sites und Flow-Bildschirmen mit übergeordnetem Datensatz.

Speichern im Flow

Die Komponente übergibt die Auswahl an Ihren Flow. Verwenden Sie die mitgelieferte Aktion Parse Date Entries from JSON und dann Ihre eigenen Elemente Schleife und Datensätze erstellen.

Einsatz auf: Flow-Bildschirmen, auf denen Sie volle Kontrolle wollen: Genehmigungen, bedingte Datensätze, zusätzliche Validierung.

Der Einrichtungsassistent füllt sie aus. Sobald alle vier einen Wert haben, erscheint die Schaltfläche Speichern.

Speichern per Klick erstellt nur neue Datensätze. Das Abwählen eines Datums löscht nie einen gespeicherten Datensatz, ein falscher Klick kann also keine Daten vernichten. Um Datensätze zu ändern oder zu entfernen, nutzen Sie den Bearbeitungsmodus oder die Themenliste.

Der Bearbeitungsmodus funktioniert in jeder Ansicht

Mit aktivem Bearbeitungsmodus aktivieren erscheint die Schaltfläche Bearbeiten in jeder Ansicht. Klicken Sie in Zeitachse, Woche oder Agenda auf einen Datensatz, um ihn zur Bearbeitungsauswahl hinzuzufügen, genau wie ein Datum im Monatskalender. Eine gesammelte Statusänderung aus der Zeitachse funktioniert genauso wie aus dem Kalender.

Zeitachse: eingeklappte Zeilen

Hat eine Ressource überlappende Buchungen, klappt ihre Zeile zu einem Streifen mit dem Chip N gleichzeitig zusammen. Ein Aufklapppfeil öffnet eine Spur pro Buchung. Eingeklappte Zeilen reagieren weiterhin auf Ziehen, Hover und Klick.

Zeitachse: per Ziehen umplanen

Mit aktivem Bearbeitungsmodus aktivieren lassen sich die Balken der Zeitachse ziehen. Greifen Sie die Mitte, um eine Buchung auf andere Tage zu verschieben. Greifen Sie einen Rand, um Beginn oder Ende zu ändern. Der Balken zeigt, wo er landet, und speichert beim Loslassen. Im Tageszoom ändern dieselben Gesten die Uhrzeiten.

Personen einplanen, nicht nur Räume

Resource Object API Name (Ressourcenobjekt) nimmt jedes Objekt an. Setzen Sie es auf User, und die Zeitachse wird zum Dienstplan, die Woche zum Schichtraster und die Auslastung zum Kapazitäts-Dashboard des Teams.

  • User hat kein Standard-Kapazitätsfeld. Legen Sie ein benutzerdefiniertes an (zum Beispiel Daily Capacity), um die Auslastung in Prozent zu sehen.
  • Ordnen Sie Business Hours Start Field (Geschäftszeiten-Startfeld) und Business Hours End Field (Geschäftszeiten-Endfeld) User-Feldern zu, und das Wochenraster folgt den Arbeitszeiten jeder Person.

Die Config Library enthält zwei fertige Beispiele: Teamkapazitätsplanung und Schichtdienstplan.

8. Ressourcenbuchung & Kapazität (Komponente Booking)

Eine Ressource

Benutzer wählen eine Ressource aus einem Dropdown. Das Zeitraster lädt die Buchungen und die Kapazität dieser Ressource.

Mehrere Ressourcen

Aktivieren Sie Allow Multiple Resources (Mehrere Ressourcen zulassen), und aus dem Dropdown werden Kontrollkästchen. Das Raster zeigt nur Zeitfenster, die bei jeder angekreuzten Ressource frei sind, und Speichern bucht sie alle auf einmal.

10. Termine, Zeiten & Ressourcen sperren (Schließungen)

Jeder Kalender kann Schließungen aus einem anderen Objekt lesen und die Tage, Zeitfenster oder Ressourcen ausgrauen, die sie abdecken, sodass Benutzer nur buchen, wenn Sie geöffnet haben. Richten Sie ein paar Einstellungen auf das Schließungsobjekt, und die Komponente erledigt den Rest. Ganztägige Sperren funktionieren in allen drei Komponenten. Sperren nach Uhrzeit und Ressource brauchen das Zeitraster von Date Time oder Booking.

Sperren vs. Ausblenden: Was ist der Unterschied?

Beides klingt ähnlich, bewirkt aber das Gegenteil. Sperren nimmt Verfügbarkeit weg: Das Zeitfenster ist sichtbar, aber nicht buchbar. Ausblenden nimmt Datensätze aus der Ansicht und gibt damit ihre Zeitfenster frei.

Ein Status kann beides bewirken, je nachdem, mit welcher Funktion Sie ihn verbinden. Nehmen Sie eine Buchung mit Status Cancelled:
  • Ignorierte Status = Cancelled → die Buchung verschwindet, und ihr Zeitfenster wird frei.
  • Objekt für gesperrte Daten = Ihr Buchungsobjekt, gefiltert auf Status = Cancelled → die Buchung sperrt ihr Datum, damit niemand es erneut bucht.
Ausblenden, um das Zeitfenster freizugeben. Sperren, um es gesperrt zu halten.

Drei Ebenen des Sperrens

  1. Ganzer Tag: Eine Schließung ohne Uhrzeiten graut das ganze Datum aus. Alle drei Komponenten. Ein geschlossener Tag bleibt geschlossen, auch wenn er schon Buchungen hat.
  2. Teil eines Tages: Eine Schließung mit Start- und Endzeit sperrt nur diese Zeitfenster. Der Rest des Tages bleibt buchbar. Gesperrte Zeitfenster erscheinen, sobald ein Datum ausgewählt ist.
  3. Eine Ressource: Eine Schließung, die auf eine Ressource zeigt, schließt nur diese Ressource. In der Ansicht einer einzelnen Ressource ist das Zeitfenster durchgestrichen. In der kombinierten Ansicht bekommt es eine kleine Eckmarkierung und bleibt für die freien Ressourcen buchbar.

Sie nutzen das Zeitraster? Dann brauchen Sie Sperren für Teile des Tages. Ganztägige Sperren passen zu reinen Datumsauswahlen.

Zwei Muster für das Schließungsobjekt

  • Dasselbe Objekt, per Status markiert: Richten Sie das Objekt für gesperrte Daten auf Ihr Buchungsobjekt und filtern Sie auf Status = Cancelled, sodass stornierte Buchungen zugleich als Schließungen dienen. Am einfachsten, aber jeder Kalender auf diesem Objekt teilt sie. Siehe die Konfiguration Terminbuchung mit Feiertagssperre in der Config Library.
  • Ein eigenes Schließungsobjekt: ein Objekt Office Closure mit einem Datum, optionaler Start- und Endzeit, einem Feld Region und einem optionalen Lookup-Feld zur Ressource. Jeder Kalender filtert nach seiner Region, und eine Schließung kann eine einzelne Ressource betreffen. Siehe die Konfiguration Stundenweise Ressourcensperren.

Damit Personen ihre eigene Zeit sperren können (etwa ein Verantwortlicher, der einen Vormittag blockt), platzieren Sie auf einer internen Seite oder Site eine Komponente Date Time, die im Schließungsobjekt speichert.

Wie sich gesperrte Zeitfenster verhalten

  • Aussehen: Ein vollständig geschlossenes Zeitfenster ist durchgestrichen und ausgegraut. Ein Zeitfenster, das nur für einige der gewählten Ressourcen geschlossen ist, bekommt eine Eckmarkierung.
  • Auswahl: Ein vollständig geschlossenes Zeitfenster lässt sich weder anklicken noch überziehen.
  • Speichern: Auf eine geschlossene Kombination aus Ressource, Datum und Uhrzeit wird nichts gespeichert. Bei mehreren Ressourcen wird nur die geschlossene ausgelassen; die freien werden trotzdem gebucht.

Eine Schließungstabelle, viele Kalender

Geben Sie dem Schließungsobjekt ein Kennzeichnungsfeld (Region, Standort, Gebäude) und legen Sie dasselbe Feld an Ihren Ressourcen an. Jeder Kalender nutzt dann Resource Filter Field / Value, um seine eigenen Ressourcen zu zeigen, und Filterfeld / Filterwert für gesperrte Daten, um seine eigenen Schließungen zu lesen.

11. Öffentliche Gastseiten (Experience Cloud)

Platzieren Sie eine Komponente auf einer Experience Cloud-Site, und jeder kann ohne Anmeldung buchen. Erledigen Sie alle fünf Schritte, bevor Sie als Gast testen.

  1. Objektberechtigungen. Geben Sie dem Gastbenutzer der Site Lesen, plus Erstellen, wenn Gäste etwas absenden, für jedes Objekt. Salesforce erlaubt Gästen nie, Datensätze zu bearbeiten oder zu löschen, behalten Sie Seiten zum Bearbeiten, Stornieren und Löschen also angemeldeten Benutzern vor.
  2. Sicherheit auf Feldebene für jedes Feld, das die Komponente berührt, auch die Geschäftszeitenfelder der Ressource und die Zeitfelder der Schließungen. Ein einziges fehlendes Feld stoppt die Abfrage der Ressourcen oder Schließungen.
  3. Eine Freigaberegel für Gäste (Lesen), damit der Gast die Datensätze sehen kann. Die externe organisationsweite Standardeinstellung des Objekts muss Privat sein, damit die Regel greift. Eine als Metadaten bereitgestellte Regel braucht im Setup unter Freigabeeinstellungen einen Klick auf Neu berechnen.
  4. Der Berechtigungssatz MultiDatePick - Guest für den Gastbenutzer der Site. Er enthält den Zugriff auf die Apex-Klassen, über die die Komponente ihre Daten lädt.
  5. Site aktivieren. Veröffentlichen und Aktivieren sind getrennte Schritte.
Leerer Kalender für Gäste? Wenn Objekte, Felder und Klassenzugriff stimmen, liegt es fast immer an der Neuberechnung der Freigaben in Schritt 3. Die Schritte 4 und 5 werden am zweithäufigsten vergessen.
  • Welchen Datensatz Gäste sehen: Eine öffentliche Seite nutzt Static Parent Record Id, jeder Gast bucht also für denselben übergeordneten Datensatz (ein Büro, einen Standort oder eine Ressource). Für einen Datensatz pro Besucher steuern Sie das über einen Flow mit URL-Parameter. Echte Kalender pro Benutzer brauchen angemeldete Benutzer.
  • Kontakte und Accounts: Salesforce schränkt den Gastzugriff darauf stark ein. Lassen Sie Gäste auf ein benutzerdefiniertes Objekt buchen oder nutzen Sie eine authentifizierte Site.
  • Mehrere Komponenten auf einer Seite: Sie synchronisieren sich nicht live. Fügen Sie dazwischen eine Aufforderung zum Aktualisieren ein, damit eine Sperre aus der einen in der nächsten erscheint.

Die Schritte zur Platzierung stehen unter App-, Start- & Experience-Seiten. Eine vollständig ausgearbeitete Site finden Sie unter Buchung in Experience Cloud.

12. Häufige Stolpersteine (FAQ)

Sie sehen ein Banner, eine fehlende Schaltfläche Speichern oder einen leeren Kalender? Die Fehlerbehebung zeigt jede Meldung mit Screenshot und Lösung.

Meine Statusfarben werden nicht angewendet
Prüfen Sie drei Dinge. (a) Ist Statusfeld genau der API-Name der Auswahlliste? Groß- und Kleinschreibung zählt. (b) Nutzt Statusfarben das Format Value:#hex, Value:#hex ohne Anführungszeichen? 'Confirmed':'#22C55E' bricht es stillschweigend. (c) Haben die Datensätze tatsächlich einen Wert in dieser Auswahlliste?
Datensätze werden mit unerwarteten Namen gespeichert
Prüfen Sie Record Name Field (Datensatz-Namensfeld): Ist das Feld kurz, werden lange Namen abgeschnitten. Prüfen Sie Append Date to Record Name (Datum/Uhrzeit an Namen anhängen): Ist es aktiv, werden ausgewähltes Datum und Uhrzeit an jeden Namen angehängt.
Wie blende ich stornierte Datensätze im Kapazitätsraster aus?
Setzen Sie Ignorierte Status auf Cancelled oder eine Liste wie Cancelled,Rejected. Sie verschwinden aus dem Kalender und aus der Kapazitätszählung.
Was ist der Unterschied zwischen Sperren und Ausblenden?
Sperren (Schließungen) hält ein Datum, eine Uhrzeit oder eine Ressource sichtbar, aber nicht buchbar: Feiertage, Wartung, ein geschlossener Raum. Ausblenden entfernt Datensätze wie Cancelled aus Kalender und Kapazität und gibt so das Zeitfenster frei. Siehe Sperren vs. Ausblenden.
Die Schaltfläche Bearbeiten erscheint nicht
Aktivieren Sie Bearbeitungsmodus aktivieren. Das ist die einzige Voraussetzung, bei allen drei Komponenten. Ein Statusfeld ist optional; es fügt im Editor nur ein Status-Dropdown hinzu. Fehlt die Schaltfläche trotzdem, ist Bearbeitungsmodus aktivieren auf der Seite oder in der Konfiguration ausgeschaltet.
Ich möchte nur bestimmte Ressourcen (Räume, keine Geräte)
Nutzen Sie Resource Filter Field (Ressourcenfilterfeld) und Resource Filter Value (Ressourcenfilterwert). Ein Wert: Feld Active__c, Wert true. Mehrere Werte (ODER): North,South. Mehrere Felder (UND): Feld Type__c;Active__c, Wert Conference Room;true.
Date Time zeigt immer eine gemeinsame Zeitauswahl
Die richtige Einstellung ist Time Display Mode (Zeitanzeigemodus): Raster oder Dropdown. Im Rastermodus teilen sich alle Termine das Raster. Für eine eigene Uhrzeit pro Datum wählen Sie Dropdown und aktivieren Allow Different Times Per Date (Unterschiedliche Zeiten zulassen).
Wie wechsle ich von Speichern im Flow zu Speichern per Klick?
Füllen Sie Parent Record Id, API-Name des untergeordneten Objekts, API-Name des Datumsfelds und API-Name des Beziehungsfelds aus. Entfernen Sie die Aktion Parse Date Entries from JSON und die Schleife, die Datensätze erstellt hat. Jetzt schreibt die eigene Schaltfläche Speichern der Komponente sie.
Ich bekomme eine Fehlermeldung ohne Details
Öffnen Sie die Entwicklerkonsole des Browsers und suchen Sie nach Zeilen, die mit [MDP:ERROR] beginnen. Der vollständige Fehler wird dort immer protokolliert, auch wenn die Meldung kurz ist.
