设置与放置

管理员在页面上放置日历或创建配置时看到的横幅和警告。

没有“保存”按钮

原因：组件没有父记录，也没有设置为显示所有记录。应用程序页面和主页本身没有记录。

解决方法

  1. 在设置向导中打开该配置并回答谁的记录?（通常选仅查看者），或在将每次选择关联到此记录（App Builder：Static Parent Record Id）中填入这些日期所属的记录。
  2. 检查对象、日期字段和关系字段是否都已填写，或者设置 Config Name（配置名称）。

在 Flow 中，绑定 Parent Record Id 后就会显示“保存”按钮。当向导中的由谁保存?为由我的流程保存，或 Parent Record Id 为空时，它保持隐藏：此时日期由 Flow 的“下一步”按钮带走。

琥珀色横幅：“此配置使用了错误的组件”

原因：Config Name 指向的是为另一个组件保存的配置。

解决方法

  1. 让 Config Name 指向为本组件创建的配置，或
  2. 换成该配置所对应的组件，或
  3. 在设置向导中打开该配置，修改其组件类型。

琥珀色横幅：“配置不匹配”

原因：页面的记录或将每次选择关联到此记录中的记录所属的对象，与配置中关系字段所查找的对象不同。

解决方法

  1. 把组件放到横幅中所提对象的记录页面上，或
  2. 将每次选择关联到该对象的一条记录，或
  3. 使用为此页面对象创建的配置。

红色横幅：“此组件无法加载其数据”

原因：设置中的某个字段名或对象名有误，或者用户无法运行 MultiDatePick，或无法读取该对象及其字段。

解决方法

  1. 查看灰色框：其中写明了具体的字段、对象或 Apex 类。缺少 MultiDatePick 访问权限时，横幅会说明应分配哪个权限集。
  2. 名称错误：从“设置”的对象管理器中复制准确的 API 名称。
  3. 没有访问权限：分配 MultiDatePick - User 权限集，并授予对您自己对象的访问权限。在公开 Experience 站点上，为访客用户分配 MultiDatePick - Guest，并授予其对您自己对象的读取权限。

Resource Booking 显示“需要配置”

原因：Resource Booking 需要资源对象、预订对象、预订日期字段和预订资源字段。面板会列出缺少的项。

解决方法

  1. 将 Config Name 设为设置向导中的一个 Resource Booking 配置，或
  2. 逐一填写面板中列出的属性。

“未找到名为‘Room_Bookings’的配置”

原因：Config Name 需填写配置的 API 名称，即设置向导“现有配置”列表中的名称（例如 Contact_Event），而不是标签。拼写错误、填了标签，或刚保存的配置仍在部署中，都会出现这个提示。

解决方法

  1. 打开设置向导，进入“现有配置”，复制该配置的 API 名称。
  2. 将它粘贴到组件的 Config Name 中，然后保存页面。
  3. 刚保存配置？Salesforce 会在后台部署，需要 30 秒到 2 分钟。刷新“现有配置”直到它出现，然后重新加载页面。

如果消息说的是用户无权访问 MultiDatePick，请参阅无权访问 MultiDatePick。

“Static Parent Record Id 中的记录（a015g00000XyZ12AAB）已不存在”

原因：日历把每次选择都保存到一条固定记录上，该记录在将每次选择关联到此记录（App Builder：Static Parent Record Id）中设置，而它已被删除。在它指向一条存在的记录之前，什么都无法保存。

解决方法

  1. 在设置向导中打开该配置，在将每次选择关联到此记录下选择另一条记录。
  2. 如果页面没有 Config Name，请在 App Builder 中将一条现有记录的 Id 粘贴到 Static Parent Record Id。

日期已保存，但下次打开时不显示

原因：显示已保存的日期（App Builder：Load Existing Dates）处于关闭状态。记录已经保存，但日历每次打开都是空的。

解决方法

  1. 开启显示已保存的日期。
  2. 重新加载页面。已保存的日期会显示出来，如果设置了状态字段，还会按状态着色。

“此日历无法显示现有记录，也无法保存新记录：Visit 上的字段‘Visit Date’已使用 Shield Platform Encryption 加密”

原因：Salesforce 无法按受 Shield Platform Encryption 保护的字段搜索或排序，而日历要靠日期、时间和名称字段查找记录并排序。这些字段必须保持未加密。日历只用于显示的字段（例如悬停卡片上的备注）可以继续加密。

解决方法

  1. 在“设置”的“加密策略”中，取消消息所指字段的加密，或
  2. 在设置向导中打开该配置，改选一个未加密的日期或时间字段。

筛选器“与可筛选的字段和值不匹配”，或“无法加载资源”

原因：筛选器中的字段不在该对象上，或者是 Salesforce 无法用于筛选的字段，或者值与字段不符。日历会指出是哪一个，例如记录筛选器：“Status__c=Confrimed”与 Visit 上可筛选的字段和值不匹配。或无法加载资源：条件“Active__c 为 yes”与该字段不符。

解决方法

  1. 在设置向导中打开该配置。
  2. 从仅限符合条件的记录（显示哪些记录）或仅显示符合条件的项（提供哪些会议室或人员）下的列表中重新选择字段和值。
  3. 在 App Builder 中手动输入？请使用字段的 API 名称和符合其类型的值：复选框填 true 或 false，日期填 2026-12-31。

“默认字段值：‘Priority=Urgent’与 Visit 上的字段和值不匹配”

原因：自动填写（App Builder：Default Field Values）会为每条新记录设置字段，而其中某一对指定了对象上没有的字段，或字段无法保存的值，例如不在选项列表中的选项列表值。

解决方法

  1. 在对象管理器中检查字段的 API 名称。
  2. 填写符合字段类型的值：复选框填 true 或 false，日期填 yyyy-mm-dd 或 TODAY+7，选项列表填它的某个值。
  3. 多对之间用分号分隔：Priority=High; Type=Call。

“Duration 不是数字字段”，或某个预订占满了一整天

原因：保存分钟数的字段（App Builder：Duration Field）必须是预订对象上的数字字段，不能是公式、汇总、货币或百分比字段。设置了它且结束于留空时，每个预订的结束时间等于开始时间加上这些分钟数，所以分钟数为空的记录没有结束时间，会占满一整天。

解决方法

  1. 选择一个保存时长（分钟）的数字字段，或新建一个。
  2. 为旧记录一次性补填分钟数，例如通过数据更新或 Flow。此后在日历上的每次保存、移动和调整大小都会自动写入。

“Visit 没有有效的记录类型‘Install’，而此日历会将新记录设为该类型”

原因：新预订的记录类型指定的记录类型已被停用或重命名。相关消息Confirmed 不是记录类型“Repair”可用的 Visit Status 值表示所选状态不在该记录类型提供的值中。

解决方法

  1. 在设置向导中打开该配置，在新预订的记录类型下选择一个有效的类型，或选择每个人的默认值或让用户选择。
  2. 如果是状态：在对象管理器中把该值添加到该记录类型的选项列表值中，或选择其他状态。

如果消息说此人无法创建该类型的记录，请参阅不允许的记录类型。

“仅管理员在生成器中可见：此日历会统计容量，但没有 Config Name”

原因：页面上没有指定已保存的配置时，日历只能统计查看者看得到的预订。因共享设置而对其隐藏的预订不计入，所以已满的时间可能显示为空闲。

解决方法

  1. 在设置向导中保存该配置。
  2. 在组件的 Config Name 中输入它的名称。此后统计会包含所有预订，且只显示数量。

只有管理员会在 App Builder 中看到这条提示，普通用户永远看不到。

保存后没有“添加到日历”按钮

原因：Show Add to Calendar After Saving 处于关闭状态。它默认关闭。

解决方法

  1. 在组件属性或配置中开启它，然后保存一条记录。按钮会出现在提示消息下方的一个提示栏中。
  2. 看到的是“添加到 Google 日历”？说明浏览器阻止了生成文件，所以单个日程改为提供 Google 日历链接。

预订与可用时间

为什么某一天、某个时间、某间会议室或某个人无法选择或预订。

Resource Booking 显示“没有可用资源”

原因：资源列表为空。通常是筛选条件匹配不到任何记录、资源对象有误，或者还没有任何资源记录。

解决方法

  1. 对照一条真实记录检查仅显示符合条件的项（App Builder：Resource Filter Field 和 Value）。
  2. 检查可供选择的列表和各项的名称字段（App Builder：Resource Object API Name 和 Resource Name Field）。
  3. 至少创建一条资源记录。

琥珀色横幅：“容量需要两个时间字段”

原因：已设置同时可容纳数量（App Builder：Capacity Field），但预订开始时间或结束时间字段为空，因此无法执行容量限制。

解决方法

  1. 同时设置开始于和结束于（App Builder：Booking Start Time Field 和 Booking End Time Field），或
  2. 清空同时可容纳数量。

无法再选择日期

原因：组件设有日期数量上限：Max Dates Allowed（允许的最大日期数）。

解决方法

  1. 取消选择一个日期，再选另一个，或
  2. 提高上限，或设为 0 表示不限制。

无法再预订其他时间

原因：已达到某个预订上限。Max Time Slots（最大时间段数）限制时间段总数，Max Bookings per Day（每天最大预订数）限制一天内的独立预订数（相邻的时间算作一个），Limit per Person（每人上限）限制一位客户即将到来的预订数，由服务器端计数。

解决方法

  1. 提高上限，或设为 0 表示不限制。
  2. 员工确认后可以超出“每人上限”预订，站点访客则不能。

部分日期或时间显示为灰色

原因：某条预订规则把它们关闭了。Minimum Notice (Hours) 会关闭开始时间太近的时段，Book Up To (Days Ahead) 会关闭滚动时间窗之外的日期，其余的则由最早或最晚可选日期、屏蔽日期以及各资源的营业时间关闭。

解决方法

  1. 在组件或其配置中检查这些设置。设为 0 即关闭提前通知和时间窗限制。
  2. 单击一个已关闭的时间段：会显示它为何关闭。

紧接在某个预订之后的时间段显示为已占用

原因：Buffer Between Bookings (Minutes) 会在同一资源的每个预订之后预留空闲时间，用于整理或周转。

解决方法

  1. 缩短缓冲时间，或设为 0 以允许预订一个接一个。
  2. 时间已被占用时仍然适用：设为跳过冲突的时间段时，落在缓冲时间内的预订会像其他冲突一样被跳过并报告。

只显示部分开始时间

原因：设置了仅这些时间，因此网格只提供列出的开始时间。在 Resource Booking 中，如果某间会议室或某个人有自己的列表，则以每个资源自己的时间为准。营业时间、停业日、提前通知要求和冲突仍会关闭列表中的时间。

解决方法

  1. 在组件或其配置中编辑该列表，或选择每个间隔。
  2. 检查资源的“每个资源自己的时间”字段中它自己的列表。

“以下所选项已不在预订时间范围内”

原因：页面打开的时间太久，所选的日期或时间已进入 Minimum Notice 期限之内。保存时会再次检查该规则，以免一个过时的页面预订得太迟。

解决方法

  1. 移除消息中列出的日期，或选择更晚的时间。
  2. 再次保存。

“无法预订。以下日期已满或已关闭：12月3日”或“已满或已关闭，保存时将跳过”

原因：该时间已被另一个预订占满，或被关闭记录覆盖。由时间已被占用时决定如何处理：阻止会拒绝整次操作，跳过冲突的时间段会预订其他日期并列出被跳过的日期，允许（仍然预订）会提供“仍然预订”按钮。

解决方法

  1. 移除消息中列出的日期，或选择其他时间或资源。
  2. 管理员可以在配置的预订规则中更改时间已被占用时。

“已达每日上限（2/2）”

原因：每天最多预订数（App Builder：Daily Limit Field）是每间会议室或每个人记录上的一个数字，例如技术人员每天 2 个工单。一天的预订达到这个数量后，该资源当天即关闭，在那天保存会提示已达每日上限，因此未保存任何内容。每条记录只计一次，跨多天的预订在每一天都计入，释放时间的状态从不计入。

解决方法

  1. 选择其他日期或其他资源。
  2. 提高资源记录上的数字，或留空表示不限制。
  3. 将时间已被占用时设为允许（仍然预订）后，预订可以超出上限。

“Garden Room 不接受预订，因此未保存任何内容”

原因：该资源的同时可容纳数量或每天最多预订数为 0。0 表示完全不接受预订，无论“时间已被占用时”如何设置。选择器、时间网格和周视图都会将其显示为灰色。

解决方法

  1. 选择其他资源。
  2. 如需开放预订，请将其记录上的数字设为 1 或更大，或留空表示不限制。

“这些日期已过去，无法预订”或“这些时间已过”

原因：日历不会预订已经过去的日期或时间。页面开了一整夜、昨天选的日期，或今天早些时候的时间，保存时都会被拒绝。

解决方法

  1. 移除消息中列出的日期或时间，改选之后的日期或时间。
  2. 需要记录过去的日子，例如工时表？管理员可以在配置中开启允许过去日期。

“这些日期已关闭：12月25日。请选择其他日期或时间。”

原因：该日有关闭记录：日历关闭日期列表中的一条记录，例如节假日或员工休假。指定了会议室或人员的关闭记录只关闭该资源。日历和保存都会拒绝它。

解决方法

  1. 请选择其他日期或时间。
  2. 如果这一天应该开放，请编辑或删除该关闭记录，或在配置中缩小仅限符合条件的关闭的范围。

“无法在此日历中预订 Garden Room。请从列表中选择资源。”

原因：该会议室或人员不在此日历的列表中，因为仅显示符合条件的项把它排除了。这通常发生在页面打开后记录有了变化，例如会议室被设为停用。服务器会在保存、移动和重新分配时拒绝它。

解决方法

  1. 重新加载页面，从列表中选择资源。
  2. 如果应该提供它，请更新资源记录，或在配置中更改仅显示符合条件的项。

“所选资源没有共同的开始时间”

原因：开启一次预订多项后，一个时间必须同时适合所选的每间会议室或每个人。它们的营业时间或各自的开始时间没有重叠，所以没有时间适合全部。较短的消息所选资源没有重叠的可用时间也是同一个意思。

解决方法

  1. 少选几个资源，或选择工作时间相同的资源。
  2. 管理员可以检查每个资源的营业时间和各自的开始时间。

两个人预订了同一时间

原因：有两个设置会导致这种情况。时间已被占用时设为允许（仍然预订）时，员工可以有意在已占用的时间上预订。或者开启了筛选器同时决定哪些时间已被占用，且筛选条件使用了 ME，这样只有每个人自己的预订才会占用时间。向导会对第二种情况发出警告：“筛选器同时决定哪些时间已被占用”已开启，且“仅限符合条件的记录”使用了 ME，因此只有每个人自己的预订才会占用时间：两个人可能会预订同一时间。

解决方法

  1. 将时间已被占用时设为阻止或跳过冲突的时间段。
  2. 关闭筛选器同时决定哪些时间已被占用，除非每个人确实只预订自己的时间。

“‘每人上限’已开启，但未设置‘客户字段’”

原因：每人上限通过为谁预订（App Builder：Client Field）统计每位客户的预订。如果没有设置字段，或设置的是 Salesforce 无法搜索的字段（例如长文本），预订就无法计数，因此保存会被拒绝。管理员会在 App Builder 中看到“每人上限”无法按 Notes 统计预订。

解决方法

  1. 在设置向导中打开该配置，在为谁预订下选择一个文本、电子邮件或查找字段。
  2. 或将“每人上限”设为 0 以关闭它。

“Salesforce 没有响应，此预订可能已经保存”

原因：按下“预订”后连接中断或 Salesforce 响应缓慢，日历无法判断保存是否完成。它会自动重新加载，方便您查看。

解决方法

  1. 在重新加载的日历上查找该预订。
  2. 只有在找不到时才再次预订。

公开站点访客

公开 Experience Cloud 站点上的日历，访问者无需登录即可预订。

访客看到的是空日历

原因：访客共享规则尚未生效，或者访客配置文件少了一步设置。

解决方法

  1. 将对象的外部组织范围默认设置设为“私有”，然后在“设置”的“共享设置”中单击重新计算。
  2. 为访客用户分配 MultiDatePick - Guest 权限集，并授予其对您自己每个对象和字段的“读取”权限。
  3. 激活站点。仅仅发布是不够的。

完整的五步访客检查清单见用户指南。设置向导中的检查我的站点会为您逐步测试。

“检查我的站点”显示“需要修复”

原因：站点日历的设置向导在“检查”和“完成”步骤中提供检查我的站点，它会以访客的视角测试站点。每一行“需要修复”就是一个缺少的步骤，并写明该怎么做。

解决方法

  1. 站点尚未上线：在站点的工作区中转到“管理 > 设置”，单击“激活”，然后发布。
  2. MultiDatePick - Guest 权限集：打开访客用户，在“权限集分配”下添加它。
  3. 对象访问权限或字段访问权限：为访客用户授予日历所显示内容的“读取”权限，以及预订所保存内容的“编辑”权限。
  4. 访客看不到任何资源：在“设置 > 共享设置”中，为资源对象添加访客共享规则。

只有拥有 MultiDatePick - Setup 的管理员才能运行此检查。

“此日历无法在此保存：它没有指定此对象的已保存配置”

原因：站点访客或门户用户的预订会在服务器上对照已保存的配置进行检查，因此隐私和预订规则无法被绕过。站点页面上的日历没有 Config Name，而该对象已经有已保存的配置。

解决方法

  1. 在 Experience Builder 中打开该站点页面。
  2. 将日历的 Config Name 设为为此站点保存的配置，然后发布。

“此日历无法在此使用：其已保存配置不是为公共站点设置的”

原因：站点页面指定的是为员工创建的配置。站点访客和门户用户只能使用为站点保存的配置，这样员工日历的隐私设置和规则就不会误向公众开放。

解决方法

  1. 将日历的 Config Name 设为为该站点保存的配置，或
  2. 新建一个：在设置向导中，将您要将此组件放在哪里？回答为Experience 站点，并以新名称保存。

“此页面将预订关联到站点访问者无法查看的记录”

原因：站点上的每个预订都关联到同一条记录（在预订关联到中设置），而访客用户无法读取该记录。除非有访客共享规则共享记录，否则 Salesforce 会对访客隐藏记录。

解决方法

  1. 在“设置 > 共享设置”中，为该记录所属的对象添加访客共享规则，以“只读”方式将其共享给站点的访客用户。
  2. 再次运行检查我的站点：预订关联的记录应显示通过。

“未在此公开页面保存”

原因：Salesforce 允许站点访客读取和创建记录，但从不允许更改或删除。访问者可以查看和预订，有访问权限的已登录用户可以编辑。

解决方法

  1. 无需修复：这是 Salesforce 的访客规则。如要让用户更改自己的预订，请为他们提供登录账户（会员站点），或由员工代为更改。

“此日历的每个预订时长为 60 分钟，因此无法预订此时间”

原因：对于站点访客和门户用户，服务器会对照已保存的配置检查每个预订：预订时长、仅这些时间、可选择的状态、提前通知、预订时间范围和各项上限。页面打开期间管理员更改了其中一项，所以页面提供了配置已不再允许的选项。相关消息：此日历只在列出的开始时间接受预订和此日历中无法选择状态 Requested。

解决方法

  1. 重新加载页面，然后再次预订。
  2. 仍被拒绝？站点管理员可以在 Config Name 指定的配置中检查这些规则。

站点成员看不到自己创建的记录

原因：Experience Cloud 共享。站点用户只能看到共享规则授予他们的记录。

解决方法

  1. 在日期所保存的对象上添加共享规则（或为成员添加共享集），或
  2. 放开它的外部组织范围默认设置。

“站点不允许其他网站显示它”

原因：您用嵌入代码把日历放到了自己的网站上，而 Salesforce 站点默认拒绝在其他网站中显示。

解决方法

  1. 在 Experience Builder 中，打开“设置”，然后打开“安全和隐私”。
  2. 将 Clickjack Protection Level 设为Allow framing of site pages on external domains。
  3. 在 Trusted Domains for Inline Framing 下添加您的网站，然后发布。

访客看到地点列表，但看不到地图

原因：地图由一项 Salesforce 服务绘制，站点在将其设为受信任之前会阻止它。日历无法判断站点是否阻止了地图，因此在站点上会先显示列表，并提供地图。

解决方法

  1. 在 Experience Builder 中，打开“设置”，然后打开“安全和隐私”。
  2. 将 maps.a.forceusercontent.com 添加为框架的受信任站点，然后发布。

权限与安全

日历以每个用户自己的权限运行。先分配合适的权限集，再授予对您自己的对象和字段的访问权限。

权限集分配给
MultiDatePick - User所有使用日历的人
MultiDatePick - Setup创建配置的管理员。包括设置向导。
MultiDatePick - All Access既创建配置又使用日历的管理员
MultiDatePick - Guest公共 Experience Cloud 站点的访客用户

错误消息会写明出错的地方：字段、对象或验证规则。如果消息以详细信息：结尾，后面的文字就是 Salesforce 自己的描述。把它发给您的管理员或我们，它会准确指出该去哪里查。

“您需要 MultiDatePick 许可证才能使用此日历”

原因：MultiDatePick 按席位授予许可证，而该用户尚未分配席位。日历会被这条提示取代，保存也会被拒绝。站点访客永远不需要席位。

解决方法

  1. 在“设置”中打开已安装的软件包，然后单击 MultiDatePick 旁边的管理许可证。
  2. 单击添加用户并添加该用户。下次加载页面时，他们就能看到日历。

“此用户无权访问 MultiDatePick，因此未加载配置”

原因：该用户没有 MultiDatePick 权限集，所以 Salesforce 不允许日历为其运行相关类。红色横幅会显示这一点，灰色框中是 Salesforce 的原文。

解决方法

  1. 为用户分配 MultiDatePick - User，为同时创建配置的管理员分配 MultiDatePick - All Access。
  2. 在公开站点上，为站点的访客用户分配 MultiDatePick - Guest。

记录打不开，或提示“权限不足”

原因：用户无法读取父对象，或者共享设置对其隐藏了该记录。如果是屏幕 Flow，用户可能没有运行 Flow 的权限。

解决方法

  1. 分配 MultiDatePick - User。
  2. 在权限集中授予对父对象的“读取”权限。
  3. 检查共享设置是否向该用户授予了该记录的访问权限。
  4. 如果是屏幕 Flow，请在用户记录上勾选 Flow User（Flow 用户），或在权限集中授予 Run Flows（运行 Flow）用户权限。

“对对象 Y 上的字段 X 没有读取权限”

原因：对于日历显示的某个字段（状态、悬停、日期或时间字段），用户没有字段级安全性的“读取”权限。

解决方法

  1. 为消息中提到的字段授予“读取”权限。
  2. 管理员也要授予。新的自定义字段对所有人隐藏，包括系统管理员，直到有权限集授予访问权限为止。

提到某个字段的“Time group failed to save”（时间组保存失败）、“创建预订失败”或“您无法编辑字段”

原因：用户可以读取这些字段，但无法编辑保存时要写入的某个字段。通常是后来添加的状态、第二个选项列表或时间字段，或者是每条新记录都会自动填写的字段。

解决方法

  1. 为日历写入的每个字段授予“编辑”权限：日期、开始和结束时间、状态、第二个选项列表、名称字段、父记录查找字段，以及自动填写中的每个字段。
  2. 为记录所保存的对象授予“创建”权限。

“您无权执行此操作”，并附有“交叉引用 ID 的访问权限不足”

原因：新记录指向了用户看不到的记录：父记录或资源。

解决方法

  1. 至少授予对父对象和资源对象的“读取”权限，并共享这些记录。
  2. 在公开站点上，让访客预订到自定义对象上。Salesforce 限制访客访问联系人和客户。

“您无权访问此日历使用的关闭记录”

原因：用户无法读取保存关闭日期的对象，因此日历无法判断哪些日期已关闭。与之对应的您无权访问此日历显示的记录，表示预订本身也存在同样的问题。

解决方法

  1. 在权限集中授予对消息所指对象和字段的“读取”权限。
  2. 检查共享设置是否向该用户授予了这些记录的访问权限。

“您无法创建记录类型为‘Install’的 Visit 记录”

原因：日历为新预订设置的记录类型，不在该用户的简档或权限集中。

解决方法

  1. 将该记录类型添加到用户的简档或某个权限集中。
  2. 或将新预订的记录类型设为让用户选择，这样只会列出每个人能创建的类型。

“Salesforce 不允许您将此 Visit 分配给 Alex Chen”

原因：预订的会议室或人员是 Salesforce 用户，而 Salesforce 拒绝让其成为所有人。消息末尾会写明原因：您没有向其分配记录的访问权限、该用户处于非活动状态，或此类型的用户不能拥有此类记录。

解决方法

  1. 选择其他人。
  2. 或请您的 Salesforce 管理员授予您向该用户分配记录的权限，或激活该用户。

“您没有保存 MultiDatePick 配置的权限”

原因：配置以 Salesforce 元数据的形式保存，需要“Modify Metadata Through Metadata API Functions”权限，由 MultiDatePick - Setup 权限集授予。

解决方法

  1. 为创建配置的管理员分配 MultiDatePick - Setup 或 MultiDatePick - All Access。

Flow 与操作

屏幕 Flow（Screen Flow）中的日历，以及运行 Flow 的按钮。

Flow 屏幕忽略了我的向导设置

原因：Config Name 为空或拼写有误。为空时，组件会悄悄使用默认设置；拼写有误时，会显示“未找到名为 ... 的配置”。

解决方法

  1. 将 Config Name 设为与设置向导中保存时完全一致的配置名称。
  2. 不要改动那些开/关输入项。所有复选框都来自配置。

“部分所选日期尚未保存。请先点击保存或清除这些日期，然后再继续。”

原因：日历中还有从未保存的选择时，就按下了屏幕的“下一步”按钮，这些选择会丢失。如果是时间，消息会显示部分所选时间尚未预订。

解决方法

  1. 先单击“保存”（或“预订”），再单击“下一步”。
  2. 或清除不需要的选择，再单击“下一步”。

“无法运行 Send Reminder：需要‘Run Flows’权限或该流程的访问权限”

原因：日历的操作按钮会运行一个 Flow，而 Salesforce 只允许有权运行该 Flow 的人启动它。

解决方法

  1. 在权限集中为用户授予 Run Flows 权限，或
  2. 为其简档或权限集授予该 Flow 的访问权限（设置 > 流 > 该 Flow > 编辑访问权限）。

“流程因错误而停止”或“此操作在这里不可用”

原因：前者表示操作按钮背后的 Flow 运行时失败了。后者表示此记录不再提供该按钮：该操作已从已保存的配置中移除，或只针对其他状态。

解决方法

  1. 如果是 Flow 错误，管理员可以打开该 Flow 的运行历史或调试日志，查看是哪一步失败。
  2. 如果是操作不可用，请重新加载页面，然后在配置的操作设置中检查该操作的状态。

“此流程没有 recordId 或 recordIds 输入变量”

原因：设置向导通过名为 recordId（一条记录）或 recordIds（多条记录，来自编辑模式）的变量，把被单击的记录传给操作的 Flow。没有这个变量，Flow 就不知道要使用哪些记录。

解决方法

  1. 在 Flow Builder 中添加一个名为 recordId 的文本变量，或名为 recordIds 的文本集合，并设为可用于输入。
  2. 保存并激活该 Flow，然后在向导中重新选择它。

甘特图

甘特图视图中的任务、任务之间的链接和进度。

切换器中没有甘特图视图

原因：甘特图视图和地图视图一样，需要手动开启。Available Views 留空时只提供日历、时间轴、周、使用率和日程。

解决方法

  1. 在设置向导的“视图”选项卡中勾选提供甘特图视图，或在 Available Views 中加上 gantt。
  2. 如需默认打开甘特图视图，请将 View 设为 gantt。

“Site survey 无法安排在 12月6日：此日历不允许该日期。未保存任何内容。”

原因：甘特图沿用与日历相同的预订规则。任务不能移到已关闭的日期或时间，不能交给当天已在做其他任务的人，也不能交给不接受预订的资源。消息每次都会写明是哪条规则。

解决方法

  1. 把任务拖到另一天，或交给有空的人。
  2. 如果这一天应该开放，管理员可以检查配置中的关闭记录和可选日期。

“Install 不能等待 Testing：这会形成循环”

原因：Testing 已经直接或通过其他任务等待 Install，反向链接会导致两者都无法开始。相关提问替换链接？会在任务通过任务上的字段链接时出现：此时每个任务只能等待另一个任务。

解决方法

  1. 先移除反方向的链接，或链接其他任务。
  2. 要让一个任务等待多个任务，请用单独的链接对象链接任务：设置向导 > 甘特图视图 > 任务之间的链接。

“状态保持不变”或“完成保持不变，没有改为 100%”

原因：已完成任务的状态把完成百分比和状态绑定在一起：设为 100% 的任务会获得该状态，设为该状态的任务会被设为 100%。如果查看者无法编辑这两个字段之一，或状态字段没有该值，则只保存他们所做的更改，并由这条消息说明原因。

解决方法

  1. 为用户授予完成百分比字段和状态字段的“编辑”权限。
  2. 检查状态字段是否为该记录类型提供所选的值，或在甘特图视图设置中另选一个，或留空使两者互不关联。

“未保存任何内容。您只能查看 Site survey，不能更改。”

原因：查看者能看到该任务但无法编辑，原因可能是共享设置、字段安全性或记录所有人。它的卡片上会显示您只能查看。

解决方法

  1. 请任务的所有人或管理员通过共享为您授予“编辑”权限。
  2. 在您的权限集中检查任务日期字段的“编辑”权限。

配置导入

把来自 Config Library 或其他组织的配置粘贴到设置向导的“导入 / 导出”选项卡中。

“这不是完整的配置”或“这看起来是 XML，而不是 JSON”

原因：粘贴的文本不是一个完整的配置：复制时被截断了，或者是 Salesforce 元数据 XML 或 Flow 而不是配置的 JSON，或者包含了一整个文件的配置（超过 100 KB）。

解决方法

  1. 用 Config Library 的复制按钮，或在另一个组织中用“导出配置”重新复制该配置。
  2. 粘贴全部文本，从第一个 { 到最后一个 }。

手上是 Flow XML？请改为将其作为 Flow 部署：从 VS Code 部署 Flow。

“此配置缺少 Related_Object__c 无法运行”

原因：粘贴的配置缺少每个配置都需要的设置，例如对象、日期字段或组件类型。

解决方法

  1. 重新完整复制该配置，或
  2. 从您的组织导出一个可用的配置来查看所需的结构，并补上缺少的设置。

某个设置“会保存‘Confirmed’，但 Visit Status 中没有该值，因此 Salesforce 会拒绝每次保存”

原因：导入的配置中某个设置（例如自动填写或可选择的状态）使用了您的状态字段中没有的状态值。照原样保存的话，每个预订都会被拒绝。在对应状态值步骤中，标记为您的字段没有类似的值的值会被省略，直到您选择一个值。

解决方法

  1. 返回对应状态值。
  2. 为每个值选择您这边含义相同的值，然后单击“应用并部署”。

“此组织中没有其流程 Send_Reminder”

原因：导入的配置中有一个操作按钮，会运行您的组织中没有的 Flow。

解决方法

  1. 在操作步骤中，为该按钮选择您自己的一个 Flow，或选择跳过此操作。
  2. 之后可以在配置的操作设置中再添加该操作。
