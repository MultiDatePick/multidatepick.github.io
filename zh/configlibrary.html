导入配置的流程

这些示例配置基于 MultiDatePick 自带的演示对象（Schedule__c、Event__c、Resource__c）构建。您的组织几乎总会使用自己的对象和字段名称。这在预期之内，并且完全支持。

  1. 在下方任意卡片上单击 Copy for Setup Wizard。
  2. 粘贴到设置向导的导入选项卡中（应用程序启动器 > MultiDatePick 设置向导 > 导入）。
  3. 映射字段：如果 JSON 中引用的对象或字段在您的组织中不存在，向导会显示智能字段映射 (Smart Field Mapping) 面板，列出每一个缺失的引用，并提供您组织中对应对象/字段的下拉列表。为每一项选好替代项，然后单击应用映射。
  4. 按 Config Name 使用：把组件放到 Lightning 页面、Experience 站点或 Flow 屏幕上，输入 Config Name。

无需代码，无需编辑 XML。向导会在部署元数据之前用您的选择改写配置，因此导入的配置部署后即可直接放到您组织的记录页面上。如果所有内容都已匹配（例如在沙盒之间克隆），映射步骤会自动跳过。

这里没有合适的配置？在向导中自己创建一个。

每个对象和字段都是按您的组织筛选好的下拉列表，几分钟就能做好一个可用的配置，无需输入任何 API 名称。

想在屏幕 Flow（Screen Flow）中使用？用同一个配置即可。

把组件拖到 Flow 屏幕上，输入 Config Name。如需让 Flow 为每个日期或班次各保存一条记录，请参阅关于 Flow 循环的文章。

避开节假日的预约排期

面向最终用户的预约选择器，自动把办公室关闭的日期变灰。它通过 Blocked Dates Object、Blocked Dates Filter Field 和 Blocked Dates Filter Value 从 办公室停业日历 的记录中读取屏蔽列表，因此客户只能在真正营业的日子预约。

以 User 作为资源：Resource Object API Name 设为 User，并用自定义复选框 Is_Advisor__c 筛选，让选择器只列出顾问，而不是组织中所有活跃用户。User 上的 Business Hours Start Field 和 Business Hours End Field 为每个人设定各自的工作时间，因此周网格显示的是他们实际工作的时段。Conflict Behavior 设为 block，因为一个人绝不能被重复预订。
关键设置
  • Resource Object API Name User resourceObjectApiName
  • Resource Filter Field (optional) Is_Advisor__c resourceFilterField
  • Booking Resource Field bookingResourceField
  • Second Picklist Field Meeting_Type__c secondStatusField
  • Conflict Behavior block conflictBehavior
  • Blocked Dates Object blockedDatesSourceObject
  • Hover Popover Fields hoverFields

子块使用场景

启用 Consolidate Time Span 后，所选时间段之间的空档会被自动识别，并作为单独的记录保存到子对象上。用户也可以手动把时间段标记为子块。

  • 含休息的排班：员工选择早 8 点到下午 5 点；中午 12 点到 1 点的午餐空档会自动在 Break__c 对象上创建一条记录
  • 差旅行程：用户锁定出行时间窗口；航班之间的中转成为 Travel_Leg__c 记录
  • 培训日程：讲师选择授课时间段；课程之间的空闲时间段保存为 Available_Slot__c 记录
  • 含预约的工作日程：经理设定工作时间；为会议或预约留出的空档会自动保存到 Appointment__c 对象
重要：本库中的每个配置都使用示例对象和字段名称。导入前，请把橙色的值替换为您的记录对象和字段 API 名称。如果使用子块，请把紫色的值替换为您的子对象和字段。如果使用屏蔽日期，还要替换红色的值。其他内容可以原样使用。
