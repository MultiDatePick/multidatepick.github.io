无需编写代码，配置 Salesforce 日历

100 多个属性听起来像个大项目。其实只是一个四步向导：自动为您填好最可能的选项，保存任何内容之前都能实时预览。

发布于 2026 年 8 月 19 日 · 更新于 2026 年 10 月 31 日 · MultiDatePick

大多数功能强大的 Salesforce 组件都要学两遍：一遍弄懂属性，一遍记住上次选的是哪种组合。设置向导让您两遍都不用学。它询问日历放在哪里、每次选择保存什么，填好能推断出的字段，把配置写成元数据，再交给您一个随处可用的名称。

一个入口，外加两条捷径

“新建”选项卡打开的是引导式设置。旁边另有两个选项卡，用于已有的配置。

引导式设置

先定日历放在哪里、每次选择保存什么，再自动填好最可能的字段。适合大多数场景。

所有设置在一个页面上

100 多项设置全部在一个页面上，并可实时预览。适合清楚知道自己要什么的时候。

现有

列出您已保存的配置及其组件类型。打开一个即可编辑或克隆。

导入

粘贴来自 Config Library 或其他组织的配置。

四步完成，从头到尾

步骤您需要设置的内容
1. 放置位置任意对象的记录页面、应用页面或主页、屏幕流或公共站点，以及日历大小。
2. 结构每次选择保存什么：每天一条记录、每个时间段一条、每个时间段块一条、含休息的一条，或者预订一个或多个资源。
3. 快速开始选择保存对象，关联、日期、标题、状态、时间和资源字段会自动填好。规则、关闭日、视图、悬停卡片、状态以及其他所有设置都有各自的选项卡。
4. 检查每个设置部分都有“更改”链接和实时预览，确认后保存。向导会显示要粘贴的 Config Name。

结构决定一切

引导式设置询问的是您想要的记录结构，而不是属性。六张卡片，每张都配有小图，展示用户选择的内容和保存到 Salesforce 的内容：

  1. 每天一条记录，还是每个时间段一条？连续六周的周一到周五，可以是三十条记录，也可以是六条。
  2. 每个时间段块一条记录，还是一条记录内含休息？有午休的培训日，可以是两条记录，也可以是一条记录加一次休息。
  3. 要预订房间或人员吗？一次一个、一次多个，或者给时间段、时间段块或含休息的一天外加一个。

这一点有意安排在这里决定，在任何数据产生之前。结构还会选好合适的组件，因此不需要再做其他决定。

保存之前就能看到实时预览

“检查”步骤中的预览会根据您的选择呈现一个可实际操作的日历。打开双月视图，它就会出现；添加状态颜色，单元格就会着色。这就是真实的组件，所见即所部署。

排期配置中代价最高的错误，是那些要等真实记录出现后才看得见的形状决策。在您还在考虑时就能看到日历的反应，大部分风险就消除了。

快速开始的内部：字段、时间、状态

在预订或排程配置中，两个选项卡承担了大部分工作。“时间”设置可预订的时段、时段长度、预订后的间隔和提前通知，并对应开始和结束时间字段。“状态”负责视觉效果：每个状态的颜色、要隐藏的状态，以及用户可选的状态。

在“状态与显示”中，选择一个状态字段，为每个值指定颜色，并选择颜色是填充日历单元格、时间段网格，还是两者都填。添加悬停字段后，指向某个预订即可预览详细信息。

它实际写入了什么

保存会部署一条自定义元数据记录。由此带来三点：

  • 可以部署。自定义元数据和其他组件一样，可以通过您常规的发布流程从沙盒迁移到生产环境。
  • 可以复用。在任何组件的 Config Name（配置名称）中填入这个名称，它就会采用整套配置。一个配置，多处使用。
  • 留在您的组织中。不会存储在供应商的服务器上，所以配置归您所有，并且在“设置”中可见。
关于部署。自定义元数据的部署是异步的。向导会等待约两分钟；如果记录仍未出现，它会显示部署 Id 以及指向“设置”→“部署状态”的链接。繁忙的组织可能需要比向导等待更长的时间，但部署仍会完成。
谁可以运行它。为构建配置的管理员分配 MultiDatePick - Setup，其中包含设置向导。所有使用日历的人分配 MultiDatePick - User，而 MultiDatePick - All Access 两者都包含。

导入、导出，以及容易被忽略的映射步骤

“导入”选项卡接收一份 JSON 配置，并把它变成已保存的配置。Config Library 就是这样运作的：40 多个现成配置，涵盖休假申请、会议室预订、共享工位、面试安排、车队预订等。

最省时间的一步是智能字段映射。资源库中的配置引用的是演示对象，而您的组织有自己的对象。粘贴的那一刻，向导就会扫描每个引用，标出您组织中不存在的引用，并在旁边放一个下拉列表，选项实时来自该对象真实的字段列表。在向导中重新映射，单击“应用映射”，它就会用改写后的 JSON 完成部署。无需文本编辑器，无需查找替换，无需重新上传。

导出的流程正好相反，这让配置可以共享。在一个组织中可用的配置，粘贴一下就能在另一个组织中使用。

配置建好之后如何使用

把三个组件中的任意一个拖到 Lightning 记录页面、应用程序页面、主页或 Experience Cloud 站点上，将 Config Name 设为您取的名称，其他属性全部留空，由配置提供。在应用程序页面、主页和 Experience 页面上，将父记录填入 Static Parent Record Id。

在屏幕 Flow（Screen Flow）中也一样：把配置名称填入 Config Name，所有开关设置都来自配置。您无需在 Flow Builder 中勾选任何复选框；少数仅限 Flow 的设置（Required、Show Inline、Output Date Ranges as JSON）默认关闭，除非您主动开启。将父记录传入 Parent Record Id。
