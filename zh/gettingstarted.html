安装MultiDatePick 尚未在 AppExchange 上架：上架时通知我，现在就可以在在线演示中试用所有功能，无需登录。上架后，单击 Get It Now，可选择仅为管理员、为所有用户或为特定简档安装。

语言如果您的组织使用翻译工作台 (Translation Workbench)，必须在“设置”中“翻译工作台”下的“翻译语言设置”中启用每位用户的语言，MultiDatePick 已翻译的选项列表值（例如状态值）才会显示。字段标签和日历本身的文字无论如何都会翻译。

5将 MultiDatePick 添加到屏幕 Flow

绑定 Parent Record Id，每个组件都会自己保存记录，无需循环。在 Flow Builder 中打开一个屏幕，搜索 MultiDatePick，将组件拖上去，设置 Config Name，并把 Parent Record Id 绑定到流程所针对的记录，例如 {!recordId}。

新建的屏幕 Flow 没有 recordId 变量。绑定之前先创建它：在工具箱中单击新建资源，资源类型选择变量，API 名称填写 recordId，数据类型选择文本，勾选可用于输入，然后单击完成。从快速操作启动时，会自动填入记录的 Id；在记录页面上，只要在其 Flow 组件中勾选将记录 ID 传递到此变量，也会自动填入。

复选框由配置决定。Flow Builder 会在每个复选框属性旁显示 True 和 False 两个选项，请保持未设置：只要设置了 Config Name，就由配置决定。只有 Flow 专用的属性（Required、Show Inline）采用您选择的值，在设为 True 之前保持关闭。

谁可以运行。每个运行该 Flow 的用户，都需要在其用户记录上勾选 Flow User（Flow 用户）复选框，或在权限集中拥有 Run Flows（运行 Flow）用户权限。否则，Salesforce 会显示“权限不足”，而不是该 Flow。

想要完全掌控？在设置向导中，将 Dates 或 Dates & Times 的由谁保存?设为由我的流程保存（或将 Parent Record Id 留空），所选内容就会交给流程。添加 Parse Date Entries from JSON 操作，循环其输出，每个条目创建一条记录。全部点选完成。所有细节都在 Flow 速查表中。

在页面自身的记录上设置日期

MultiDatePick 会把选择保存为独立的记录。要把一个选中的日期写入记录本身的日期字段（例如客户上的“跟进日期”），请使用一个小型屏幕 Flow。

  1. 在 Flow Builder 中创建一个屏幕 Flow，并添加一个名为 recordId、可用于输入的文本变量。
  2. 添加一个包含 Dates 的屏幕。将 Max Dates Allowed 设为 1，并将 Parent Record Id 留空，这样所选日期会传给 Flow，而不会被保存。
  3. 添加一个循环，遍历组件的 Selected Dates (Output)（其中只有这一个日期），并在循环内添加一个更新记录元素：更新 Id 为 {!recordId} 的记录，把您的日期字段设为公式 DATEVALUE({!Loop_Item})，并用您的循环名称替换 Loop_Item。
  4. 保存并激活，然后用 Flow 组件把它添加到记录页面（把记录 Id 传入 recordId），或作为快速操作添加。

设置常见问题

管理员最先问到的问题，简短作答。

设置 MultiDatePick 需要 Apex 或开发人员吗？

不需要。安装软件包后，在设置向导中从下拉列表选择对象和字段来创建配置，再把组件放到页面或 Flow 屏幕上即可。无需 Apex。

应该分配哪个 MultiDatePick 权限集？

MultiDatePick - Setup 给负责创建配置的管理员，MultiDatePick - User 给只使用日历的人，MultiDatePick - All Access 给两者都做的管理员，MultiDatePick - Guest 给公开 Experience Cloud 站点的访客用户。用户还需要对您自己的对象和字段拥有访问权限。

为什么应用程序页面或主页上的日历没有“保存”按钮？

应用程序页面和主页没有自己的记录。在设置向导中回答“谁的记录?”（“仅查看者”、“所有人”和“仅符合条件的”都不需要父记录；“某一条记录的”需要在“将每次选择关联到此记录”中填入该记录的 Id），然后再次保存配置。

在 Flow Builder 中必须逐个设置复选框吗？

不必。把 Config Name 设为您在设置向导中保存的配置，所有复选框设置都会来自该配置。只有在不填 Config Name、手动设置属性时，才需要自己设置复选框。

可以把 MultiDatePick 配置迁移到另一个 Salesforce 组织吗？

可以。在“现有配置”选项卡中导出配置，然后把 JSON 粘贴到另一个组织的“导入 / 导出”选项卡中。导入时可以匹配名称不同的对象或字段。

使用 MultiDatePick 需要哪些 Salesforce 对象？

预订需要一个预订对象，带一个日期和一个查找字段，指向带名称的资源对象。选择需要一个子对象，带一个日期和一个查找字段，指向它所属的记录。规划需要一个带开始日期的对象；指向项目的查找字段可以把任务归组。可以用您自己的对象，也可以用 MultiDatePick 自带的现成对象 MDP Schedule 和 MDP Resource。
