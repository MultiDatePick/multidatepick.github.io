Flow Cheat Sheet

Build a Screen Flow with MultiDatePick from scratch — step by step, no deploy required — then wire up the bundled Apex action to loop the results and create records. Everything an admin needs to go from a calendar on a screen to rows in Salesforce.

What you'll do: drop the component on a flow screen → capture its JSON output → run it through Parse Date Entries from JSON → loop the entries → create one record each. Jump to the step-by-step build or the Apex reference.

Build the flow, step by step

This walkthrough uses the Date Time component (dates + time slots), because that's the case where the Apex parser earns its keep. The Date and Booking components work the same way — just fewer or more fields per entry. Nothing here gets deployed; you test it right inside Flow Builder's Debug.

1 Create a new Screen Flow

In your org, go to Setup → Flows → New Flow, choose Screen Flow, and click Create. A Screen Flow is the only flow type that can render a Lightning component, which is what MultiDatePick is.

2 Add a Screen and drop in the component

On the canvas, add a Screen element. In the screen editor's left-hand component list, search for MultiDatePick and drag Date Time onto the screen.

3 Configure the component for Flow output

In the component's settings panel on the right, set a Label and any options you like (Max Selections, Time Interval, business hours, etc.). To use the Flow-managed pattern, leave the Click-to-Save fields blank — Record Id, Related Object, Date Field, and Relationship Field. With those empty, the component emits its selections as output variables instead of saving records itself.

Shortcut (Date component only): the Date component also exposes selectedDates, a plain Text collection you can loop directly — no parser needed. Use the parser when you need ranges or times (Date Time / Booking).

4 Grab the JSON output

The Date Time component exposes selectedDatesWithTimesJson as an output. You can store it in a Text variable for clarity (e.g. varDatesJson), or reference the screen component's output directly in the next step. This single string holds every selected date and its start/end time.

5 Add the "Parse Date Entries from JSON" action

After the Screen, add an Action element and search for Parse Date Entries from JSON. Set its input to your JSON string ({!varDatesJson} or the component output). This bundled Apex action turns the string into a list of typed entries Flow can loop.

6 Store the parsed result

For the action's output, create a new variable of type Apex-Defined, class MultiDatePickEntryCollection (e.g. parsedEntries). Its .data property is the list of entries you'll loop in the next step.

7 Loop the entries and create records

Add a Loop element over {!parsedEntries.data}. Inside the loop, add a Create Records element pointed at your object, mapping the loop variable's fields:

Loop variable fieldYour record field
currentEntry.fromDateDate field (e.g. Appointment_Date__c)
currentEntry.startTimeStart Time field
currentEntry.endTimeEnd Time field
currentEntry.toDateEnd Date field (only differs from fromDate for ranges)

8 Save and Debug — no deploy needed

Click Save, then Debug. The flow runs right inside Flow Builder: pick a few dates and times, finish, and confirm your records were created. When you're happy with it, Activate and drop it wherever you need it — an action button, a Lightning page, or an Experience Site.

Prefer no Apex at all? Set the component's Record Id, Related Object, Date Field, and Relationship Field and it saves records itself (Click-to-Save mode) — skip steps 4–7 entirely. The User Guide covers both modes.

The Apex you'll wire up

You don't write any code — these three classes ship with the package. Here's what each one is for, so the Flow steps above make sense.

Invocable Action

Parse Date Entries from JSON (MultiDatePickParser)

The action you add in step 5. It takes the component's JSON output and returns a typed collection Flow can loop. It accepts either output format below, and handles date-only or date+time automatically.

Find it in Flow asAction → search "Parse Date Entries from JSON"
InputA JSON string — selectedDateRangesJson (Date) or selectedDatesWithTimesJson (Date Time)
OutputA MultiDatePickEntryCollection
Apex-Defined Type

MultiDatePickEntryCollection

The wrapper the action returns. Store it in step 6; loop its .data in step 7.

PropertyWhat it holds
dataThe list of entries — this is what you loop
totalCountHow many entries were parsed
successtrue if parsing worked; false if the JSON was malformed
errorMessageThe parse error, if any (handy for a decision element)
Apex-Defined Type

MultiDatePickEntry

One row inside .data — this is your loop variable. Map these onto your record's fields in the Create Records element.

FieldTypeNotes
idNumberSequential index of the entry
fromDateDateThe selected date (start of the range)
toDateDateEnd of the range — equals fromDate for single dates
startTimeTimePopulated for Date Time selections
endTimeTimePopulated for Date Time selections

Booking scenarios also carry resourceId, resourceName, and bookingStatus on each entry.

The two output formats

Which output you feed the parser depends on the component.

Output variableFromShape
selectedDateRangesJson Date Consecutive dates grouped into ranges
selectedDatesWithTimesJson Date Time Each date with its start and end time

Date ranges JSON

{
  "data": [
    { "id": 1, "fromDate": "2026-02-10", "toDate": "2026-02-12" },
    { "id": 2, "fromDate": "2026-02-15", "toDate": "2026-02-15" }
  ]
}

Dates + times JSON

{
  "data": [
    { "id": 1, "fromDate": "2026-02-10", "toDate": "2026-02-10", "startTime": "09:00", "endTime": "17:00" },
    { "id": 2, "fromDate": "2026-02-11", "toDate": "2026-02-11", "startTime": "09:00", "endTime": "17:00" }
  ]
}
