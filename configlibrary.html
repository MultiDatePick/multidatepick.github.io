How importing a config works

These sample configs are built against MultiDatePick's bundled demo objects (Schedule__c, Event__c, Resource__c). Your org will almost always use its own objects and field names. That's expected and supported.

  1. Copy for Setup Wizard on any card below.
  2. Paste it into the Setup Wizard's Import tab (App Launcher, MultiDatePick Setup Wizard, Import).
  3. Map the fields: if any objects or fields referenced in the JSON don't exist in your org, the wizard will surface a Smart Field Mapping panel listing every missing reference with a dropdown of your org's matching objects/fields. Pick the replacement for each and click Apply & Deploy.
  4. Use its Config Name: place the component on a Lightning page, an Experience site or a Flow screen and type the Config Name.

No code, no XML editing. The wizard rewrites the config with your selections before the metadata deploy, so the imported config lands ready to drop on a record page in your org. If everything already matches (e.g. you're cloning between sandboxes), the mapping step is skipped automatically.

No config here that fits? Build one in the wizard.

Every object and field is a dropdown filtered to your org, so a working config takes a few minutes and no API names.

Want it in a Screen Flow? Use the same config.

Drag the component onto a Flow screen and type the Config Name. For a flow that saves one record per date or shift, see the Flow loops post.

One config, five ways to look at it

Every config below sets a default View and an Available Views list. The data, the fields and the save behavior stay identical: only the layout changes. Users switch with the pills above the calendar, and you decide which ones they get.

calendar

Month grid

The default. A month at a time, status colors per day, click or drag to pick dates. Best when the question is "what is happening on the 14th".

timeline

Resources down, dates across

Two weeks by default so every booking has room for its name. Multi-day bookings draw as one bar. Busy resources collapse to a single row you can expand.

week

Day by hour

Seven days across, your business hours down. Drag horizontally, vertically, or both to select a block of time across several days at once.

utilization

Capacity heatmap

Percentage of capacity used per resource per day, colored green through red. Needs a Capacity Field to show percentages rather than raw counts.

Read only
agenda

Chronological list

The next 60 days as a flat, scannable list with times and statuses. Good for a handover, a daily brief, or a mobile screen.

Read only
Before you pick a default. Utilization and Agenda are read only, so they are a poor default for a config whose whole job is booking: put them in Available Views and default to a writable view instead. And the default view is always offered in the switcher whether or not you list it, so Available Views only ever needs the extras.

Sub-Block Use Cases

When Consolidate Time Span is enabled, gaps between selected time slots are automatically detected and saved as separate records on a child object. Users can also manually mark slots as sub-blocks.

  • Shift scheduling with breaks: Employee selects 8 AM to 5 PM; the 12 to 1 PM lunch gap auto-creates a record on a Break__c object
  • Travel itineraries: User blocks travel windows; layovers between flights become Travel_Leg__c records
  • Training schedules: Instructor selects teaching blocks; free periods between sessions save as Available_Slot__c records
  • Work schedules with appointments: Manager defines work hours; gaps for meetings or appointments auto-save to an Appointment__c object
