शेड्यूलिंग की हर आम ज़रूरत के लिए आयात के लिए तैयार 41 कॉन्फ़िगरेशन, हर एक के व्यू पहले से चुने हुए। एक को Setup Wizard में कॉपी करें, फिर उसके Config Name से उसे किसी Lightning पेज, Experience साइट या Flow स्क्रीन पर इस्तेमाल करें। फ़ील्ड के नाम एक क्लिक में आपके org से मैप हो जाते हैं।

कॉन्फ़िगरेशन आयात कैसे होता है

ये नमूना कॉन्फ़िगरेशन MultiDatePick के साथ आने वाले डेमो ऑब्जेक्ट (Schedule__c, Event__c, Resource__c) पर बने हैं। आपका org लगभग हमेशा अपने ऑब्जेक्ट और फ़ील्ड नाम इस्तेमाल करेगा। यह अपेक्षित है और पूरी तरह सपोर्टेड है।

  1. नीचे किसी भी कार्ड पर Copy for Setup Wizard।
  2. Setup Wizard के आयात टैब में पेस्ट करें (App Launcher, MultiDatePick Setup Wizard, आयात)।
  3. फ़ील्ड मैप करें: अगर JSON में बताए कुछ ऑब्जेक्ट या फ़ील्ड आपके org में नहीं हैं, तो Wizard एक Smart Field Mapping पैनल दिखाता है, जिसमें हर गायब नाम के साथ आपके org के मिलते-जुलते ऑब्जेक्ट/फ़ील्ड का ड्रॉपडाउन होता है। हर एक का विकल्प चुनें और लागू करें और डिप्लॉय पर क्लिक करें।
  4. उसका Config Name इस्तेमाल करें: कंपोनेंट को किसी Lightning पेज, Experience साइट या Flow स्क्रीन पर रखें और Config Name टाइप करें।

न कोड, न XML एडिटिंग। metadata डिप्लॉय से पहले Wizard आपके चुनावों के साथ कॉन्फ़िगरेशन को दोबारा लिखता है, इसलिए आयात किया गया कॉन्फ़िगरेशन आपके org में किसी रिकॉर्ड पेज पर रखने के लिए तैयार पहुँचता है। अगर सब पहले से मेल खाता है (जैसे आप sandbox से sandbox क्लोन कर रहे हैं), तो मैपिंग का चरण अपने आप छूट जाता है।

यहाँ कोई कॉन्फ़िगरेशन फ़िट नहीं बैठता? Wizard में एक बनाएँ।

हर ऑब्जेक्ट और फ़ील्ड आपके org तक सीमित एक ड्रॉपडाउन है, इसलिए एक चालू कॉन्फ़िगरेशन कुछ ही मिनट लेता है और कोई API नाम नहीं।

इसे Screen Flow में चाहते हैं? वही कॉन्फ़िगरेशन इस्तेमाल करें।

कंपोनेंट को Flow स्क्रीन पर ड्रैग करें और Config Name टाइप करें। हर तारीख या शिफ़्ट का एक रिकॉर्ड सहेजने वाले Flow के लिए Flow loop वाला लेख देखें।

  • ब्रेक वाली शिफ़्ट शेड्यूलिंग: कर्मचारी सुबह 8 से शाम 5 बजे तक चुनता है; दोपहर 12 से 1 बजे का लंच अंतराल अपने आप Break__c ऑब्जेक्ट पर एक रिकॉर्ड बनाता है
  • यात्रा कार्यक्रम: यूज़र यात्रा की विंडो ब्लॉक करता है; फ़्लाइट के बीच के लेओवर Travel_Leg__c रिकॉर्ड बनते हैं
  • ट्रेनिंग शेड्यूल: इंस्ट्रक्टर पढ़ाने के ब्लॉक चुनता है; सेशन के बीच के खाली पीरियड Available_Slot__c रिकॉर्ड के रूप में सहेजे जाते हैं
  • अपॉइंटमेंट वाले काम के शेड्यूल: मैनेजर काम के घंटे तय करता है; मीटिंग या अपॉइंटमेंट के अंतराल अपने आप Appointment__c ऑब्जेक्ट में सहेजे जाते हैं
ज़रूरी: इस लाइब्रेरी का हर कॉन्फ़िगरेशन उदाहरण के ऑब्जेक्ट और फ़ील्ड नाम इस्तेमाल करता है। आयात से पहले नारंगी मानों को अपने रिकॉर्ड ऑब्जेक्ट और फ़ील्ड API नामों से बदलें। अगर आप sub-block इस्तेमाल करते हैं, तो बैंगनी मानों को अपने चाइल्ड ऑब्जेक्ट और फ़ील्ड से बदलें। अगर आप अवरुद्ध तारीखें इस्तेमाल करते हैं, तो लाल मान भी बदलें। बाकी सब जैसा है वैसा काम करता है।
