समस्या निवारण

स्क्रीन पर दिख रहा संदेश खोजें या कोई श्रेणी चुनें, फिर समाधान अपनाएँ। हर तस्वीर असली कंपोनेंट की है।

श्रेणियाँ

इस पेज पर कुछ भी मेल नहीं खाता। कम शब्द या कोई दूसरी श्रेणी आज़माएँ, या जो दिख रहा है उसके स्क्रीनशॉट के साथ सपोर्ट को ईमेल करें।

सेटअप और प्लेसमेंट

पेज पर कैलेंडर लगाते समय या उसका कॉन्फ़िगरेशन बनाते समय एडमिन को दिखने वाले बैनर और चेतावनियाँ।

सहेजें बटन नहीं है

कारण: कंपोनेंट के पास कोई parent रिकॉर्ड नहीं है और वह सभी रिकॉर्ड दिखाने के लिए सेट नहीं है। ऐप और होम पेज का अपना कोई रिकॉर्ड नहीं होता।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें और किसके रिकॉर्ड? का जवाब दें (आम तौर पर सिर्फ़ देखने वाले के), या हर चयन को इस रिकॉर्ड से जोड़ें (App Builder: Static Parent Record Id) में वह रिकॉर्ड सेट करें जिससे तारीखें जुड़ी हैं।
  2. जाँचें कि ऑब्जेक्ट, तारीख फ़ील्ड और relationship फ़ील्ड भरे हैं, या Config Name सेट करें।

Flow में Parent Record Id जुड़ते ही सहेजें बटन दिखता है। यह तब छिपा रहता है जब विज़ार्ड में इन्हें कौन सेव करेगा? का जवाब मेरा फ़्लो सेव करता है हो, या Parent Record Id खाली हो: तब तारीखें Flow का Next बटन आगे ले जाता है।

पीला बैनर: "इस कॉन्फ़िगरेशन के लिए गलत घटक" (Wrong component for this configuration)

कारण: Config Name किसी दूसरे कंपोनेंट के लिए सहेजे गए कॉन्फ़िगरेशन की ओर इशारा करता है।

समाधान

  1. Config Name में इसी कंपोनेंट के लिए बना कॉन्फ़िगरेशन डालें, या
  2. उसकी जगह वह कंपोनेंट लगाएँ जिसके लिए कॉन्फ़िगरेशन बना था, या
  3. Setup Wizard में कॉन्फ़िगरेशन खोलें और उसका घटक प्रकार (Component Type) बदलें।

पीला बैनर: "कॉन्फ़िगरेशन में बेमेल" (Configuration mismatch)

कारण: पेज का रिकॉर्ड, या हर चयन को इस रिकॉर्ड से जोड़ें वाला रिकॉर्ड, उस ऑब्जेक्ट से अलग है जिसकी ओर कॉन्फ़िगरेशन का relationship फ़ील्ड lookup करता है।

समाधान

  1. कंपोनेंट को उस ऑब्जेक्ट के रिकॉर्ड पेज पर लगाएँ जिसका नाम बैनर में है, या
  2. हर चयन को उसी ऑब्जेक्ट के किसी रिकॉर्ड से जोड़ें, या
  3. इस पेज के ऑब्जेक्ट के लिए बना कॉन्फ़िगरेशन इस्तेमाल करें।

लाल बैनर: "यह घटक अपना डेटा लोड नहीं कर सका" (This component couldn't load its data)

कारण: सेटअप में किसी फ़ील्ड या ऑब्जेक्ट का नाम गलत है, या यूज़र MultiDatePick नहीं चला सकता या ऑब्जेक्ट और उसके फ़ील्ड नहीं पढ़ सकता।

समाधान

  1. ग्रे बॉक्स पढ़ें: उसमें ठीक वह फ़ील्ड, ऑब्जेक्ट या Apex क्लास लिखी होती है। MultiDatePick का एक्सेस न हो तो बैनर बताता है कि कौन सा permission set असाइन करना है।
  2. गलत नाम: Setup के Object Manager से ठीक वही API नाम कॉपी करें।
  3. एक्सेस नहीं: MultiDatePick - User permission set असाइन करें, साथ में अपने ऑब्जेक्ट का एक्सेस दें। सार्वजनिक Experience साइट पर guest user को MultiDatePick - Guest असाइन करें और उसे अपने ऑब्जेक्ट पर Read एक्सेस दें।

Resource Booking पर "कॉन्फ़िगरेशन आवश्यक" लिखा आता है

कारण: Resource Booking को एक संसाधन ऑब्जेक्ट, एक बुकिंग ऑब्जेक्ट, एक बुकिंग तारीख फ़ील्ड और एक बुकिंग संसाधन फ़ील्ड चाहिए। पैनल में वे दिखते हैं जो अभी कम हैं।

समाधान

  1. Config Name में Setup Wizard का कोई Resource Booking कॉन्फ़िगरेशन डालें, या
  2. पैनल में दी गई हर प्रॉपर्टी भरें।

""Room_Bookings" नाम का कोई कॉन्फ़िगरेशन नहीं मिला"

कारण: Config Name में कॉन्फ़िगरेशन का API नाम चाहिए, जो Setup Wizard की मौजूदा कॉन्फ़िगरेशन सूची में होता है (उदाहरण Contact_Event), उसका लेबल नहीं। स्पेलिंग की गलती, लेबल डालना, या अभी-अभी सहेजा गया कॉन्फ़िगरेशन जो अभी डिप्लॉय हो रहा है, इन सबका नतीजा यही संदेश है।

समाधान

  1. Setup Wizard खोलें, फिर मौजूदा कॉन्फ़िगरेशन में जाकर कॉन्फ़िगरेशन का API नाम कॉपी करें।
  2. इसे कंपोनेंट के Config Name में पेस्ट करें और पेज सहेजें।
  3. कॉन्फ़िगरेशन अभी सहेजा है? Salesforce इसे बैकग्राउंड में डिप्लॉय करता है, जिसमें 30 सेकंड से 2 मिनट लगते हैं। जब तक वह दिख न जाए, मौजूदा कॉन्फ़िगरेशन रीफ़्रेश करें, फिर पेज रीलोड करें।

अगर संदेश यह बताता है कि यूज़र के पास MultiDatePick की पहुँच नहीं है, तो MultiDatePick की पहुँच नहीं देखें।

"Static Parent Record Id (a015g00000XyZ12AAB) वाला रिकॉर्ड अब मौजूद नहीं है"

कारण: कैलेंडर हर चयन को एक तय रिकॉर्ड में सहेजता है, जो हर चयन को इस रिकॉर्ड से जोड़ें (App Builder: Static Parent Record Id) में सेट है, और वह रिकॉर्ड डिलीट हो चुका है। जब तक यह किसी मौजूद रिकॉर्ड की ओर इशारा न करे, कुछ भी सहेजा नहीं जा सकता।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें और हर चयन को इस रिकॉर्ड से जोड़ें में कोई दूसरा रिकॉर्ड चुनें।
  2. जिस पेज पर Config Name नहीं है, वहाँ App Builder में Static Parent Record Id में किसी मौजूदा रिकॉर्ड का Id पेस्ट करें।

तारीखें सहेजी जाती हैं, पर अगली बार नहीं दिखतीं

कारण: पहले से सहेजी तिथियाँ दिखाएँ (App Builder: Load Existing Dates) बंद है। रिकॉर्ड सहेजे गए, पर कैलेंडर हर बार खाली खुलता है।

समाधान

  1. पहले से सहेजी तिथियाँ दिखाएँ चालू करें।
  2. पेज रीलोड करें। सहेजी गई तारीखें दिखने लगती हैं, और स्थिति फ़ील्ड सेट हो तो स्थिति के रंग में।

"यह कैलेंडर मौजूदा रिकॉर्ड नहीं दिखा सकता और नए रिकॉर्ड सहेज नहीं सकता: Visit पर फ़ील्ड "Visit Date" Shield Platform Encryption से एन्क्रिप्ट किया गया है"

कारण: Shield Platform Encryption से सुरक्षित फ़ील्ड से Salesforce न खोज सकता है, न क्रमबद्ध कर सकता है, और कैलेंडर अपने रिकॉर्ड तारीख, समय और नाम फ़ील्ड से ही ढूँढता और क्रम में लगाता है। इसलिए ये फ़ील्ड बिना एन्क्रिप्शन के रहने चाहिए। जो फ़ील्ड कैलेंडर सिर्फ़ दिखाता है, जैसे होवर कार्ड पर नोट्स, वे एन्क्रिप्ट रह सकते हैं।

समाधान

  1. संदेश में बताए गए फ़ील्ड का एन्क्रिप्शन Setup के Encryption Policy में बंद करें, या
  2. Setup Wizard में कॉन्फ़िगरेशन खोलें और उसकी जगह बिना एन्क्रिप्शन वाला कोई तारीख या समय फ़ील्ड चुनें।

फ़िल्टर "किसी फ़िल्टर करने योग्य फ़ील्ड और मान से मेल नहीं खाता", या "संसाधन लोड नहीं हो सके"

कारण: फ़िल्टर में ऐसा फ़ील्ड है जो ऑब्जेक्ट पर नहीं है, ऐसा फ़ील्ड जिससे Salesforce फ़िल्टर नहीं कर सकता, या ऐसा मान जो फ़ील्ड में फ़िट नहीं होता। कैलेंडर बताता है कि कौन सा, उदाहरण के लिए रिकॉर्ड फ़िल्टर: "Status__c=Confrimed" Visit पर किसी फ़िल्टर करने योग्य फ़ील्ड और मान से मेल नहीं खाता। या संसाधन लोड नहीं हो सके: शर्त "Active__c है yes" उस फ़ील्ड से मेल नहीं खाती।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें।
  2. केवल वे रिकॉर्ड जहाँ (दिखाए जाने वाले रिकॉर्ड) या केवल वे दिखाएँ जहाँ (दिए जाने वाले कमरे या लोग) के नीचे की सूचियों से फ़ील्ड और मान दोबारा चुनें।
  3. App Builder में टाइप कर रहे हैं? फ़ील्ड का API नाम और उसके प्रकार में फ़िट होने वाला मान डालें: चेकबॉक्स के लिए true या false, तारीख के लिए 2026-12-31।

"अपने आप भरें (Priority = High) में Priorty__c का उपयोग होता है, लेकिन Visit में यह फ़ील्ड नहीं है"

कारण: अपने आप भरें (App Builder: Default Field Values) हर नए रिकॉर्ड पर फ़ील्ड सेट करता है, और उसकी किसी जोड़ी में ऐसा फ़ील्ड है जो ऑब्जेक्ट पर नहीं है। Setup Wizard समीक्षा स्टेप पर यही बताता है और वह फ़ील्ड बताता है जो उसे नहीं मिला। ऐसा मान जो फ़ील्ड में नहीं आ सकता, जैसे कोई picklist मान जो उसकी सूची में नहीं है, कैलेंडर के सहेजते समय दिखता है: डिफ़ॉल्ट फ़ील्ड मान: "Priority=Urgent" Visit पर किसी फ़ील्ड और मान से मेल नहीं खाता।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें और अपने आप भरें (Priority = High) के नीचे वाली जोड़ी ठीक करें। फ़ील्ड का API नाम Object Manager में जाँचें।
  2. फ़ील्ड में फ़िट होने वाला मान लिखें: चेकबॉक्स true या false लेते हैं, तारीखें yyyy-mm-dd या TODAY+7, और picklist अपने मानों में से कोई एक।
  3. कई जोड़ियों को सेमीकोलन से अलग करें: Priority=High; Type=Call।

"Duration संख्या फ़ील्ड नहीं है", या कोई बुकिंग पूरा दिन घेर लेती है

कारण: मिनट रखने वाला फ़ील्ड (App Builder: Duration Field) बुकिंग पर एक संख्या (Number) फ़ील्ड होना चाहिए, न कि formula, roll-up, currency या percent। जब यह सेट हो और समाप्ति खाली छोड़ा गया हो, तो हर बुकिंग अपने शुरू होने के समय में उतने मिनट जोड़कर खत्म होती है, इसलिए जिस रिकॉर्ड में मिनट खाली हैं उसका कोई अंत नहीं होता और वह पूरा दिन घेर लेता है।

समाधान

  1. ऐसा संख्या फ़ील्ड चुनें जिसमें लंबाई मिनटों में हो, या नया बनाएँ।
  2. पुराने रिकॉर्ड में मिनट एक बार भर दें, जैसे data update या Flow से। उसके बाद कैलेंडर से हर सहेजना, खिसकाना और आकार बदलना इन्हें अपने आप लिखता है।

"Visit में Install नाम का कोई सक्रिय रिकॉर्ड प्रकार नहीं है, जिसे यह कैलेंडर नए रिकॉर्ड को देता है"

कारण: नई बुकिंग का रिकॉर्ड प्रकार में ऐसा रिकॉर्ड प्रकार है जो निष्क्रिय कर दिया गया या जिसका नाम बदल गया। इससे जुड़ा संदेश, Confirmed, Repair रिकॉर्ड के लिए Visit Status का मान नहीं है, बताता है कि चुनी गई स्थिति उस रिकॉर्ड प्रकार के मानों में नहीं है।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें और नई बुकिंग का रिकॉर्ड प्रकार में कोई सक्रिय प्रकार चुनें, या हर व्यक्ति का डिफ़ॉल्ट या लोगों को चुनने दें चुनें।
  2. स्थिति के लिए: Object Manager में उस रिकॉर्ड प्रकार के picklist मानों में यह मान जोड़ें, या कोई दूसरी स्थिति चुनें।

अगर संदेश कहता है कि व्यक्ति उस प्रकार के रिकॉर्ड नहीं बना सकता, तो रिकॉर्ड प्रकार की अनुमति नहीं देखें।

"यह केवल व्यवस्थापकों को बिल्डर में दिखता है: यह कैलेंडर क्षमता गिनता है पर इसका Config Name नहीं है"

कारण: पेज पर किसी सहेजे गए कॉन्फ़िगरेशन का नाम न हो, तो कैलेंडर सिर्फ़ वही बुकिंग गिन सकता है जो देखने वाले को दिखती हैं। sharing की वजह से छिपी बुकिंग गिनती से छूट जाती हैं, इसलिए भरा हुआ समय खाली दिख सकता है।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन सहेजें।
  2. कंपोनेंट के Config Name में उसका नाम लिखें। तब गिनती में हर बुकिंग शामिल होती है, सिर्फ़ संख्या के रूप में।

यह नोट सिर्फ़ एडमिन को, App Builder में दिखता है। यूज़र को कभी नहीं।

सहेजने के बाद कैलेंडर में जोड़ें (Add to Calendar) बटन नहीं दिखता

कारण: Show Add to Calendar After Saving (सहेजने के बाद "कैलेंडर में जोड़ें" दिखाएँ) बंद है। यह डिफ़ॉल्ट रूप से बंद रहता है।

समाधान

  1. इसे कंपोनेंट की प्रॉपर्टी या कॉन्फ़िगरेशन में चालू करें, फिर कोई रिकॉर्ड सहेजें। बटन टोस्ट के नीचे एक पट्टी में दिखता है।
  2. उसकी जगह "Google Calendar में जोड़ें" दिख रहा है? ब्राउज़र ने फ़ाइल बनाने से रोक दिया, इसलिए एक इवेंट के लिए Google Calendar लिंक मिलता है।

बुकिंग और उपलब्धता

कोई दिन, समय, कमरा या व्यक्ति क्यों चुना या बुक नहीं हो पा रहा।

Resource Booking पर "कोई संसाधन उपलब्ध नहीं" लिखा आता है

कारण: संसाधनों की सूची खाली लौटी। आम तौर पर ऐसा फ़िल्टर जो किसी से मेल नहीं खाता, गलत संसाधन ऑब्जेक्ट, या अभी तक कोई संसाधन रिकॉर्ड ही नहीं।

समाधान

  1. केवल वे दिखाएँ जहाँ (App Builder: Resource Filter Field और Value) को किसी असली रिकॉर्ड से मिलाकर जाँचें।
  2. विकल्पों की सूची और हर एक के नाम वाला फ़ील्ड जाँचें (App Builder: Resource Object API Name और Resource Name Field)।
  3. कम से कम एक संसाधन रिकॉर्ड बनाएँ।

पीला बैनर: "क्षमता के लिए दोनों समय फ़ील्ड आवश्यक हैं" (Capacity needs both time fields)

कारण: एक साथ कितने (App Builder: Capacity Field) सेट है, पर बुकिंग का आरंभ या अंत समय फ़ील्ड खाली है, इसलिए क्षमता लागू नहीं की जा सकी।

समाधान

  1. शुरुआत और समाप्ति दोनों सेट करें (App Builder: Booking Start Time Field और Booking End Time Field), या
  2. एक साथ कितने खाली कर दें।

मैं और तारीख नहीं चुन पा रहा

कारण: कंपोनेंट में तारीखों की सीमा तय है: Max Dates Allowed (अधिकतम अनुमत दिनांक)।

समाधान

  1. दूसरी तारीख चुनने के लिए किसी एक तारीख का चयन हटाएँ, या
  2. सीमा बढ़ाएँ, या कोई सीमा न रखने के लिए 0 कर दें।

मैं कोई और समय बुक नहीं कर पा रहा

कारण: कोई बुकिंग सीमा पूरी हो गई है। Max Time Slots (अधिकतम समय स्लॉट) कुल स्लॉट की सीमा तय करता है, Max Bookings per Day (प्रति दिन अधिकतम बुकिंग) एक दिन में अलग-अलग बुकिंग की (एक-दूसरे से सटे समय एक गिने जाते हैं), और Limit per Person (प्रति व्यक्ति सीमा) एक क्लाइंट की आने वाली बुकिंग की, जिनकी गिनती सर्वर पर होती है।

समाधान

  1. सीमा बढ़ाएँ, या कोई सीमा न रखने के लिए 0 कर दें।
  2. स्टाफ़ पुष्टि करके “प्रति व्यक्ति सीमा” से आगे बुक कर सकता है। साइट विज़िटर नहीं कर सकते।

कुछ दिन या समय ग्रे दिखते हैं

कारण: कोई बुकिंग नियम उन्हें बंद करता है। Minimum Notice (Hours) (न्यूनतम अग्रिम सूचना (घंटे)) बहुत जल्दी शुरू होने वाली हर चीज़ बंद करता है, Book Up To (Days Ahead) (इतने दिन पहले तक बुक करें (दिन)) आगे बढ़ती विंडो के बाद के दिन बंद करता है, और बाकी को Earliest या Latest Selectable Date, अवरुद्ध तारीखें और हर संसाधन के व्यावसायिक घंटे बंद करते हैं।

समाधान

  1. ये सेटिंग कंपोनेंट या उसके कॉन्फ़िगरेशन में जाँचें। 0 डालने पर नोटिस और विंडो दोनों बंद हो जाते हैं।
  2. किसी बंद टाइम स्लॉट पर क्लिक करें: बंदी बताती है कि वह क्यों बंद है।

बुकिंग के ठीक बाद वाला स्लॉट भरा हुआ दिखता है

कारण: Buffer Between Bookings (Minutes) (बुकिंग के बीच बफ़र (मिनट)) उसी संसाधन की हर बुकिंग के बाद सफ़ाई या तैयारी के लिए कुछ समय खाली रखता है।

समाधान

  1. बफ़र कम करें, या लगातार एक के बाद एक बुकिंग के लिए 0 कर दें।
  2. जब समय पहले से बुक हो तब भी लागू रहता है: टकराव वाले स्लॉट छोड़ें के साथ, बफ़र से टकराने वाला स्लॉट किसी भी दूसरे टकराव की तरह छोड़ा जाता है और रिपोर्ट होता है।

सिर्फ़ कुछ शुरुआती समय दिख रहे हैं

कारण: केवल ये समय सेट है, इसलिए ग्रिड सिर्फ़ सूची में दिए शुरुआती समय दिखाता है। Resource Booking में, जब किसी कमरे या व्यक्ति की अपनी सूची हो, तो हर संसाधन के अपने समय लागू होता है। व्यावसायिक घंटे, बंदी, अग्रिम सूचना और टकराव फिर भी सूची के किसी समय को बंद कर देते हैं।

समाधान

  1. कंपोनेंट या उसके कॉन्फ़िगरेशन में सूची बदलें, या हर अंतराल चुनें।
  2. संसाधन के “हर संसाधन के अपने समय” फ़ील्ड में उसकी अपनी सूची जाँचें।

"ये चयन अब बुकिंग अवधि के भीतर नहीं हैं" (These picks are no longer inside the booking window)

कारण: पेज इतनी देर खुला रहा कि चुना गया दिन या समय Minimum Notice की अवधि के अंदर आ गया। सहेजते समय नियम दोबारा जाँचा जाता है, ताकि पुराना खुला पेज बहुत देर से बुकिंग न कर सके।

समाधान

  1. संदेश में बताई गई तारीखें हटाएँ, या बाद का समय चुनें।
  2. फिर से सहेजें।

"बुकिंग नहीं की जा सकती। इन तिथियों पर पहले से भरा हुआ या बंद है: 3 दिसंबर" या "पहले से भरा हुआ या बंद है, इसलिए सहेजते समय छोड़ दिया जाएगा"

कारण: उस समय को कोई दूसरी बुकिंग पहले से भर चुकी है, या कोई बंदी उसे ढकती है। जब समय पहले से बुक हो तय करता है कि आगे क्या होगा: अवरुद्ध करें पूरा अनुरोध मना कर देता है, टकराव वाले स्लॉट छोड़ें बाकी दिन बुक करता है और छोड़े गए दिन बताता है, और अनुमति दें (फिर भी बुक करें) एक “फिर भी बुक करें” बटन देता है।

समाधान

  1. संदेश में बताई गई तारीखें हटाएँ, या कोई दूसरा समय या संसाधन चुनें।
  2. एडमिन कॉन्फ़िगरेशन के बुकिंग नियमों में जब समय पहले से बुक हो बदल सकता है।

"दैनिक सीमा पूरी हो गई (2 में से 2)"

कारण: एक दिन में अधिकतम बुकिंग (App Builder: Daily Limit Field) हर कमरे या व्यक्ति पर एक संख्या है, जैसे किसी टेक्नीशियन के एक दिन में 2 काम। जब किसी दिन उतनी बुकिंग हो जाती हैं, तो वह दिन उस संसाधन के लिए बंद हो जाता है, और वहाँ सहेजने पर दैनिक सीमा पूरी हो गई, इसलिए कुछ भी सहेजा नहीं गया आता है। हर रिकॉर्ड एक बार गिना जाता है, कई दिन की बुकिंग हर दिन गिनी जाती है, और समय खाली करने वाली स्थितियाँ कभी नहीं गिनी जातीं।

समाधान

  1. कोई दूसरा दिन या दूसरा संसाधन चुनें।
  2. संसाधन रिकॉर्ड पर संख्या बढ़ाएँ, या कोई सीमा न रखने के लिए उसे खाली छोड़ दें।
  3. जब समय पहले से बुक हो को अनुमति दें (फिर भी बुक करें) पर सेट करने से बुकिंग सीमा से आगे जा सकती है।

"Garden Room बुकिंग स्वीकार नहीं करता, इसलिए कुछ भी सहेजा नहीं गया"

कारण: संसाधन का एक साथ कितने या एक दिन में अधिकतम बुकिंग 0 है। 0 का मतलब है कि वह कोई बुकिंग नहीं लेता, “जब समय पहले से बुक हो” की हर सेटिंग में। पिकर, टाइम ग्रिड और सप्ताह व्यू उसे ग्रे कर देते हैं।

समाधान

  1. कोई दूसरा संसाधन चुनें।
  2. इसे बुकिंग के लिए खोलने के लिए, उसके रिकॉर्ड पर संख्या 1 या उससे ज़्यादा करें, या कोई सीमा न रखने के लिए खाली छोड़ दें।

"ये तारीखें बीत चुकी हैं और बुक नहीं की जा सकतीं" या "ये समय बीत चुके हैं"

कारण: कैलेंडर बीत चुके दिन या समय बुक नहीं करता। रात भर खुले छोड़े गए पेज पर कल चुना गया दिन, या आज का कोई पहले का समय, सहेजते समय मना हो जाता है।

समाधान

  1. संदेश में बताई गई तारीखें या समय हटाएँ और बाद के चुनें।
  2. बीते दिन दर्ज करने हैं, जैसे टाइमशीट? एडमिन कॉन्फ़िगरेशन में पिछली दिनांकों की अनुमति दें चालू कर सकता है।

"ये तारीखें बंद हैं: 25 दिसंबर। कोई दूसरी तारीख या समय चुनें।"

कारण: उस दिन पर बंदी लागू है: कैलेंडर की बंद दिनों की सूची का कोई रिकॉर्ड, जैसे छुट्टी या स्टाफ़ अवकाश। जिस बंदी में किसी कमरे या व्यक्ति का नाम हो, वह सिर्फ़ उसी संसाधन को बंद करती है। कैलेंडर और सहेजना, दोनों इसे मना करते हैं।

समाधान

  1. कोई दूसरी तारीख या समय चुनें।
  2. अगर दिन खुला होना चाहिए, तो बंदी रिकॉर्ड एडिट या डिलीट करें, या कॉन्फ़िगरेशन में केवल वे बंदियाँ जहाँ को सीमित करें।

"Garden Room को इस कैलेंडर में बुक नहीं किया जा सकता। सूची से कोई संसाधन चुनें।"

कारण: कमरा या व्यक्ति इस कैलेंडर की सूची में नहीं है, क्योंकि केवल वे दिखाएँ जहाँ उसे बाहर रखता है। अक्सर ऐसा तब होता है जब पेज खुलने के बाद कोई रिकॉर्ड बदल गया, जैसे किसी कमरे को निष्क्रिय कर दिया गया। सर्वर सहेजने, खिसकाने और दोबारा असाइन करने पर इसे मना कर देता है।

समाधान

  1. पेज रीलोड करें और सूची से कोई संसाधन चुनें।
  2. अगर यह विकल्प में होना चाहिए, तो संसाधन रिकॉर्ड अपडेट करें, या कॉन्फ़िगरेशन में केवल वे दिखाएँ जहाँ बदलें।

"चुने गए संसाधनों का कोई साझा शुरू होने का समय नहीं है"

कारण: एक साथ कई बुक करें के साथ, एक ही समय हर चुने गए कमरे या व्यक्ति के लिए ठीक होना चाहिए। उनके व्यावसायिक घंटे या अपने शुरुआती समय आपस में मेल नहीं खाते, इसलिए कोई भी समय सब पर फ़िट नहीं होता। छोटा संदेश चयनित संसाधनों के व्यावसायिक घंटे मेल नहीं खाते भी यही बताता है।

समाधान

  1. कम संसाधन चुनें, या ऐसे जो एक जैसे घंटों में काम करते हों।
  2. एडमिन हर संसाधन के खुलने के घंटे और अपने शुरुआती समय जाँच सकता है।

दो लोगों ने एक ही समय बुक कर लिया

कारण: दो में से कोई एक सेटिंग ऐसा होने देती है। जब समय पहले से बुक हो को अनुमति दें (फिर भी बुक करें) पर रखने से स्टाफ़ जानबूझकर भरे हुए समय पर बुक कर सकता है। या फ़िल्टर यह भी तय करे कि क्या व्यस्त है चालू है और फ़िल्टर ME का उपयोग करता है, इसलिए हर व्यक्ति की केवल अपनी बुकिंग ही समय घेरती है। विज़ार्ड दूसरी स्थिति के बारे में चेतावनी देता है: “फ़िल्टर यह भी तय करे कि क्या व्यस्त है” चालू है और “केवल वे रिकॉर्ड जहाँ” ME का उपयोग करता है, इसलिए हर व्यक्ति की केवल अपनी बुकिंग ही समय घेरती है: दो लोग एक ही समय बुक कर सकते हैं।

समाधान

  1. जब समय पहले से बुक हो को अवरुद्ध करें या टकराव वाले स्लॉट छोड़ें पर सेट करें।
  2. फ़िल्टर यह भी तय करे कि क्या व्यस्त है बंद करें, जब तक हर व्यक्ति सच में सिर्फ़ अपना समय बुक न करता हो।

"प्रति व्यक्ति सीमा चालू है, लेकिन कोई क्लाइंट फ़ील्ड सेट नहीं है"

कारण: प्रति व्यक्ति सीमा हर क्लाइंट की बुकिंग किसके लिए है (App Builder: Client Field) के ज़रिए गिनती है। कोई फ़ील्ड सेट न हो, या ऐसा फ़ील्ड हो जिसमें Salesforce खोज नहीं कर सकता, जैसे लंबा टेक्स्ट, तो बुकिंग गिनी नहीं जा सकती और सहेजना मना हो जाता है। एडमिन को App Builder में प्रति व्यक्ति सीमा Notes के आधार पर बुकिंग नहीं गिन सकती दिखता है।

समाधान

  1. Setup Wizard में कॉन्फ़िगरेशन खोलें और किसके लिए है में कोई टेक्स्ट, ईमेल या लुकअप फ़ील्ड चुनें।
  2. या इसे बंद करने के लिए प्रति व्यक्ति सीमा को 0 कर दें।

"Salesforce से कोई जवाब नहीं मिला, इसलिए यह बुकिंग शायद पहले ही सहेजी जा चुकी है"

कारण: बुक करें दबाने के बाद कनेक्शन टूट गया या Salesforce धीमा रहा, इसलिए कैलेंडर यह नहीं बता सका कि सहेजना पूरा हुआ या नहीं। यह अपने आप रीलोड होता है ताकि आप देख सकें।

समाधान

  1. रीलोड हुए कैलेंडर पर बुकिंग देखें।
  2. दोबारा तभी बुक करें जब वह वहाँ न हो।

सार्वजनिक साइट के अतिथि

सार्वजनिक Experience Cloud साइट पर कैलेंडर, जहाँ विज़िटर बिना साइन इन किए बुक करते हैं।

guest को खाली कैलेंडर दिखता है

कारण: guest का sharing rule अभी लागू नहीं हुआ, या guest प्रोफ़ाइल में कोई स्टेप छूट गया है।

समाधान

  1. ऑब्जेक्ट का external org-wide default Private करें, फिर Setup के Sharing Settings में Recalculate पर क्लिक करें।
  2. guest user को MultiDatePick - Guest permission set असाइन करें, और उसे अपने हर ऑब्जेक्ट और फ़ील्ड पर Read दें।
  3. साइट को Activate करें। सिर्फ़ Publish करना काफ़ी नहीं है।

guest के लिए पूरी छह-चरण वाली चेकलिस्ट User Guide में है। Setup Wizard में मेरी साइट जाँचें आपके लिए हर चरण जाँचता है।

मेरी साइट जाँचें में "सुधार ज़रूरी" दिखता है

कारण: मेरी साइट जाँचें, जो साइट कैलेंडर के लिए Setup Wizard के “समीक्षा” और “हो गया” स्टेप पर है, साइट को उसी तरह जाँचता है जैसे कोई अतिथि उसे देखता है। “सुधार ज़रूरी” वाली हर पंक्ति एक छूटा हुआ स्टेप है, और वह बताती है कि क्या करना है।

समाधान

  1. साइट अभी लाइव नहीं है: साइट के Workspaces में Administration, Settings पर जाएँ, Activate पर क्लिक करें, फिर Publish करें।
  2. MultiDatePick - Guest अनुमति सेट: guest user खोलें और इसे Permission Set Assignments में जोड़ें।
  3. ऑब्जेक्ट पहुँच या फ़ील्ड पहुँच: guest user को कैलेंडर जो दिखाता है उस पर Read दें, और बुकिंग जो सहेजती है उस पर Edit।
  4. अतिथि संसाधनों में से एक भी नहीं देख सकता: Setup के Sharing Settings में संसाधन ऑब्जेक्ट पर guest sharing rule जोड़ें।

यह जाँच सिर्फ़ MultiDatePick - Setup वाला एडमिन चला सकता है।

"इस संगठन में अभी कोई Experience Cloud साइट नहीं है"

कारण: मेरी साइट जाँचें को जाँचने के लिए कोई साइट नहीं मिली, इसलिए चुनने के लिए कोई साइट नहीं है। पूरा संदेश है इस संगठन में अभी कोई Experience Cloud साइट नहीं है। Setup में Digital Experiences चालू करें और एक साइट बनाएँ, फिर उसे यहाँ जाँचें। कॉन्फ़िगरेशन में कोई गड़बड़ी नहीं है और उसे सहेजा जा सकता है।

समाधान

  1. Setup में Digital Experiences खोजें, Settings खोलें और Enable Digital Experiences पर टिक करें। Salesforce इसे बाद में बंद नहीं करने देता।
  2. Digital Experiences, All Sites, New में साइट बनाएँ।
  3. Setup Wizard में कॉन्फ़िगरेशन फिर से खोलें और समीक्षा स्टेप पर मेरी साइट जाँचें दबाएँ।

"यह कैलेंडर यहाँ सहेज नहीं सकता: यह इस ऑब्जेक्ट के लिए कोई सहेजा गया कॉन्फ़िगरेशन नहीं बताता"

कारण: साइट अतिथि या पोर्टल यूज़र की बुकिंग सर्वर पर किसी सहेजे गए कॉन्फ़िगरेशन से जाँची जाती है, ताकि प्राइवेसी और बुकिंग नियम छोड़े न जा सकें। साइट पेज के कैलेंडर में Config Name नहीं है, जबकि ऑब्जेक्ट का एक सहेजा गया कॉन्फ़िगरेशन पहले से है।

समाधान

  1. Experience Builder में साइट पेज खोलें।
  2. कैलेंडर का Config Name इस साइट के लिए सहेजे गए कॉन्फ़िगरेशन पर सेट करें, फिर Publish करें।

"यह कैलेंडर यहाँ उपयोग नहीं किया जा सकता: इसका सहेजा गया कॉन्फ़िगरेशन सार्वजनिक साइट के लिए नहीं बना है"

कारण: साइट पेज पर स्टाफ़ के लिए बना कॉन्फ़िगरेशन दिया गया है। साइट अतिथि और पोर्टल यूज़र सिर्फ़ साइट के लिए सहेजा गया कॉन्फ़िगरेशन इस्तेमाल कर सकते हैं, ताकि स्टाफ़ कैलेंडर की प्राइवेसी और नियम कभी गलती से जनता तक न पहुँचें।

समाधान

  1. कैलेंडर का Config Name साइट के लिए सहेजे गए किसी कॉन्फ़िगरेशन पर सेट करें, या
  2. नया बनाएँ: Setup Wizard में यह कैलेंडर कहाँ दिखेगा? का जवाब सार्वजनिक साइट पर दें और उसे नए नाम से सहेजें।

"यह पेज बुकिंग को ऐसे रिकॉर्ड से जोड़ता है जिसे साइट के आगंतुक नहीं देख सकते"

कारण: साइट से हर बुकिंग एक रिकॉर्ड से जुड़ती है, जो बुकिंग इससे जुड़ेंगी में सेट है, और guest user उसे पढ़ नहीं सकता। जब तक कोई guest sharing rule रिकॉर्ड साझा न करे, Salesforce उन्हें अतिथियों से निजी रखता है।

समाधान

  1. Setup के Sharing Settings में उस रिकॉर्ड के ऑब्जेक्ट पर एक guest sharing rule जोड़ें, जो उसे साइट के guest user के साथ Read Only साझा करे।
  2. मेरी साइट जाँचें दोबारा चलाएँ: वह रिकॉर्ड जिससे बुकिंग जुड़ती हैं पास होना चाहिए।

"इस सार्वजनिक पृष्ठ पर सहेजा नहीं गया"

कारण: Salesforce साइट अतिथियों को रिकॉर्ड पढ़ने और बनाने देता है, पर बदलने या डिलीट करने कभी नहीं। विज़िटर देख और बुक कर सकते हैं। पहुँच वाले साइन-इन यूज़र एडिट कर सकते हैं।

समाधान

  1. ठीक करने को कुछ नहीं: यह Salesforce का guest नियम है। लोगों को अपनी बुकिंग खुद बदलने देने के लिए उन्हें साइन-इन दें (member साइट), या बदलाव स्टाफ़ से करवाएँ।

"इस कैलेंडर पर हर बुकिंग 60 मिनट की है, इसलिए यह समय बुक नहीं किया जा सकता"

कारण: साइट अतिथियों और पोर्टल यूज़र के लिए सर्वर हर बुकिंग को सहेजे गए कॉन्फ़िगरेशन से जाँचता है: बुकिंग की लंबाई, केवल ये समय, लोग जो स्थितियाँ चुन सकते हैं, अग्रिम सूचना, बुकिंग विंडो और सीमाएँ। पेज खुला था और इसी बीच एडमिन ने इनमें से कोई सेटिंग बदल दी, इसलिए पेज ने वह विकल्प दिया जिसकी कॉन्फ़िगरेशन अब अनुमति नहीं देता। इससे जुड़े संदेश: यह कैलेंडर केवल सूचीबद्ध शुरुआती समयों पर बुकिंग लेता है और इस कैलेंडर पर स्थिति Requested नहीं चुनी जा सकती।

समाधान

  1. पेज रीलोड करें और दोबारा बुक करें।
  2. फिर भी मना हो रहा है? साइट का एडमिन Config Name में दिए कॉन्फ़िगरेशन पर ये नियम जाँच सकता है।

साइट सदस्य अपने ही बनाए रिकॉर्ड नहीं देख पाते

कारण: Experience Cloud की sharing। साइट यूज़र केवल वही रिकॉर्ड देखते हैं जो sharing उन्हें देती है।

समाधान

  1. जिस ऑब्जेक्ट में तारीखें सहेजी जाती हैं, उस पर एक sharing rule (या सदस्यों के लिए sharing set) जोड़ें, या
  2. उसका external org-wide default खोल दें।

"साइट दूसरी वेबसाइटों को उसे दिखाने नहीं देती"

कारण: आपने embed कोड से कैलेंडर अपनी वेबसाइट पर लगाया है, और Salesforce साइट किसी दूसरी वेबसाइट के अंदर दिखने से मना करती है, जो उसकी डिफ़ॉल्ट सेटिंग है।

समाधान

  1. Experience Builder में Settings खोलें, फिर Security & Privacy।
  2. Clickjack Protection Level को Allow framing of site pages on external domains पर सेट करें।
  3. Trusted Domains for Inline Framing में अपनी वेबसाइट जोड़ें, फिर Publish करें।

अतिथियों को लोकेशन की सूची दिखती है, पर मानचित्र नहीं

कारण: मानचित्र Salesforce की एक सेवा बनाती है, जिसे साइट तब तक रोकती है जब तक उसे विश्वसनीय न माना जाए। कैलेंडर यह नहीं जान सकता कि साइट उसे रोक रही है, इसलिए साइट पर यह पहले सूची खोलता है और मानचित्र का विकल्प देता है।

समाधान

  1. Experience Builder में Settings खोलें, फिर Security & Privacy।
  2. maps.a.forceusercontent.com को फ़्रेम के लिए विश्वसनीय साइट के रूप में जोड़ें, फिर Publish करें।

अनुमतियाँ और सुरक्षा

कैलेंडर हर यूज़र की अपनी permission से चलता है। सही permission set से शुरू करें, फिर अपने ऑब्जेक्ट और फ़ील्ड का एक्सेस दें।

परमिशन सेटकिसे असाइन करें
MultiDatePick - Userकैलेंडर इस्तेमाल करने वाले सभी लोग
MultiDatePick - Setupकॉन्फ़िगरेशन बनाने वाले एडमिन। इसमें Setup Wizard शामिल है।
MultiDatePick - All Accessएडमिन जो इन्हें बनाते भी हैं और इस्तेमाल भी करते हैं
MultiDatePick - Guestसार्वजनिक Experience Cloud साइट का guest user

एरर संदेश बताते हैं कि क्या गलत है: फ़ील्ड, ऑब्जेक्ट या validation rule। जब संदेश विवरण: पर खत्म होता है, तो उसके बाद का टेक्स्ट Salesforce का अपना विवरण है। इसे अपने एडमिन को, या हमें, भेजें: उसमें ठीक लिखा होता है कि कहाँ देखना है।

"इस कैलेंडर का उपयोग करने के लिए आपको MultiDatePick लाइसेंस चाहिए" (You need a MultiDatePick license to use this calendar)

कारण: MultiDatePick का लाइसेंस हर सीट के हिसाब से है, और इस यूज़र को सीट असाइन नहीं हुई है। कैलेंडर की जगह यह सूचना दिखती है, और सहेजना मना हो जाता है। साइट guest को कभी सीट की ज़रूरत नहीं होती।

समाधान

  1. Setup में Installed Packages खोलें, फिर MultiDatePick के आगे Manage Licenses पर क्लिक करें।
  2. Add Users पर क्लिक करें और यूज़र जोड़ें। अगली बार पेज लोड होते ही उन्हें कैलेंडर दिखेगा।

"इस उपयोगकर्ता के पास MultiDatePick की पहुँच नहीं है, इसलिए कॉन्फ़िगरेशन लोड नहीं हुआ"

कारण: यूज़र के पास कोई MultiDatePick permission set नहीं है, इसलिए Salesforce कैलेंडर को उसके लिए अपनी क्लास चलाने नहीं देता। लाल बैनर यही दिखाता है, और ग्रे बॉक्स में Salesforce के अपने शब्द होते हैं।

समाधान

  1. यूज़र को MultiDatePick - User असाइन करें, या कॉन्फ़िगरेशन भी बनाने वाले एडमिन को MultiDatePick - All Access।

कारण: ये Salesforce के अपने शब्द हैं, और इनका मतलब है कि permission set नहीं है: यूज़र के पास कोई MultiDatePick permission set नहीं है, इसलिए Salesforce कैलेंडर को अपनी क्लास चलाने नहीं देता। क्लास का नाम इस पर निर्भर करता है कि कैलेंडर उस समय क्या कर रहा था। यह लाइन आमतौर पर लाल बैनर के नीचे ग्रे बॉक्स में, इस उपयोगकर्ता के पास MultiDatePick की पहुँच नहीं है के नीचे दिखती है।

समाधान

  1. यूज़र को MultiDatePick - User असाइन करें, या कॉन्फ़िगरेशन भी बनाने वाले एडमिन को MultiDatePick - All Access।

रिकॉर्ड नहीं खुलता, या "insufficient privileges" (अपर्याप्त विशेषाधिकार) आता है

कारण: यूज़र parent ऑब्जेक्ट नहीं पढ़ सकता, या sharing वह रिकॉर्ड उससे छिपाती है। स्क्रीन फ़्लो में, हो सकता है यूज़र को Flow चलाने की अनुमति न हो।

समाधान

  1. MultiDatePick - User असाइन करें।
  2. किसी permission set में parent ऑब्जेक्ट पर Read दें।
  3. जाँचें कि sharing यूज़र को वह रिकॉर्ड देती है।
  4. स्क्रीन फ़्लो में, यूज़र रिकॉर्ड पर Flow User पर टिक करें, या किसी permission set में Run Flows यूज़र परमिशन दें।

"Y ऑब्जेक्ट पर X फ़ील्ड तक पढ़ने की पहुँच नहीं" (No read access to field X on object Y)

कारण: कैलेंडर जो फ़ील्ड दिखाता है (स्थिति, होवर, तारीख या समय फ़ील्ड), उनमें से किसी पर यूज़र के पास Read field-level security नहीं है।

समाधान

  1. संदेश में बताए गए फ़ील्ड पर Read दें।
  2. एडमिन के लिए भी यही करें। नया कस्टम फ़ील्ड सबसे छिपा रहता है, System Administrator से भी, जब तक कोई permission set उसका एक्सेस न दे।

"Time group failed to save", "बुकिंग बनाने में विफल" या किसी फ़ील्ड के नाम के साथ "आप फ़ील्ड ... को संपादित नहीं कर सकते"

कारण: यूज़र फ़ील्ड पढ़ सकता है, पर सहेजते समय लिखे जाने वाले किसी फ़ील्ड को एडिट नहीं कर सकता। अक्सर यह बाद में जोड़ा गया स्थिति, दूसरा picklist या समय फ़ील्ड होता है, या ऐसा फ़ील्ड जो हर नए रिकॉर्ड पर अपने आप भरा जाता है।

समाधान

  1. कैलेंडर जो भी फ़ील्ड लिखता है, हर एक पर Edit दें: तारीख, आरंभ और अंत समय, स्थिति, दूसरा picklist, नाम फ़ील्ड, parent lookup और अपने आप भरें का हर फ़ील्ड।
  2. जिस ऑब्जेक्ट में रिकॉर्ड सहेजे जाते हैं, उस पर Create दें।

"आपको यह करने की अनुमति नहीं है" (You don't have permission to do this) के साथ "insufficient access rights on cross-reference id" (cross-reference id पर अपर्याप्त पहुँच अधिकार)

कारण: नया रिकॉर्ड ऐसे रिकॉर्ड की ओर इशारा करता है जिसे यूज़र देख नहीं सकता: parent या संसाधन।

समाधान

  1. parent और संसाधन ऑब्जेक्ट पर कम से कम Read दें, और उन रिकॉर्ड पर sharing दें।
  2. सार्वजनिक साइट पर guest की बुकिंग किसी कस्टम ऑब्जेक्ट पर करें। Salesforce, Contact और Account पर guest का एक्सेस सीमित रखता है।

"इस कैलेंडर में उपयोग होने वाली बंदी तक आपकी पहुँच नहीं है"

कारण: यूज़र उस ऑब्जेक्ट को नहीं पढ़ सकता जिसमें बंद दिन रखे जाते हैं, इसलिए कैलेंडर नहीं बता सकता कि कौन से दिन बंद हैं। इसका जुड़वाँ संदेश, इस कैलेंडर में दिखाए गए रिकॉर्ड तक आपकी पहुँच नहीं है, खुद बुकिंग के लिए यही बताता है।

समाधान

  1. किसी permission set में, संदेश में बताए गए ऑब्जेक्ट और फ़ील्ड पर Read दें।
  2. जाँचें कि sharing यूज़र को वे रिकॉर्ड देती है।

"आप Install रिकॉर्ड प्रकार के Visit रिकॉर्ड नहीं बना सकते"

कारण: कैलेंडर नई बुकिंग को ऐसा रिकॉर्ड प्रकार देता है जो इस यूज़र की प्रोफ़ाइल या permission set में शामिल नहीं है।

समाधान

  1. रिकॉर्ड प्रकार को यूज़र की प्रोफ़ाइल या किसी permission set में जोड़ें।
  2. या नई बुकिंग का रिकॉर्ड प्रकार को लोगों को चुनने दें पर सेट करें, जो हर व्यक्ति को सिर्फ़ वही प्रकार दिखाता है जो वह बना सकता है।

"Salesforce ने आपको यह Visit Alex Chen को असाइन करने नहीं दिया"

कारण: बुकिंग का कमरा या व्यक्ति एक Salesforce यूज़र है, और Salesforce ने उसे owner बनाने से मना कर दिया। संदेश के आखिर में कारण होता है: आपके पास उसे रिकॉर्ड देने की पहुँच नहीं है, यूज़र निष्क्रिय है, या उस प्रकार का यूज़र इस तरह के रिकॉर्ड का स्वामी नहीं हो सकता।

समाधान

  1. किसी और को चुनें।
  2. या अपने Salesforce एडमिन से उस यूज़र को रिकॉर्ड देने की पहुँच माँगें, या यूज़र को सक्रिय करने को कहें।

"आपको MultiDatePick कॉन्फ़िगरेशन सहेजने की अनुमति नहीं है"

कारण: कॉन्फ़िगरेशन Salesforce metadata के रूप में सहेजे जाते हैं, जिसके लिए Modify Metadata Through Metadata API Functions अनुमति चाहिए। MultiDatePick - Setup permission set यह अनुमति देता है।

समाधान

  1. कॉन्फ़िगरेशन बनाने वाले एडमिन को MultiDatePick - Setup, या MultiDatePick - All Access, असाइन करें।

Flow और एक्शन

स्क्रीन फ़्लो (Screen Flow) पर कैलेंडर, और Flow चलाने वाले बटन।

Flow स्क्रीन मेरी विज़ार्ड सेटिंग नहीं मानती

कारण: Config Name खाली है या उसकी स्पेलिंग गलत है। खाली हो तो कंपोनेंट चुपचाप अपनी डिफ़ॉल्ट सेटिंग इस्तेमाल करता है। स्पेलिंग गलत हो तो वह "... नाम का कोई कॉन्फ़िगरेशन नहीं मिला" दिखाता है।

समाधान

  1. Config Name में कॉन्फ़िगरेशन का नाम ठीक वैसा ही डालें जैसा Setup Wizard ने सहेजा है।
  2. चालू/बंद वाले इनपुट को न छेड़ें। हर चेकबॉक्स कॉन्फ़िगरेशन से आता है।

"चुनी गई कुछ तारीखें अभी सहेजी नहीं गई हैं। आगे बढ़ने से पहले सहेजें पर क्लिक करें या उन्हें हटा दें।"

कारण: स्क्रीन का Next बटन तब दबाया गया जब कैलेंडर में ऐसे चयन थे जो कभी सहेजे नहीं गए, इसलिए वे खो जाते। समय के साथ संदेश कहता है चुने गए कुछ समय अभी बुक नहीं हुए हैं।

समाधान

  1. पहले सहेजें (या बुक करें) पर क्लिक करें, फिर Next।
  2. या जो चयन नहीं चाहिए उन्हें हटाएँ, फिर Next।

"Send Reminder नहीं चल सकती: इसके लिए "Run Flows" अनुमति या उसके फ़्लो तक पहुँच चाहिए"

कारण: कैलेंडर का एक्शन बटन एक Flow चलाता है, और Salesforce उसे सिर्फ़ उन लोगों को शुरू करने देता है जिन्हें वह Flow चलाने की अनुमति है।

समाधान

  1. किसी permission set में यूज़र को Run Flows अनुमति दें, या
  2. उसकी प्रोफ़ाइल या permission set को उस Flow की पहुँच दें (Setup, Flows, वह Flow, Edit Access)।

"फ़्लो एक त्रुटि के साथ रुक गया" या "यह कार्रवाई यहाँ उपलब्ध नहीं है"

कारण: पहला संदेश बताता है कि एक्शन बटन के पीछे का Flow चला और फ़ेल हो गया। दूसरा बताता है कि यह बटन अब इस रिकॉर्ड के लिए नहीं दिया जाता: एक्शन सहेजे गए कॉन्फ़िगरेशन से हटा दिया गया, या वह दूसरी स्थितियों के लिए सेट है।

समाधान

  1. Flow त्रुटि के लिए, एडमिन Flow की run history या debug log खोलकर देखता है कि कौन सा स्टेप फ़ेल हुआ।
  2. एक्शन उपलब्ध न होने पर, पेज रीलोड करें, फिर कॉन्फ़िगरेशन के एक्शन में उस एक्शन की स्थितियाँ जाँचें।

"इस फ़्लो में recordId या recordIds इनपुट वेरिएबल नहीं है"

कारण: Setup Wizard क्लिक किया गया रिकॉर्ड एक्शन के Flow को recordId (एक रिकॉर्ड) या recordIds (कई, संपादन मोड से) नाम के वेरिएबल में भेजता है। इनमें से एक भी न हो, तो Flow को पता नहीं चलेगा कि कौन से रिकॉर्ड इस्तेमाल करने हैं।

समाधान

  1. Flow Builder में recordId नाम का Text वेरिएबल, या recordIds नाम का Text collection जोड़ें, जो input के लिए उपलब्ध हो।
  2. Flow सहेजें और activate करें, फिर विज़ार्ड में उसे दोबारा चुनें।

गैंट चार्ट

गैंट दृश्य में कार्य, उनके बीच लिंक और प्रगति।

स्विचर में गैंट दृश्य नहीं है

कारण: मानचित्र व्यू की तरह गैंट दृश्य भी आपको ख़ुद चालू करना होता है। Available Views (उपलब्ध दृश्य) खाली हो, तो कैलेंडर, टाइमलाइन, सप्ताह, उपयोग और एजेंडा मिलते हैं।

समाधान

  1. Setup Wizard के व्यू टैब पर गैंट दृश्य उपलब्ध कराएँ पर टिक करें, या Available Views (उपलब्ध दृश्य) में gantt जोड़ें।
  2. कैलेंडर इसी पर खुले, इसके लिए View को gantt पर सेट करें।

"Site survey को 6 दिसंबर पर नहीं रखा जा सकता: यह कैलेंडर उस दिन की अनुमति नहीं देता। कुछ भी सहेजा नहीं गया।"

कारण: गैंट में कैलेंडर वाले ही बुकिंग नियम लागू होते हैं। कोई कार्य बंद दिन या समय पर, उस दिन किसी दूसरे कार्य पर लगे व्यक्ति पर, या बुकिंग न लेने वाले संसाधन पर नहीं जा सकता। संदेश हर बार नियम का नाम बताता है।

समाधान

  1. कार्य को किसी दूसरे दिन पर खींचें, या किसी खाली व्यक्ति को दें।
  2. अगर दिन खुला होना चाहिए, तो एडमिन कॉन्फ़िगरेशन में बंदियाँ और वे दिन जाँचता है जिन्हें लोग चुन सकते हैं।

"Install, Testing की प्रतीक्षा नहीं कर सकता: इससे एक चक्र बन जाएगा"

कारण: Testing पहले से Install की प्रतीक्षा करता है, सीधे या दूसरे कार्यों के ज़रिए, इसलिए उल्टी दिशा में लिंक करने का मतलब होगा कि कोई भी शुरू नहीं हो सकता। इससे जुड़ा सवाल, लिंक बदलें?, तब आता है जब कार्य, कार्य पर ही किसी फ़ील्ड से लिंक होते हैं: तब हर कार्य सिर्फ़ एक दूसरे कार्य की प्रतीक्षा कर सकता है।

समाधान

  1. पहले उल्टी दिशा वाला लिंक हटाएँ, या कोई दूसरा कार्य लिंक करें।
  2. किसी कार्य को कई कार्यों की प्रतीक्षा करने देने के लिए, कार्यों को एक अलग लिंक ऑब्जेक्ट से लिंक करें: Setup Wizard, गैंट दृश्य, कार्यों के बीच लिंक।

"स्थिति पहले जैसी रही" या "पूरा पहले जैसा रहा, 100% नहीं हुआ"

कारण: पूरे हुए कार्य की स्थिति पूर्ण प्रतिशत और स्थिति को साथ बाँधता है: 100% पर सेट कार्य को वह स्थिति मिलती है, और वह स्थिति पाने वाला कार्य 100% हो जाता है। जब देखने वाला दोनों में से किसी फ़ील्ड को एडिट नहीं कर सकता, या Status Field में वह मान नहीं है, तो सिर्फ़ उसका किया बदलाव सहेजा जाता है, और यह संदेश बताता है क्यों।

समाधान

  1. यूज़र को पूर्ण प्रतिशत फ़ील्ड और Status Field (स्थिति), दोनों पर Edit दें।
  2. जाँचें कि Status Field (स्थिति) में उस रिकॉर्ड प्रकार के लिए चुना गया मान है, या गैंट दृश्य की सेटिंग में कोई दूसरा चुनें, या दोनों को अलग रखने के लिए इसे खाली छोड़ दें।

"कुछ भी सहेजा नहीं गया। Site survey आपके लिए केवल पढ़ने योग्य है।"

कारण: देखने वाला कार्य देख सकता है पर उसे एडिट नहीं कर सकता, sharing, field security या रिकॉर्ड के owner की वजह से। उसके कार्ड पर आपके लिए केवल पढ़ने योग्य लिखा होता है।

समाधान

  1. कार्य के owner या किसी एडमिन से sharing के ज़रिए Edit पहुँच देने को कहें।
  2. अपने permission set में कार्य के तारीख फ़ील्ड पर Edit जाँचें।

कॉन्फ़िग आयात

Config Library या किसी दूसरे org से कॉन्फ़िगरेशन को Setup Wizard के आयात / निर्यात टैब में पेस्ट करना।

"यह पूरा कॉन्फ़िग नहीं है" या "यह XML जैसा लगता है, JSON नहीं"

कारण: पेस्ट किया गया टेक्स्ट एक पूरा कॉन्फ़िगरेशन नहीं है। कॉपी करते समय वह कट गया, वह कॉन्फ़िगरेशन के JSON की जगह Salesforce metadata XML या Flow है, या उसमें कॉन्फ़िगरेशन की पूरी फ़ाइल है (100 KB से ज़्यादा)।

समाधान

  1. Config Library के कॉपी बटन से, या दूसरे org में कॉन्फ़िगरेशन निर्यात करें से, कॉन्फ़िगरेशन दोबारा कॉपी करें।
  2. पूरा टेक्स्ट पेस्ट करें, पहले { से आखिरी } तक।

आपके पास Flow XML है? उसे Flow के रूप में डिप्लॉय करें: VS Code से Flow डिप्लॉय करें।

"यह कॉन्फ़िगरेशन Related_Object__c के बिना नहीं चल सकता"

कारण: पेस्ट किए गए कॉन्फ़िगरेशन में वह सेटिंग नहीं है जो हर कॉन्फ़िगरेशन को चाहिए, जैसे ऑब्जेक्ट, तारीख फ़ील्ड या कंपोनेंट प्रकार।

समाधान

  1. कॉन्फ़िगरेशन दोबारा पूरा कॉपी करें, या
  2. अपने org से कोई चालू कॉन्फ़िगरेशन निर्यात करें, ताकि ज़रूरी ढाँचा दिखे, और छूटी हुई सेटिंग जोड़ें।

कोई सेटिंग ""Confirmed" सेव करेगा, जो Visit Status में नहीं है, इसलिए Salesforce हर सेव को अस्वीकार करेगा"

कारण: आयात किए गए कॉन्फ़िगरेशन की कोई सेटिंग, जैसे अपने आप भरें या लोग जो स्थितियाँ चुन सकते हैं, ऐसा स्थिति मान इस्तेमाल करती है जो आपके स्थिति फ़ील्ड की सूची में नहीं है। जैसा है वैसा सहेजने पर हर बुकिंग मना हो जाएगी। स्टेटस मान मिलाएँ स्टेप पर, आपके फ़ील्ड में ऐसा कोई मान नहीं है वाला मान तब तक छोड़ा जाता है जब तक आप कोई मान न चुनें।

समाधान

  1. वापस स्टेटस मान मिलाएँ पर जाएँ।
  2. हर एक के लिए चुनें कि आपका कौन सा मान वही अर्थ रखता है, फिर लागू करें और डिप्लॉय पर क्लिक करें।

"इसका फ़्लो Send_Reminder इस संगठन में नहीं है"

कारण: आयात किए गए कॉन्फ़िगरेशन में एक एक्शन बटन है जो ऐसा Flow चलाता है जो आपके org में नहीं है।

समाधान

  1. एक्शन स्टेप पर बटन के लिए अपना कोई Flow चुनें, या यह एक्शन छोड़ें चुनें।
  2. एक्शन बाद में कॉन्फ़िगरेशन के एक्शन में जोड़ सकते हैं।

जो दिख रहा है उसका स्क्रीनशॉट भेजें, हम इसे ठीक करने में आपकी मदद करेंगे।
