1AppExchange से MultiDatePick इंस्टॉल करें

एक managed package: तीनों कंपोनेंट, Setup Wizard और Flow एक्शन।

इंस्टॉलMultiDatePick अभी AppExchange पर नहीं है: लॉन्च पर सूचना पाएँ, और आज ही लाइव डेमो पर हर फ़ीचर आज़माएँ, बिना लॉगिन। लिस्ट होते ही Get It Now पर क्लिक करें और केवल एडमिन, सभी यूज़र या चुनिंदा profile के लिए इंस्टॉल करें।
जाँचेंSetup, Installed Packages में MultiDatePick दिखता है। Lightning App Builder या Flow Builder में MultiDatePick खोजें, तो Dates, Dates & Times और Resource Booking दिखेंगे।
सीखेंपैकेज के साथ गाइडेड टूर आते हैं: Intro to MultiDatePick पूछता है कि आप क्या करना चाहते हैं, फिर बुक करें, चुनें या प्लान करें टूर शुरू करता है। इन्हें Setup Wizard से शुरू करें। टूर Enterprise Edition और उससे ऊपर चलते हैं, क्योंकि Salesforce, Professional Edition को इंस्टॉल किए गए ऐप के Flow एक्शन चलाने नहीं देता। Flow Parser एक्शन के लिए भी Enterprise Edition चाहिए। बाकी सब Professional Edition पर काम करता है, Experience Cloud पर गेस्ट बुकिंग समेत: देखें कौन से org MultiDatePick इस्तेमाल कर सकते हैं।
भाषाएँअगर आपका org Translation Workbench इस्तेमाल करता है, तो MultiDatePick की अनुवादित पिकलिस्ट वैल्यू, जैसे स्टेटस वैल्यू, दिखाने के लिए हर यूज़र की भाषा Setup, Translation Workbench, Translation Language Settings में सक्रिय होनी चाहिए। फ़ील्ड लेबल और कैलेंडर का अपना टेक्स्ट हर हाल में अनुवादित रहता है।

2MultiDatePick permission set असाइन करें

इंस्टॉल करने से किसी को पहुँच नहीं मिलती। Setup, Permission Sets में इनमें से एक असाइन करें।

परमिशन सेटकिसे दें
MultiDatePick - Setupवे एक-दो एडमिन जो कॉन्फ़िगरेशन बनाते हैं। Setup Wizard भी शामिल।
MultiDatePick - Userकैलेंडर इस्तेमाल करने वाले सभी लोग। Wizard नहीं।
MultiDatePick - All Accessएडमिन जो कॉन्फ़िगरेशन बनाते भी हैं और इस्तेमाल भी करते हैं।
MultiDatePick - Guestसार्वजनिक Experience Cloud साइट का guest user।

आपके ऑब्जेक्ट अलग हैं। यूज़र को उन ऑब्जेक्ट और फ़ील्ड पर read और create की पहुँच भी चाहिए जो आपका कॉन्फ़िगरेशन इस्तेमाल करता है। कुछ कमी हो, तो कैलेंडर ठीक उस फ़ील्ड या ऑब्जेक्ट का नाम बताता है।

गाइडेड सेटअपकैलेंडर कहाँ दिखेगा, रिकॉर्ड सहेजने का तरीका, फिर संभावित फ़ील्ड अपने आप भरे हुए। पहली बार के लिए सबसे अच्छा।
सभी सेटिंग एक ही पेज परहर सेटिंग एक साथ सामने। पावर यूज़र और बदलाव करने के लिए सबसे अच्छा।

सहेजे गए कॉन्फ़िगरेशन दोबारा इस्तेमाल होते हैं। किसी पेज या Flow को बस कॉन्फ़िगरेशन का नाम चाहिए। मौजूदा कॉन्फ़िगरेशन टैब पर, कोई बदला हुआ रूप बनाने के लिए कॉन्फ़िगरेशन क्लोन करें, या दूसरे org के लिए उसे JSON के रूप में निर्यात करें।

या Config Library से तैयार कॉन्फ़िगरेशन आयात करें

Config Library के किसी कार्ड पर सेटअप विज़ार्ड के लिए कॉपी करें पर क्लिक करें, उसे विज़ार्ड के आयात / निर्यात टैब में पेस्ट करें, और डिप्लॉय करें।

आपके अपने नाम होना स्वाभाविक है। आयात आपको एक-एक चरण में आगे ले जाता है, और हर जवाब आपके org के सबसे क़रीबी मेल से पहले से भरा होता है: अपने ऑब्जेक्ट चुनें (बुकिंग कहाँ रहती हैं, और क्या बुक होता है), हर फ़ील्ड मिलाएँ उसके काम के हिसाब से, जैसे दिन, आरंभ समय या स्टेटस, या किसी वैकल्पिक फ़ील्ड के लिए उपयोग न करें चुनें, स्टेटस मान मिलाएँ अपनी picklist के मानों से, और कार्रवाइयाँ में अपना कोई Flow चुनें या कोई बटन छोड़ दें। फिर लागू करें और डिप्लॉय, या पहले विज़ार्ड में खोलें ताकि कुछ भी सहेजे जाने से पहले आप उसे समीक्षा चरण में देख सकें।

4Salesforce रिकॉर्ड पेज पर कैलेंडर जोड़ें

Lightning App Builder में MultiDatePick कंपोनेंट को पेज पर ड्रैग करें, अपना Config Name टाइप करें, और सहेजें। ऊपर का आयात डेमो ठीक इसी पर ख़त्म होता है।

पेजआप क्या सेट करते हैं
रिकॉर्ड पेजConfig Name। पेज का रिकॉर्ड अपने आप पैरेंट बन जाता है।
ऐप और होम पेजConfig Name। Static Parent Record Id सिर्फ़ तब, जब विज़ार्ड में जवाब “एक रिकॉर्ड के” हो।

बाकी हर प्रॉपर्टी खाली छोड़ें। उन्हें कॉन्फ़िगरेशन देता है। App Builder की किसी दूसरी प्रॉपर्टी में आप जो भी टाइप करते हैं, वह उस पेज पर सहेजे गए कॉन्फ़िगरेशन की जगह ले लेता है, इसलिए गलती से भरी गई प्रॉपर्टी बिना किसी चेतावनी के कैलेंडर बदल देती है।

पेज पर या बटन के पीछे। जब आप कैलेंडर को पेज पर ड्रैग करते हैं, तो Show Inline (Always Visible) पर टिक लगा होता है, इसलिए कैलेंडर पेज पर ही दिखता है। टिक हटाएँ, तो उसकी जगह एक बटन दिखेगा जो कैलेंडर को पॉप-अप में खोलता है।

नया पेज? उसे Activate करें। Save के बाद, जब Lightning App Builder पूछे तो Activate पर क्लिक करें, और पेज को org default के रूप में या किसी app और profile को असाइन करें। नया पेज activate होने तक किसी को नहीं दिखता।

Load Existing Dates पहले से सहेजी तारीखें दिखाता है। सेव केवल रिकॉर्ड जोड़ता है; मौजूदा रिकॉर्ड कभी delete नहीं करता।

ऐप और होम पेज: किसके रिकॉर्ड?

इन पेज का अपना कोई रिकॉर्ड नहीं होता। विज़ार्ड पूछता है कि किसके रिकॉर्ड दिखाने हैं; सिर्फ़ देखने वाले के डिफ़ॉल्ट है और इसके लिए कुछ और नहीं चाहिए। किसी एक तय रिकॉर्ड पर सहेजने के लिए एक रिकॉर्ड के चुनें, और उसकी Id हर चयन को इस रिकॉर्ड से जोड़ें में पेस्ट करें।

पूरा वॉकथ्रू और उपयोग के उदाहरण: ऐप, होम और Experience पेज।

5MultiDatePick को स्क्रीन फ़्लो (Screen Flow) में जोड़ें

Parent Record Id बाइंड करें और हर कंपोनेंट अपने रिकॉर्ड खुद सहेजता है, loop की ज़रूरत नहीं। Flow Builder में एक Screen खोलें, MultiDatePick खोजें, कंपोनेंट को ड्रैग करें, Config Name सेट करें, और Parent Record Id को उस रिकॉर्ड से बाइंड करें जिसके लिए Flow चलता है, जैसे {!recordId}।

नए स्क्रीन फ़्लो में recordId variable नहीं होता। उसे बाँधने से पहले बनाएँ: Toolbox में New Resource पर क्लिक करें, resource type के रूप में Variable चुनें, API Name में recordId लिखें, data type के रूप में Text चुनें, Available for input पर टिक करें और Done पर क्लिक करें। quick action इसमें रिकॉर्ड की Id भर देता है, और record page भी, जब आप उसके Flow कंपोनेंट पर Pass record ID into this variable पर टिक कर देते हैं।

चेकबॉक्स कॉन्फ़िगरेशन से आते हैं। Flow Builder हर चेकबॉक्स प्रॉपर्टी के पास True और False का विकल्प दिखाता है। उन्हें सेट न करें: Config Name सेट होने पर कॉन्फ़िगरेशन ही उन्हें तय करता है। सिर्फ़ Flow वाली प्रॉपर्टी (Required, Show Inline) आपका चुना मान लेती हैं, और जब तक आप उन्हें True पर सेट नहीं करते, वे बंद रहती हैं।

कौन चला सकता है। Flow चलाने वाले हर व्यक्ति के यूज़र रिकॉर्ड पर Flow User चेकबॉक्स चाहिए, या किसी permission set में Run Flows यूज़र परमिशन। इसके बिना Salesforce Flow की जगह “Insufficient Privileges” दिखाता है।

Flow को वापस क्या मिलता है

कंपोनेंटइस्तेमाल करें
Resource Bookingअपने रिकॉर्ड खुद सहेजता है। bookingSuccessCount और bookingConflictDates पढ़ें।
DatesselectedDates, या रेंज के लिए selectedDateRangesJson।
Dates & TimesselectedDatesWithTimesJson।

पूरा कंट्रोल चाहिए? Dates या Dates & Times के लिए Setup Wizard में इन्हें कौन सेव करेगा? का जवाब मेरा फ़्लो सेव करता है दें (या Parent Record Id खाली छोड़ें), तब चुनी गई तारीखें Flow को मिलती हैं। Parse Date Entries from JSON एक्शन जोड़ें, उसके आउटपुट पर loop चलाएँ, और हर entry का एक रिकॉर्ड बनाएँ। सब कुछ क्लिक से। हर विवरण Flow Cheat Sheet पर है।

पेज के अपने रिकॉर्ड पर तारीख सेट करें

MultiDatePick चुनी गई तारीखों को उनके अपने रिकॉर्ड के रूप में सहेजता है। चुनी गई एक तारीख को रिकॉर्ड के ही किसी Date फ़ील्ड में लिखने के लिए, जैसे किसी Account पर Follow-up Date, एक छोटा Screen Flow इस्तेमाल करें।

  1. Flow Builder में एक Screen Flow बनाएँ, जिसमें recordId नाम का एक Text variable हो, input के लिए उपलब्ध।
  2. Dates के साथ एक Screen जोड़ें। Max Dates Allowed को 1 पर सेट करें और Parent Record Id खाली छोड़ें, ताकि चुनी गई तारीख सहेजी न जाए, बल्कि Flow में जाए।
  3. कंपोनेंट के Selected Dates (Output) पर एक Loop जोड़ें (इसमें वही एक तारीख होती है), और उसके अंदर एक Update Records एलिमेंट: वह रिकॉर्ड जिसकी Id {!recordId} है, आपका Date फ़ील्ड formula DATEVALUE({!Loop_Item}) पर सेट हो, और Loop_Item की जगह आपके loop का अपना नाम हो।
  4. सेव करें, activate करें, और Flow को Flow कंपोनेंट से रिकॉर्ड पेज पर जोड़ें (record Id को recordId में पास करें), या quick action के रूप में।

सेटअप से जुड़े सवाल

एडमिन सबसे पहले जो पूछते हैं, उनके छोटे जवाब।

क्या MultiDatePick सेटअप करने के लिए Apex या डेवलपर चाहिए?

नहीं। आप पैकेज इंस्टॉल करते हैं, ड्रॉपडाउन से ऑब्जेक्ट और फ़ील्ड चुनकर Setup Wizard में कॉन्फ़िगरेशन बनाते हैं, और कंपोनेंट को किसी पेज या Flow स्क्रीन पर रख देते हैं। Apex की ज़रूरत नहीं।

मुझे MultiDatePick का कौन-सा permission set असाइन करना चाहिए?

कॉन्फ़िगरेशन बनाने वाले एडमिन के लिए MultiDatePick - Setup, केवल कैलेंडर इस्तेमाल करने वालों के लिए MultiDatePick - User, दोनों काम करने वाले एडमिन के लिए MultiDatePick - All Access, और सार्वजनिक Experience Cloud साइट के guest user के लिए MultiDatePick - Guest। यूज़र को आपके अपने ऑब्जेक्ट और फ़ील्ड की पहुँच भी चाहिए।

मेरे App Page या Home Page वाले कैलेंडर पर Save बटन क्यों नहीं है?

ऐप और होम पेज का अपना कोई रिकॉर्ड नहीं होता। Setup Wizard में “किसके रिकॉर्ड?” का जवाब दें (“सिर्फ़ देखने वाले के”, “सबके” या “सिर्फ़ मेल खाने वाले” को parent की ज़रूरत नहीं; “एक रिकॉर्ड के” चुनने पर “हर चयन को इस रिकॉर्ड से जोड़ें” में उस रिकॉर्ड की Id डालनी होती है) और कॉन्फ़िगरेशन फिर से सहेजें।

क्या मुझे Flow Builder में हर चेकबॉक्स सेट करना होगा?

नहीं। Config Name में Setup Wizard में सहेजा कॉन्फ़िगरेशन डालें, और हर चेकबॉक्स सेटिंग उसी से आती है। केवल तब चेकबॉक्स खुद सेट करने होते हैं जब आप Config Name छोड़कर प्रॉपर्टी हाथ से सेट करते हैं।

क्या मैं MultiDatePick कॉन्फ़िगरेशन को दूसरे Salesforce org में ले जा सकता हूँ?

हाँ। मौजूदा कॉन्फ़िगरेशन (Existing Configurations) टैब से इसे निर्यात करें, फिर दूसरे org में JSON को आयात / निर्यात टैब में पेस्ट करें। आयात करते समय आप अलग नाम वाले किसी भी ऑब्जेक्ट या फ़ील्ड को मिला सकते हैं।

MultiDatePick के लिए कौन से Salesforce ऑब्जेक्ट चाहिए?

बुक करें के लिए एक बुकिंग ऑब्जेक्ट चाहिए, जिसमें एक तारीख हो और नाम वाले संसाधन ऑब्जेक्ट का lookup हो। चुनें के लिए एक child ऑब्जेक्ट चाहिए, जिसमें एक तारीख हो और अपने रिकॉर्ड का lookup हो। प्लान करें के लिए आरंभ तिथि वाला एक ऑब्जेक्ट चाहिए; प्रोजेक्ट का lookup टास्क को समूह में रखता है। अपने ऑब्जेक्ट इस्तेमाल करें, या MultiDatePick के साथ आने वाले तैयार MDP Schedule और MDP Resource।
