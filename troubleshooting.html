Troubleshooting

Find what you see on screen, then follow the fix. Every picture is the real component.

  • No Save button
  • Wrong component banner
  • Configuration mismatch banner
  • Red "couldn't load its data" banner
  • Configuration Required
  • No resources available
  • Capacity needs both time fields
  • Saved dates don't show
  • Can't pick another date
  • Flow ignores wizard settings
  • Site members see no records
  • Access errors

There is no Save button

Why: the component has no parent record to save the dates against. App, Home and Experience pages have no record of their own.

Fix

  1. Set Static Parent Record Id to the Id of the record the dates belong to.
  2. Check the object, date field and relationship field are filled in, or set Config Name.

In a Flow, no Save button is expected: the flow's own Next button carries the dates.

Amber banner: "Wrong component for this configuration"

Why: Config Name points at a config saved for a different component.

Fix

  1. Point Config Name at a config made for this component, or
  2. Swap in the component the config was built for, or
  3. Open the config in the Setup Wizard and change its Component Type.

Amber banner: "Configuration mismatch"

Why: the page's record, or the Static Parent Record Id, is a different object from the one the config's relationship field looks up to.

Fix

  1. Place the component on a record page of the object the banner names, or
  2. Set Static Parent Record Id to a record of that object, or
  3. Use a config built for this page's object.

Red banner: "This component couldn't load its data"

Why: a field or object name in the setup is wrong, or the user cannot read the object, its fields or the MultiDatePick Apex class.

Fix

  1. Read the gray box: it names the field, object or access that failed.
  2. Wrong name: copy the exact API name from Setup, Object Manager.
  3. No access: assign the MultiDatePick - User permission set plus access to your own objects. On a public Experience site, assign MultiDatePick - Guest to the guest user and give it read access to your own objects.

Booking says "Configuration Required"

Why: Booking needs a resource object, a booking object, a booking date field and a booking resource field. The panel lists the ones that are missing.

Fix

  1. Set Config Name to a Booking config from the Setup Wizard, or
  2. Fill in each property the panel lists.

Booking says "No resources available"

Why: the resource list came back empty. Usually a filter that matches nothing, a wrong resource object, or no resource records yet.

Fix

  1. Check Resource Filter Field and Resource Filter Value against a real record.
  2. Check Resource Object API Name and Resource Name Field.
  3. Create at least one resource record.

Amber banner: "Capacity needs both time fields"

Why: Capacity Field is set, but a booking start or end time field is empty, so capacity could not be enforced.

Fix

  1. Set both Booking Start Time Field and Booking End Time Field, or
  2. Clear Capacity Field.

Dates save, but don't show next time

Why: Load Existing Dates is off. The records saved, but the calendar opens empty every time.

Fix

  1. Turn on Load Existing Dates.
  2. Reload the page. Saved dates appear, colored by status if a status field is set.

I can't pick another date

Why: the component has a date limit: Max Dates Allowed (Date and Date Time) or Max Dates Per Booking (Booking).

Fix

  1. Deselect a date to choose a different one, or
  2. Raise the limit, or set it to 0 for no limit.

Some days or times are grayed out

Why: a booking rule closes them. Minimum Notice (Hours) closes anything starting too soon, Book Up To (Days Ahead) closes days past the rolling window, and Earliest or Latest Selectable Date, blocked dates and each resource's business hours close the rest.

Fix

  1. Check those settings on the component or its config. 0 turns notice and the window off.
  2. Click a closed time slot: a closure says why it is closed.

The slot right after a booking shows as taken

Why: Buffer Between Bookings (Minutes) keeps time free after every booking on the same resource, for cleanup or turnaround.

Fix

  1. Lower the buffer, or set it to 0 for back-to-back bookings.
  2. Conflict Behavior still applies: with Skip, a buffer hit is skipped and reported like any other clash.

"These picks are no longer inside the booking window"

Why: the page sat open long enough for the picked day or time to fall inside the Minimum Notice period. Save checks the rule again so a stale page cannot book too late.

Fix

  1. Remove the dates the message names, or pick a later time.
  2. Save again.

No Add to Calendar button after saving

Why: Show Add to Calendar After Saving is off. It is off by default.

Fix

  1. Turn it on in the component properties or the config, then save a record. The button appears in a bar under the toast.
  2. See "Add to Google Calendar" instead? The browser blocked creating a file, so a single event gets a Google Calendar link.

A Flow screen ignores my wizard settings

Why: Config Name is empty or misspelled. A wrong name shows no error: the component quietly falls back to its defaults.

Fix

  1. Set Config Name to the config's name exactly as the Setup Wizard saved it.
  2. Leave the on/off inputs alone. Every checkbox comes from the config.

Site members can't see records they created

Why: Experience Cloud sharing. Site users only see records that sharing gives them.

Fix

  1. Add a sharing rule (or a sharing set for members) on the object the dates save to, or
  2. Open its external org-wide default.

Access errors

The calendar runs in each user's own permissions. Start with the right permission set, then give access to your own objects and fields.

Permission setAssign to
MultiDatePick - UserEveryone who uses the calendars
MultiDatePick - SetupAdmins who build configs. Includes the Setup Wizard.
MultiDatePick - All AccessAdmins who build and use them
MultiDatePick - GuestThe guest user of a public Experience Cloud site

Error messages name what is wrong: the field, object or validation rule. When a message ends in Details:, that text is Salesforce's own description. Send it to your admin, or to us, and it says exactly where to look.

"You need a MultiDatePick license to use this calendar"

Why: MultiDatePick is licensed per seat, and this user has not been assigned one. The calendar is replaced by this notice, and saves are refused. Site guests never need a seat.

Fix

  1. In Setup, open Installed Packages, then Manage Licenses next to MultiDatePick.
  2. Click Add Users and add the user. They see the calendar on their next page load.

The record won't open, or "insufficient privileges"

Why: the user cannot read the parent object, or sharing hides that record from them.

Fix

  1. Assign MultiDatePick - User.
  2. Give Read on the parent object in a permission set.
  3. Check that sharing gives the user that record.

"No read access to field X on object Y"

Why: the user has no Read field-level security on a field the calendar shows: a status, hover, date or time field.

Fix

  1. Grant Read on the field named in the message.
  2. Do it for admins too. A new custom field is hidden from everyone, System Administrators included, until a permission set grants it.

"Time group failed to save" or "Failed to create bookings" naming a field

Why: the user can read the fields but cannot edit one the save writes. Often a status, second picklist or time field added later.

Fix

  1. Grant Edit on every field the calendar writes: date, start and end time, status, second picklist, name field and the parent lookup.
  2. Grant Create on the object the records save to.

"You don't have permission to do this" with "insufficient access rights on cross-reference id"

Why: the new record points at a record the user cannot see: the parent or the resource.

Fix

  1. Give at least Read on the parent and resource objects, and sharing on those records.
  2. On a public site, book guests against a custom object. Salesforce restricts guest access to Contacts and Accounts.

Guests see an empty calendar

Why: the guest sharing rule is not in effect yet, or the guest profile is missing a step.

Fix

  1. Set the object's external org-wide default to Private, then click Recalculate in Setup, Sharing Settings.
  2. Assign the MultiDatePick - Guest permission set to the guest user, and give it Read on each of your own objects and fields.
  3. Activate the site. Publishing alone is not enough.

The full five-step guest checklist is in the User Guide.
