Troubleshooting

Search for the message you see, or pick a category, then follow the fix. Every picture is the real component.

Setup and placement

Banners and warnings an admin sees while placing a calendar on a page or building its config.

There is no Save button

Why: the component has no parent record and is not set to show all records. App and Home pages have no record of their own.

Fix

  1. Open the config in the Setup Wizard and answer Whose records? (Just the person looking is the usual one), or set Link every pick to this record (App Builder: Static Parent Record Id) to the record the dates belong to.
  2. Check the object, date field and relationship field are filled in, or set Config Name.

In a Flow, Save shows once Parent Record Id is bound. It stays hidden when the wizard's Who saves them? is My flow saves them, or when Parent Record Id is blank: then the flow's Next button carries the dates.

Amber banner: "Wrong component for this configuration"

Why: Config Name points at a config saved for a different component.

Fix

  1. Point Config Name at a config made for this component, or
  2. Swap in the component the config was built for, or
  3. Open the config in the Setup Wizard and change its Component Type.

Amber banner: "Configuration mismatch"

Why: the page's record, or the record in Link every pick to this record, is a different object from the one the config's relationship field looks up to.

Fix

  1. Place the component on a record page of the object the banner names, or
  2. Link every pick to a record of that object, or
  3. Use a config built for this page's object.

Red banner: "This component couldn't load its data"

Why: a field or object name in the setup is wrong, or the user cannot run MultiDatePick or read the object and its fields.

Fix

  1. Read the gray box: it names the exact field, object or Apex class. When MultiDatePick access is missing, the banner says which permission set to assign.
  2. Wrong name: copy the exact API name from Setup, Object Manager.
  3. No access: assign the MultiDatePick - User permission set plus access to your own objects. On a public Experience site, assign MultiDatePick - Guest to the guest user and give it read access to your own objects.

Resource Booking says "Configuration Required"

Why: Resource Booking needs a resource object, a booking object, a booking date field and a booking resource field. The panel lists the ones that are missing.

Fix

  1. Set Config Name to a Resource Booking config from the Setup Wizard, or
  2. Fill in each property the panel lists.

"No configuration named "Room_Bookings" was found"

Why: Config Name takes the config's API name, the one in the Setup Wizard's Existing Configurations list (for example Contact_Event), not its label. A typo, the label, or a config saved a moment ago that is still deploying all end here.

Fix

  1. Open the Setup Wizard, then Existing Configurations, and copy the config's API name.
  2. Paste it into Config Name on the component and save the page.
  3. Just saved the config? Salesforce deploys it in the background, which takes 30 seconds to 2 minutes. Refresh Existing Configurations until it shows, then reload the page.

If the message says the user has no access to MultiDatePick instead, see no access to MultiDatePick.

"The record in Static Parent Record Id (a015g00000XyZ12AAB) no longer exists"

Why: the calendar saves every pick to one fixed record, set in Link every pick to this record (App Builder: Static Parent Record Id), and that record was deleted. Nothing can be saved until it points at a record that exists.

Fix

  1. Open the config in the Setup Wizard and pick another record under Link every pick to this record.
  2. On a page with no Config Name, paste the Id of a current record into Static Parent Record Id in App Builder.

Dates save, but don't show next time

Why: Show dates already saved (App Builder: Load Existing Dates) is off. The records saved, but the calendar opens empty every time.

Fix

  1. Turn on Show dates already saved.
  2. Reload the page. Saved dates appear, colored by status if a status field is set.

"This calendar can't show existing records or save new ones: the field "Visit Date" on Visit is encrypted with Shield Platform Encryption"

Why: Salesforce cannot search or sort by a field that Shield Platform Encryption protects, and the calendar finds and orders its records by their date, time and name fields. Those fields must stay unencrypted. Fields the calendar only displays, such as notes on the hover card, can stay encrypted.

Fix

  1. Turn off encryption for the field the message names, in Setup, Encryption Policy, or
  2. Open the config in the Setup Wizard and choose an unencrypted date or time field instead.

A filter "does not match a field and value", or "Resources could not load"

Why: a filter names a field that is not on the object, a field Salesforce cannot filter by, or a value that does not fit the field. The calendar says which one, for example Record Filter: "Status__c=Confrimed" does not match a field and value you can filter by on Visit. or Resources could not load: the condition "Active__c is yes" does not fit that field.

Fix

  1. Open the config in the Setup Wizard.
  2. Pick the field and value again from the lists under Only records where (the records shown) or Only show ones where (the rooms or people offered).
  3. Typing it in App Builder? Use the field's API name and a value that fits its type: a checkbox takes true or false, a date 2026-12-31.

"Default Field Values: "Priority=Urgent" does not match a field and value on Visit"

Why: Fill in automatically (App Builder: Default Field Values) sets fields on every new record, and one of its pairs names a field the object does not have, or a value the field cannot hold, such as a picklist value that is not in its list.

Fix

  1. Check the field's API name in Object Manager.
  2. Write a value that fits the field: checkboxes take true or false, dates take yyyy-mm-dd or TODAY+7, picklists take one of their values.
  3. Separate several pairs with semicolons: Priority=High; Type=Call.

"Duration is not a Number field", or a booking takes up its whole day

Why: Field that holds the minutes (App Builder: Duration Field) must be a Number field on the booking, not a formula, roll-up, currency or percent. When it is set and Ends at is left blank, each booking ends at its start plus those minutes, so a record whose minutes are blank has no end and takes up its whole day.

Fix

  1. Pick a Number field that holds the length in minutes, or create one.
  2. Fill in the minutes on older records once, for example with a data update or a Flow. Every save, move and resize from the calendar writes them from then on.

"Visit has no active record type Install, which this calendar gives new records"

Why: Record type of new bookings names a record type that was deactivated or renamed. A related message, Confirmed is not a Visit Status for Repair records, means the status picked is not one of the values that record type offers.

Fix

  1. Open the config in the Setup Wizard and pick an active type under Record type of new bookings, or choose Each person's default or Let people choose.
  2. For a status: add the value to that record type's picklist values in Object Manager, or pick another status.

If the message says the person can't create records of that type, see record type not allowed.

"Only admins see this, in the builder: this calendar counts capacity but has no Config Name"

Why: without a saved config named on the page, the calendar can count only the bookings the viewer can see. Bookings hidden from them by sharing are left out, so a full time can look open.

Fix

  1. Save the config in the Setup Wizard.
  2. Type its name into Config Name on the component. Counts then include every booking, as numbers only.

Only admins see this note, in App Builder. Users never do.

No Add to Calendar button after saving

Why: Show Add to Calendar After Saving is off. It is off by default.

Fix

  1. Turn it on in the component properties or the config, then save a record. The button appears in a bar under the toast.
  2. See "Add to Google Calendar" instead? The browser blocked creating a file, so a single event gets a Google Calendar link.

Booking and availability

Why a day, a time, a room or a person can't be picked or booked.

Resource Booking says "No resources available"

Why: the resource list came back empty. Usually a filter that matches nothing, a wrong resource object, or no resource records yet.

Fix

  1. Check Only show ones where (App Builder: Resource Filter Field and Value) against a real record.
  2. Check List people pick from and Field with each one's name (App Builder: Resource Object API Name and Resource Name Field).
  3. Create at least one resource record.

Amber banner: "Capacity needs both time fields"

Why: How many at once (App Builder: Capacity Field) is set, but a booking start or end time field is empty, so capacity could not be enforced.

Fix

  1. Set both Starts at and Ends at (App Builder: Booking Start Time Field and Booking End Time Field), or
  2. Clear How many at once.

I can't pick another date

Why: the component has a date limit: Max Dates Allowed.

Fix

  1. Deselect a date to choose a different one, or
  2. Raise the limit, or set it to 0 for no limit.

I can’t book another time

Why: a booking limit is reached. Max Time Slots caps slots in total, Max Bookings per Day caps separate bookings on one day (times next to each other count as one), and Limit per Person caps one client’s upcoming bookings, counted on the server.

Fix

  1. Raise the limit, or set it to 0 for no limit.
  2. Staff can book past Limit per Person after a confirmation. Site visitors cannot.

Some days or times are grayed out

Why: a booking rule closes them. Minimum Notice (Hours) closes anything starting too soon, Book Up To (Days Ahead) closes days past the rolling window, and Earliest or Latest Selectable Date, blocked dates and each resource's business hours close the rest.

Fix

  1. Check those settings on the component or its config. 0 turns notice and the window off.
  2. Click a closed time slot: a closure says why it is closed.

The slot right after a booking shows as taken

Why: Buffer Between Bookings (Minutes) keeps time free after every booking on the same resource, for cleanup or turnaround.

Fix

  1. Lower the buffer, or set it to 0 for back-to-back bookings.
  2. When a time is taken still applies: with Skip conflicting slots, a buffer hit is skipped and reported like any other clash.

Only some start times show

Why: Only these times is set, so the grid offers only the listed start times. On Resource Booking, Each Resource's Own Times takes over when a room or person holds its own list. Business hours, closures, notice and conflicts still close a listed time.

Fix

  1. Edit the list, or choose Every interval, on the component or its config.
  2. Check the resource's own list in its Each Resource's Own Times field.

"These picks are no longer inside the booking window"

Why: the page sat open long enough for the picked day or time to fall inside the Minimum Notice period. Save checks the rule again so a stale page cannot book too late.

Fix

  1. Remove the dates the message names, or pick a later time.
  2. Save again.

"Cannot book. Already full or closed on: Dec 3" or "Already full or closed, so skipped on save"

Why: another booking already fills that time, or a closure covers it. When a time is taken decides what happens: Block refuses the whole press, Skip conflicting slots books the other days and names the ones it left out, and Allow (book anyway) offers a Book anyway button.

Fix

  1. Remove the dates the message names, or pick another time or resource.
  2. An admin can change When a time is taken on the config's booking rules.

"Daily limit reached (2 of 2)"

Why: Most bookings a day (App Builder: Daily Limit Field) is a number on each room or person, such as a technician's 2 jobs a day. Once a day holds that many bookings it closes for that resource, and a save there says Daily limit reached, so nothing was saved. Every record counts once, a booking over several days counts on each day, and statuses that free the time never count.

Fix

  1. Pick another day or another resource.
  2. Raise the number on the resource record, or leave it blank for no limit.
  3. With When a time is taken set to Allow (book anyway), a booking can go past the limit.

"Garden Room takes no bookings, so nothing was saved"

Why: the resource's How many at once or Most bookings a day is 0. A 0 means it takes no bookings at all, in every setting of When a time is taken. The pickers, the time grid and Week gray it out.

Fix

  1. Pick another resource.
  2. To open it for booking, set the number on its record to 1 or more, or leave it blank for no limit.

"These dates are in the past and cannot be booked" or "These times have already passed"

Why: the calendar does not book days or times that are already over. A day picked yesterday on a page left open overnight, or a time earlier today, is refused when you save.

Fix

  1. Remove the dates or times the message names and pick later ones.
  2. Need to log past days, such as timesheets? An admin can turn on Allow Past Dates on the config.

"These dates are closed: Dec 25. Pick another date or time."

Why: a closure covers the day: a record in the calendar's List of closed days, such as a holiday or staff leave. A closure that names a room or person closes only that resource. The calendar and the save both refuse it.

Fix

  1. Pick another date or time.
  2. If the day should be open, edit or delete the closure record, or narrow Only closures where on the config.

"Garden Room cannot be booked on this calendar. Pick a resource from its list."

Why: the room or person is not in this calendar's list, because Only show ones where leaves it out. It often happens when a record changed after the page opened, for example a room set to inactive. The server refuses it on save, move and reassign.

Fix

  1. Reload the page and pick a resource from the list.
  2. If it should be offered, update the resource record, or change Only show ones where on the config.

"The resources you picked have no start time in common"

Why: with Book several at once, one time must suit every room or person picked. Their business hours or their own start times do not overlap, so no time fits them all. A shorter message, Selected resources have no overlapping business hours, means the same.

Fix

  1. Pick fewer resources, or ones that work the same hours.
  2. An admin can check each resource's opening hours and own start times.

Two people booked the same time

Why: one of two settings lets it happen. When a time is taken set to Allow (book anyway) lets staff book over a taken time on purpose. Or Filter also decides what's busy is on with a filter that uses ME, so only each person's own bookings take up a time. The wizard warns about the second: Filter also decides what's busy is on and Only records where uses ME, so only each person's own bookings take up a time: two people can book the same time.

Fix

  1. Set When a time is taken to Block or Skip conflicting slots.
  2. Turn off Filter also decides what's busy, unless each person really books only their own time.

"Limit per Person is on, but no Client Field is set"

Why: Limit per Person counts each client's bookings through Who it is for (App Builder: Client Field). With no field set, or one Salesforce cannot search, such as long text, a booking cannot be counted, so the save is refused. Admins see Limit per Person can't count bookings by Notes in App Builder.

Fix

  1. Open the config in the Setup Wizard and pick a text, email or lookup field under Who it is for.
  2. Or set Limit per Person to 0 to turn it off.

"Salesforce did not answer, so this booking may already be saved"

Why: the connection dropped or Salesforce was slow after Book was pressed, so the calendar could not tell whether the save finished. It reloads itself so you can see.

Fix

  1. Look for the booking on the reloaded calendar.
  2. Book again only if it is not there.

Public site guests

Calendars on a public Experience Cloud site, where visitors book without signing in.

Guests see an empty calendar

Why: the guest sharing rule is not in effect yet, or the guest profile is missing a step.

Fix

  1. Set the object's external org-wide default to Private, then click Recalculate in Setup, Sharing Settings.
  2. Assign the MultiDatePick - Guest permission set to the guest user, and give it Read on each of your own objects and fields.
  3. Activate the site. Publishing alone is not enough.

The full five-step guest checklist is in the User Guide. Check my site in the Setup Wizard tests each step for you.

Check my site says "Fix needed"

Why: Check my site, on the Setup Wizard's Review and Done steps for a site calendar, tests the site the way a guest meets it. Each line that says Fix needed is one missing step, and it names what to do.

Fix

  1. The site is not live yet: in the site's Workspaces, go to Administration, Settings, click Activate, then publish.
  2. MultiDatePick - Guest permission set: open the guest user and add it under Permission Set Assignments.
  3. Object access or Field access: give the guest user Read on what the calendar shows and Edit on what a booking saves.
  4. A guest can see none of the resources: add a guest sharing rule on the resource object in Setup, Sharing Settings.

Only an admin with MultiDatePick - Setup can run the check.

"This calendar cannot save here: it names no saved configuration for this object"

Why: a site guest's or portal user's booking is checked on the server against a saved config, so privacy and booking rules cannot be skipped. The calendar on the site page has no Config Name, while the object already has a saved config.

Fix

  1. Open the site page in Experience Builder.
  2. Set the calendar's Config Name to the config saved for this site, then publish.

"This calendar cannot be used here: its saved configuration is not set up for a public site"

Why: the site page names a config built for staff. Site guests and portal users may use only a config saved for a site, so a staff calendar's privacy and rules never reach the public by mistake.

Fix

  1. Set the calendar's Config Name to a config saved for the site, or
  2. Make one: in the Setup Wizard, answer Where will you place this component? with Experience Site and save it under a new name.

"This page attaches bookings to a record that site visitors cannot see"

Why: every booking from the site links to one record, set in Bookings attach to, and the guest user cannot read it. Salesforce keeps records private to guests unless a guest sharing rule shares them.

Fix

  1. In Setup, Sharing Settings, add a guest sharing rule on that record's object that shares it with the site's guest user, Read Only.
  2. Run Check my site again: Record bookings attach to should pass.

"Not saved on this public page"

Why: Salesforce lets site guests read and create records, but never change or delete them. Visitors can view and book. Signed-in users with access can edit.

Fix

  1. Nothing to fix: this is Salesforce's guest rule. To let people change their own bookings, give them a sign-in (a member site), or let staff make the change.

"Each booking on this calendar is 60 minutes long, so this time cannot be booked"

Why: for site guests and portal users the server checks every booking against the saved config: Booking Length, Only these times, the statuses people can pick, notice, the booking window and the limits. The page was open while the admin changed one of them, so it offered something the config no longer allows. Related: This calendar takes bookings only at its listed start times and The status Requested cannot be chosen on this calendar.

Fix

  1. Reload the page and book again.
  2. Still refused? The site's admin can check those rules on the config named in Config Name.

Site members can't see records they created

Why: Experience Cloud sharing. Site users only see records that sharing gives them.

Fix

  1. Add a sharing rule (or a sharing set for members) on the object the dates save to, or
  2. Open its external org-wide default.

"The site does not let other websites show it"

Why: you put the calendar on your own website with the embed code, and the Salesforce site refuses to be shown inside another website, which is its default.

Fix

  1. In Experience Builder, open Settings, then Security & Privacy.
  2. Set Clickjack Protection Level to Allow framing of site pages on external domains.
  3. Add your website under Trusted Domains for Inline Framing, then publish.

Guests see the list of locations but no map

Why: the map is drawn by a Salesforce service the site blocks until it is trusted. The calendar cannot tell when a site blocks it, so on a site it opens on the list and offers the map.

Fix

  1. In Experience Builder, open Settings, then Security & Privacy.
  2. Add maps.a.forceusercontent.com as a trusted site for frames, then publish.

Permissions and security

The calendar runs in each user's own permissions. Start with the right permission set, then give access to your own objects and fields.

Permission setAssign to
MultiDatePick - UserEveryone who uses the calendars
MultiDatePick - SetupAdmins who build configs. Includes the Setup Wizard.
MultiDatePick - All AccessAdmins who build and use them
MultiDatePick - GuestThe guest user of a public Experience Cloud site

Error messages name what is wrong: the field, object or validation rule. When a message ends in Details:, that text is Salesforce's own description. Send it to your admin, or to us, and it says exactly where to look.

"You need a MultiDatePick license to use this calendar"

Why: MultiDatePick is licensed per seat, and this user has not been assigned one. The calendar is replaced by this notice, and saves are refused. Site guests never need a seat.

Fix

  1. In Setup, open Installed Packages, then Manage Licenses next to MultiDatePick.
  2. Click Add Users and add the user. They see the calendar on their next page load.

"This user has no access to MultiDatePick, so the configuration was not loaded"

Why: the user has no MultiDatePick permission set, so Salesforce does not let the calendar run its classes for them. The red banner shows it, with Salesforce's own words in the gray box.

Fix

  1. Assign MultiDatePick - User to the user, or MultiDatePick - All Access to an admin who also builds configs.
  2. On a public site, assign MultiDatePick - Guest to the site's guest user.

The record won't open, or "insufficient privileges"

Why: the user cannot read the parent object, or sharing hides that record from them. On a Screen Flow, the user may not be allowed to run flows.

Fix

  1. Assign MultiDatePick - User.
  2. Give Read on the parent object in a permission set.
  3. Check that sharing gives the user that record.
  4. On a Screen Flow, tick Flow User on the user record, or give the Run Flows user permission in a permission set.

"No read access to field X on object Y"

Why: the user has no Read field-level security on a field the calendar shows: a status, hover, date or time field.

Fix

  1. Grant Read on the field named in the message.
  2. Do it for admins too. A new custom field is hidden from everyone, System Administrators included, until a permission set grants it.

"Time group failed to save", "Failed to create bookings" or "You can't edit the field" naming a field

Why: the user can read the fields but cannot edit one the save writes. Often a status, second picklist or time field added later, or a field filled in automatically on every new record.

Fix

  1. Grant Edit on every field the calendar writes: date, start and end time, status, second picklist, name field, the parent lookup and each field in Fill in automatically.
  2. Grant Create on the object the records save to.

"You don't have permission to do this" with "insufficient access rights on cross-reference id"

Why: the new record points at a record the user cannot see: the parent or the resource.

Fix

  1. Give at least Read on the parent and resource objects, and sharing on those records.
  2. On a public site, book guests against a custom object. Salesforce restricts guest access to Contacts and Accounts.

"You don't have access to the closures this calendar uses"

Why: the user cannot read the object that holds the closed days, so the calendar cannot tell which days are closed. Its twin, You don't have access to the records this calendar shows, means the same for the bookings themselves.

Fix

  1. Give Read on the object and the fields the message points to, in a permission set.
  2. Check that sharing gives the user those records.

"You can't create Visit records of the Install record type"

Why: the calendar gives new bookings a record type that this user's profile or permission sets do not include.

Fix

  1. Add the record type to the user's profile or a permission set.
  2. Or set Record type of new bookings to Let people choose, which lists only the types each person can create.

"Salesforce did not let you assign this Visit to Alex Chen"

Why: the booking's room or person is a Salesforce user, and Salesforce refused to make them the owner. The message ends with the reason: you have no access to give records to them, the user is inactive, or their type of user cannot own this kind of record.

Fix

  1. Pick someone else.
  2. Or ask your Salesforce admin for access to give records to that user, or to activate the user.

"You do not have permission to save MultiDatePick configurations"

Why: configs are saved as Salesforce metadata, which needs the Modify Metadata Through Metadata API Functions permission. The MultiDatePick - Setup permission set grants it.

Fix

  1. Assign MultiDatePick - Setup, or MultiDatePick - All Access, to the admin who builds configs.

Flows and actions

The calendar on a Screen Flow, and buttons that run a Flow.

A Flow screen ignores my wizard settings

Why: Config Name is empty or misspelled. Empty, the component quietly uses its defaults. Misspelled, it shows "No configuration named ... was found".

Fix

  1. Set Config Name to the config's name exactly as the Setup Wizard saved it.
  2. Leave the on/off inputs alone. Every checkbox comes from the config.

"Some picked dates are not saved yet. Click Save, or clear them, before continuing."

Why: the screen's Next button was pressed while the calendar still held picks that were never saved, so they would be lost. With times, the message says Some picked times are not booked yet.

Fix

  1. Click Save (or Book) first, then Next.
  2. Or clear the picks you don't want, then Next.

"You cannot run Send Reminder: it needs the "Run Flows" permission or access to its Flow"

Why: the calendar's action button runs a Flow, and Salesforce lets only people who may run that Flow start it.

Fix

  1. Give the user the Run Flows permission in a permission set, or
  2. Give their profile or permission set access to that Flow (Setup, Flows, the Flow, Edit Access).

"The Flow stopped with an error" or "This action is not available here"

Why: the first means the Flow behind an action button ran and failed. The second means the button is not offered for this record anymore: the action was removed from the saved config, or it is set for other statuses.

Fix

  1. For a Flow error, an admin opens the Flow's run history or debug log to see which step failed.
  2. For an action not available, reload the page, then check the action's statuses on the config's actions.

"This Flow has no recordId or recordIds input variable"

Why: the Setup Wizard passes the clicked record to an action's Flow in a variable named recordId (one record) or recordIds (several, from Edit Mode). Without one, the Flow will not know which records to use.

Fix

  1. In Flow Builder, add a Text variable named recordId, or a Text collection named recordIds, available for input.
  2. Save and activate the Flow, then pick it again in the wizard.

Gantt chart

Tasks, links between them and progress on the Gantt view.

There is no Gantt view in the switcher

Why: the Gantt view is opt-in, like the Map view. Available Views left blank offers Calendar, Timeline, Week, Utilization and Agenda.

Fix

  1. In the Setup Wizard, tick Offer the Gantt view on the Views tab, or add gantt to Available Views.
  2. To open on it, set View to gantt.

"Site survey can't go on Dec 6: this calendar doesn't allow that day. Nothing was saved."

Why: the Gantt keeps the same booking rules as the calendar. A task can't move to a closed day or time, onto a person already on another task that day, or to a resource that takes no bookings. The message names the rule each time.

Fix

  1. Drag the task to another day, or give it to someone free.
  2. If the day should be open, an admin checks closures and the days people can pick on the config.

"Install cannot wait on Testing: that would make a loop"

Why: Testing already waits on Install, directly or through other tasks, so linking them the other way would mean neither could start. A related question, Replace the link?, appears when tasks are linked by a field on the task: each task can then wait on only one other.

Fix

  1. Remove the link that runs the other way first, or link a different task.
  2. To let a task wait on several, link tasks with a separate link object: Setup Wizard, Gantt view, Links between tasks.

"The status stays as it was" or "Done stays as it was, not 100%"

Why: Status for a finished task ties Percent done and Status together: a task set to 100% gets that status, and a task given that status is set to 100%. When the viewer cannot edit one of the two fields, or the Status Field does not offer the value, only the change they made is saved, and this message says why.

Fix

  1. Give the user Edit on both the Percent done field and the Status Field.
  2. Check that the Status Field offers the chosen value for that record type, or pick another in the Gantt view settings, or leave it blank to keep them apart.

"Nothing was saved. Read only for you: Site survey"

Why: the viewer can see the task but cannot edit it, because of sharing, field security or the record's owner. Its card says Read only for you.

Fix

  1. Ask the task's owner, or an admin, to give you Edit access through sharing.
  2. Check Edit on the task's date fields in your permission set.

Config import

Pasting a config from the Config Library or another org into the Setup Wizard's Import / Export tab.

"This isn't a complete config" or "This looks like XML, not JSON"

Why: the pasted text is not one whole config. It was cut off while copying, it is Salesforce metadata XML or a Flow instead of the config's JSON, or it holds a whole file of configs (over 100 KB).

Fix

  1. Copy the config again with the Config Library's copy button, or with Export Configuration in the other org.
  2. Paste the whole text, from the first { to the last }.

Have Flow XML? Deploy it as a Flow instead: Deploy a Flow from VS Code.

"This config can't run without Related_Object__c"

Why: the pasted config leaves out a setting every config needs, such as the object, the date field or the component type.

Fix

  1. Copy the config again in full, or
  2. Export a working config from your org to see the shape it needs, and add the missing settings.

A setting "would save "Confirmed", which Visit Status does not have, so Salesforce would refuse every save"

Why: a setting in the imported config, such as Fill in automatically or Statuses people can pick, uses a status value your status field does not list. Saved as it is, every booking would be refused. On the Match status values step, a value marked Your field has no value like this one is left out until you pick one.

Fix

  1. Go back to Match status values.
  2. Pick which of your values means the same for each one, then Apply & Deploy.

"Its Flow Send_Reminder is not in this org"

Why: the imported config has an action button that runs a Flow your org does not have.

Fix

  1. On the Actions step, pick one of your own Flows for the button, or choose Skip this action.
  2. You can add the action later on the config's actions.
